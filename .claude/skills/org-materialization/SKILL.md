# 기관 사전 실체화 — 이름 초안에 출처를 붙여 사전으로

`assets/datasets/08-26-org-dict/org-draft.json` 은 **이름만 있는 초안**입니다.
`src/kb/org.json` 은 **출처가 붙어 실제로 적재되는 사전**입니다.
이 스킬은 **초안 → 사전** 한 칸을 옮기는 절차입니다.

`kb-load.ts` 가 `source_url`·`verified_at` 이 없으면 **통째로 적재를 거부**합니다 —
한 곳이 틀리면 은행 열여섯도 같이 안 실립니다. 그래서 「일단 넣고 나중에」가 없습니다.

## ⚠️ 이 절차의 존재 이유 — 요약시키면 이름이 밀립니다

`org.json` 의 `_note` 가 기록해 둔 사고입니다. 은행연합회 페이지를 **자동 요약**했더니
「한국산업은행」이 「국민은행」으로, 「신한은행」이 「우리은행」으로 붙었습니다.

**위험한 것은 「자동으로 읽는 것」이 아니라 「모델에게 이름을 뽑아 달라고 하는 것」입니다.**
그 방향에서는 없는 이름이 만들어집니다.

> **방향을 뒤집으세요.** 원문을 받아 **우리가 이미 아는 이름이 그 안에 있는지**만
> 문자열로 봅니다. 모델이 이름을 만지지 않으므로 만들어질 이름도, 밀릴 이름도 없습니다.

이 규칙을 어기면 **피해자가 골든타임에 엉뚱한 기관에 겁니다.**

## 절차

1. **`origin/main` 을 별도 워크트리로 받습니다.** 이 저장소는 세션이 여럿 동시에 돕니다 —
   공유 워킹트리에서 작업하면 남의 미커밋 변경을 같이 커밋합니다.
   `git worktree add <scratchpad>/wt-org -b feat/org-<유형> origin/main`

2. **[04-기관정보](../../../docs/research/04-기관정보.md) 를 먼저 읽습니다.**
   이름·유형이 이미 조사돼 있고, **어디서 확인해야 하는지(§8.1)와 무엇이 아직 빈칸인지(§9.1)**
   까지 적혀 있습니다. 우선순위(§9)도 거기 있습니다 — 등록부를 뒤지기 전에 보세요.

3. **출처를 찾습니다** — 아래 「등록부 사다리」를 위에서부터.

4. **대조합니다. 요약시키지 않습니다.**
   ```bash
   python assets/datasets/08-26-org-dict/verify_source.py <URL> CH-xxx
   python assets/datasets/08-26-org-dict/verify_source.py <URL> --table CH-xxx   # 큰 목록
   python assets/datasets/08-26-org-dict/dart_lookup.py <이름>                   # 법인 확인
   ```
   **전부 찾혀야 그 URL 을 씁니다.** 하나라도 없으면 그 곳은 초안에 둡니다.

5. **올립니다.**
   ```bash
   python .claude/skills/org-materialization/scripts/materialize.py \
       --org <org_id> --source <URL> [--tel 1588-0000 --hours "24시간" --caution "..."]
   ```
   초안에서 빼고 사전에 넣으면서 **손으로 맞춰 온 서식을 그대로 유지**합니다
   (`json.dumps(indent=2)` 로 다시 쓰면 실제 몇 줄짜리 변경이 350줄 diff 가 됩니다).

6. **다시 잽니다.** `python assets/datasets/08-26-org-dict/dict_probe.py`
   그리고 `--with-draft` 도. 커버리지·오탐이 어떻게 움직였는지 봅니다.

7. **research 를 되먹입니다.** 04 의 해당 절·§9.1 빈칸 표·변경 이력, 17 의 커버리지 표.
   **막힌 것도 적습니다** — 「무엇을 시도했다가 왜 안 됐나」가 다음 사람의 출발점입니다.

8. **검사** — `npm test` · `typecheck` · `python .github/scripts/doc-integrity.py`.

## 등록부 사다리 — 위에서부터

| | 어디 | 무엇을 증명하나 | 실측 |
| --- | --- | --- | --- |
| 1 | **업권 협회 회원사** | 실재 + **그 업권 소속** — 가장 강합니다 | 여신금융협회는 열립니다(카드사 9/9). 금융투자협회·KTOA·FIU 는 **전부 스크립트로 그려 못 씁니다**(본문 38~83자) |
| 2 | **[한국거래소 상장법인 목록](https://kind.krx.co.kr/corpgeneral/corpList.do?method=download)** | 실재 + 정식 법인명. **업종은 아닙니다** | 2,800곳. **`--table` 필수** — 28만 자라 부분문자열은 「KT」가 「SKT」 안에서 걸립니다 |
| 3 | **[DART 전자공시](https://opendart.fss.or.kr/)** | 실재 + **홈페이지** + **업종명** | 11만 곳(비상장 포함). 기업개황이 셋을 함께 줍니다 — `dart_lookup.py` |
| 4 | **각 사 공식 페이지** | 표기와 연락처 | [04 §8.1](../../../docs/research/04-기관정보.md)이 지정한 방법. 다만 **SPA 는 본문이 6~63자(제목)뿐**이라 근거가 얇습니다 |

**3번이 가장 잘 듭니다.** 기업개황의 **홈페이지 칸이 「법인 ↔ 브랜드」를 이어 줍니다** —
그게 없으면 「스트리미가 고팍스인가」를 못 가립니다(실제로 **아니었습니다**).

## 판단 기준 — 무엇을 근거로 치나

| ✅ 친다 | ✗ 안 친다 |
| --- | --- |
| 등록부 표의 **회사명 칸과 정확히 일치** | 큰 페이지에서 **부분문자열**로 걸린 것 |
| 초안에 **이미 있던 표기**와 일치 | 내가 새로 지어낸 별칭과 일치 |
| DART **홈페이지가 우리가 쓰는 도메인**과 이어짐 | 이름만 비슷하고 도메인·업종이 다름 |
| 법인 사이트 **본문에 브랜드명**이 실려 있음 | 페이지 **제목**에만 있음 (SPA 껍데기) |
| 그 회사 자기 사이트의 **사업자 정보 푸터** | 스토어 리스팅 (경쟁사 이름이 섞임) |

**연락처는 더 엄격합니다.** `report_tel` 은 **신고 창구**를 뜻합니다 —
회사 대표번호를 넣으면 뜻이 어긋납니다. 성격을 모르면 `caution` 에 그대로 적으세요
(「보이스피싱 전용 창구가 아니라 일반 고객센터입니다」). **확인 못 한 칸은 아예 안 넣습니다**
(§11.1 ①) — `null` 을 두면 「확인 못 함」과 「해당 없음」이 한 분기로 뭉갭니다.

## 걸리는 것들 — 전부 실제로 당한 것

| 증상 | 원인 · 대처 |
| --- | --- |
| 어떤 인코딩으로도 안 풀림 | `curl` 에 **`--compressed`** 를 빼면 압축본이 옵니다 |
| 한글이 57자만 남음 | 인코딩을 「먼저 성공한 것」으로 고르면 안 됩니다. 은행연합회는 meta 가 UTF-8 인데 실제로는 cp949 — **한글이 가장 많이 나오는 것**을 고릅니다 |
| 다 찾았는데 하나가 이상함 | 큰 목록에 부분문자열. `--table` 로 회사명 칸과 정확히 |
| 본문이 6~63자 | SPA 껍데기. 제목만 걸린 것이니 **올리지 않습니다** |
| 이름은 맞는데 업종이 엉뚱 | 11만 곳이라 **같은 이름이 여럿**입니다(「빗썸」만 일곱). 홈페이지·업종을 같이 보세요 |
| 커버리지는 올랐는데 오탐도 오름 | 임계값은 사전 크기가 아니라 **표기 길이**입니다 — 세 글자에 거리 1 을 주면 두 글자만 맞아도 걸립니다 → [17 §9 ③](../../../docs/research/17-기관명-사전-실측.md) |

## 이름을 어느 쪽으로 두나

**사전이 하는 일은 인식입니다.** `name` 은 **사람이 실제로 쓰는 표기**로 두고,
법인명은 별칭으로 내립니다 — 「KT」(법인명 「케이티」), 「헬로모바일」(법인 「LG헬로비전」).

**단 출처가 곧 그 업권의 등록부일 때는 반대입니다.** 여신금융협회가 「비씨카드」라고
적으므로 `name` 이 「비씨카드」이고 「BC카드」가 별칭입니다 —
**`source_url` 이 말하는 것과 `name` 이 어긋나면 출처가 출처 구실을 못 합니다.**

## 끝나지 않는 것

**「못 채웠다」도 결과입니다.** 왜 안 됐는지를 `_note` 와 04·17 에 적으면
다음 사람이 같은 벽에 다시 부딪히지 않습니다. 실제로 이 저장소에서
**04 §8.1 이 이미 답을 적어 뒀는데 모르고 등록부를 한참 뒤진 일**이 있었습니다.
