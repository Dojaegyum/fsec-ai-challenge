# 문서 손질 — drift 감사와 은퇴

**판정은 코드가 하고, 링크는 방법을 정한다.** 문서가 살아 있는지는 `src/` 가 그 내용을 따르는지로 판정하고,
피참조 수는 「옮기지 않는 이유」일 뿐입니다. 규칙은 [RFC-001 「은퇴」](../../../rfc/001-repo-structure.md).

| 판정 | 기준 | 하는 일 |
| --- | --- | --- |
| **살아 있음** | 코드가 따르고 있고 읽을 가치가 있음 | 해소된 TODO·「미구현」 표시만 닫음 |
| **낡음** | 코드가 앞서가 문서가 뒤처짐 (구현이 *다르게* 됨) | 백로그에 적고 문서별 PR 로 갱신. **은퇴가 아닙니다** |
| **은퇴** | 전제가 폐기됐거나 내용이 다른 정본에 흡수됨. 끝난 계획 | 제자리 배너 + README 「은퇴」 절. 옮기지도 지우지도 않음 |

「아직 구현 전」은 drift 가 아닙니다 — 문서에 「구현 전」 표시가 없으면 그것만 지적합니다.

## 절차

1. **`origin/main` 을 별도 워크트리에 받습니다.** 공유 워킹트리는 다른 세션이 고치는 중이라 그 상태로 판정하면 남의 미커밋 작업을 사실로 읽습니다.
   `git worktree add <scratchpad>/wt-gardening -b chore/doc-gardening origin/main`
2. **재료를 뽑습니다** — `markers`(문서가 스스로 열어 둔 것) · `inbound`(누가 가리키나) · 파일별 `git log -1 --format=%cs`.
3. **문서 묶음별로 감사관을 병렬로 띄웁니다** (한 묶음 5편·10만 자 안팎). 프롬프트에 반드시: 워크트리 절대 경로 · 읽기 전용 · 판정 셋의 정의 · **모든 주장에 file:line** · 「구현 전」과 「다르게 구현」 구분 · 자기 표기(TODO·미정)가 지금도 맞는지 · 다른 문서·모듈 README 와의 중복 · 검사기(`route-contract`·`schema-names`·`inventory --check`)를 직접 돌려 인용.
4. **판정표를 만듭니다.** 은퇴 후보는 `inbound` 로 「옮기면 무엇이 깨지나」를 같이 봅니다 — 결론은 늘 「옮기지 않는다」이고, 이 결과는 배너에 적을 「이제 볼 곳」을 정하는 데 씁니다.
5. **은퇴시킵니다.** `retire` 로 배너 → README 「은퇴」 절 → **아직 사실인 절은 먼저 제 폴더로 꺼냅니다**(결정 트리대로; 바깥 사실이면 `docs/research/`). 은퇴 문서가 들고 있던 열린 항목은 백로그로.
6. **메타 문서의 거짓을 고칩니다** — `CLAUDE.md`·`spec/README`·`docs/plans/README` 가 「비어 있음」·「뼈대만」 같은 시점 서술을 안고 있는지.
7. **해소된 표시를 닫습니다** — 근거가 file:line 으로 확정된 것만, 취소선 + 「→ 어디서 확정」. **다른 세션이 고치는 중인 파일(`git status` 의 `M`)은 손대지 않고 백로그에 적습니다.**
8. **백로그를 갱신합니다** — `docs/plans/MM-dd-doc-gardening.md`(없으면 새로, 있으면 그 문서에). 낡음 목록은 「갱신 안 하면 반대로 읽히는가」로 순서를 매깁니다. 코드·판단이 필요한 것은 문서 손질 PR 에 섞지 않고 따로 적습니다.
9. **검사기를 전부 돌립니다** — `check` + `doc-integrity` + `inventory --check` + `route-contract` + `schema-names`.
10. **경로를 하나씩 적어 `git add`** 하고 커밋 메시지에 「은퇴 n편 · 정정 n곳 · 백로그」를 나눠 적습니다. `spec/backend/` 를 건드렸으면 백엔드 주인에게 넘어갈 문장을 넣습니다.

## 스크립트

저장소 루트에서. 표준 라이브러리만 씁니다.

```bash
G=".claude/skills/doc-gardening/scripts/gardening.py"

python $G markers                     # 열린 TODO·⬜·미정·미구현·미반영 — file:line
python $G markers --count             # 파일별 건수만
python $G inbound spec/backend/08-14-kb-operations.md   # 누가 가리키나 (decisions/spec/rfc/docs/src 로 묶음)
python $G retire docs/plans/08-22-layer-c-viewers.md \
   --why "태스크 9개가 2026-08-23 에 전부 끝났습니다" \
   --see "각 모듈의 README 와 [qa-readiness](08-23-qa-readiness.md)"
python $G check                       # 은퇴 배너 ↔ README 「은퇴」 절 · RFC 「최종 개정」 ↔ 개정 이력
python $G check -v                    # 은퇴한 문서 목록도
```

`retire` 는 배너만 넣습니다. README 이동과 살아 있는 절 꺼내기는 사람이 하고, `check` 가 그 둘이 맞물렸는지 봅니다.

## 배너 — 이 모양 그대로

```
> **은퇴(YYYY-MM-DD)** — <왜 끝났나 한 줄>. 이제 볼 곳 — <정본 링크>.
> 파일은 링크를 지키려 제자리에 둡니다 — 더 갱신하지 않습니다.
```

「동결」·「폐기」·「아카이브」 같은 다른 말을 쓰지 않습니다 — `check` 가 이 글자만 봅니다.
`rfc/` 는 `폐지됨(→ RFC-NNN)`, `decisions/` 는 `대체됨(→ ADR-NNN)` 이 따로 있습니다.

## 흔한 실수

| 실수 | 실제 |
| --- | --- |
| 「참조가 50곳이니 살아 있는 문서」 | 피참조 수는 판정 근거가 아닙니다. `kb-operations` 는 50곳이 가리켰지만 전제(승인→릴리스 파이프라인)가 폐기돼 은퇴했습니다 |
| 「옮기면 ADR-020 문턱에 걸려 ADR 이 필요」 | 은퇴는 결정을 뒤집는 게 아니라 정본이 어디인지 적는 것입니다. ADR 없이 RFC-001 「은퇴」로 끝납니다 |
| `docs/plans/archived/` 를 만들어 옮김 | ADR·`src/` 주석·`deploy/` 스크립트가 옛 주소를 가리킵니다. ADR 은 고칠 수 없습니다 |
| README 현행 표의 행에 「동결」만 붙임 | 현행과 은퇴가 한 표에 섞이면 목차가 지도 노릇을 못 합니다. 「은퇴」 절로 내립니다 |
| 은퇴 문서 안에 살아 있는 절을 둠 | 「이 문서는 은퇴했지만 이 절만 정본」은 다음 사람이 못 읽습니다. 먼저 꺼냅니다 |
| 공유 워킹트리에서 판정 | 남의 미커밋 변경이 사실로 읽힙니다. `origin/main` 워크트리에서 |
| 낡은 문서를 은퇴시킴 | 코드가 앞서간 것은 갱신 대상입니다. 은퇴는 전제가 폐기된 것만 |
| 해소된 TODO 를 뜨거운 파일에서 닫음 | 다른 세션의 작업과 충돌합니다. 백로그에 적고 머지 뒤에 |
