# assets — 자산 원본

로고·favicon·컴포넌트 원본처럼 **작업의 출처가 되는 파일**을 둡니다.
앱이 빌드에 싣는 파일이 아니라, 그것을 만들어내는 원본입니다.

## `assets/` vs `src/public/` — 헷갈리면 여기

| | `assets/` | `src/public/` |
| --- | --- | --- |
| 무엇 | **원본** — 고해상도 로고, 아이콘 소스, 컴포넌트 raw | **서빙되는 사본** — 실제로 브라우저가 받는 파일 |
| 누가 씀 | 사람이 열어서 편집·추출 | Next.js가 URL로 서빙 |
| 빌드 포함 | 안 됨 | 됨 |

**원본을 `src/public/`에만 두지 마세요.** 크기를 줄이거나 형식을 바꾸는 순간 되돌릴 수 없습니다.
반대로 **`assets/`에 둔 파일은 앱에서 그냥 쓸 수 없습니다** — 필요한 규격으로 내보내
`src/public/`에 넣는 것까지가 한 작업입니다.

## 폴더

| 폴더 | 무엇 |
| --- | --- |
| `brand/` | 로고·favicon·색·타이포 등 브랜드 자산 원본 |
| `components/` | 외부에서 가져온 컴포넌트 raw (출처를 함께 적습니다) |

## 규칙

- **출처를 적습니다.** 외부에서 받은 자산은 어디서 왔고 라이선스가 무엇인지 파일 옆에
  남기세요(같은 이름의 `.md` 또는 폴더 README). 대회 제출물에 들어가는 자산이라
  출처 불명은 나중에 문제가 됩니다.
- 이름 표기는 [ADR-0002](../decisions/0002-프로젝트-이름.md)를 따릅니다 — 브랜드는 `FinAlly`,
  파일·폴더 슬러그는 `fin-ally`.
- 위치 규약은 [RFC-0001](../rfc/0001-저장소-구조-규약.md).
