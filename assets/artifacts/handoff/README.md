# handoff — 화면 디자인 핸드오프

**Claude Design에서 만든 화면 시안을 넘겨받은 그대로 담아둡니다.**
규약은 [RFC-003](../../../rfc/003-design-handoff.md), 근거는 [ADR-030](../../../decisions/030-design-handoff.md)입니다.

**캔버스는 하나입니다** — [FSEC 렌더 페이지 설계](https://claude.ai/design/p/4a2237c5-4584-4fac-aeaa-a256b3404f0b).
화면마다 아트보드가 따로 있고 `?file=` 로 고릅니다. 각 폴더의 `README.md` 가
자기 아트보드를 가리킵니다.

여기 있는 것은 **스냅샷**입니다. 코드가 나중에 바뀌어도 이 폴더는 고치지 않습니다 —
`archived/`와 같은 성격입니다. 시안을 고쳐야 하면 캔버스에서 고쳐 **새 핸드오프를 받습니다.**

## 폴더 하나의 생김새

```
08-19-s04-landing/
  README.md              캔버스 URL · 아트보드 이름 · 대상 화면 ID · 적용 커밋
  PR.md                  시안이 스스로 밝힌 적용 방법·바뀐 것·지킨 것·미결
  globals-additions.css  전역 CSS 추가분 (있으면)
  src/app/page.tsx       적용 위치를 경로로 드러냅니다 (src/ 기준 그대로)
```

폴더 이름은 **`MM-dd-{화면ID}-{slug}`** 이고, `MM-dd`는 **넘겨받은 날**입니다.
개정해도 바꾸지 않습니다 (→ [RFC-001](../../../rfc/001-repo-structure.md) 「파일명 규약」).

**화면 하나에 매이지 않는 핸드오프는 화면 ID 자리를 뺍니다** — `08-21-icons`.
없는 화면 ID를 지어내는 것보다 낫습니다 (→ [RFC-003](../../../rfc/003-design-handoff.md) 규칙 1).

## 여기 있는 `src/`는 앱이 읽지 않습니다

`assets/`는 원본만 두는 곳이고 빌드에 들어가지 않습니다.
경로를 `src/` 기준으로 적어두는 것은 **어디로 옮길지를 경로가 말하게 하려는 것**이지,
앱이 여기서 읽어가기 때문이 아닙니다.
