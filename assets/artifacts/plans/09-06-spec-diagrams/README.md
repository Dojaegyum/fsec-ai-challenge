**원본은 이 PNG 가 아닙니다.** 원본은 기능명세서 원고(저장소 루트 `기능명세서-FinAlly.md`)의
mermaid 코드 블록이고, PNG 는 그것을 구운 산출물입니다. 그림을 고치려면 **원고의 mermaid 를 고치고
다시 굽습니다** — PNG 를 손으로 고치면 원고와 그림이 어긋납니다.

## 굽는 방법

Playwright 의 chromium 에 mermaid 11 을 로컬 스크립트로 넣고, 각 블록을 `mermaid.render` 로 그린 뒤
요소 스크린샷을 찍습니다. 글꼴은 Malgun Gothic, 배율은 2배(deviceScaleFactor 2), 그림이 뷰포트에 맞춰
줄어들지 않도록 `useMaxWidth: false` 로 둡니다. 원고를 CRLF 로 저장하면 블록이 0개로 잡히므로
읽을 때 줄끝을 LF 로 정규화합니다.

## 왜 여기인가

- `assets/artifacts/plans/` 는 「우리가 정한 설계」의 사람이 보는 완성본 자리입니다 ([RFC-001](../../../../rfc/001-repo-structure.md)).
  제출물의 도표는 기획서·명세서와 같은 성격이라 여기 둡니다.
- 폴더 하나로 묶은 것은 번호가 곧 삽입 순서이고 아홉 장이 한 문서에 속하기 때문입니다.
- 접수 제출물 자체(기획서 hwpx · 기능명세서 hwpx 와 원고 md)는 저장소 루트에 한글 이름 그대로 둡니다
  ([접수 핸드오프](../../../../docs/plans/09-04-submission-handoff.md)).
