# 02 · 경유 서비스 8유형별 절차

**같은 "돈을 보냈다"여도 경유한 금융 서비스에 따라 지급정지의 주체·방법·환급 가능성이 다릅니다.**

`spec/03-channel-matrix.md`의 원천 자료이며, `spec/09-data-model.md`의 `kb_entry.channel_id` 분기를 채웁니다.

---

## 1. 유형별 요약

| `channel_id` | 경유 서비스 | 지급정지 요청처 | 환급법 적용 | 신뢰도 |
| --- | --- | --- | --- | --- |
| `CH-bank` | 시중은행 계좌이체 | 송금은행 콜센터 (24h) | 적용 | 확인 |
| `CH-neobank` | 인터넷은행 | 앱 내 신고 + 고객센터 | 적용 | 확인 |
| `CH-securities` | 증권사 계좌 | 해당 증권사 고객센터 | 적용 | 확인 |
| `CH-easypay` | 간편송금 | 이용 선불업자 **+ 연계 은행** | 적용 (개정) | 보도 |
| `CH-crypto` | 가상자산 (거래소) | 거래소 + 수사기관 | **2026.10~ 적용** | 확인 |
| `CH-facetoface` | 대면편취 (현금) | 112 → 수사기관 | 2023.11~ 적용 | 확인 |
| `CH-giftcard` | 상품권 (핀번호) | 발행사 고객센터 | **사각지대** | 추론 |
| `CH-carrier` | 휴대폰 소액결제 | 통신사 + 결제대행사 | **사각지대** | 추론 |

---

## 2. 유형별 상세

### 2.1 `CH-bank` — 시중은행 계좌이체

**표준 절차입니다.** 다른 유형은 이것과의 차이로 설명됩니다.

절차와 기한은 [01-환급절차-기한.md](01-환급절차-기한.md) §1 참조.

| 항목 | 내용 |
| --- | --- |
| 요청처 | 송금한 은행 콜센터. **24시간 접수** |
| 요청 주체 | **피해자 본인** |
| 순서 | 전화 정지 → 3영업일 내 신청 → 공고 2개월 → 환급 |

### 2.2 `CH-neobank` — 인터넷은행

**절차는 표준과 같고 창구가 다릅니다.**

| 항목 | 내용 |
| --- | --- |
| 요청처 | 앱 내 신고 + 고객센터 |
| 차이점 | 영업점이 없어 **비대면 접수 방법**을 안내해야 함 |
| 기한 | `CH-bank`와 동일 |

**예: 토스뱅크, 카카오뱅크, 케이뱅크**

> **TODO(근거 필요)** 각 인터넷은행의 앱 내 신고 경로. 은행마다 메뉴 구조가 다릅니다 → [04-기관정보.md](04-기관정보.md)

### 2.3 `CH-securities` — 증권사 계좌

금융회사 범위에 포함되어 **표준 트리를 그대로 씁니다.** 연락처만 증권사로 바뀝니다.

| 항목 | 내용 |
| --- | --- |
| 요청처 | 해당 증권사 고객센터 |
| 기한 | `CH-bank`와 동일 |

### 2.4 `CH-easypay` — 간편송금

**요청처가 둘입니다.**

| 항목 | 내용 |
| --- | --- |
| 요청처 | 이용한 선불업자 **+ 연계 은행** |
| 개정 내용 | 업자 간 사기이용계좌 정보공유·지급정지 연계 의무화 |
| **핵심** | **"어느 페이로 보냈는지"를 특정해야 정확한 요청처가 나옴** |
| 신뢰도 | **보도** |

**예: 카카오페이, 토스, 네이버페이, 페이코**

**이 유형 때문에 기관(`org`) 축이 필요합니다.** 유형만 알아서는 어디에 연락할지 정할 수 없습니다 → `spec/09-data-model.md` §4.1

> **TODO(근거 필요)** 개정 환급법의 조문 번호와 시행일. 간편송금 정보공유 의무화 부분의 1차 출처를 확인하지 못했습니다.

### 2.5 `CH-crypto` — 가상자산

**시행일로 절차가 완전히 갈립니다.**

| | 2026-09-30까지 | 2026-10-01부터 |
| --- | --- | --- |
| 환급법 적용 | **없음** | **있음** |
| 요청처 | 거래소 (임의 협조) + 112 | 거래소 (**의무**) + 수사기관 |
| 절차 | 형사 절차 중심 | 지급정지 → 환급 |
| 반환 방식 | — | 코인 종류·수량 단위 반환 **또는** 전담기관 매도 후 금전 지급 |
| 평가 시점 | — | **지급정지 시점 기준** |

**출처** — 금융위원회 보도자료 https://www.fsc.go.kr/no010101/86446 (확인 2026-08-16)

**이 유형이 시행일 분기가 실제로 작동하는지 보여주는 증거입니다.** `spec/03-channel-matrix.md`가 "`CH-crypto`는 2026.10.1을 기준으로 같은 질문에 다른 답이 나가야 합니다"라고 정했습니다.

`kb_entry`를 두 벌 두면 됩니다.

```
kb_entry_id             effective_from   effective_until
crypto-no-relief        2020-01-01       2026-09-30
crypto-freeze-request   2026-10-01       NULL
```

> **TODO(근거 필요)** 시행령 세부 규정이 입법예고 단계입니다. 시행 전에 실제 절차를 확인해 `crypto-freeze-request`의 단계를 채워야 합니다.

### 2.6 `CH-facetoface` — 대면편취

**단계 순서 자체가 다릅니다.** 표준 트리에 조건문을 붙이는 방식으로 구현하면 안내 순서가 틀어집니다.

| 항목 | 내용 |
| --- | --- |
| 요청처 | **112 → 수사기관이 계좌 특정** |
| 요청 주체 | **수사기관.** 피해자가 직접 지급정지 불가 |
| 순서 | **112 신고가 절차의 출발점** |
| 적용 시점 | 2023-11-17 |

**출처** — 금융위원회 보도자료 https://www.fsc.go.kr/no010101/81090 (확인 2026-08-16)

**계좌이체형의 3영업일 기한을 그대로 적용하면 안 됩니다.** 기산점과 주체가 다릅니다.

`spec/09-data-model.md`의 `kb_entry.step_seq`가 이 순서 역전을 표현합니다.

> **TODO(근거 필요)** 대면편취형의 30영업일 통지 절차. 조사에서 언급됐으나 시행령 조문 번호를 직접 확인하지 못했습니다. **확인 전까지 KB에 넣지 않습니다.**

### 2.7 `CH-giftcard` — 상품권

**환급 제도 밖입니다.**

| 항목 | 내용 |
| --- | --- |
| 요청처 | 발행사 고객센터 (핀 사용정지 시도) |
| 환급법 | **적용 안 됨** |
| 대안 | 분쟁조정(소비자원) + 형사 절차 |
| 신뢰도 | **추론** |

**근거** — 통신사기피해환급법 제3조 제1항이 재화·용역 거래를 가장한 사기를 제외하고, 지급정지·환급 틀 자체가 계좌를 전제합니다.

> **TODO(근거 필요)** 상품권형이 구제 대상 밖이라는 **명시적 정부 문헌을 찾지 못했습니다.** 법 조문에서 논리적으로 도출한 것입니다. **확인 전까지 사용자 응답에 쓰지 않습니다.**

**기대치를 정직하게 안내해야 합니다.** 환급 가능한 것처럼 안내하면 안 됩니다.

### 2.8 `CH-carrier` — 휴대폰 소액결제

**환급 제도 밖입니다.**

| 항목 | 내용 |
| --- | --- |
| 요청처 | 통신사 + 결제대행사 |
| 환급법 | **적용 안 됨** |
| 대안 | 결제 차단·민원, 민사·형사 |
| 재발 방지 | 소액결제 차단 설정 안내 |
| 신뢰도 | **추론** |

`CH-giftcard`와 같은 TODO가 걸립니다.

## 3. 공통 후속 레이어

어느 분기든 공통으로 붙습니다. `kb_entry.channel_id = NULL` (3순위)에 해당합니다.

| 항목 | 내용 | 신뢰도 |
| --- | --- | --- |
| 명의도용 점검 | 어카운트인포(계좌·카드·대출), 엠세이퍼(휴대폰 개통) | 확인 |
| 악성앱 의심 시 | 초기화 안내 | 확인 |
| 은행권 자율배상 | 2024.1~ 시행. **대상 진단만** → [04-기관정보.md](04-기관정보.md) §3 | 보도 |
| 환급 타임라인 | 통상 3~6개월 기대치 관리 | 보도 |

## 4. 통장묶기 — 별도 트랙

**피해자가 아니라 억울하게 묶인 사람입니다.** `track = 'frozen_account'`.

사기범이 남의 계좌에 소액을 넣어 그 계좌를 사기이용계좌로 만들어 버리는 수법입니다.

| 항목 | 피해자 트랙 | 통장묶기 트랙 |
| --- | --- | --- |
| 목표 | 지급정지를 **걸기** | 지급정지를 **풀기** |
| 첫 행동 | 은행에 지급정지 요청 | 은행에 이의제기 + 소명자료 |
| 기한의 주인 | **본인** (3영업일) | **은행** (5영업일 결과 통보) |
| 필요 서류 | 피해구제 신청서 | 소명자료 |

2026년 5월부터 소명자료 제출 시 **5영업일 안에 결과 통보**하도록 표준화됐습니다. 소액이거나 이력이 없거나 생계와 관련되면 접수 즉시 나머지 금액이 풀립니다.

**출처** — https://www.newsis.com/view/NISX20260430_0003614017 (확인 2026-08-16) · 신뢰도 **보도**

**같은 흐름에 넣으면 안 됩니다.** 통장묶기 사용자에게 "지급정지를 요청하세요"라고 안내하게 됩니다 — 정반대입니다.
