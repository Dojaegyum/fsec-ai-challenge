# RFC-001. 저장소 구조 규약 — 무엇을 어디에 두는가

- 상태: **시행 중**
- 제정: 2026-08-16
- 최종 개정: 2026-08-16
- 근거: [ADR-003](../decisions/003-spec-layout.md) (spec 폴더) ·
  [ADR-004](../decisions/004-agenda-and-assets.md) (AGENDA 이전·assets 신설) ·
  [ADR-005](../decisions/005-filename-convention.md) (파일명 통일) ·
  [ADR-006](../decisions/006-artifacts-and-numbering.md) (HTML 분리·번호 복원) ·
  [ADR-007](../decisions/007-architecture-doc.md) (ARCHITECTURE.md 신설) ·
  [ADR-008](../decisions/008-structure-gate-ci.md) (구조 변경 CI 게이트) ·
  [ADR-017](../decisions/017-doc-integrity-ci.md) (문서 참조 CI 게이트 · `docs/research/` 파일명)

> **이 문서는 규약입니다.** 새 문서나 코드를 만들기 전에 여기를 보고 위치를 정합니다.
> 판단이 애매하면 아래 결정 트리를 순서대로 따르세요 — 위에서 먼저 걸리는 곳이 답입니다.

## 폴더 지도

```
CLAUDE.md         에이전트가 매번 읽는 규약 진입점
README.md         사람이 처음 여는 소개
ARCHITECTURE.md   시스템이 어떻게 구성되는가 — 기술 선택·모듈 배치·배포

rfc/              규약 — 앞으로 이렇게 한다        (현행 · 갱신됨)
decisions/        판단 근거 — 왜 그렇게 정했나      (이력 · 불변)
spec/             제품 계약 — 무엇을 만들어야 하나
  common/           양쪽이 함께 지키는 것
  backend/          서버가 지키는 것
  frontend/         화면이 지키는 것
docs/             읽고 고치는 Markdown 문서
  plans/            구현 계획
  context/          배경·대회 정보 (AGENDA.md)
  research/         바깥 사실 조사 — 법령·기관·제도 (근거 링크 필수)
assets/           산출물·자산 원본 — 빌드에 안 들어가는 것
  brand/            로고·favicon·아이콘
  artifacts/        HTML 아티팩트 (브라우저로 여는 완성 문서)
    plans/            우리가 정한 설계
    context/          확인한 바깥 사실
    archived/         역할이 끝난 것 (이름도 내용도 안 건드림)
src/              코드
  public/           앱이 실제로 서빙하는 사본
.github/          CI — 이 규약을 지키는지 검사하는 게이트
  workflows/        게이트
  scripts/          게이트가 돌리는 검사기 (로컬에서도 같은 명령으로 돕니다)
.claude/          에이전트가 쓰는 도구. 제품에 안 들어감
  skills/{name}/    스킬 — 물어보면 정본을 읽어 답한다 (SKILL.md + scripts/)
```

## 결정 트리 — 새로 만드는 것을 어디에 둘까

위에서부터 순서대로 물어, **먼저 "예"가 나오는 곳**에 둡니다.

1. **제품 코드인가?** (앱이 실행하는 것) → `src/`
2. **저장소를 돌보는 도구인가?** (제품에 안 들어가는 것)
   - 규약을 검사해 **머지를 막는** 것 → `.github/`
   - 물어보면 **답하는** 것, 에이전트가 쓰는 스킬 → `.claude/skills/{name}/`
3. **브랜드 자산인가?** (로고·favicon·아이콘 소스) → `assets/brand/`
   - 앱이 URL로 서빙할 **사본**은 `src/public/`입니다. 원본과 사본을 같은 곳에 두지 않습니다.
4. **HTML 아티팩트인가?** (브라우저로 여는 완성 문서) → `assets/artifacts/`
   - 역할이 끝났다 → `archived/`
   - 우리가 정한 설계 → `plans/`
   - 확인한 바깥 사실 → `context/`
5. **구현이 따라야 할 제품 계약인가?** (이걸 어기면 제품이 틀린다) → `spec/`
   - 백엔드·프론트가 **함께** 지켜야 → `common/`
   - 서버만 → `backend/` · 화면만 → `frontend/`
6. **시스템이 무엇으로 어떻게 도는가인가?** (기술 선택·모듈 배치·저장소·외부 의존·배포) → `ARCHITECTURE.md`
   - 계약은 `spec/`, 구현 선택은 여기입니다. 둘이 어긋나면 **`spec/`이 이깁니다** (→ [ADR-007](../decisions/007-architecture-doc.md))
7. **"왜 이렇게 정했나"의 기록인가?** (맥락·대안·근거) → `decisions/`
8. **"앞으로 이렇게 한다"는 규칙인가?** (작업 방식·구조·규약) → `rfc/`
9. **구현 계획인가?** (무엇을 어떤 순서로 만들지) → `docs/plans/`
10. **배경·대회 정보인가?** → `docs/context/` (대회 일정·진행 상황은 `AGENDA.md`)
11. **바깥 사실을 조사한 것인가?** (법령·기관·제도) → `docs/research/`
12. **에이전트가 매 작업마다 알아야 하는가?** → `CLAUDE.md`

어디에도 안 걸리면 **만들지 말고 물어보세요.** 새 최상위 폴더를 임의로 만들지 않습니다.

## `docs/`와 `assets/artifacts/` — 형식으로 가릅니다

**Markdown은 `docs/`, HTML은 `assets/artifacts/`입니다.** 성격(plans·context)은 양쪽에서 같은 이름으로 반복됩니다.

| | `docs/` | `assets/artifacts/` |
| --- | --- | --- |
| 형식 | Markdown | HTML |
| 무엇 | 읽고 **고치는** 문서 | 브라우저로 여는 **완성 산출물** |
| 크기 | 작음 — 에이전트가 매번 읽어도 됨 | 50KB+ — 스타일·목업 마크업이 대부분 |
| 누가 | 사람·에이전트 | 사람 (발표·공유용) |

형식으로 가르는 이유는 **읽는 비용이 다르기 때문**입니다. HTML 아티팩트는 에이전트가 통째로 읽을 대상이 아니고,
필요한 계약은 이미 `spec/`으로 뽑혀 있습니다. 같은 폴더에 두면 glob·grep이 매번 그걸 긁습니다.

**아티팩트에서 뽑아낸 계약은 `spec/`에 두고, 출처를 문서 머리에 적습니다.**
폴더는 갈라두되 "이 계약이 어디서 왔나"는 문서만 열어도 보이게 합니다.

```
> **출처** — [서비스 기획서 v1.2](<상대경로>/assets/artifacts/plans/08-13-service-plan.html) §4
```

## 파일명 규약

폴더에 따라 **둘 중 하나**입니다.

### `NNN-{slug}` — `rfc/` · `decisions/`

번호가 곧 ID입니다. 문서 안 H1과 참조에서 `RFC-001`·`ADR-003`으로 부릅니다.

```
decisions/003-spec-layout.md   →   # ADR-003. spec을 common·backend·frontend로 …
rfc/001-repo-structure.md      →   # RFC-001. 저장소 구조 규약 …
```

- 3자리 순번, **재사용하지 않습니다.**
- 템플릿은 `000-template.md`.
- 각 폴더 `README.md`의 목록에 반드시 등록합니다.

### `MM-dd-{slug}` — `spec/` · `docs/` · `assets/artifacts/{plans,context}`

순서를 약속하지 않는 이름입니다(→ [ADR-003](../decisions/003-spec-layout.md)).

```
spec/backend/08-14-channel-matrix.md
assets/artifacts/plans/08-13-service-plan.html
```

- **`MM-dd`는 최초 작성일이고, 개정해도 바꾸지 않습니다.** 날짜는 순서가 아니라 **출생기록**입니다 —
  바꾸면 그 문서를 가리키는 모든 링크가 한꺼번에 깨집니다. 최신성은 문서 **안에** 적습니다.
- 같은 날 같은 slug이 겹치면 slug을 더 구체적으로 바꿉니다 (`08-14-api.md` → `08-14-api-case.md`).

### `NN-{제목}` — `docs/research/`

**읽는 순서가 있는 연작**이라 여기만 순번을 씁니다. 제목은 한국어로 씁니다.

```
docs/research/01-환급절차-기한.md
docs/research/06-경로별-실측조사.md
```

- 조사 자료는 **하나가 다음을 전제**합니다(절차 → 유형 → 제도 변경 → 기관 → 미확인 → 실측).
  날짜 접두는 그 순서를 감춥니다.
- **번호를 재배치하지 않습니다.** `decisions/`가 이 파일들을 링크하고 있고,
  ADR은 고치지 않기 때문입니다 — 이름을 바꾸면 **고칠 수 없는 문서의 링크가 깨집니다**.
- 새 자료는 뒤에 붙입니다. 사이에 끼우지 않습니다.

### 공통

- **slug은 영문 kebab-case**, 문서 안 H1은 한국어로 씁니다.
  `docs/research/`만 예외 — 위 항목을 보세요.
- `assets/artifacts/archived/`와 `assets/brand/`는 **예외** — 이름을 건드리지 않습니다.

## 폴더별 규약

### `rfc/` — 규약

- 상태는 `시행 중` 또는 `폐지됨(→ RFC-NNN)`.
- **규약이 바뀌면 이 폴더의 문서를 고칩니다.** 새 번호를 남발하지 마세요 — 규약은 흩어지면 안 지켜집니다.
- 폐지된 규약은 파일을 남기되 맨 위에 `폐지됨`과 후속 번호를 적습니다.

### `decisions/` — 판단 근거 (ADR)

- **한번 쓴 ADR은 고치지 않습니다.** 오탈자 정도는 되지만 결정 내용은 그대로 둡니다.
- 뒤집을 때는 새 ADR을 쓰고 기존 것의 상태를 `대체됨(→ ADR-NNN)`으로 바꿉니다. 상태 줄만은 고쳐도 됩니다.
- 담을 것: 맥락 · 결정 · 근거(검토한 대안 포함) · 결과(감수하는 것) · 재검토 트리거.

### `spec/` — 제품 계약

- **폴더는 "누가 지키는 계약인가"로 가릅니다.** 한쪽만 지켜서 되는 게 아니면 `common/`입니다.
- 각 문서 머리에 **출처 한 줄**을 적습니다.
- 새 문서를 추가하면 **`spec/README.md` 목차에 반드시 넣습니다.** 파일명이 읽는 순서를 알려주지 않으므로, 목차에 없는 문서는 사실상 없는 문서입니다.
- 근거 없는 절차·수치를 쓰지 않습니다. 모르면 `TODO(근거 필요)`.

### `docs/` — Markdown 문서

- `plans/` — **구현 계획.** 무엇을 어떤 순서로 만들지. HTML 기획서는 여기가 아니라 `assets/artifacts/plans/`입니다.
- `context/` — 배경과 대회 정보. `AGENDA.md`가 여기 있습니다 (→ [ADR-004](../decisions/004-agenda-and-assets.md)).
- `research/` — **바깥 사실을 조사한 결과.** 법령 조문·기관 정보·제도 변경 이력입니다.
  `context/`가 대회와 우리 사정이라면 여기는 **제품이 안내할 내용의 근거**입니다.
  **확인 못 한 것은 `TODO(근거 필요)`로 남깁니다** — 추측으로 채우면 잘못된 안내가 곧 피해자의 금전 손실입니다.
  KB 항목을 만들 때 여기의 출처를 그대로 인용합니다 → [KB 운영](../spec/backend/08-14-kb-operations.md).

### `assets/` — 산출물·자산 원본

- **원본만 둡니다.** 앱이 서빙하는 사본은 `src/public/`이고, 둘을 같은 곳에 두지 않습니다.
- **HTML 아티팩트는 단일 파일로** 작성합니다(외부 CSS·JS·폰트 의존 없음).
- 외부에서 받은 자산은 **출처와 라이선스를 함께 적습니다** — 대회 제출물에 들어가므로 출처 불명은 위험합니다.
- `artifacts/archived/`는 **읽되 갱신하지 않고, 이름도 바꾸지 않습니다.**

### `.claude/` — 에이전트가 쓰는 도구

- **스킬은 `.claude/skills/{name}/SKILL.md`** 이고, 실행할 것이 있으면 같은 폴더의 `scripts/`에 둡니다.
- **정본을 복제하지 않습니다.** 스킬은 `spec/`·`ARCHITECTURE.md` 같은 정본을 **읽어서** 답합니다.
  목록을 스킬 안에 적어두면 정본이 둘이 되고, 둘은 반드시 어긋납니다 (→ [ADR-018](../decisions/018-inventory-skill.md)).
- **표준 라이브러리만 씁니다.** 설치 없이 사람이 손으로도 같은 명령을 돌릴 수 있어야 합니다.
- 제품에 들어가지 않습니다 — 빌드·배포 대상이 아닙니다.

### `src/` — 코드

- 패키지·폴더·슬러그는 `fin-ally`, 코드 식별자는 `finAlly`/`FinAlly` (→ [ADR-002](../decisions/002-project-name.md)).
- `AGENTS.md`·`src/CLAUDE.md`는 create-next-app이 생성하고 `next dev`가 다시 씁니다. 지우지 마세요.

## 하지 않는 것

- **같은 주제를 두 폴더에 두지 않습니다.** 정본이 어디인지 알 수 없게 됩니다.
- **`spec/`의 계약을 `ARCHITECTURE.md`에 되풀이하지 않습니다.** 구조 문서는 "무엇으로 구현하는가"만 적습니다.
- **새 최상위 폴더를 임의로 만들지 않습니다.** 필요하면 이 규약을 먼저 고칩니다.
- **HTML을 `docs/`나 `spec/`에 두지 않습니다.** 에이전트가 매번 긁습니다.
- **아카이브를 갱신하거나 이름을 바꾸지 않습니다.**
- **`MM-dd`를 개정 때 바꾸지 않습니다.** 링크가 한꺼번에 깨집니다.
- **번호를 재사용하지 않습니다** (RFC·ADR 모두).

## 이 규약을 바꾸려면

1. 이 문서를 고칩니다(현행 규약이므로).
2. **왜 바꿨는지는 `decisions/`에 새 ADR로 남깁니다.**
3. 영향받는 곳을 같이 고칩니다 — `CLAUDE.md`, `README.md`, 각 폴더의 `README.md`.
4. 상대 링크가 깨지지 않았는지 확인합니다 — **아래 검사기를 돌리면 됩니다.**

## CI가 강제합니다

게이트는 둘입니다. **커밋 전에 로컬에서 먼저 돌려보세요** — CI는 문지기가 아니라 안전망입니다.

```
python .github/scripts/doc-integrity.py
```

### 폴더 구조 (→ [ADR-008](../decisions/008-structure-gate-ci.md))

**폴더가 생기거나 사라지거나 이름이 바뀌면, 같은 변경에 `rfc/` 수정이 없으면 CI가 막습니다**
(`.github/workflows/repo-structure-gate.yml`). 규약이 실제 저장소와 어긋나면 다음 사람이 잘못된 지도를 보기 때문입니다.

- 검사 대상은 **추적되는 파일의 폴더 집합**입니다. git은 빈 폴더를 추적하지 않으므로, 파일이 들어오는 순간 잡힙니다.
- `src/`와 `.github/`의 **내부** 폴더는 제외합니다 — 코드 구조는 계속 늘어나고, 그때마다 규약을 고칠 일은 아닙니다.
  다만 `src`·`.github` **자체**가 생기거나 사라지는 것은 감시합니다.
- 제외 목록을 넓히려면 워크플로의 `EXCLUDE`를 고칩니다. **그 변경도 이 문서 수정을 동반해야 합니다.**

### 문서 간 참조 (→ [ADR-017](../decisions/017-doc-integrity-ci.md))

**문서가 서로를 가리키는 방식이 이 규약과 어긋나면 CI가 막습니다**
(`.github/workflows/doc-integrity.yml` · `.github/scripts/doc-integrity.py`).

| 검사 | 무엇이 걸리나 |
| --- | --- |
| 링크 | 없는 파일을 가리키는 상대링크 |
| 앵커 | 대상 문서에 없는 `#절` |
| ID | 정의되지 않은 `ADR-NNN`·`RFC-NNN`·`F-xx`·`S-xx`·`CH-xxx` |
| 파일명 | 위 「파일명 규약」 위반 |
| 번호 | RFC·ADR 번호 중복 |
| 목차 | 폴더 `README.md`에 등록되지 않은 문서 |
| ADR | **결정 내용**의 사후 수정 · 삭제 · 번호 변경 |
| 대체 | `대체됨(→ ADR-NNN)`의 상대가 없거나, 대체한 쪽이 그 사실을 안 적은 것 |

- **ADR에서 막는 것은 "결정 내용"뿐입니다** — H1의 결정 문장과 「## 결정」 절.
  맥락·근거·결과·링크·오탈자·상태 줄은 고쳐도 됩니다.
- **코드블록 안의 링크는 보지 않습니다.** 예시이지 참조가 아니기 때문입니다.
- **순환참조는 검사하지 않습니다.** 문서끼리 서로 가리키는 것은 결함이 아닙니다.
- **문서 사이의 모순은 이 게이트가 잡지 못합니다.** 기계가 판정할 수 없는 것이라
  일부러 넣지 않았습니다 — 그건 사람이 봅니다.
- ID 정의처를 옮기면 검사기의 `ID_SOURCES`도 같이 고칩니다.
