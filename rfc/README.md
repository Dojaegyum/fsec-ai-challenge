# RFC — 제안과 논의

구현 방식이 갈리는 문제를 **spec을 고치기 전에** 글로 정리하는 곳입니다.

## 언제 RFC를 쓰나

- 선택지가 둘 이상이고 되돌리기 비싼 것 (저장소·인증·상태 관리 구조 등)
- spec의 `TODO(미정)`을 채우려는데 정하는 데 근거가 필요한 것
- 이미 채택된 결정을 뒤집자는 제안

반대로, **정답이 하나뿐인 것은 RFC 없이** 그냥 spec에 쓰고 구현하세요.

## 흐름

```
rfc/NNNN-제목.md (초안)
   ↓ 논의
채택 → decisions/NNNN-....md (왜 그렇게 정했나)
      + spec/ 갱신              (무엇을 지켜야 하나)
      + RFC 상태를 '채택됨'으로
폐기 → RFC 상태를 '폐기'로. 파일은 지우지 않습니다
```

RFC는 **제안**이고 ADR은 **결정**입니다. 하나의 RFC가 여러 ADR을 낳을 수 있습니다.

## 파일명

`NNNN-제안을-한-문장으로.md` — 예: `0001-사건-스토어-선택.md`

번호는 순번이며 재사용하지 않습니다. 템플릿은 [0000-template.md](0000-template.md).
