# RFC — 규약

**지금 지켜야 할 규칙**을 모아둔 곳입니다. 작업 방식·저장소 구조·명명처럼
"앞으로 이렇게 한다"에 해당하는 것이 여기 삽니다.

## 시행 중인 규약

| 번호 | 규약 | 상태 |
| --- | --- | --- |
| [001](001-repo-structure.md) | 저장소 구조 — 무엇을 어디에 두는가 | 시행 중 |
| [002](002-kb-authoring.md) | 매뉴얼 KB를 파일로 쓰고, 검수를 거쳐 적재한다 | 시행 중 |

## `rfc/`와 `decisions/`의 차이

| | `rfc/` (여기) | `decisions/` |
| --- | --- | --- |
| 시제 | **현재형** — "이렇게 한다" | **과거형** — "이렇게 정했다" |
| 성격 | 현행 규약 | 판단 근거의 이력 |
| 바뀌면 | **문서를 고친다** | 고치지 않고 **새 번호**를 쓴다 |
| 읽는 목적 | 지금 뭘 지켜야 하나 | 왜 그렇게 됐나 |

**규약을 바꾸면 여기를 고치고, 그 문서의 「개정 이력」에 한 줄 적습니다.**
왜 바꿨는지는 커밋 메시지에 남습니다.

**ADR까지 가는 것은 규약을 뒤집거나 새 규약을 세울 때뿐입니다**
(→ [ADR-020](../decisions/020-adr-threshold.md)). 파일 위치나 이름을 손보는 변경은
여기서 끝냅니다 — 그때마다 ADR을 만들면 `decisions/`에서 진짜 판단이 묻힙니다.

## 제품 규칙은 여기가 아닙니다

서비스가 무엇을 해야 하는지는 [`spec/`](../spec/)입니다. 기준은 **"어기면 무엇이 깨지나"**입니다.

- 어기면 **제품이 잘못 동작한다** → `spec/` (예: PII 경계, 슬롯 티어링)
- 어기면 **저장소가 어질러진다** → `rfc/` (예: 폴더 배치, 파일명)

## 파일명과 번호

**파일명은 `NNN-{slug}.md`** — 번호가 곧 ID입니다 (→ [RFC-001](001-repo-structure.md)).

```
파일   rfc/001-repo-structure.md
문서   # RFC-001. 저장소 구조 규약 — 무엇을 어디에 두는가
참조   "RFC-001 참조"
```

- 3자리 순번이며 **재사용하지 않습니다.**
- slug은 영문 kebab-case, 문서 안 H1은 한국어.
- 템플릿은 [000-template.md](000-template.md).
- 새 규약을 추가하면 **위 「시행 중인 규약」 표에 등록**합니다.

번호 001은 처음에 출전 주제 선정 제안에 썼다가, RFC를 규약 전용으로 정리하면서
그 내용을 [ADR-001](../decisions/001-topic-selection.md)로 옮기고 번호를 다시 썼습니다.
**이후로는 재사용하지 않습니다.**

## 규약을 새로 쓸 때

- **먼저 기존 규약을 고칠 수 있는지 봅니다.** 규약은 흩어지면 안 지켜집니다 —
  새 번호는 정말 별개 주제일 때만 만듭니다.
- 폐지할 때는 파일을 지우지 말고 맨 위에 `폐지됨(→ RFC-NNN)`을 적습니다.
- **새 규약을 세우거나 기존 규약을 뒤집었다면** [`decisions/`](../decisions/)에 ADR을 남깁니다.
  다듬거나 항목을 더한 것은 해당하지 않습니다 (→ [ADR-020](../decisions/020-adr-threshold.md)).
- 각 규약 문서에는 **「개정 이력」 절**을 둡니다. 고칠 때마다 날짜·무엇·근거를 한 줄 적습니다.
