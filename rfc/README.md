# RFC — 규약

**지금 지켜야 할 규칙**을 모아둔 곳입니다. 작업 방식·저장소 구조·명명처럼
"앞으로 이렇게 한다"에 해당하는 것이 여기 삽니다.

## 시행 중인 규약

| 번호 | 규약 | 상태 |
| --- | --- | --- |
| [0001](0001-저장소-구조-규약.md) | 저장소 구조 — 무엇을 어디에 두는가 | 시행 중 |

## `rfc/`와 `decisions/`의 차이

| | `rfc/` (여기) | `decisions/` |
| --- | --- | --- |
| 시제 | **현재형** — "이렇게 한다" | **과거형** — "이렇게 정했다" |
| 성격 | 현행 규약 | 판단 근거의 이력 |
| 바뀌면 | **문서를 고친다** | 고치지 않고 **새 번호**를 쓴다 |
| 읽는 목적 | 지금 뭘 지켜야 하나 | 왜 그렇게 됐나 |

**한 변경이 둘 다 낳는 것이 정상입니다.** 규약을 바꾸면 여기를 고치고(현행),
왜 바꿨는지는 ADR로 남깁니다(이력).

## 제품 규칙은 여기가 아닙니다

서비스가 무엇을 해야 하는지는 [`spec/`](../spec/)입니다. 기준은 **"어기면 무엇이 깨지나"**입니다.

- 어기면 **제품이 잘못 동작한다** → `spec/` (예: PII 경계, 슬롯 티어링)
- 어기면 **저장소가 어질러진다** → `rfc/` (예: 폴더 배치, 파일명)

## 파일명

`NNNN-제목.md` — 번호는 순번이며 **재사용하지 않습니다.** 템플릿은 [0000-template.md](0000-template.md).

번호 0001은 처음에 출전 주제 선정 제안에 썼다가, RFC를 규약 전용으로 정리하면서
그 내용을 [ADR-0001](../decisions/0001-출전-주제-선정.md)로 옮기고 번호를 다시 썼습니다.
**이후로는 재사용하지 않습니다.**

## 규약을 새로 쓸 때

- **먼저 기존 규약을 고칠 수 있는지 봅니다.** 규약은 흩어지면 안 지켜집니다 —
  새 번호는 정말 별개 주제일 때만 만듭니다.
- 폐지할 때는 파일을 지우지 말고 맨 위에 `폐지됨(→ RFC-NNNN)`을 적습니다.
- 규약을 바꿨으면 왜 바꿨는지 [`decisions/`](../decisions/)에 ADR을 남깁니다.
