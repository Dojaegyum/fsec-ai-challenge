# RFC-0001. 저장소 구조 규약 — 무엇을 어디에 두는가

- 상태: **시행 중**
- 제정: 2026-08-16
- 최종 개정: 2026-08-16
- 근거: [ADR-0003](../decisions/08-16-spec-layout.md) (spec 폴더·파일명) ·
  [ADR-0004](../decisions/08-16-agenda-and-assets.md) (AGENDA 이전·assets 신설) ·
  [ADR-0005](../decisions/08-16-filename-convention.md) (파일명 전 폴더 통일·번호 분리)

> **이 문서는 규약입니다.** 새 문서나 코드를 만들기 전에 여기를 보고 위치를 정합니다.
> 판단이 애매하면 아래 결정 트리를 순서대로 따르세요 — 위에서 먼저 걸리는 곳이 답입니다.

## 폴더 지도

```
CLAUDE.md         에이전트가 매번 읽는 규약 진입점
README.md         사람이 처음 여는 소개

rfc/              규약 — 앞으로 이렇게 한다        (현행 · 갱신됨)
decisions/        판단 근거 — 왜 그렇게 정했나      (이력 · 불변)
spec/             제품 계약 — 무엇을 만들어야 하나
  common/           양쪽이 함께 지키는 것
  backend/          서버가 지키는 것
  frontend/         화면이 지키는 것
docs/             사람이 보는 문서
  plans/            우리가 만들 것의 설계
  context/          바깥 세상의 사실 — 법령·절차 리서치, 주최기관 분석, 대회 정보(AGENDA.md)
  archived/         역할이 끝난 문서 (이름도 내용도 건드리지 않음)
assets/           자산 원본 — 로고·favicon·컴포넌트 raw
  brand/            브랜드 자산
  components/       외부 컴포넌트 원본
src/              코드
  public/           앱이 실제로 서빙하는 사본
```

## 결정 트리 — 새로 만드는 것을 어디에 둘까

위에서부터 순서대로 물어, **먼저 "예"가 나오는 곳**에 둡니다.

1. **실행되는 코드인가?** → `src/`
2. **자산의 원본인가?** (로고·favicon·아이콘 소스·컴포넌트 raw) → `assets/`
   - 앱이 URL로 서빙할 **사본**은 `src/public/`입니다. 원본과 사본을 같은 곳에 두지 않습니다.
3. **사람이 읽는 문서인가?** (기획서·리서치·분석)
   - 역할이 끝났다(더 이상 갱신하지 않는다) → `docs/archived/`
   - **우리가 만들 것의 설계** → `docs/plans/`
   - **바깥 세상의 사실 조사** (법령·기관 절차·주최기관·경쟁) → `docs/context/`

   `plans`와 `context`는 **형식이 아니라 성격으로 가릅니다.** "우리가 정한 것"이면 plans,
   "확인한 사실"이면 context입니다 — Markdown이든 HTML이든 같습니다
   (그래서 `AGENDA.md`도, 사후처리 절차 리서치도 `context/`에 있습니다).
4. **구현이 따라야 할 제품 계약인가?** (이걸 어기면 제품이 틀린다) → `spec/`
   - 백엔드·프론트가 **함께** 지켜야 → `spec/common/`
   - 서버만 → `spec/backend/`
   - 화면만 → `spec/frontend/`
5. **"왜 이렇게 정했나"의 기록인가?** (맥락·대안·근거) → `decisions/`
6. **"앞으로 이렇게 한다"는 규칙인가?** (작업 방식·구조·규약) → `rfc/`
7. **대회 정보·일정·진행 상황인가?** → `docs/context/AGENDA.md`
8. **에이전트가 매 작업마다 알아야 하는가?** → `CLAUDE.md`

어디에도 안 걸리면 **만들지 말고 물어보세요.** 새 최상위 폴더를 임의로 만들지 않습니다.

## 헷갈리는 세 쌍 — 이것만 구분하면 됩니다

### `spec/` vs `rfc/` — 제품이냐 우리냐

| | `spec/` | `rfc/` |
| --- | --- | --- |
| 무엇에 대한 규칙 | **제품** — 서비스가 무엇을 해야 하는가 | **우리** — 팀과 저장소가 어떻게 일하는가 |
| 어기면 | 제품이 잘못 동작한다 | 저장소가 어질러진다 |
| 예 | PII 경계, 슬롯 티어링, 화면 계약 | 폴더 배치, 파일명, 커밋 규칙 |

*"기한 계산에 LLM을 쓰지 않는다"* 는 제품 규칙이라 `spec/`(과 `CLAUDE.md` 불변 규칙)입니다.
*"spec 파일명은 `MM-dd-{title}.md`"* 는 작업 규칙이라 `rfc/`입니다.

### `rfc/` vs `decisions/` — 현재형이냐 과거형이냐

| | `rfc/` | `decisions/` |
| --- | --- | --- |
| 시제 | **현재형** — "이렇게 한다" | **과거형** — "이렇게 정했다" |
| 수명 | 규약이 바뀌면 **문서를 고친다** | **고치지 않는다.** 뒤집으면 새 번호를 쓰고 옛것을 `대체됨`으로 |
| 읽는 목적 | 지금 뭘 지켜야 하는지 | 왜 그렇게 됐는지 |

**한 변경이 둘 다 낳는 것이 정상입니다.** 규약을 바꾸면 → `rfc/`를 고치고(현행) + `decisions/`에 새 ADR을 쓴다(왜 바꿨나).
ADR-0003이 spec 폴더 구조를 정했고, 그 결과 지켜야 할 규칙이 이 문서에 적혀 있는 관계입니다.

### `docs/plans/` vs `docs/archived/` — 살아 있나

역할이 끝난 문서는 **지우지 않고 `archived/`로 옮깁니다.** 근거 원문이기 때문입니다.
옮긴 뒤에는 **갱신하지 않습니다** — 고쳐야 할 내용이 생겼다면 그건 `spec/`이나 새 기획 문서로 갑니다.

## 파일명 규약 — `MM-dd-{slug}` (전 폴더 공통)

`rfc/` · `decisions/` · `spec/` · `docs/plans/` · `docs/context/`는 **같은 파일명 규칙**을 씁니다.

```
decisions/08-16-topic-selection.md
          └┬─┘ └──────┬───────┘
           │          └─ 영문 kebab-case slug
           └─ 최초 작성한 월-일 (MM-dd)
```

- **`MM-dd`는 최초 작성일이고, 개정해도 바꾸지 않습니다.** 날짜는 순서가 아니라 **출생기록**입니다 — 바꾸면 그 문서를 가리키는 모든 링크가 한꺼번에 깨집니다. 최신성은 문서 **안에** 적습니다.
- **slug은 영문 kebab-case**, 문서 안 H1은 한국어로 씁니다.
- 같은 날 같은 slug이 겹치면 slug을 더 구체적으로 바꿉니다 (`08-14-api.md` → `08-14-api-case.md`).
- 날짜가 의미 없는 문서(템플릿)는 `00-00-`을 씁니다.

### 번호 ID는 파일명이 아니라 문서 안에

`rfc/`와 `decisions/`만 번호 ID를 갖습니다 — **`RFC-0001`·`ADR-0003`**. 이건 **문서 안 H1과 참조에만** 쓰고 파일명에는 넣지 않습니다.

| | 파일 | 문서 안 ID |
| --- | --- | --- |
| RFC | `rfc/08-16-repo-structure.md` | `# RFC-0001. 저장소 구조 규약 …` |
| ADR | `decisions/08-16-topic-selection.md` | `# ADR-0001. 출전 주제를 …` |

**번호로 파일을 찾을 수 없으므로, 각 폴더 `README.md`의 목록이 번호↔파일 대응표입니다.**
새 문서를 만들면 반드시 그 표에 넣으세요. 번호는 재사용하지 않습니다.

## 폴더별 규약

### `rfc/` — 규약

- 상태는 `시행 중` 또는 `폐지됨(→ RFC-NNNN)`.
- **규약이 바뀌면 이 폴더의 문서를 고칩니다.** 새 번호를 남발하지 마세요 — 규약은 흩어지면 안 지켜집니다.
- 폐지된 규약은 파일을 남기되 맨 위에 `폐지됨`과 후속 번호를 적습니다.
- 템플릿: [00-00-template.md](00-00-template.md)

### `decisions/` — 판단 근거 (ADR)

- **한번 쓴 ADR은 고치지 않습니다.** 오탈자 정도는 되지만 결정 내용은 그대로 둡니다.
- 뒤집을 때는 새 ADR을 쓰고 기존 것의 상태를 `대체됨(→ ADR-NNNN)`으로 바꿉니다.
- 담을 것: 맥락 · 결정 · 근거(검토한 대안 포함) · 결과(감수하는 것) · 재검토 트리거.
- `MM-dd`는 **결정한 날**입니다. 같은 날 여러 결정이 나오는 것은 정상입니다.

### `spec/` — 제품 계약

- **폴더는 "누가 지키는 계약인가"로 가릅니다.** 한쪽만 지켜서 되는 게 아니면 `common/`입니다 (→ [ADR-0003](../decisions/08-16-spec-layout.md)).
- 각 문서 머리에 **출처를 적습니다** — `출처: docs/plans/08-13-service-plan.html §7`. 이 계약이 어디서 왔는지가 문서만 열어도 보여야 합니다.
- 새 문서를 추가하면 **`spec/README.md` 목차에 반드시 넣습니다.** 파일명이 읽는 순서를 알려주지 않으므로, 목차에 없는 문서는 사실상 없는 문서입니다.
- 근거 없는 절차·수치를 쓰지 않습니다. 모르면 `TODO(근거 필요)`.

### `docs/` — 사람이 보는 문서

- **HTML 아티팩트는 단일 파일로** 작성합니다(외부 CSS·JS·폰트 의존 없음).
- **형식으로 가르지 않습니다.** HTML이든 Markdown이든 성격에 따라 `plans/`(우리가 정한 설계)와 `context/`(확인한 외부 사실)로 갑니다. `AGENDA.md`(Markdown)가 `context/`에 있는 것이 그 예입니다 (→ [ADR-0004](../decisions/08-16-agenda-and-assets.md)).
- `plans/`·`context/`는 위 `MM-dd-{slug}` 규칙을 따릅니다(확장자만 `.html`).
- **`archived/`는 예외입니다** — 읽되 갱신하지 않는 곳이라 **파일명을 바꾸지 않습니다.** 이름을 정리해봐야 링크만 깨지고 얻는 게 없습니다.

### `assets/` — 자산 원본

- **원본만 둡니다.** 앱이 서빙하는 사본은 `src/public/`이고, 둘을 같은 곳에 두지 않습니다.
- 외부에서 받은 자산은 **출처와 라이선스를 함께 적습니다** — 대회 제출물에 들어가므로 출처 불명은 위험합니다.
- 상세는 [assets/README.md](../assets/README.md).

### `src/` — 코드

- 패키지·폴더·슬러그는 `fin-ally`, 코드 식별자는 `finAlly`/`FinAlly` (→ [ADR-0002](../decisions/08-16-project-name.md)).
- `AGENTS.md`·`src/CLAUDE.md`는 create-next-app이 생성하고 `next dev`가 다시 씁니다. 지우지 마세요.

## 하지 않는 것

- **같은 주제를 두 폴더에 두지 않습니다.** 정본이 어디인지 알 수 없게 됩니다.
- **새 최상위 폴더를 임의로 만들지 않습니다.** 필요하면 이 규약을 먼저 고칩니다.
- **아카이브를 갱신하거나 이름을 바꾸지 않습니다.**
- **파일의 `MM-dd`를 개정 때 바꾸지 않습니다.** 링크가 한꺼번에 깨집니다.
- **파일명에 번호(`0001-`)를 넣지 않습니다.** 번호는 문서 안 ID입니다.
- **번호를 재사용하지 않습니다** (RFC·ADR 모두).
- **HTML이라는 이유로 폴더를 가르지 않습니다.** 형식이 아니라 성격으로 나눕니다 — 형식 기준은 `AGENDA.md` 같은 Markdown 배경 문서에서 바로 깨집니다.

## 이 규약을 바꾸려면

1. 이 문서를 고칩니다(현행 규약이므로).
2. **왜 바꿨는지는 `decisions/`에 새 ADR로 남깁니다.**
3. 영향받는 곳을 같이 고칩니다 — `CLAUDE.md`, `README.md`, 각 폴더의 `README.md`.
4. 상대 링크가 깨지지 않았는지 확인합니다.
