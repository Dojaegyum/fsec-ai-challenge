## 이 판정은 절차를 가르지 않습니다

**분기축은 경유 서비스 하나입니다** → [03-channel-matrix.md](../../../spec/backend/08-14-channel-matrix.md).
여기 결과는 **화면 표시와 관리자 조회에서만** 소비됩니다.

그래서 판정이 없어도 사용자가 막히지 않습니다. 이 사실이 아래 설계를 전부 결정합니다 —
**못 내면 안 내고, 그래도 멈추지 않습니다.**

## 판정보다 검증이 중심입니다

판정 자체는 모델이 합니다. 이 모듈이 맡는 것은 **그 판정이 근거를 갖고 있는지**
확인하는 일입니다. `13-module-boundaries.md` 가 이 모듈의 「절대 하지 않는 것」을
**「근거 없이 판정하기」** 하나로 적었습니다.

| # | 확인 | 어기면 |
| --- | --- | --- |
| 1 | 분류·위험도가 **허용 목록 안**인가 | 판정을 버립니다 (`unknown_value`) |
| 2 | 근거가 **하나 이상** 붙어 있는가 | 버립니다 (`no_span`) |
| 3 | 그 근거가 **입력에 실제로 있는가** | 그 근거를 버리고, 남은 게 없으면 판정도 버립니다 |

**3번이 핵심입니다.** 모델은 그럴듯한 문장을 만들어 붙일 수 있는데, 입력에 없는
문장은 그 자리에서 걸립니다. `pii-restorer` 가 매핑에 없는 토큰을 복원하지 않는
것과 같은 구조입니다 — **목록에 없는 것은 구조적으로 통과하지 못합니다.**

### 자리 번호를 믿지 않습니다

모델은 글자 수를 세는 것을 잘 못합니다. 그래서 모델이 준 자리 번호를 버리고,
**옮겨 적은 문장이 입력에 있는지를 직접 찾아 자리를 우리가 셉니다.**

요약하거나 다듬은 인용은 입력에서 못 찾아 버려집니다 — **그대로 옮긴 것만 근거입니다.**

## 값 목록을 지어내지 않았습니다

⬜ **정본에 수법 분류와 위험도의 값 목록이 없습니다.** `F-04` 가 「수법 분류·위험도」
라고만 적었고, 어떤 분류가 있는지는 어디에도 없습니다.

**여기서 지어내면 그 분류가 피해자 화면에 뜹니다.** 근거 없는 판정이고, 이 모듈이
막으려는 바로 그것입니다.

그래서 `Taxonomy` 로 밖에서 받습니다. **비어 있으면 아무 판정도 내지 않고 모델을
부르지도 않습니다** — 검증할 기준이 없는데 통과시키면 목록을 두는 뜻이 없어지고,
쓸 수 없는 답에 돈을 쓸 이유도 없습니다.

## 판정을 저장할 자리가 아직 없습니다

⬜ 도메인 설계([08-16-domain-model.md](../../../spec/common/08-16-domain-model.md))에는
`Analysis` 가 있는데, **물리 스키마의 표 14개에는 없습니다.**

이 모듈은 판정을 **돌려주기만 합니다.** 어디에 어떻게 두는지는 표가 생긴 뒤에
부르는 쪽이 정합니다.

## 판정을 못 내도 멈추지 않습니다

던지는 것은 **모델 호출 자체가 실패했을 때**뿐입니다 — 그건 판정 실패가 아니라
시스템 실패라 재시도 판단으로 넘어갑니다 → [10-errors.md](../../../spec/backend/08-16-errors.md) §2.

못 낸 이유는 `rejected` 로 함께 나갑니다. **에러 코드가 아닙니다** — 관리자 조회에서
「왜 판정이 비었나」를 설명하는 내부 진단값입니다.

| 값 | 무슨 뜻 |
| --- | --- |
| `no_taxonomy` | ⬜ 분류·위험도 목록이 안 붙어 있습니다 |
| `unreadable` | 모델이 형식을 안 지켰습니다 |
| `unknown_value` | 목록 밖 값을 냈습니다 (모델이 판정을 포기한 경우 포함) |
| `no_span` | 근거를 못 댔거나, 댄 근거가 입력에 없습니다 |

## 토큰화된 텍스트만 받습니다

⚠️ 원문을 넣으면 **불변 규칙 2 위반**입니다. 가려진 값(`[계좌-1]`)이 근거에
들어가도 그대로 둡니다.

**지시문에 절차 지식을 담지 않았습니다.** 고를 수 있는 값과 낼 모양만 적습니다 —
절차를 여기 적으면 KB 밖에 지식이 생겨 불변 규칙 1이 깨집니다. 시험이 그 낱말들이
지시문에 없는지 봅니다.

⬜ 지시문 문구의 정본은 없습니다. [13-system-prompt.md](../../../spec/backend/08-17-system-prompt.md)
는 챗(`F-07`) 전용입니다.

## 쓰는 법

```ts
import { createCaseReader } from '@/modules/case-reader'

const reader = createCaseReader({ llm, taxonomy })

const { analysis, rejected, droppedSpans } = await reader.read({ maskedText })
```

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **분류·위험도 값** | ⬜ **밖에서 받는다** | 정본에 없습니다. 지어내면 근거 없는 판정이 화면에 뜹니다 |
| **목록이 비었을 때** | **아무것도 안 낸다. 모델도 안 부른다** | 검증할 기준이 없는데 통과시키면 목록을 두는 뜻이 없어집니다 |
| **근거를 못 댈 때** | **판정을 버린다. 던지지는 않는다** | 근거 없는 판정은 스펙 위반이지만, 이 값은 절차를 안 갈라 없어도 사용자가 안 막힙니다 |
| **모델이 준 자리 번호** | **버리고 다시 센다** | 모델은 글자 수를 잘 못 셉니다. 자리가 틀리면 엉뚱한 대목이 근거로 표시됩니다 |
| **일부 근거만 진짜일 때** | **진짜만 남기고 판정은 낸다** | 하나라도 실제 근거가 있으면 그 판정은 근거를 가진 것입니다 |
