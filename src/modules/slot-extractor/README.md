## `slot-checker` 와 다른 모듈입니다

**값을 뽑는 것은 LLM 이 하고(층 1), 충분한지 판정하고 다음 질문을 고르는 것은
규칙이 합니다(층 3).** 한 이름으로 묶으면 LLM 을 쓰는 곳과 쓰지 않는 곳의 경계가
이름에서 사라집니다 → [12-module-names.md](../../../spec/common/08-16-module-names.md).

```
전사 → pii-tokenizer(경계) → slot-extractor(여기 · LLM)
                                   ↓ 후보
                             slot-checker(규칙) → 충분한가? 다음 질문은?
```

## 추출 실패는 정상 경로입니다

정본이 *"자동 추출 실패는 정상 경로입니다. 예외로 처리하지 말고 질문 경로로
흘려보내세요"* 라고 못 박았습니다.

**그래서 모델이 무엇을 내놓든 추출 실패로 던지지 않습니다.** 아무것도 못 뽑아도,
JSON 이 아니어도, 헛소리를 해도 빈 결과가 나갑니다.

던지는 것은 **모델 호출 자체가 실패했을 때**뿐입니다 — 그건 추출 실패가 아니라
시스템 실패라 재시도 판단으로 넘어갑니다 → [10-errors.md](../../../spec/backend/08-16-errors.md) §2.

> **부르는 쪽이 정할 것** — 모델이 죽었을 때 증거 접수까지 실패시킬지, 전사만 남기고
> 슬롯은 나중에 뽑을지. 이 모듈은 예외를 올려 보내기만 합니다.

## 목록 밖 이름은 나가지 않습니다

`case_slot.slot_key` 는 [§5.1](../../../spec/backend/08-16-data-model.md) 의 열세 개뿐이고,
**목록에 없는 이름을 쓰면 적재가 거부됩니다.** 이름이 자유 문자열이면 오타 하나로
슬롯이 안 채워지고 그 사실이 조용히 넘어갑니다.

모델이 낸 것 중 아래는 버립니다. **몇 개를 버렸는지는 밝히되 값은 담지 않습니다** —
왜 안 뽑혔는지를 봐야 지시문을 고칠 단서가 생깁니다.

- 목록 밖 이름
- 값이 비어 있는 것
- 확신도가 없거나 0~1 밖인 것
- 이미 채워진 슬롯과 같은 이름
- 같은 이름이 두 번 온 것 (앞의 것만 씁니다)

## 값 타입은 스키마가 정합니다

모델은 **값만** 냅니다. 타입은 [§5.1](../../../spec/backend/08-16-data-model.md) 의 표가
이미 정해 뒀습니다 — 모델에게 타입까지 물으면 `case_slot.value_type` 의 `CHECK` 를
어기는 값이 옵니다.

## 값을 다듬지 않습니다

「어제」를 날짜로 바꾸거나 「삼백만원」을 숫자로 바꾸지 않습니다.

**이 모듈에는 시계가 없고, 날짜를 세는 것은 `date-checker` 하나입니다**
→ `CLAUDE.md` 불변 규칙 7. 여기서 날짜를 계산하면 시계가 둘이 됩니다.

사용자가 말한 표현을 그대로 옮기고, 해석은 뒤에서 합니다.

## 확신도로 거르지 않습니다

⬜ **임계값의 정본이 없습니다** → [02-slot-tiering.md](../../../spec/backend/08-14-slot-tiering.md)
*"TODO(미정): 슬롯별 자동 추출 신뢰도 임계값 — 얼마나 확신해야 「질문 생략」인지"*.

숫자를 지어내면 **그 숫자가 곧 「사용자에게 다시 묻느냐 마느냐」를 가릅니다.**
너무 낮으면 틀린 값으로 플랜이 만들어지고, 너무 높으면 다 알아냈는데도 계속 묻습니다.

그래서 이 모듈은 **확신도를 그대로 실어 보내고 거르지 않습니다.** 임계값이 정해지면
거르는 자리는 부르는 쪽이나 `slot-checker` 이지 여기가 아닙니다.

## 지시문에 절차 지식을 담지 않았습니다

허용된 이름과 낼 모양만 적었습니다. **절차를 여기 적으면 KB 밖에 지식이 생겨
불변 규칙 1이 깨집니다.** 시험이 지급정지·3영업일 같은 낱말이 지시문에 없는지 봅니다.

⬜ 지시문 문구의 정본은 없습니다. [13-system-prompt.md](../../../spec/backend/08-17-system-prompt.md)
는 챗(`F-07`) 전용입니다.

## 토큰화된 텍스트만 받습니다

⚠️ 원문을 넣으면 **불변 규칙 2 위반**입니다. `pii-tokenizer` 를 지난 것만 넣으세요.
가려진 값(`[계좌-1]`)은 가려진 채로 슬롯에 들어갑니다 — 칼럼 이름이
`value_masked` 인 이유입니다.

## 쓰는 법

```ts
import { createSlotExtractor } from '@/modules/slot-extractor'

const extractor = createSlotExtractor({ llm })

const { slots, dropped } = await extractor.extract({
  maskedText,                    // pii-tokenizer 를 지난 것
  evidenceId,                    // 뽑은 값마다 source_ref 로 붙습니다
  known: ['org_name'],           // 이미 채워진 것은 다시 안 뽑습니다
})
```

**다 채워져 있으면 모델을 부르지 않습니다.** 부를 이유가 없고, 부르면 이미 확정된
값을 흔들 후보가 생깁니다.

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **모델이 JSON 을 안 낼 때** | **던지지 않고 빈 결과** | 추출 실패는 정상 경로입니다. 형식 오류도 결과적으로 「못 뽑았다」입니다 |
| **앞뒤에 말이 붙을 때** | 첫 `{` 부터 마지막 `}` 까지 본다 | 모델이 설명을 덧붙이는 일이 흔합니다 |
| **확신도 임계값** | **거르지 않는다** — 부르는 쪽이 거릅니다 | `flows/read-evidence.ts` 가 **0.7** 미만을 버립니다([ADR-069](../../../decisions/069-evidence-slot-extraction.md) ③). 여기서 거르면 임계값이 둘이 됩니다 |
| **값 정규화** | **안 한다** | 시계가 둘이 되면 안 됩니다 → 불변 규칙 7 |
| **같은 이름이 두 번** | 앞의 것 | 뒤엣것을 쓰면 모델이 스스로를 정정하는 셈인데, 어느 쪽이 맞는지 알 근거가 없습니다 |

## 누가 부르나 (2026-09-04)

`flows/read-evidence.ts` 의 `extractSlots` — 토큰화와 기관명 사전 대조([ADR-056](../../../decisions/056-transcript-org-normalization.md))

- 다섯 이름만 받습니다 — `slot-checker` 의 `CONFIRMABLE_KEYS`. `org_name` 은 사전 대조가, T1 은 사람이.
- 확신도 0.7 미만을 버립니다.
- 값을 슬롯 모양으로 옮깁니다(`lib/extracted-value.ts`) — 절대 표기만. 못 옮기면 버립니다.
- `extracted` 로 적고, `slot-checker` 가 문진 자리에서 「맞아요」 한 탭으로 확인받습니다.

2026-09-04 까지는 아무도 부르지 않았습니다 — 위 「값을 다듬지 않습니다」·「임계값」이 「배선 전」을 전제로 적혀 있었습니다.
