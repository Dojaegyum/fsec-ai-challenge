# poll-checker

서버에 다시 물을지, 언제 물을지 정합니다. **층 C(브라우저)** 입니다.

| | |
| --- | --- |
| 받는 것 | 서버 응답·에러의 요약 |
| 내놓는 것 | 「다시 물어라 + 몇 ms 뒤」 또는 「멈춰라 + 왜」 |
| 절대 하지 않는 것 | **스트리밍·웹소켓** · **예외 종류로 분기** · 스스로 기다리기 · 간격 지어내기 |

## 왜 스트리밍이 아닌가

Vercel 서버리스는 장시간 연결에 제약이 있습니다. 서버가 `poll_after_ms` 로
다음 호출 시점을 지시해 부하를 조절합니다 → [API](../../../spec/common/08-14-api.md) §3.3.
챗도 같습니다 — 근거 검증이 끝난 뒤 한 번에 나갑니다
([ADR-022](../../../decisions/022-chat-turn-boundaries.md)).

## 정상 진행에는 예산이 없습니다

전사는 몇 분이 걸릴 수 있습니다. 폴링은 §3.3 이 정한 정상 경로라 끊을 이유가 없고,
[에러](../../../spec/backend/08-16-errors.md) §2.1 의 예산(20초·120초)은
**서버리스 함수 안의 재시도**에 건 것입니다.

## 에러에서는 다시 부르지 않습니다

「클라이언트는 자동으로 다시 부르지 않습니다」 —
[에러](../../../spec/backend/08-16-errors.md) §3.1. 서버가 이미 재시도한 뒤의 응답이라,
여기서 또 때리면 아픈 서버에 요청이 배로 늡니다.

**멈출 때 화면에 넘기는 둘은 버튼을 그리는 재료입니다** (에러 §3.1.1):

| 값 | 무엇을 정하나 |
| --- | --- |
| `retryable` | 「다시 시도」 버튼을 **띄울지**. `true` 일 때만 띄웁니다 |
| `retryAfterSec` | 「N초 뒤 다시 시도할 수 있습니다」의 **N** |

**둘 다 재호출을 뜻하지 않습니다 — 누르는 것은 사용자가 합니다.**

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **에러에서 자동 재시도** | **안 합니다** | 에러 §3.1 이 「누르는 것은 사용자」로 확정. 서버는 이미 §2.1 예산 안에서 재시도한 뒤입니다 |
| **`poll_after_ms` 가 없을 때** | 지어내지 않고 **멈춥니다** | 화면이 간격을 만들면 서버의 부하 조절이 무의미해집니다 |
| **정상 진행의 상한** | **없습니다** | 전사는 몇 분이 걸립니다. §2.1 의 예산은 서버 함수 안의 것입니다 |
| **`retryable` 을 verdict 에 싣기** | 싣습니다 | 화면이 버튼을 띄울지 정하려면 필요합니다 (에러 §3.1.1). `Retry-After` 유무로 **추론**하면 둘이 갈릴 때 조용히 틀립니다 |
| **`retryable`·`Retry-After` 가 어긋날 때** | **`retryable` 을 따릅니다** | 판단이 담긴 칸입니다. 그런 응답은 서버 결함이고, 그때도 버튼은 띄우되 시간만 안 보입니다 |

## 아직 아닌 것

- ⬜ **응답 본문을 화면 상태로 옮기는 자리.** `decidePoll` 은 **다시 물을지만** 정합니다.
  `ingest_status`·`progress.phase` 를 화면 문구로 옮기는 것은 부른 쪽의 일이고,
  `chat.tsx` 의 `PendingBubble` 이 그 자리입니다 — 라우트가 붙는 날 함께 잇습니다.
- ⏳ **`retryable` 은 서버가 아직 안 줍니다.** 계약에 **넣기로 확정**됐습니다
  (2026-08-23 · 에러 §3.1.1). 없으면 `retryable` 이 `undefined` 로 와서
  화면이 버튼을 안 띄웁니다 — **틀려서 안 눌러 주는 쪽**이 안전합니다.
