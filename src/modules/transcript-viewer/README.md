# transcript-viewer

전사·OCR 결과를 보여줍니다. **층 C(브라우저)** 입니다.

| | |
| --- | --- |
| 받는 것 | 토큰화된 전사 (`GET …/evidence/{id}` [§3.3](../../../spec/common/08-14-api.md)) + 브라우저의 복원 매핑 |
| 내놓는 것 | 화면 (**전체 복원**) |
| 절대 하지 않는 것 | **복원된 원문을 서버로 되돌려 보내기** · 여기서 OCR 하기 |

## `file-sender` 와 규칙이 정반대입니다

하나는 가리고 하나는 펼칩니다. 이 자리는 사용자가 **자기 통화를 대조하는 곳**이라
전체 복원이 허용됩니다 — 부분 복원이면 대조가 안 됩니다
([chat-context](../../../spec/backend/08-16-chat-context.md) §8).

## 못 펼쳐도 고장이 아닙니다

다른 기기에서 열면 복호화 키가 없어 토큰이 그대로 남습니다. 그때도 화면은 그려지고,
「처음 시작하신 기기에서 열면 그대로 보입니다」를 함께 보여줍니다.

## 상태 점은 여기 없습니다

「업로드 + **처리 상태**」는 `file-sender` 의 몫입니다
([경계 표](../../../spec/common/08-16-module-boundaries.md)). 이 모듈은
「토큰화 전사 → 화면」만 맡습니다 — 자료 레일의 점(`DOT`)은 ~~아직 `evidence.tsx` 에 있고
[서버와 이야기하는 넷 계획](../../../docs/plans/08-22-layer-c-transport.md) Task 7 이 가져갑니다~~
→ `file-sender/rail.tsx` 로 갔습니다 (2026-09-04 확인 · 그 계획은 은퇴).

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **못 펼친 토큰을 어떻게 아나** | `pii-restorer` 의 `onDenied` 만 씁니다 | 정규식으로 다시 긁으면 패턴이 두 곳이 되고, 어긋난 쪽이 조용히 새는 쪽이 됩니다 |
| **개수의 종류 이름** | 토큰 표기(「[이름-1]」의 「이름」) | §3.3 의 `kind` 는 영문 코드라 그대로 쓰면 헤더가 「name 1 · account 2」가 됩니다 |
| **「00:12」을 그려도 되나** | 그립니다 | `start_ms` 의 표기 변환이라 **기한 계산이 아닙니다** — 시계를 안 봅니다 |
| **개수 줄을 어디에** | `tokens` 를 넘길 때만 본문 위에 | 시안은 헤더 막대에 둡니다. 그 자리를 쓰는 화면은 `countTokens` 를 직접 불러 헤더에 적습니다 |

## 아직 아닌 것

- ⬜ **사칭 정황 구간 · 미확인 표기.** 근거 스팬은 `case-reader`(층 1)가 내는데
  미구현이고, §3.3 응답에도 그 자리가 없습니다. **화면 교체로 지금은 안 보입니다** —
  값이 오면 이 모듈에 붙습니다.
- ⬜ **화자 이름.** §3.3 은 `speaker: "A"/"B"` 뿐이라 「상대방 · 나」를 못 씁니다.
  누가 「나」인지 밝히는 칸을 정본에 물어야 합니다.
