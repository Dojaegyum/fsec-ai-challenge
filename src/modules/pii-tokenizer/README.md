## 여기를 지나지 않은 텍스트는 외부로 나갈 수 없습니다

`CLAUDE.md` 불변 규칙 2이고, 협상 대상이 아닙니다. **우회 경로를 만드는 것 자체가
위반**입니다 — 이 모듈의 존재 이유가 그 한 줄입니다.

## 2중 스크러빙에서 여기는 2차입니다

| 단계 | 어디 | 무엇을 잡나 |
| --- | --- | --- |
| 1차 | 브라우저 `pii-masker` | 계좌 · 주민번호 · 카드 · 전화 (정규식) |
| **2차** | **여기** | **이름** (모델) + **1차 넷을 다시** |

### 왜 정규식을 여기서 또 도나

**브라우저를 안 거치는 경로가 있기 때문입니다.** `transcriber` 가 낸 전사·OCR
결과는 서버에서 만들어져 1차를 지나지 않았습니다 → 층 1 흐름도.

**패턴을 여기 옮겨 적지 않았습니다.** 정본은 `pii-masker/patterns.ts` 하나이고,
정본 문서가 *"두 곳에 두면 반드시 어긋나고, 어긋난 쪽이 조용히 새는 쪽이 됩니다"*
라고 못 박았습니다. 그래서 층 C 모듈의 공개 API 를 가져다 씁니다 — **층을 넘는
import 이지만 패턴을 복제하는 것보다 이쪽이 정본의 요구입니다.** 그 파일에는
브라우저 전용 API 가 없습니다(순수 함수만).

## 2차 모델이 아직 없습니다

~~⬜ **NER 모델·서비스가 미선정입니다**~~ → **`gemma3:4b`** 로 정해졌고(research/09 R-1 · [ARCHITECTURE.md §10](../../../ARCHITECTURE.md)),
서버는 2026-08-31 에 올라갔으나 운영은 `NER_URL` 을 **일부러** 비워 둡니다(deploy/README 「2차 탐지를 켜려면」 · CPU 10~12초).

**그래도 이 모듈은 섭니다.** [착수 기준선](../../../docs/plans/08-18-backend-baseline.md)이
*"③ 에서 NER 을 기다리지 않습니다. 1차 정규식만으로 경계가 섭니다. NER 은 2차 방어라
나중에 끼워 넣어도 구조가 안 바뀝니다"* 라고 정했습니다.

**대신 그 상태를 숨기지 않습니다.** 결과의 `nerApplied` 가 거짓으로 나가고,
설정 현황에 「개인정보 2차 탐지 ✗」가 뜹니다.

> ⚠️ **모델이 붙기 전에는 외부 모델에 실데이터를 보내지 않습니다.** 이름이 안 걸립니다.
> 이건 코드가 막는 것이 아니라 운영 규칙입니다 — 막게 만들면 붙어 있는 1차까지 못 씁니다.

> ⚠️ **원격 API 를 고르면 그 API 가 원문을 봅니다.** 이 자리는 아직 토큰화 이전이라,
> 외부로 나가는 모델을 쓰면 경계가 그쪽으로 옮겨 갑니다 — STT·OCR 에 붙은 경고와
> 같은 성질입니다 → [ARCHITECTURE.md §6](../../../ARCHITECTURE.md).

## 제외 목록이 모델 결과보다 우선합니다

**기관명·금액·시각은 개인정보가 아니면서 절차 분기의 직접 입력입니다.**

`"카카오페이로 300만원"` 이 `"[이름-1]로 300만원"` 이 되면 경유 서비스를 특정할 수 없고,
슬롯 T1 미충족으로 판정돼 **에러 없이 슈퍼셋 플랜이 나갑니다** — 사용자는 정보를
다 줬는데 「모름」 취급을 받습니다.

막는 자리가 둘입니다.

1. **토큰으로 바꾸는 이름표를 나열합니다.** 빼는 쪽이 아니라 넣는 쪽을 적었습니다 —
   모델이 새 이름표를 들고 와도 그것이 조용히 토큰화되지 않습니다.
2. **`allowedTerms` 가 그 위에 한 겹 더 있습니다.** 모델이 기관명을 사람 이름으로
   잘못 집어도 여기서 걸립니다.

> ~~⬜ **`allowedTerms` 를 채우는 자리가 아직 없습니다.**~~ → 2026-08-27 에 제품 경로 넷에 물렸고
> (`flows/answer-slot.ts` 의 `allowedTermsFor` 등 · qa-readiness 「그날 안에 뚫렸습니다」), `org` 표는
> 51곳입니다(research/04). 두 겹이 다 서 있습니다.

## 같은 값은 같은 토큰

일련번호가 리셋되면 서로 다른 발화의 `[계좌-1]` 이 다른 계좌를 가리켜,
**복원이 엉뚱한 값을 되살립니다.**

이어 부를 때는 앞선 결과의 `mappings` 를 넘기세요. 브라우저가 만든 1차 매핑도
함께 넘기되 — ⚠️ **원문은 빼고 종류와 번호만** 넘깁니다.

**원문 표를 서버로 보내면 안 됩니다.** 요청 본문·서버 메모리·로그에 계좌번호와
주민번호가 남고, *"서버가 통째로 유출돼도 원문을 읽을 수 없다"* 는 이 서비스의
신뢰 근거가 무너집니다 → 불변 규칙 1. **번호를 이어 붙이는 데는 원문이 필요
없습니다.**

**이미 아는 원문이 텍스트에 다시 나오면 같은 토큰으로 가립니다.** 모델의 재현율은
100%가 아니라 같은 이름을 다음 턴에 놓칠 수 있는데, 그걸 오류로 던지면 그 이름이
나오는 모든 턴이 영영 실패합니다 — 고칠 수 있는 상황을 영구 장애로 바꾸는 셈입니다.

## 나가기 직전에 한 번 더 셉니다 — 다만 같은 규칙은 아닙니다

`scan()` 이 `chat-publisher` 의 잔여 검사 자리에 그대로 들어갑니다.

⚠️ **`tokenize` 와 같은 규칙이 아닙니다.** 그 자리의 계약이 동기 함수라
모델을 부를 수 없어 **정규식만 돕니다.** 그래서 **모델이 답변에 남긴 이름은
여기서 안 걸리고**, `X-Pii-Egress-Residual` 은 그때도 0 을 보고합니다.

⬜ 계약을 비동기로 넓히든 별도 검사를 두든 정해야 하는 자리입니다.
**한계 자체보다, 그 한계를 「같은 규칙」이라는 말로 덮는 것이 위험합니다.**

**값이 아니라 종류별 건수만 냅니다.** 무엇이 남았는지 값으로 알려주지 않는 것이
규칙입니다 → [10-errors.md](../../../spec/backend/08-16-errors.md) 원칙 2.

## 입력에 있던 토큰 모양

⬜ **어떻게 다룰지 정본에 없어 세기만 합니다** (`foreignTokens`).

사기범이 보낸 캡처에 `[계좌-1]` 이라는 **글자**가 적혀 있고 OCR 이 그대로 읽으면,
그 자리가 나중에 **피해자 본인의 계좌번호로 복원돼 보입니다.** 불변 규칙 4가
겨냥한 종류의 우회인데, *"모델이 지어낸 토큰은 매핑에 없어 복원되지 않습니다"*
라는 방어는 이 모양에 안 통합니다 — 우리 매핑에 **있는** 토큰이라서입니다.

지우거나 바꾸지 않는 이유는 **사용자가 쓴 글자를 우리가 고치는 것**이라
규칙이 필요하기 때문입니다.

## 던지는 자리 둘

| 언제 | 무엇 | 다시 시도 |
| --- | --- | :---: |
| 모델을 못 부를 때 | `PiiTokenizerUnavailableError` (503) | ✓ 최대 2회 |
| **이번에 가린 값이** 출력에 남았을 때 | `PiiBoundaryError` (500) | ✗ |

**둘 다 통과시키지 않습니다.** 앞엣것은 *"pii-tokenizer 가 죽으면 LLM 기능 전체가
멈춘다 — 의도된 것이다"* 입니다.

⚠️ **뒤엣것이 무엇을 못 잡는지 분명히 해 둡니다.** 이 검사는 **탐지는 됐는데
치환이 잘못된 경우**만 잡습니다. **패턴이 애초에 못 찾은 값은 매핑이 없어
비교할 대상 자체가 없습니다** — 「패턴을 늘리다 실수하면 이 검사가 막아 준다」는
줄 수 없는 보증입니다. 탐지의 폭은 `pii-masker/patterns.ts` 와 2차 모델이 정합니다.

## 쓰는 법

```ts
import { createPiiTokenizer } from '@/modules/pii-tokenizer'

const tokenizer = createPiiTokenizer({ ner })   // ner 는 없어도 됩니다

const { masked, mappings, counts, nerApplied } = await tokenizer.tokenize(text, {
  mappings: previous,                  // 1차가 만든 것도 함께
  allowedTerms: ['국민은행', '카카오페이'],
})
```

**조립은 `lib/container.ts` 가 합니다.** 라우트가 직접 만들지 마세요 —
경계가 여러 개면 어느 것이 진짜인지 알 수 없게 됩니다.

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **2차 모델이 없을 때** | **던지지 않고 1차만으로 돈다** | 던지면 붙어 있는 1차까지 못 씁니다. 착수 기준선이 「NER 을 기다리지 않는다」로 정했습니다. 대신 `nerApplied` 로 드러냅니다 |
| **모델 이름표 처리** | **토큰화할 것을 나열** (빼는 쪽이 아니라) | 모델이 새 이름표를 들고 와도 조용히 토큰화되지 않습니다 |
| **모델이 엉뚱한 자리를 가리킬 때** | **버린다** | 자리가 실제 글자와 안 맞으면 지워야 할 것을 놔두고 멀쩡한 글자를 지웁니다 |
| **정규식과 모델이 겹칠 때** | **정규식이 이기되, 진 쪽의 남는 조각을 살린다** | 통째로 버리면 겹치지 않은 부분이 평문으로 남습니다 — 모델이 「김민수 010」을 한 덩어리로 집으면 전화 뒷자리가 새어 나갔습니다 |
| **허용 목록 판정** | **허용어로 시작하고 뒤에 조사만** | 「포함하면 허용」이면 기관 별칭 「국민」 때문에 「박국민」 같은 실명이 통째로 새어 나갑니다 |
| **유니코드 변형** | **길이를 지키는 정규화** | 전각 숫자·en dash·제로폭으로 패턴 넷이 전부 비껴갔습니다. 표준 정규화는 길이가 달라져 자리가 어긋납니다 |
| **계측 헤더의 영문 이름** | ⬜ 카드·전화는 골랐다 | `account`·`name`·`resident_id` 는 정본에 있고 나머지 둘은 없습니다 |

## 아직 아닌 것

⬜ **2차 토큰의 복원 매핑을 볼트에 넣는 경로가 없습니다** →
[04-pii-boundary.md](../../../spec/common/08-14-pii-boundary.md) TODO.

1차 토큰은 브라우저가 만들고 `key-handler` 가 봉해 볼트에 넣습니다. 그런데 **2차는
서버가 만드는데 서버에는 키가 없어 봉할 수 없습니다.** 그러면 `[이름-1]` 의 원문이
어디에도 없어 화면에서 되살릴 수 없습니다.

이 모듈은 `added` 로 새 매핑을 **돌려주기만 합니다.** 어디에 어떻게 두는지는
계약이 정해진 뒤에 부르는 쪽이 정합니다 — 여기서 지어내면 키 없는 서버가 원문을
들고 있게 됩니다.
