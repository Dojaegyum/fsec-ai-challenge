# date-checker

법정 기한을 **규칙으로** 계산하고 잔여일을 추적합니다. 기한을 저장하거나 알리지는 않습니다 —
계산 결과만 돌려주고, 저장은 `deadline` 표가, 알림은 `reminder-sender` 가 합니다.

## 왜 이 모듈이 따로 있는가

**기획서 다이어그램에 없는 모듈입니다.** "기한 계산에 LLM을 쓰지 마세요"를 지키려면
계산 주체가 코드여야 하는데, 그 코드가 갈 자리가 없어서 세웠습니다
→ [모듈 경계](../../../spec/common/08-16-module-boundaries.md).

**LLM 이 닿지 않습니다.** 3영업일·14일 유예·5영업일은 전부 여기의 규칙입니다.
절차를 *고르는* 것은 LLM, 날짜를 *세는* 것은 규칙입니다.

## 절대 하지 않는 것

- **날짜를 모델에 묻지 않습니다.** 이 폴더에 LLM 호출이 들어오면 불변 규칙 7 위반입니다.
- **기한 값을 여기에 굽지 않습니다.** `3`·`14` 같은 숫자는 KB 에서 옵니다. 이 모듈은
  「며칠인가」를 받아 「언제인가」를 답할 뿐입니다 → [KB 운영](../../../spec/backend/08-14-kb-operations.md).
- **공휴일 배열을 코드에 굽지 않습니다.** 매년 바뀌고 임시공휴일은 갑자기 생깁니다.
  `HolidayCalendar` 로 밖에서 받습니다.
- **클라이언트 시계를 믿지 않습니다.** `Clock` 은 서버 시계를 넣습니다.
- **확정 안 된 기산점으로 기한을 확정하지 않습니다.** `estimated: true` 로 표시합니다.

## 하루가 틀리는 자리 넷

기한을 하루 잘못 세면 사용자가 권리를 잃습니다. 실수가 나는 자리는 정해져 있습니다.

| | 규칙 | 안 지키면 |
| --- | --- | --- |
| **초일 불산입** | 기산일 다음 날이 1일차 — 민법 제157조 | 기한이 하루 앞당겨집니다 |
| **근로자의 날(5/1)** | 영업일에서 뺍니다 | **특일 정보 API 에 안 나옵니다.** 그대로 쓰면 5/1 을 영업일로 세어 하루 앞당겨집니다 |
| **말일 이월** | 달력일의 말일이 토요일·공휴일이면 다음 날 — 민법 제161조 | 기한이 하루 앞당겨집니다 |
| **타임존** | 산술은 UTC 자정으로 정규화, `Asia/Seoul` 은 마지막에 한 번 | 서버 위치에 따라 하루가 어긋납니다 |

**「영업일」과 「달력일」은 휴일의 기준이 다릅니다.** 영업일은 은행 기준이라 근로자의 날을 빼고,
말일 이월은 민법 조문이라 관공서 공휴일만 봅니다 — 근로자의 날은 거기 안 들어갑니다.
그래서 5/1 이 말일인 14일 유예는 그날 만료하고, 5/1 을 지나는 3영업일은 하루 밀립니다.

**말일 이월은 영업일에 적용하지 않습니다.** 영업일은 애초에 휴일을 세지 않아 말일이 휴일일 수
없습니다. 그런데도 또 밀면 3영업일이 4영업일이 됩니다.

## 쓰는 법

```ts
import { createDateChecker } from '@/modules/date-checker'

const dateChecker = createDateChecker({ holidays, clock })

const deadline = dateChecker.compute({
  anchor: { source: 'relief_applied_at', date: '2026-08-18', confirmed: true },
  rule: { kind: 'business_days', amount: 3 },   // 값은 KB 에서 옵니다
  kind: 'primary',
})
// { dueDate: '2026-08-21', dueAt: '2026-08-21T23:59:59+09:00',
//   computedFrom: 'relief_applied_at', estimated: false, holidaysUsed: [] }

dateChecker.daysLeft(deadline.dueDate)   // 음수면 지났다는 뜻
```

**`holidaysUsed` 를 `rule_snapshot` 에 함께 저장하세요.** 공휴일 데이터가 나중에 바뀌어도
그때의 계산을 되살릴 수 있어야 합니다 → [09-data-model.md](../../../spec/backend/08-16-data-model.md) §8.2.

**지난 기한을 화면에서 지우지 마세요.** 유예(14일)가 남아 있을 수 있습니다.

## 밖에서 넣어야 하는 것

| 무엇 | 어디서 | 비고 |
| --- | --- | --- |
| `HolidayCalendar` | **한국천문연구원 특일 정보 API** (공공데이터포털 15012690) | ⬜ 어댑터 미구현. 근로자의 날은 답하지 않아도 됩니다 |
| `Clock` | 서버 시계 (`Asia/Seoul`) | 시험에서는 고정값을 넣습니다 |

## 시험할 때

둘 다 넣어서 결과를 고정합니다. **바깥에 나가는 것이 없어 테스트가 결정적입니다.**

```ts
const checker = createDateChecker({
  holidays: { isPublicHoliday: (d) => d === '2026-08-19' },
  clock: { today: () => '2026-08-18' },
})
```

## 아직 아닌 것

- ~~⬜ **`months` 가 없습니다.**~~ → **2026-08-26 에 들어왔습니다**(`compute.ts` `addMonths` · 민법 제160조
  역법 계산 · 말일은 그 달의 마지막 날로). 채권소멸공고 2개월과 통장묶기 이의제기 창(ADR-066)이 씁니다
  → [기한 계산 규칙](../../../spec/common/08-16-deadline-rules.md) 「개월은 역법으로 셉니다」.
- ⬜ **초일 불산입이 아직 추론입니다.** 통신사기피해환급법에 별도 기간 규정이 있는지
  조문 전문을 대조하지 않았습니다 → [기한 계산 규칙](../../../spec/common/08-16-deadline-rules.md)
  §「초일은 세지 않습니다」의 TODO. **D-day 를 단정적으로 표시하기 전에 확인해야 합니다.**
- ⬜ **특일 정보 API 어댑터가 없습니다.** 인증키와 캐싱 전략이 아직 없습니다.

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **말일 이월(민법 제161조)** | **달력일에만 적용한다** | 정본이 *"「영업일」로 정한 기간에는 겹치지 않는다"*고 범위를 그어 놨습니다. 영업일에도 적용하면 3영업일이 4영업일이 됩니다 |
| **말일 이월의 휴일 기준** | **근로자의 날을 빼지 않는다** | 조문이 말하는 「공휴일」은 관공서 공휴일이고 근로자의 날은 근로기준법상 유급휴일이라 거기 없습니다. 영업일 계산과 기준이 다른 것이 맞습니다 |
| **`holidaysUsed` 에 주말을 넣을지** | **넣지 않는다** | 요일은 날짜로 다시 알 수 있습니다. 바뀔 수 있는 것(공휴일)만 남겨야 재현 목록이 뜻을 갖습니다 |
| ~~**`months` 를 지금 넣을지**~~ | ~~**넣지 않는다**~~ → 08-26 에 넣었습니다 | ~~말일 처리의 근거가 정본에 없습니다~~ → 민법 제160조(역에 의한 계산)로 근거가 섰습니다 |
| **날짜를 `Date` 로 다룰지** | **`YYYY-MM-DD` 문자열로 다룬다** | `Date` 는 로컬 시간대로 해석돼 서버 위치에 따라 하루가 어긋납니다. UTC 자정으로만 산술하고 `+09:00` 은 마지막에 한 번 붙입니다 |
| **휴일 조회가 늘 참일 때** | **상한을 두고 던진다** | 어댑터가 잘못되면 무한 루프에 빠집니다. 조용히 도는 것보다 멈추는 편이 드러납니다 |
