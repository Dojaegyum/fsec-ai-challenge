## 서류를 만들어 주지 않습니다

**틀린 서류는 안 만든 것만 못합니다.** 반려되면 3영업일을 놓치고, 그 순간
지급정지가 무효가 됩니다.

법령이 **별지 제1호서식**을 지정하고 있고, 우리가 조판한 것은 그 서식이 아닙니다.
서식 실물은 **2차 출처로만** 확보돼(`U-17`) 1차 대조가 남아 있고, 파일 제출 경로도
미확인입니다(`U-25`). ADR-037 이 *"둘 중 하나라도 없으면 만들지 않습니다"* 로 정했습니다.

**안내는 어느 경로에서나 쓸모가 있습니다.** 앱 폼을 채우든 창구에서 손으로 쓰든
전화로 구술하든 「이 값을 이렇게 적으세요」는 그대로 쓰입니다.

## 칸 목록을 갖지 않습니다

ADR-037: *"필수 기재사항은 여전히 KB 에서 옵니다 … 화면이나 프롬프트에
하드코딩하지 않습니다."*

여기 있는 것은 **짝짓는 규칙**뿐이고, 무엇을 짝지을지는 `FormDefinition` 으로
밖에서 옵니다. 칸 이름을 코드에 박으면 서식 개정에 배포가 따라오고, 지금 가진
것이 2차 출처라 **바뀔 것을 박는 셈**이 됩니다.

> ⬜ **서식 정의가 아직 KB 에 없습니다.** `src/kb/common.json` 에 절차 넷만 있고
> 칸 목록은 없습니다. `S-10` 이 *"확보하면 KB 항목으로 등재하고 칸 이름을 그대로
> 부를 수 있습니다"* 라고 적어 둔 자리입니다.

## 칸의 네 상태

| 상태 | 무슨 뜻 | 어디서 |
| --- | --- | --- |
| `confirmed` | 사용자가 확인했거나 직접 입력 | 슬롯 `confirmed` |
| `unread` | 증거에서 읽었지만 **확인 전** | 슬롯 `extracted` |
| `unknown` | 값이 없습니다 — 직접 적습니다 | 슬롯 없음·`empty`·`unknown` |
| `staff` | **신청인이 안 적는 칸** | 서식의 「색상이 어두운 란」 |

**`extracted` 를 `confirmed` 로 올리지 않습니다.** 잘못 읽은 계좌번호를 확인된
값으로 보여주면 사용자가 그대로 서류에 옮겨 적습니다.

## 못 채운 칸을 실패처럼 보이게 하지 않습니다

서식이 요구하는 것 중 **성명·생년월일·주소·개설점포·예금종별·환급받을 계좌는
슬롯이 아예 없습니다** → [research/01](../../../docs/research/01-환급절차-기한.md) §5.3.
환급받을 계좌는 **원래 알 수 없는 값**이고, 그 구획이 `0` 으로 뜨면 우리가 실패한
것처럼 읽힙니다.

그래서 구획마다 둘을 셉니다.

| | |
| --- | --- |
| `filled` | 값이 있는 칸 |
| `toWrite` | **사용자가 적어야 하는 칸** (`staff` 제외) |

화면이 「전부 직접 적습니다」로 말할 수 있게 하려는 것입니다 —
`CLAUDE.md` 불변 규칙 5 「모름은 실패가 아니다」의 화면판입니다.

**접수처가 채우는 칸을 사용자 몫으로 세지 않습니다.** 사용자가 못 하는 일까지
자기 할 일로 읽으면 안 됩니다.

## 원문을 다루지 않습니다

값은 **토큰화된 상태 그대로** 나갑니다. 서버에는 복호화 키가 없어 원문을 만들 수
없고, 만들면 [04-pii-boundary.md](../../../spec/common/08-14-pii-boundary.md) 규칙 6
위반입니다. 복원은 셸 화면(`doc.tsx`)이 `pii-restorer` 로 **브라우저에서** 합니다 (ADR-064).

돌려주는 칸에는 `raw`·`display` 같은 자리를 아예 두지 않았습니다.

## 순서를 정하지 않습니다

**구획 순서는 서식 실물 그대로**이고, 사용자가 실물과 1:1 로 대조하라고 그렇게
둔 것입니다. **채우는 순서는 없습니다** — 아는 것부터 채워도 되고 빈칸이 남아도
신청은 진행됩니다 → `S-10`.

이 모듈은 받은 순서를 바꾸지 않고, 번호도 매기지 않습니다.

## 근거 없는 안내를 내보내지 않습니다

서식 정의에 `kb_entry_id`·`kb_version`·`source_url`·`effective_from` 이 하나라도
비면 던집니다. `plan_step` 이 근거 네 칸이 비면 적재를 거부하는 것과 같은 자리입니다
→ 불변 규칙 1.

**특히 시행일입니다.** 서식은 개정되고, 어느 개정본을 보고 안내했는지가 남아야
나중에 「왜 이렇게 안내했나」를 재현할 수 있습니다.

## 쓰는 법

```ts
import { createDocBuilder } from '@/modules/doc-builder'

const guide = createDocBuilder().build({
  form,      // ⬜ KB 에서 온 서식 정의
  slots,     // 사건이 아는 값 (토큰화된 상태)
})
```

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **칸 목록** | ⬜ **밖에서 받는다** | ADR-037 이 KB 에서 온다고 정했고, 지금 가진 서식은 2차 출처라 바뀔 수 있습니다 |
| **보조문 문구** | **정의와 함께 온다** | 「통장 표지에 있습니다」도 사용자에게 보이는 말이라 지어낼 자리가 아닙니다 |
| **`extracted` 값** | **`unread` 로 남긴다** | 확인 전 값을 확인된 것으로 보여주면 틀린 값이 서류로 갑니다 |
| **세는 방식** | **`filled` 과 `toWrite` 둘** | 하나만 세면 「우리가 못 채웠다」로 읽힙니다 |
| **`staff` 칸** | **값을 찾지 않는다** | 서식이 신청인은 안 적는다고 표시한 자리입니다 |
