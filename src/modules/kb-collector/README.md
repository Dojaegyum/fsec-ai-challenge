# kb-collector

**바뀐 것을 찾아 검수 큐에 쌓습니다. 매뉴얼에 쓰지 않습니다.**

| | |
| --- | --- |
| 왜 수집하나 | [ADR-012](../../../decisions/012-kb-collection.md) |

| 이름·층 | [12-module-names.md](../../../spec/common/08-16-module-names.md) 층 4 |
| 원본 → 매뉴얼 경로 | [RFC-002](../../../rfc/002-kb-authoring.md) |

## 왜 이게 있나

**이 서비스에서 가장 중요한 정보가 「곧 바뀐다」입니다.** 가상자산 환급은
2026.10 시행이고, 그날 우리 매뉴얼이 낡으면 사용자는 없는 절차를 안내받습니다.

절차를 하드코딩하지 않기로 한 것(불변 규칙 1)의 나머지 절반입니다 — KB 로 뺐으면
**그 KB 가 낡는 것을 누가 알아채는가**가 남습니다.

## 매뉴얼에 직접 쓰지 않습니다

[원칙 4](../../../spec/backend/08-14-kb-operations.md) 「사람 검수는 생략 불가」.
이 모듈이 하는 일은 **원문을 보존하고 바뀐 것을 `pending` 으로 쌓는 것**까지입니다.

포트 목록에 `kb_entry` 를 건드리는 자리가 아예 없습니다. 있으면 언젠가 쓰입니다.

```
kb-collector  →  source_snapshot (원문 보존)
              →  source_change (pending)  →  kb-reviewer  →  사람
```

## 변경 감지에 비교 로직이 없습니다

`source_snapshot` 이 `(source_key, content_hash)` 를 잠그고 있어
**삽입에 성공하면 그것이 곧 변경입니다** → §12.1.

앞엣것과 견주는 코드를 따로 두지 않았습니다. **두 곳에 두면 어긋나고, 어긋난
쪽이 조용히 놓치는 쪽이 됩니다.** 그래서 `SnapshotStore.append` 는 「넣었나」를
불리언으로 돌려주고, 그 값이 곧 판정입니다.

### 그래서 저장과 검수 큐 등록이 한 자리입니다

감지 신호가 **삽입 하나**에 걸려 있다는 것은, 해시가 저장되는 순간 「바뀌었다」가
소멸한다는 뜻입니다. 둘을 갈라 두면 사이에서 끊겼을 때 해시만 남고, 다음 바퀴부터
`append` 가 거짓을 돌려주어 **그 개정이 영영 검수 큐에 못 올라옵니다.**
재수집으로도 복구되지 않습니다.

포트를 둘로 두면 어떤 저장소 구현도 이 구멍을 막을 수 없어서, `append` 가 스냅샷과
검수 큐 행을 **함께** 받습니다. 실제 저장소는 한 트랜잭션으로 처리해야 합니다.

## 게시판은 겹칠 때까지 읽습니다

보도자료 RSS 는 최근 10건만 주고 그 10건이 4일치입니다. **수집이 며칠 멈추면
그 사이 게시물이 밀려나 영구히 사라집니다.** 게시글 번호로도 못 잡습니다 —
번호가 게시판별 연속이 아니라 전체 게시판이 공유합니다 → §12.5.

그래서 **고정 쪽수를 읽지 않습니다.** 마지막으로 본 게시물 날짜와 겹칠 때까지
쪽을 넘깁니다. 한 달 멈췄다 재개돼도 그 구간이 자동으로 복구됩니다.

| 멈추는 조건 | |
| --- | --- |
| 빈 쪽 | 더 줄 것이 없습니다 |
| 겹침 | 가장 오래된 게시물이 마지막으로 본 날짜 이하 — **구멍 없음 확인** |
| 게시판이 아님 | API 는 쪽 개념이 없어 한 쪽으로 끝냅니다 |
| **20쪽** | 안전장치. **여기 걸리면 `hitPageLimit` 으로 밝힙니다** |

20쪽이면 반년 가까이입니다(쪽당 10건 · 2쪽이 약 2주치). **거기까지 읽고도 겹치는
지점을 못 찾았으면 구멍이 남았을 수 있어** 조용히 넘기지 않습니다.

### 잘린 바퀴는 커서를 밀지 않습니다

정본이 두 갈래를 갈라 놓았습니다 — 겹침은 「구멍 없음이 확인됨」, 20쪽은
「경고 남기고 중단」입니다. 그래서 저장도 갈라야 합니다.

**잘렸으면 `last_seen_date` 를 안 적고 `last_error` 도 안 지웁니다.** 밀어 버리면
다음 바퀴가 1쪽에서 바로 겹쳐 멈추고, **구멍이 남았다는 사실이 결과에서도
저장소에서도 사라집니다** — 경고가 딱 한 번 뜨고 영영 안 뜹니다.

그대로 두면 사람이 손댈 때까지 매 바퀴 같은 경고가 뜹니다. 20쪽을 계속 읽는 값을
치르지만, 구멍을 모르고 지나가는 것보다 낫습니다.

## 한 소스가 실패해도 나머지를 계속합니다

법령 API 가 죽었다고 게시판 수집까지 멈추면 **그날 나온 정책 발표를 통째로
놓칩니다.** 소스마다 따로 감싸고, 소스 하나의 실패로는 던지지 않습니다.

**실패를 기록하려는 호출도 실패할 수 있습니다.** 수집 실패의 가장 흔한 원인이
저장소·네트워크라, 그때 `registry.update` 도 함께 죽습니다. 그것이 새어 나가면
뒤 소스가 통째로 안 돌기 때문에 그 호출도 감쌌습니다 — 못 남긴 것은 그 소스의
결과에 실패로 담아 내보냅니다.

실패는 감시 목록에 남깁니다 — **오류의 종류만** 남기고 메시지는 안 남깁니다.
원문에 무엇이 들었는지 우리가 모르기 때문입니다.

**감시 목록 자체를 못 읽으면 던집니다.** 돌 소스를 모르면 결과를 만들 수 없고,
빈 결과를 돌려주면 「전부 정상」으로 읽혀 아래가 경고한 상태를 새로 만듭니다.

## 조용히 멈춘 수집기를 알립니다

> *"조용히 멈춘 수집기가 가장 위험합니다 — 아무 일도 안 일어나므로 아무도
> 모릅니다"* → §12.3

주기의 **두 배**를 넘긴 소스를 `stale` 로 내놓습니다. 한 번도 성공한 적 없는
것도 포함입니다.

**이번 바퀴에 성공한 소스는 빼고 셉니다.** 바퀴 시작 시점의 값으로만 판정하면
최초 배포 바퀴와 장애 복구 첫 바퀴에 「전부 멈춤」이 뜨고, **그런 경고가 상시로
뜨는 동안 진짜 멈춘 소스가 묻힙니다.**

**`watch_method='human'` 은 세지 않습니다.** 기관 연락처처럼 자동 감시가 안 되는
층이라(§12.6) 원래 안 도는 것이고, 그것을 고장으로 세면 진짜 고장이 묻힙니다.

## 쓰는 법

```ts
import { createKbCollector } from '@/modules/kb-collector'

const { results, stale } = await createKbCollector({
  fetcher, snapshots, registry, changes, ids, clock, hasher,
}).collect()
```

하루 1회 크론에서 돕니다. 결과는 소스별 `added`·`unchanged`·`pages`·`hitPageLimit`
이고, 실패한 소스는 `error` 가 붙습니다.

## 안 채우는 칸 둘

스키마에 자리는 있지만 넣지 않습니다 → §12.2.

| 칼럼 | 왜 |
| --- | --- |
| `snapshot_before` | **검수 화면이 그때 조회합니다.** 화면이 어차피 원문 둘을 다 읽어야 합니다 |
| `dedupe_key` | **묶지 않기로 했습니다** — 아래 참고 |

## 같은 발표를 묶지 않습니다

§12.2 는 같은 발표가 게시판 여럿에 올라오는 것을 `dedupe_key` 로 묶으라고 정했습니다.
그런데 **수집기는 원문만 봐서 그 값을 계산할 수 없습니다** — 본문이 다르기 때문에
「같은 시행령 개정」임을 알아보려면 의미 판단이 필요하고, 정본도 누가 채우는지
정하지 않았습니다.

**지금은 안 채웁니다.** 그래서 검수 화면에 같은 발표가 여러 줄로 뜹니다. 사람이
같은 것을 두세 번 보는 값을 치르지만, **잘못 묶어서 하나를 승인하며 다른 하나까지
승인하는 것보다 낫습니다.** 필요해지면 그때 넣습니다.

## 판단이 필요했던 자리

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| **변경 판정** | **저장소가 한다** | 비교 로직을 두 곳에 두면 어긋납니다 → §12.1 |
| **저장 + 큐 등록** | **한 포트로 묶는다** | 갈라 두면 사이에서 끊겼을 때 그 개정이 영영 안 보입니다 |
| **잘린 바퀴** | **커서를 안 민다** | 밀면 경고가 한 번만 뜨고 구멍이 안 보이게 됩니다 |
| **해시 방식** | **밖에서 받는다** | 알고리즘을 코드에 박으면 바꿀 때 전체 재수집이 필요합니다 |
| **원문 가공** | **안 한다** | 요약하면 근거가 아니게 됩니다 |
| **쪽 안전장치** | **20쪽 · 밝힌다** | 무한히 읽을 수 없지만, 잘렸다는 사실은 남아야 합니다 |
| **실패 사유** | **종류만** | 메시지에 원문 조각이 섞일 수 있습니다 |
| **`human` 소스** | **세지도 돌리지도 않는다** | 원래 안 도는 것을 고장으로 세면 진짜 고장이 묻힙니다 |
| **같은 발표 묶기** | **안 한다** | 잘못 묶으면 하나를 승인하며 다른 것까지 승인합니다 |
| **직전 원문** | **화면이 찾는다** | 화면이 어차피 원문 둘을 다 읽습니다 |

## 아직 아닌 것

⬜ **감시 목록 초기 행이 아직 없습니다.** §12.3 이 `source_registry` 를 정의했고,
**넣을 값은 정본에 이미 있습니다** — [ADR-012](../../../decisions/012-kb-collection.md)
결정 표(소스 넷 · `watch_method`), [07-kb-operations.md](../../../spec/backend/08-14-kb-operations.md)
「소스 주소 — 실측 확인」(`law.go.kr/DRF` · `data.go.kr/15090734` · 금융위 RSS `fid` 0111·0112·0114),
§12.4(하루 1회), §12.3 예시(`source_key_prefix`). 조립 자리에서 등록합니다.

**정말 미정인 것은** 기관 페이지 목록·주기(§12.6 `TODO(미정)`), 경찰청 소스
(ADR-012 「남은 것」), 그리고 법령 API `OC` 키·입법예고 인증키입니다.

⬜ **`SourceFetcher` 구현이 없습니다.** 이 모듈은 「어떻게 가져오나」를 모릅니다 —
법령 API 키·RSS 주소·HTML 파서는 조립 자리에서 붙습니다(ADR-028).
