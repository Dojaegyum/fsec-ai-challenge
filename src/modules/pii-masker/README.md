# pii-masker

원문이 네트워크를 타기 전에 **브라우저에서** 계좌·주민번호·카드·전화를 토큰으로 바꿉니다.
개인정보 보호의 첫 겹입니다.

| | |
| --- | --- |
| 계약의 정본 | [04-pii-boundary.md](../../../spec/common/08-14-pii-boundary.md) 「2중 스크러빙」·「토큰화 제외 목록」 |
| 근거 | [ADR-011](../../../decisions/011-pii-boundary-hardening.md) · [ADR-021](../../../decisions/021-runtime-and-module-shape.md) |

## 두 겹 중 첫 겹입니다

| 겹 | 어디서 | 방식 | 무엇을 막나 |
| --- | --- | --- | --- |
| **1차 (여기)** | 브라우저 | 정규식 | 원문이 **우리 서버까지 오는 것** |
| 2차 `pii-tokenizer` | 서버 | NER | 정규식이 못 잡는 이름·기관이 **외부 LLM 으로 나가는 것** |

**1차가 있다고 2차를 건너뛸 수 없고, 2차가 있다고 1차를 생략할 수 없습니다.**

**이름은 여기서 안 잡습니다.** 정규식으로 사람 이름을 가릴 수 없어 2차의 몫입니다.

## 두 방향으로 틀릴 수 있고 둘 다 제품을 망칩니다

| | 결과 |
| --- | --- |
| **못 잡으면** | 원문이 네트워크를 탑니다 |
| **과하게 잡으면** | **금액·날짜가 가려져 슬롯이 안 채워지고 8유형 분기가 무너집니다** |

뒤쪽이 덜 알려져 있어 적어둡니다. 정본의 「토큰화 제외 목록」이 금액·시각·기관명을
**일부러 남기라고** 정하고 있습니다 — 그것들이 절차 분기의 직접 입력이기 때문입니다.
`"카카오페이로 300만원"` 이 `"[기관-1]로 [금액-1]"` 이 되면 경유 서비스를 특정할 수 없고,
사용자는 정보를 다 줬는데 「모름」 취급을 받습니다.

## 가리는 것과 안 가리는 것

| 가립니다 | 예 |
| --- | --- |
| 주민번호 | `900101-1234567` · 붙여 쓴 13자리 |
| 카드 | `1234-5678-9012-3456` · 붙여 쓴 16자리 |
| 전화 | `010-1234-5678` · `02-1234-5678` · `01012345678` |
| 계좌 | `110-234-567890` — **하이픈으로 세 덩이인 것만** |

| 안 가립니다 | 왜 |
| --- | --- |
| 금액 (`3000000원`) | 슬롯 T2 · 서류 필수 기재사항 |
| 날짜 (`2026-08-16`) | 기한 계산의 기산점 |
| 기관명 (`국민은행`·`카카오페이`) | 8유형 분기의 직접 입력 |
| 짧은 숫자 (`112`·`3영업일`) | 개인정보가 아님 |

### 하이픈 없는 계좌는 일부러 안 잡습니다

붙여 쓴 숫자를 계좌로 보면 **금액이 가려집니다.** 그래서 1차에서는 넘기고 2차(NER)에
맡깁니다. 못 잡는 것을 아는 채로 두는 것이 과하게 잡는 것보다 낫다는 판단입니다 —
2차가 있기 때문에 가능한 선택입니다.

### 날짜가 걸러지는 방법

계좌 패턴(`\d{2,6}-\d{2,6}-\d{2,8}`)은 `2026-08-16` 에도 걸립니다. 그래서 매칭된 뒤
**숫자가 열 자리 미만이면 버립니다.** 날짜는 여덟 자리라 여기서 걸러집니다.

## 순서가 결과를 바꿉니다

```
주민번호 → 카드 → 전화 → 계좌
```

휴대폰 11자리와 카드 16자리는 계좌 패턴에도 걸리므로 **좁은 것부터** 잡아야 합니다.
순서를 바꾸면 카드가 계좌로 기록되고, 복원할 때 종류별 규칙이 어긋납니다.

## 같은 값은 같은 토큰을 유지합니다

챗은 매 턴 마스킹하는데 `[계좌-1]` 이 턴마다 달라지면 복원이 어긋납니다. 앞선 매핑을
넘기면 이미 본 값은 그 토큰을 그대로 쓰고, 새 값만 이어지는 번호를 받습니다.

```ts
import { createPiiMasker } from '@/modules/pii-masker'

const masker = createPiiMasker()

const first = masker.mask('110-234-567890 에 보냈어요')
// text: '[계좌-1] 에 보냈어요'

const second = masker.mask('110-234-567890 맞나요', first.mappings)
// text: '[계좌-1] 맞나요'  ← 번호가 유지된다
```

**`mappings` 의 `value` 는 원문입니다.** 브라우저 밖으로 내보내지 마세요 — 암호화해서
볼트에 보관하고 복호화 키는 이 브라우저에만 둡니다
→ [ADR-009](../../../decisions/009-restore-mapping-location.md).
