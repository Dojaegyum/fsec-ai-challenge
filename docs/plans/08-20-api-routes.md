### 미설정을 어느 코드로 내나

**새 `code` 를 지어내지 않았습니다.** 정본의 코드 표에 미설정용이 없어
`INTERNAL`·500·재시도 없음 그대로입니다.

**503 을 쓰지 않은 이유**는 `Retry-After: 10` 이 붙어 사용자가 10초마다
헛되이 다시 누르고, `retry-checker` 가 20초 예산을 태우기 때문입니다.
「있는데 지금 안 된다」와 「아직 없다」는 다른 사건입니다.

### 타입이 실제로 안 맞던 자리 셋

`tsc` 로 직접 확인했습니다 (2026-08-20). 무보정 주입이면 셋 다 깨집니다.

| 자리 | 왜 |
| --- | --- |
| `audit-logger` → `case-purger` | 한쪽은 기록을 돌려주고 받는 쪽은 안 받습니다 |
| `retry-checker` → `chat-receiver` | `error`·`lane` 의 넓이가 **서로 반대**입니다 |
| `kb-finder` → `chat-receiver` | 표는 `title`·JSONB, 프롬프트는 `label`·문자열 |

전부 [`lib/adapters.ts`](../../src/lib/adapters.ts) 에 **손으로 쓴** 어댑터를 뒀습니다.
자동 변환을 안 쓰는 이유는 **내보내면 안 되는 필드가 같이 실려 나가기** 때문입니다
(저장소 내부 경로 · 원문 개인정보 · 평문 이메일).

## 남은 순서

기반(1~3단계)과 요청 껍데기(4단계)는 끝났습니다. **5단계부터입니다.**

```
4  wire.ts · telemetry.ts · request.ts · rate-limit.ts        ✔ 끝
     라우트보다 먼저 — 첫 라우트의 즉석 결정이 나머지에 굳는 것을 막습니다
5  proxy.ts · session-cookie.ts
     관리자·크론 라우트보다 먼저 — 나중에 붙이면 그 사이 라우트가 무방비로 돕니다
     ⚠ Next 16 에서 `middleware.ts` 가 `proxy.ts` 로 바뀌었습니다. 함수 이름도
       `middleware` → `proxy` 입니다 → `node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md`.
       정본 §5.1 이 요구한 「경로 접두사로 일괄 인증」은 그대로 성립합니다
6  POST /api/cases + flows/regenerate-plan.ts
     첫 라우트로 고른 이유: 모듈 셋 조립·표기 변환·계측 헤더·미설정 실패가 한 경로에 전부
7  증거 셋 (POST evidence → POST complete → GET evidence)
8  슬롯 둘 (GET → PATCH)          ← 6번의 flow 를 재사용하는 두 번째 호출자
9  조회 둘 (GET plan · GET deadlines)
10 POST artifacts
11 POST messages + flows/chat-turn.ts
12 크론 둘 + vercel.json (src/ 에 둡니다)
13 관리자 조회
14 server-only · client-only 표시를 모듈에 답니다
```

## 4단계에서 만든 넷 — 무엇을 왜

| 파일 | 무엇 | 왜 이 모양인가 |
| --- | --- | --- |
| `lib/telemetry.ts` | 계측 헤더 넷을 모으고 찍는 **한 자리** | §1.1 이 「모든 응답에 붙습니다」입니다. 붙이는 자리가 둘이면 한쪽만 고쳐져 조건부로 되돌아갑니다 |
| `lib/rate-limit.ts` | §1.3 의 다섯 줄을 규칙으로 | 세는 곳만 갈아 끼우면 되게 갈라 뒀습니다. 증거 상한은 **여기 없습니다** — `case-intake` 가 이미 갖고 있어 숫자를 두 곳에 두지 않습니다 |
| `lib/wire.ts` | 조립본을 프로세스에 **하나만** | 라우트마다 조립하면 카운터가 요청마다 새로 나서 **아무도 상한에 안 걸립니다** |
| `lib/request.ts` | 요청 하나를 여는 껍데기 | 라우트가 `Response` 를 직접 만들면 어느 한 곳이 계측 헤더를 빠뜨려도 코드로는 안 보입니다 |

**속도 제한을 「부르면 터지는 것」으로 두지 않았습니다.** 다른 미설정 자원과 다릅니다 —
모든 요청이 지나는 길목이라 터지게 두면 서비스 전체가 500 이 됩니다. §1.3 의
*"제한이 정상 사용을 막으면 안 됩니다"* 의 가장 심한 형태입니다. 문진 문구와 같은
예외로 두고, **못 하는 일은 설정 현황에 드러냅니다.**

### 4단계 검토에서 실제로 고친 것

네 갈래로 대조하고 지적마다 반증해 **27건 중 8건**이 남았습니다. 라우트를 쓸 때
같은 실수를 반복하지 않도록 남깁니다.

| 무엇이 틀렸었나 | 왜 위험했나 |
| --- | --- |
| `EGRESS_BLOCKED` 응답이 `X-Pii-Egress-Residual: 0` | 잔여 때문에 막은 응답이 「잔여 0건」이라고 증언했습니다. §6 (1) 이 `1` 을 못 박은 자리입니다. 던지는 쪽은 건수를 `detail.counts` 에만 싣습니다 |
| 창 없는 429 에 `Retry-After: 1` | 정본에 없는 값입니다. 증거 상한은 기다려도 안 풀리는데 1초마다 다시 누르게 됩니다 |
| 메모리 카운터가 **삽입 순서로** 축출 | 창이 가장 긴 사건 생성 카운터(1시간)가 먼저 밀려나 §1.3 의 「IP당 시간당 20건」이 0으로 돌아갑니다. **먼저 끝나는 창부터** 버리게 고쳤습니다 |
| 세션 키와 IP 대체 키가 같은 이름 공간 | `X-Session-Id: ip:1.2.3.4` 를 보내면 그 주소 뒤 사람들의 통을 대신 태울 수 있었습니다. 접두사(`s:`·`ip:`)로 갈랐습니다 |

## 안 풀린 blocker

### ① `GET /api/cases/{case_id}` 의 계약이 없습니다

엔드포인트 목록(§2)에 한 줄 있는데 **§3 에 응답 절이 없습니다.**

이 경로가 **재방문 진입(`/c/{token}` 첫 로드)의 유일한 입구**입니다. 없으면
[ADR-021](../../decisions/021-reentry-and-identity.md)이 약속한 「며칠 뒤 링크를 열면
곧장 플랜으로」가 성립하지 않습니다.

**라우트를 지어내기 전에 정본을 채워야 합니다** — 슬롯·플랜·기한의 합본인지,
초기 화면을 서버가 지목하는지.

### ② 개인정보 쓰기 경로가 경계를 우회합니다

`PATCH /slots` 와 `POST /artifacts` 가 「클라이언트가 이미 토큰화했다」를 믿고
값을 그대로 저장하는데, **그 값은 나중에 프롬프트로 외부 모델에 나갑니다.**

불변 규칙 2가 *"`pii-tokenizer` 를 통과하지 않는 LLM 호출 경로를 만들지 마세요"*
입니다. 지금 설계에서 토큰화를 지나는 것은 **챗 발화 하나뿐**입니다.

**쓰기 경로를 서버 2차 토큰화에 통과시켜야 하고**, 그 자리를 `flows/` 한 곳으로
모아야 합니다.

### ③ 볼트에 매핑을 넣는 경로가 없습니다

라우트 어디에도 브라우저가 봉한 토큰↔원문 매핑을 볼트에 넣는 자리가 없습니다.
설계의 볼트 포트는 **파기용 둘뿐**입니다. 이대로면 `[계좌-1]` 이 영영 복원되지
않아 [ADR-009](../../decisions/009-restore-mapping-location.md)가 무의미해집니다.

## 계약 대조에서 나온 것 (major)

라우트를 쓸 때 놓치기 쉬운 것들입니다.

- `GET evidence` 응답에 **`poll_after_ms` 를 빠뜨리면** 화면이 언제 다시 물을지 모릅니다
- **「그 외 조회 — 세션당 분당 300회」** 를 거는 자리가 없습니다. 폴링이 여기 포함됩니다
- §1.1 이 **「모든 응답에 붙습니다」** 인데 계측 헤더를 조건부로 두면 그걸 뒤집습니다
- `GET deadlines` 를 확정 슬롯만으로 여과하면 **기한 목록이 조용히 비어서 200 으로 나갑니다.**
  §3.7 에 그런 여과 규칙이 없습니다
- `unlocked_steps` · `referenced_steps` · `referenced_deadlines` 세 배열이 계약 예시에
  있는데 「주인이 없다」로 빠졌습니다
- 모든 슬롯을 「모름」으로 답한 사용자가 근거 부족 턴을 만나면 **갈래가 없습니다** —
  `citation-checker` 는 물을 슬롯이 있는지 안 보는데 `chat-publisher` 는 질문을 필수로 받습니다
