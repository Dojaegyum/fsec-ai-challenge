## QA 가능이란 무엇인가 — 이 문서가 겨누는 선

**한 사람이 브라우저로 이 한 바퀴를 실제 서버로 돌 수 있는 것**입니다.

```
/start 에서 동의 → 사건 생성 → 링크 받음
  → 진술 한 턴 → 슬롯 하나 답함 → 플랜이 뜸
  → 파일 하나 올림 → 전사가 뜨고 파란 토큰이 보임
  → 브라우저 닫음 → 받은 링크로 다시 들어옴 → 플랜이 그대로 있음
```

**목업이 아니라 서버 응답으로** 이게 되면 QA 를 시작할 수 있습니다.
화면 대부분이 **08-24 에 실제 응답으로 옮겨졌습니다** — 남은 것은 증거함과, 값을
보내는 쪽(발화·업로드)입니다.

### ① 슬롯 답변이 서버로 안 갑니다 — 경로는 이미 정해져 있었습니다

> **정정 (2026-08-24).** 이 항목을 처음엔 「계약이 서로 어긋난다」고 적었는데,
> **제가 경계 문서를 안 읽어서 그렇게 보였습니다.** 어긋나지 않습니다.

[PII 격리 경계](../../spec/common/08-14-pii-boundary.md) 「2중 스크러빙」이 이미 정해 뒀고,
도재겸 판단도 같았습니다 — *「LLM 이 알아야 하는 정보를 전달받는 곳에 대해서만 경계를 지나면 된다」*.

| 단계 | 어디서 | 무엇을 |
| --- | --- | --- |
| **1차** | 브라우저 | 정규식 — 계좌·주민번호·카드·전화. **네트워크를 타기 전** |
| **2차** | 서버 (`pii-tokenizer`) | NER — 이름·기관처럼 정규식이 못 잡는 것 |

[ADR-040](../../decisions/040-write-path-boundary.md)이 **슬롯 입력을 이름으로 집어** 「값을 받는 모든
경로가 2차를 지난다」고 적었고, 이유가 바로 *"나중에 `prompt-builder` 가 사건 상황을 프롬프트에
담을 때 **외부 모델로 나간다**"* 입니다. 슬롯 값은 실제로 프롬프트에 들어갑니다 —
`flows/chat-turn.ts` 의 `caseState` 가 `valueMasked` 를 싣습니다.

**그래서 `pii_confirm` 은 모순이 아닙니다.** 1차를 지나서 온 값에서 2차 NER 이 남은 것을
집으면, **서버가 대신 토큰화하지 않고 사용자에게 되묻는** 것입니다 (ADR-041).

#### 배선할 말 — ✅ 2026-08-24 이었습니다

      ⚠️ 그 표시가 §3.4 `options` 에 **없어 문구로 알아봅니다** — 계약에 칸을 둘지 함께 보세요

모델을 GPU 에 **처음** 올리는 데 60초가 넘어 요청이 타임아웃했습니다. 이름 찾기가
죽으면 앱은 슬롯 저장을 **503 으로 막습니다**(경계라서 못 가리면 안 내보냅니다).
즉 **막 띄운 서비스의 첫 사용자는 사건을 진행하지 못합니다.** 시연 직전에 켜는
흐름이라 정확히 그 자리를 밟습니다.

원인이 둘이었습니다.

| | 무엇 | 왜 안 보였나 |
| --- | --- | --- |
| ⛔ | 뜰 때 미리 올리는 목록에 **이름 찾기만 빠져 있었습니다** | *"모델이 Ollama 안에 있으니 올릴 것이 없다"* 는 주석이 붙어 있었습니다. 프로세스 밖이지 **안 올라오는 게 아닙니다** |
| ⛔ | `keep_alive` 를 **문자열로** 보냈습니다 | Ollama 는 숫자면 초, 글자면 기간입니다. `"-1"` 은 400 (`time: missing unit`). 환경변수는 전부 글자로 들어옵니다 |

고친 뒤 **첫 요청 0.2~0.4초**이고, `ollama ps` 가 아무 요청 없이 `Forever` 로
올라와 있습니다. 시험 셋을 붙였고 **배선을 도로 끊어 떨어지는 것까지 확인**했습니다.

### ⛔ 배포본에는 **아직 붙이면 안 됩니다** — 켜는 것이 끄는 것보다 나쁩니다

처음에는 「GPU 가 사라지면 503 이니 시연 흐름을 정하고 붙이자」로 미뤄 뒀는데,
과차단 한 건을 파다 **그보다 앞선 이유**가 나왔습니다(짝 세션이 찾았고 제가 코드로
확인했습니다).

**토큰화 제외 목록이 제품 경로 셋에 안 물려 있습니다.**

```
flows/read-evidence.ts        전사    ← allowedTerms 안 줌
modules/chat-receiver/…       챗      ← 안 줌
app/api/…/artifacts/route.ts  증거    ← 안 줌
flows/answer-slot.ts          「아니에요」를 눌렀을 때만 [raw] 를 줌
```

`tokenize()` 가 `ctx.allowedTerms ?? []` 로 받으므로 **제품 경로에서는 언제나 빈
목록**입니다. 켜면 **문장 안의 기관명이 `[이름-N]`** 이 되어 경유 서비스를 못 고르고,
[17 머리말](../research/17-기관명-사전-실측.md)이 못 박은 대로 — 기관명은
**8유형 분기의 입력**이라 사라지면 **에러 없이 엉뚱한 매뉴얼이 나갑니다.**

**지금까지 안 터진 이유는 `NER_URL` 이 비어 있어서**입니다 — NER 분기 자체를
건너뛰니 목록이 있든 없든 같았습니다. **스위치를 켜는 순간 살아납니다.**

> 기한에서 겪은 것과 **똑같은 모양**입니다. 표를 지키는 시험(`tokenize.test.ts` 가
> `allowedTerms` 를 **손으로 넣고** 통과)은 있는데 **부르는 쪽을 지키는 시험이
> 없습니다.** 이번 주에 이 모양으로 두 건이 나왔습니다.

### ✅ 그날 안에 뚫렸습니다 — 배선이 붙었고, 걸어서 확인했습니다

짝 세션이 네 경로에 다 물렸고(#73), 가장 나쁜 문장(`~에 전화해서`)으로 **앱을
통해** 17곳을 다시 걸었습니다.

```
붙이기 전   12/17 가려짐   ← 경유 서비스 9곳 포함 ⛔
붙인 뒤      3/17 가려짐   ← 경유 서비스 14곳은 14/14 살아남음 ✅
                            남은 셋은 금융감독원·보이스피싱 지킴이·서초경찰서
```

**유형 분기에 쓰이는 값은 전부 살아남습니다** — 이 결함이 무너뜨리던 것이
그것이라 그 자리는 닫혔습니다. 남은 셋은 `org` 표에 못 들어가는 기관이라
사전에 없습니다(`channel_id` 필수 · 04 §8). 유형 분기에 안 쓰이므로 절차는
안 틀어지고, 짝 세션이 자리를 따로 올립니다.

**그래서 남은 것은 하나뿐입니다** — GPU 가 사라지면 슬롯 저장이 503 입니다.

```
안 붙이면   이름이 안 가려집니다 (1차 정규식만) — nerApplied=false 로 드러납니다
붙이면      이름이 가려집니다. 대신 GPU 가 사라지면 사건 진행이 멈춥니다
```

⛔ **팟이 시간당 $0.74 로 과금 중입니다.** 시연까지 켜 둘지, 지금 지울지가
같은 결정에 붙어 있습니다.
