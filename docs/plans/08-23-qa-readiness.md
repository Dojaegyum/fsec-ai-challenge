# QA 까지 남은 일

> 2026-08-23 작성. **세션이 바뀌어도 이어받는 자리입니다** — 컴팩트 뒤에 이 파일부터 여세요.
>
> 조사한 사실만 적었습니다. 각 태스크의 「지금 상태」는 그날 코드를 직접 보고 쓴 것이고,
> **틀렸으면 고치는 것까지가 그 태스크입니다.**

## QA 가능이란 무엇인가 — 이 문서가 겨누는 선

**한 사람이 브라우저로 이 한 바퀴를 실제 서버로 돌 수 있는 것**입니다.

```
/start 에서 동의 → 사건 생성 → 링크 받음
  → 진술 한 턴 → 슬롯 하나 답함 → 플랜이 뜸
  → 파일 하나 올림 → 전사가 뜨고 파란 토큰이 보임
  → 브라우저 닫음 → 받은 링크로 다시 들어옴 → 플랜이 그대로 있음
```

**목업이 아니라 서버 응답으로** 이게 되면 QA 를 시작할 수 있습니다.
화면 대부분이 **08-24 에 실제 응답으로 옮겨졌습니다** — 남은 것은 증거함과, 값을
보내는 쪽(발화·업로드)입니다.

## Task 2: 화면을 라우트에 잇는다 — 픽스처 여섯을 `fetch` 로

**이 문서에서 가장 큰 덩어리이고, 프론트가 혼자 할 수 있는 일입니다.**

`src/app/c/[token]/fixtures.ts` 는 **§3 응답 모양 그대로** 만들어 뒀습니다.
그래서 「부르던 자리를 `fetch` 로 바꾸는 것」이 배선의 전부입니다 — 모양을 고칠 일이 없습니다.

| 자리 | 지금 | 바꿀 것 |
| --- | --- | --- |
| ~~`page.tsx`~~ | ✅ `useCaseBundle(token)` → §3.10 **한 번** | |
| ~~`plan.tsx` 단계~~ | ✅ `bundle.steps` (§3.6) | |
| ~~`plan.tsx` 기한~~ | ✅ `bundle.deadlines` (§3.7) | |
| `plan.tsx` 공고 카드 | `FIXTURE_NOTICE` | 같은 응답의 `starts_at`·`elapsed` (**Task 4 대기**) |
| ~~`evidence.tsx`~~ | ✅ `useEvidence()` → §3.3 + `decidePoll` | 자료 레일·복원 매핑은 아직 브라우저 몫 |
| ~~`chat.tsx`~~ | ✅ `bundle.question` (§3.4) | |

- [x] 사건 하나를 한 번에 읽는 자리를 만든다 — `src/app/c/[token]/load.ts`.
      **`fetch` 하는 유일한 자리**이고 층 C 모듈은 그대로 판단만 돌려줍니다
- [x] 로딩·에러 상태를 화면에 둔다 — `gate.tsx`. 판정은 `decidePoll` 이 냅니다
      (폴링이 아니어도 **같은 물음**이라서). 자동 재시도는 없습니다
- [x] 픽스처를 지우지 말고 **개발용으로 남긴다** — `?view=` 가 붙어 있으면
      서버를 부르지 않고 `FIXTURE_BUNDLE` 로 그립니다
- [x] 증거함을 잇는다 — `GET …/evidence/{id}` + `decidePoll`.
      **간격은 서버가 준 `poll_after_ms` 만** 쓰고, `ingest_status: "failed"` 는
      200 이라 실패 화면으로 보내지 않습니다 (갈림길이지 막는 자리가 아닙니다)

> **히어로 스트립도 함께 이었습니다** — 계획서 표에 없던 자리입니다. 그냥 두면
> **살아 있는 보드 위에 죽은 첫 줄**(「8월 20일」·「D-2」가 박힌 채)이 남습니다.
> 지금은 진행 중인 단계와 그 단계의 본 기한·추가 기간에서 만들고,
> **`days_left` 가 없으면 D-day 배지가 아예 안 뜹니다** — 화면이 날짜를 세지 않습니다.
>
> 남은 하드코딩은 **「사건 진행」 레일 다섯**(지급정지→피해구제→공고→결정→환급)입니다.
> 계약에 사건의 큰 국면을 내리는 칸이 없어 단계에서 유도할 수 없습니다 → Task 4 에서 판단합니다.

> ⚠️ **`fetch` 를 모듈 안에 넣지 마세요.** 층 C 모듈은 전부 「판단만 돌려주고 부르지 않는다」로
> 서 있습니다. 부르는 것은 화면의 일입니다.

## Task 6: 파일 한 장이 실제로 올라간다

`file-sender` 가 **다음에 무엇을 할지**만 정하고 있습니다. 실제 세 단계를 잇습니다.

      레일에 그리는 이름이 그 결과입니다(`RailFile.name` 의 뜻).
      「입금내역_110-2345-678901.png」가 `[계좌-1]` 로 바뀝니다
- [ ] 전사가 뜨면 `transcript-viewer` 가 원문으로 펼치는지 **실제로** 본다 ←
      **전사기가 필요합니다**(`TRANSCRIBER_URL`). 볼트 되받기는 ADR-050 으로 섰습니다

**시험 10건.** 파일을 우리 서버로 보내게 고쳐 보고 **2건이 정확히 깨지는 것**을
확인했습니다 — 서버리스 함수의 본문 크기 제한 때문에 **객체 저장소로 곧장** 가야 합니다.

> ⬜ **PDF 를 어디에 넣을지가 정본에 없습니다.** §3.2 의 `kind` 는 `audio·image·text`
> 셋뿐인데 PDF 는 `text/*` 가 아닙니다. 판독은 OCR 이라 `image` 에 가깝지만 데이터
> 모델이 말하지 않아 **지어내지 않고 안 받습니다** — 잘못된 `kind` 로 올리면 전사기가
> 다른 일을 합니다. 화면의 자료 슬롯 넷은 전부 소리 아니면 사진이라 지금 막히는
> 사람은 없습니다 → Task 9 ⑧

> ⚠️ **파일 속 주민등록번호 검출은 여전히 미결입니다** ([ADR-026](../../decisions/026-raw-upload-retention.md)
> 「착수 전 가장 큰 미결」). QA 에서는 **신분증을 올리지 않는 것으로 진행**하고,

### ① 슬롯 답변이 서버로 안 갑니다 — 경로는 이미 정해져 있었습니다

> **정정 (2026-08-24).** 이 항목을 처음엔 「계약이 서로 어긋난다」고 적었는데,
> **제가 경계 문서를 안 읽어서 그렇게 보였습니다.** 어긋나지 않습니다.

[PII 격리 경계](../../spec/common/08-14-pii-boundary.md) 「2중 스크러빙」이 이미 정해 뒀고,
도재겸 판단도 같았습니다 — *「LLM 이 알아야 하는 정보를 전달받는 곳에 대해서만 경계를 지나면 된다」*.

| 단계 | 어디서 | 무엇을 |
| --- | --- | --- |
| **1차** | 브라우저 | 정규식 — 계좌·주민번호·카드·전화. **네트워크를 타기 전** |
| **2차** | 서버 (`pii-tokenizer`) | NER — 이름·기관처럼 정규식이 못 잡는 것 |

[ADR-040](../../decisions/040-write-path-boundary.md)이 **슬롯 입력을 이름으로 집어** 「값을 받는 모든
경로가 2차를 지난다」고 적었고, 이유가 바로 *"나중에 `prompt-builder` 가 사건 상황을 프롬프트에
담을 때 **외부 모델로 나간다**"* 입니다. 슬롯 값은 실제로 프롬프트에 들어갑니다 —
`flows/chat-turn.ts` 의 `caseState` 가 `valueMasked` 를 싣습니다.

**그래서 `pii_confirm` 은 모순이 아닙니다.** 1차를 지나서 온 값에서 2차 NER 이 남은 것을
집으면, **서버가 대신 토큰화하지 않고 사용자에게 되묻는** 것입니다 (ADR-041).

#### 배선할 말

- [ ] 타이핑한 값 → `outgoing()` → 볼트 → `PATCH {action:"answer", value: 가린 것}`
- [ ] 「모름」 버튼 → `PATCH {action:"unknown"}`. ⚠️ 그 표시가 §3.4 `options` 에 **없어**
      `chat-handler` 가 문구로 알아봅니다 — 계약에 칸을 둘지 함께 보세요
- [ ] `pii_confirm` 이 오면 카드 둘 → `action: "mask"` · `"keep"` (같은 값을 다시 보냅니다)

#### ⚠️ 단, `action: "mask"` 는 경계 문서와 어긋납니다 — 백엔드 몫

경계 문서는 이렇습니다.

> **쓰기 경로에서는 잡히면 거부입니다. 서버가 대신 토큰화하지 않습니다.**
> 서버가 만든 토큰은 브라우저가 복원하지 못해 그 값이 영영 빈칸이 되고,
> 매핑을 서버가 갖게 되어 ADR-009 도 깨집니다.

그런데 `flows/answer-slot.ts` 의 `action: "mask"` 는 **서버가 토큰화해서 저장**합니다
(`valueMasked: masked.masked`). 그 값은 브라우저가 무엇인지 모릅니다 — 서류에 빈칸이 됩니다.
**새는 것은 아니고** §3.5 가 정한 동작이라 화면은 그대로 잇지만,
**경계 문서와 코드 둘 중 어느 쪽이 정본인지는 사람이 정해야 합니다.**

- [ ] `action: "mask"` 를 서버가 하는 것이 맞는지 정한다 (kth9245)

### ④ 「잘 모르겠어요」가 갈 `track` 이 계약에 없습니다

지어낸 값이 아니라 이 저장소가 이미 택해 둔 기본입니다.

**그래도 위험이 남습니다.** 통장묶기는 절차가 완전히 다르고(`08-14-channel-matrix.md`),
**`track` 을 나중에 고치는 경로가 없습니다** — 잘못 들어가면 그대로 굳습니다.

- [ ] 셋 중 하나를 정한다 — ⓐ `track` 에 세 번째 값을 둔다 · ⓑ `track` 을 선택 항목으로
