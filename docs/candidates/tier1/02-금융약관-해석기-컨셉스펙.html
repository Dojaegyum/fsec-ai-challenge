사인하기 전에 — 금융약관 해석기

"서명하기 전 3분, AI에게 물어보세요." 대출·보험·카드 약관의 위험 조항을 짚어주고 내 눈높이로 설명하는 불완전판매 예방 비서.

타깃금융상품 가입 직전의 모든 소비자 (고령층·사회초년생 우선)
핵심 가치정보 비대칭 해소 — 읽지 않고 서명하는 관행을 끊는다
채널모바일 우선 반응형 웹 (창구/앱에서 서명 직전 사용)
포지셔닝소비자 편에 선 유일한 약관 리뷰어 — 판매자 이해관계 無

디자인 원칙

신뢰가 곧 UI다. ① 파랑 기반의 차분한 톤 — 공포 조장 금지, 위험은 정확하게만 표시 ② 모든 판정에 원문 조항 근거를 인용(환각 방지 장치를 UI로 노출) ③ 위험 등급은 색+아이콘+텍스트 3중 표기 ④ "설명 눈높이" 스위치(표준/쉬운말/큰글씨)를 1탭 거리에 ⑤ 요약보다 하이라이트 — 원문 위에 표시해 신뢰 확보.

데이터 소스 — 금감원 파인 금융상품 공시(비교 기능), 각 사 공개 약관(테스트 코퍼스), 금소법상 설명의무 항목(점검 체크리스트 설계 근거). 개인 데이터는 업로드 문서뿐 — 세션 종료 시 파기 정책 명시.

AI 활용 보안·컴플라이언스 설계 (4개 스펙 공통 섹션)

3줄 요약 — ① 금융권의 외부 AI API 제약(망분리 규제)은 금융회사 내부망에 걸리는 규제다. ② 2026년 4월 전자금융감독규정 개정으로 금융회사조차 업무망에서는 생성형 AI 사용이 허용됐다(고객 금융거래정보를 다루는 핵심망만 계속 통제). ③ 따라서 문제는 "외부 AI를 쓰느냐"가 아니라 "AI에게 무엇을 보내느냐"이며, 이는 설계로 통제한다.

✅ 이 서비스의 규제 위치: 리스크 낮음
사인하기 전에는 금융회사 내부 시스템이 아니라 소비자가 자기 계약서·약관을 자발적으로 올리는 일반 웹서비스 — 망분리 규제의 적용 대상이 아니다. 관리할 것은 업로드 문서 속 개인정보(이름·계약금액 등)이며, 아래 4단계 파이프라인으로 통제한다. 약관 원문 자체는 공개 문서라 민감도가 낮은 것도 이 주제의 강점.
1입력 마스킹 — 이름·주민번호·계좌를 API 전송 전 자동 가림→ 2미저장 — 세션 종료 시 문서 즉시 파기(UI에 명시)→ 3출력 필터 — 응답에 개인정보 재노출 차단→ 4인젝션 방어 — 문서에 심긴 악성 지시문 무력화

심사 예상 질문 대비 — "외부 AI에 계약 정보를 보내는 것 아닌가?" → "전송 전 마스킹·미저장·출력 필터의 3중 통제를 두었고, 이는 주최기관(금융보안원)의 생성형 AI 보안 가이드라인 통제 항목을 서비스 설계에 그대로 반영한 것"이라고 답한다. 근거 인용 UI(F-05)와 함께 'AI 신뢰성을 설계로 구현한 팀'으로 포지셔닝.
