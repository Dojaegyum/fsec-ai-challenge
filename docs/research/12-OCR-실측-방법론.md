## 1. 화면 이미지 만들기

**Pillow 로 직접 그렸습니다.** 헤드리스 브라우저(Edge)를 먼저 썼는데 스크린샷이 조용히 비는 일이
있어 의존을 뺐습니다 — 좌표를 우리가 쥐면 나중에 bbox 정답도 낼 수 있습니다.

```
폭 900px · 맑은 고딕(malgun.ttf / malgunbd.ttf)
상단 바(기관명 + 화면 제목) → 라벨/값 행 반복 → 꼬리말
문자 화면은 발신번호 + 말풍선
```

**라벨은 왼쪽, 값은 오른쪽**입니다. 이 배치가 짝짓기 지표의 전제입니다 —
한 행에서 라벨과 값이 가로로 멀리 떨어져 있어야 OCR 이 짝을 흘릴 여지가 생깁니다.

### 1.1 열화 3단

| 조건 | 처리 |
| --- | --- |
| `clean` | 원본 PNG |
| `lowres` | 긴 변 720px 로 축소(LANCZOS) · JPEG q80 |
| `photo` | 1100px 확대 → **2.4도 회전** → **대각선 조명 합성** → 가우시안 블러 0.7 → JPEG q62 |

조명은 좌우로 밝기가 기우는 그라데이션을 만들어 합성했습니다. 실제로 화면을 찍으면
한쪽이 밝고 반대쪽이 어두워집니다.

## 2. OCR 엔진 넷

| 이름 | 호출 |
| --- | --- |
| `tesseract` | 5.4.0 · `-l kor+eng --psm 6` · tessdata(main) 의 `kor.traineddata` |
| `easyocr` | `Reader(['ko','en'], gpu=False).readtext(detail=0, paragraph=False)` |
| `easyocr-layout` | 같은 호출을 `detail=1` 로 — **좌표로 행을 복원** (§3) |
| `gemma3-vision` | Ollama `gemma3:4b` 멀티모달 · `temperature=0 · seed=7` |

Tesseract 한국어 데이터는 설치본에 없어 따로 받아 `TESSDATA_PREFIX` 로 붙였습니다.

### 2.1 비전 모델 프롬프트

```
이 이미지에 보이는 글자를 **그대로** 옮겨 적어라.
- 화면에 있는 순서대로, 줄바꿈을 지켜서 적는다.
- 항목 이름과 값이 짝지어져 있으면 `항목: 값` 형태로 한 줄에 적는다.
- 숫자는 한 글자도 바꾸지 말고 보이는 대로 적는다.
- 설명하지 말고 옮긴 글자만 출력한다.
```

**「한 줄에 적으라」고 했는데도 갈라서 냈습니다** — 프롬프트로 레이아웃을 요구하는 것이
잘 안 된다는 뜻입니다.

## 3. 좌표로 행 복원 (`easyocr-layout`)

EasyOCR 은 글자 덩어리를 **찾은 순서대로** 뱉습니다. 화면에서 한 줄이던
`받는 분 | 김도현` 이 두 줄로 갈리고 순서까지 뒤집힙니다.

```
1. detail=1 로 (박스, 텍스트, 신뢰도) 를 받는다
2. 각 박스의 세로 중심 cy 와 높이 h 를 구한다
3. 이미 만든 행 중 |행.cy - cy| ≤ max(h, 행.h) × 0.6 인 것이 있으면 그 행에 넣는다
4. 없으면 새 행을 만든다
5. 행을 cy 순으로 정렬하고, 각 행 안은 x 순으로 이어 붙인다
```

높이의 60% 를 허용치로 둔 것은 라벨(25px)과 값(27px)의 글자 크기가 달라 중심이 조금 어긋나기 때문입니다.

## 4. 채점

**PII·분기입력 채점은 [10](10-PII인식-실측-방법론.md) §4 와 같은 규칙**입니다
(차단·누출·보존·과차단·손상, 모수는 손상을 뺀 생존분). 여기서는 **더한 것만** 적습니다.

### 4.1 필드 짝짓기

라벨과 값이 **같은 줄에** 있는지 봅니다. 줄마다 공백을 지운 뒤 대조합니다 —
Tesseract 가 한글 낱자 사이에 공백을 넣기 때문에, 안 지우면 라벨이 하나도 안 맞습니다.

| 판정 | 조건 |
| --- | --- |
| **짝유지** | 한 줄 안에 라벨과 값이 함께 |
| **라벨오독** | 라벨과 **한 글자만 다른** 조각이 값과 같은 줄에 |
| 짝깨짐 | 둘 다 읽혔는데 줄이 갈림 |
| 라벨소실 · 값소실 · 둘다소실 | 한쪽 또는 양쪽이 없음 |

값이 숫자 6자리 이상이면 숫자 기준으로, 아니면 문자열 기준으로 대조합니다.

> **문자 화면 12건은 이 지표에서 뺐습니다.** 문자는 라벨-값 구조가 없는 선형 텍스트라
> 「보낸 사람」·「내용」이 화면에 글자로 찍히지 않습니다 — 그걸 라벨 소실로 세면
> **평가셋의 생김새를 OCR 의 실패로 잘못 읽습니다.** 처음 돌렸을 때 실제로 그렇게 잡혀,
> 18건 중 12건이 이 착각이었습니다.

### 4.2 자형 혼동

「글자 → 숫자」 방향의 되돌림표를 두고, 정답 숫자가 **원문 그대로는 없는데 되돌리면 나오는** 경우를 셉니다.

```
O o D Q → 0    l I i | ! → 1    Z z → 2    A → 4
S s → 5        G b → 6         T ? → 7    B → 8    g q → 9
```

숫자 값이 어떤 꼴로 남았는지도 세 갈래로 가릅니다 — **리터럴**(숫자 그대로) ·
**자형혼동**(글자로 읽힘) · **소실**. [10](10-PII인식-실측-방법론.md) §4.2 의
「리터럴 / 한글 / 소실」과 같은 자리입니다.

### 4.3 한글 낱자 공백 복원

Tesseract 전용 후처리입니다. 줄을 공백으로 자른 뒤, **한 글자짜리 한글 토큰이 둘 이상
잇달을 때만** 붙입니다. `받는 분` 처럼 원래 띄어 쓴 자리는 토큰이 두 글자라 안 건드립니다.

```
받 는 계 좌 신 한 은 행 110-234-567890
→ 받는계좌신한은행 110-234-567890
```

완벽하지 않습니다 — `분 김 도현` 처럼 한 글자 라벨과 성씨가 붙어 `분김 도현` 이 되기도 합니다.
그래도 기관명은 확실히 살아납니다.

## 5. 다시 재려면

측정 하네스는 저장소에 넣지 않았습니다 — 버리는 것을 전제로 쓴 코드입니다.
위 절차와 프롬프트면 다시 만들 수 있습니다.

**`ocr-text.json` 이 있어 OCR 을 다시 돌리지 않고 탐지기·후처리만 바꿔 잴 수 있습니다** —
EasyOCR 이 장당 80\~95초, 비전 모델이 176\~240초라 그 시간을 통째로 아낍니다.

`pii-tokenizer` 를 구현할 때 이 평가셋이 [10](10-PII인식-실측-방법론.md) 의 것과 함께
회귀 테스트가 됩니다 — **누출 0건 · 과차단 0건**이 통과 기준입니다.
