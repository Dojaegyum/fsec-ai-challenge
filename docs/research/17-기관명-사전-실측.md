# 기관명 사전 실측 — 사전은 듣지만, 8유형 중 2유형만 있다

> 2026-08-26 측정. 측정 원본은 [assets/datasets/08-26-org-dict/](../../assets/datasets/08-26-org-dict/),
> 하네스는 [dict_probe.py](../../assets/datasets/08-26-org-dict/dict_probe.py) 입니다.
>
> **GPU 없이 잰 것입니다.** [15](15-STT-GPU-실측.md)·[16](16-OCR-GPU-실측.md) 이 저장해 둔
> 전사문·판독문에 `src/kb/org.json` 을 대 본 것뿐입니다.

## 왜 쟀나

두 실측이 **같은 자리에서** 샜습니다.

| | 기관명 손상 |
| --- | ---: |
| 전사 · `large-v3` ([15](15-STT-GPU-실측.md)) | 19% |
| 화면 · GPU ([16](16-OCR-GPU-실측.md)) | **35%** (26건 중 9건) |

기관명은 [8유형 분기](../../spec/backend/08-14-channel-matrix.md)의 입력입니다.
사라지면 **에러 없이 엉뚱한 매뉴얼이 나갑니다** — 잘못된 안내가 곧 금전 손실인
서비스에서 조용히 틀리는 쪽이라 더 나쁩니다.

## 결론 — 셋

**① 사전은 듣습니다.** 사전에 있는 기관은 회수됩니다 — 전사 2/2, 화면 4/7,
**오탐 0**.

**② 그런데 8유형 중 두 유형만 있습니다.** `org.json` 은 은행 계열 19곳뿐이고
증권사·간편송금·가상자산·대면편취·상품권·소액결제는 **한 곳도 없습니다.**
잃은 기관의 **7/9(전사)·4/11(화면)이 애초에 사전에 없어서** 회수 자체가 불가능했습니다.

**③ 통로는 서 있는데 비어 있습니다.** `vocabulary` 배선이 앱에서 전사 서비스까지
끝까지 연결돼 있는데, **`read-evidence.ts` 가 아무것도 안 넘깁니다** → §4.

## 1. 사전이 덮는 범위

```
src/kb/org.json — 기관 19곳 · 표기 73가지(정식명 + 별칭)
```

| | 채널 | 사전 |
| --- | --- | ---: |
| ✅ | `CH-bank` 시중은행 | 16곳 |
| ✅ | `CH-neobank` 인터넷은행 | 3곳 |
| ✅ | `CH-securities` 증권사 | **8곳** — 상장법인 목록·공식 사이트·DART → §12·§13 |
| ✅ | `CH-easypay` 간편송금 | **4곳** — 이 측정 뒤에 각 사 공식 페이지에서 채웠습니다 → §10 |
| ◐ | `CH-crypto` 가상자산 | **4곳** / 5 — 고팍스만 남음 → §13 |
| ❌ | `CH-facetoface` 대면편취 | **0** |
| ◐ | `CH-giftcard` 상품권 | **2곳** / 6 — 컬쳐랜드 · 해피머니 → §13 |
| ✅ | `CH-carrier` 소액결제 | **5곳** — 통신사 넷 + 다날. KG모빌리언스만 남음 → §12 |
| ✅ | `CH-card` 카드 | **9곳** — 이 측정 **뒤에** 선 유형이고([ADR-055](../../decisions/055-channel-card.md)), 출처까지 붙어 사전에 들어갔습니다 → §10 |

평가셋에 대면 이렇게 나옵니다.

| 평가셋 | 기관 | 상품권사 | 통신사 |
| --- | ---: | ---: | ---: |
| 전사(40발화) | 7/24 덮음 | **0/5** | **0/4** |
| 화면(20장) | 8/18 덮음 | **0/2** | **0/2** |

빠진 것들이 **유형별로 통째로** 빕니다 — 증권사(NH투자증권·미래에셋증권·삼성증권·
키움증권) · 간편송금(카카오페이·네이버페이·토스·페이코) · 가상자산(업비트·빗썸·
코인원·코빗) · 공공기관(금융감독원·서울중앙지검·서초경찰서) · 상품권(컬쳐랜드·
해피머니·신세계상품권·북앤라이프·구글) · 통신사(KT·SK텔레콤·LG유플러스·헬로모바일).

**`CH-giftcard`·`CH-carrier` 는 [채널 매트릭스](../../spec/backend/08-14-channel-matrix.md)가
「사각지대」로 표시한 유형입니다.** 환급 절차가 없어 안내가 더 조심스러운 자리인데,
**기관을 못 알아보면 그 안내에 도달하지도 못합니다.**

## 2. 회수 — 사전에 있으면 되찾습니다

잃은 기관 중 **사전에 있는 것만** 모수로 셌습니다. 없는 것은 회수할 방법이 없습니다.

| 사전 19곳 | 거리 0 | 거리 1 | 거리 2 |
| --- | --- | --- | --- |
| 전사 | **2/2 · 오탐 0** | 2/2 · 오탐 6 | 2/2 · 오탐 **200** |
| 화면 | 0/7 · 오탐 0 | **4/7 · 오탐 0** | 7/7 · 오탐 **133** |

**경로마다 안전한 지점이 다릅니다** — 전사는 거리 0, 화면은 거리 1.

> ⚠️ **이 표는 측정 당시의 19곳짜리 사전 값입니다.** 사전이 커지면 **오탐이 함께
> 커집니다** — 임계값은 사전 크기와 같이 움직입니다.
>
> | 사전 | 화면 거리 1 오탐 | 전사 거리 2 오탐 | 화면 거리 2 오탐 |
> | --- | ---: | ---: | ---: |
> | 19곳 (이 표) | **0** | 200 | 133 |
> | 28곳 · 카드사 합류 | **0** | 226 | 143 |
> | 32곳 · 간편송금 합류 (`results-dict.json` 이 지금 담은 값) | **4** | 330 | 178 |
> | 57곳 · 초안까지 (`results-dict-draft.json`) | **5** | 457 | 246 |
>
> **「화면 거리 1 · 오탐 0」이 32곳에서 깨졌습니다.** 카드사 아홉이 들어왔을 때는
> 버텼는데 간편송금 넷에서 무너졌습니다. **어느 표기가 범인인지 세어 봤습니다** —
> 네 건이 전부 **세 글자 표기**였습니다.
>
> ```
> N페이 · 네페이  -> 네이버페이 로 오인
> 카페이          -> 카카오페이 로 오인
> 페이코          -> 페이코 를 엉뚱한 자리에서 발견
> ```
>
> **곳 수가 아니라 표기의 길이입니다.** 세 글자에 거리 1 을 허용하면 **두 글자만
> 맞아도 걸립니다.** 카드사 아홉은 「신한카드」·「비씨카드」처럼 넉 자 이상이라
> 버텼던 것이고, 사전이 커진 것 자체가 원인이 아니었습니다.
>
> `dict_probe.py` 는 두 글자 표기를 이미 걸러 냅니다(`MIN_FORM = 3`) — 「토스」는
> 애초에 매칭에 안 들어갑니다. **그 문턱이 한 글자 낮았던 셈입니다.**

## 3. 왜 다른가 — 깨지는 방식이 다릅니다

**전사는 띄어쓰기가 흔들립니다.** 공백만 떼면 만납니다.

**화면은 글자가 바뀝니다.** 그것도 **자모 하나** 차이로.

```
농협은행   ->  농험은행     협 / 험
토스뱅크   ->  토스빵크     뱅 / 빵   (ㅂ/ㅃ)
카카오뱅크 ->  카카오방크   뱅 / 방   (ㅐ/ㅏ)
케이뱅크   ->  테이빵크     케/테 + 뱅/빵   (거리 2)
```

**`뱅` 이 반복해서 깨집니다.** 은행 이름의 핵심 글자라 타격이 큽니다.

> [12 §4.2](12-OCR-실측-방법론.md) 의 자형 혼동표는 **글자→숫자** 방향만 다룹니다.
> 위 한글 혼동은 표가 없습니다 — 이번에 처음 본 것입니다.

**자모로 풀어 재 봤지만 더 낫지 않았습니다.** 「테이빵크」가 8자모 중 2자모 차이라
가까워질 것으로 봤는데, 그 문턱을 열면 무관한 은행들이 같이 들어옵니다(허용 25%에서
회수 6/7 · 오탐 6). **글자 단위 거리 1이 더 안전합니다.**

## 4. 통로는 서 있는데 비어 있습니다

```
transcriber.start({ media, jobId })          <- read-evidence.ts:55  ⚠️ vocabulary 없음
  -> transcribe.ts:400   vocabulary 를 실어 보냄
  -> inference.ts:166    body.vocabulary
  -> 전사 서비스          initial_prompt
```

**끝까지 이어져 있고 테스트도 있는데, 흐름이 아무것도 안 채웁니다.**
`container.orgs` 로 사전을 읽는 길도 이미 있습니다([regenerate-plan.ts](../../src/flows/regenerate-plan.ts)가 씁니다).

**다만 그냥 잇는다고 되지 않습니다.** 전사 시점에는 **어느 채널인지 모릅니다** —
그걸 알아내려고 전사하는 것이니까요. 그래서 사전 전체를 넘겨야 하는데,
whisper 의 `initial_prompt` 는 길이 상한이 있습니다(224 토큰). 표기 73가지를 다 넣으면
넘칩니다. **무엇을 골라 넣을지는 재 봐야 압니다** — §5.

## 5. 이 실측이 답하지 못한 것

- **`initial_prompt` 에 사전을 넣으면 전사가 실제로 좋아지나** — **안 쟀습니다.**
  이 문서는 **이미 나온 전사문에 사전을 댄 것**이고, 전사 자체를 바꾼 게 아닙니다.
  재려면 GPU 가 필요합니다([runpod-bench](../../deploy/runpod-bench.md)).
- **길이 상한을 어떻게 넘기나** — 표기 73가지가 224 토큰에 안 들어갑니다.
  정식명만(19개) 넣을지, 별칭까지 넣을지, 자주 나오는 것만 넣을지 — 셋 다 안 쟀습니다.
- **표본이 작습니다.** 전사에서 회수 가능했던 것이 **2건**뿐입니다. 「2/2」는
  비율로 읽을 숫자가 아닙니다. 화면도 7건입니다.
- **거리 임계값을 정밀하게 맞추면 과적합입니다** — 20장·40발화에서 고른 값입니다.
- **`pii-tokenizer` 의 허용목록 쪽은 안 봤습니다.** [09 §5.5](09-로컬모델-PII인식-실측.md)
  가 「`KT` 를 사람 이름으로 본다」며 사전을 요구한 자리인데, 이번 측정은
  **분기 입력이 살아남았나**만 봤습니다.

## 6. 그래서 무엇을 할 것인가

| | 판정 |
| --- | --- |
| **사전을 6유형 더 채운다** | ✅ **가장 큽니다.** 잃은 것의 대부분이 「사전에 없어서」입니다. **초안은 §7 에 있고 커버리지가 21% → 85% 로 오릅니다** — 남은 것은 유형마다 출처 URL 하나씩입니다 |
| 후처리 사전 매칭 | ✅ 오탐 0 으로 회수됩니다. **공백을 떼고, 네 글자 이상 표기에만 거리 1** — 한 규칙으로 두 경로를 다 덮습니다 → §9 ③ |
| ~~경로마다 다른 임계값~~ | ✗ **필요 없어졌습니다.** 「전사는 거리 0, 화면은 거리 1」로 나누려던 것인데, 길이 조건을 넣으면 한 규칙으로 묶입니다 |
| 거리 2 | ✗ 오탐이 133\~457건. 없는 기관을 만들어 **분기를 더 크게 망칩니다** |
| 자모 거리 | ✗ 글자 거리 1보다 낫지 않았습니다 |
| `read-evidence.ts` 배선 | △ 통로는 있는데 **무엇을 넣을지 안 쟀습니다** — 길이 상한 때문에 그냥 못 잇습니다 |

## 7. 초안을 짜 뒀습니다 — 출처만 남았습니다

[04 §3~§7](04-기관정보.md) 이 **이름과 유형을 이미 조사해 뒀습니다.** *"기관 이름과 유형
분류는 공개 사실이라 채워 뒀습니다"* 라고 적혀 있고, 사전에 필요한 것이 정확히 그것입니다 —
**연락처는 사전과 무관합니다.**

그래서 [org-draft.json](../../assets/datasets/08-26-org-dict/org-draft.json) 에 27곳을
옮겼습니다. 합치면 이렇게 됩니다.

| | 기관 | 표기 | 전사 평가셋 | 화면 평가셋 |
| --- | ---: | ---: | ---: | ---: |
| 측정 당시 | 19곳 | 73가지 | 21% 덮음 | 36% 덮음 |
| **지금** (§10~§13 을 거쳐) | **51곳** | **161가지** | **90.0%** | **100.0%** |
| **초안까지 합치면** | **57곳** | **162가지** | **90.9%** | **90.9%** |

> **처음 적었던 46곳·85%는 예측이었고, 실제로 합쳐 재니 위와 같습니다** → §9.
> 늘어난 11곳은 카드사 아홉과 결제대행사 둘입니다 — 아래 「자리가 다른 여섯」이
> 못 넣는다고 적었던 것들인데, [ADR-055](../../decisions/055-channel-card.md)로
> `CH-card` 가 서면서 자리가 생겼습니다.

**아직 `src/kb/org.json` 이 아닙니다.** `source_url`·`verified_at` 이 비어 있고,
[kb-load.ts](../../src/lib/kb-load.ts) 가 둘 다 없으면 적재를 거부합니다 —
*"연락처는 근거가 있어야 합니다"*.

### ⚠️ 자동으로 읽어 채우면 안 됩니다

`org.json` 의 `_note` 가 사고를 기록해 두었습니다 — 은행연합회 페이지를 **자동 요약했더니
「한국산업은행」이 「국민은행」으로, 「신한은행」이 「우리은행」으로 밀렸습니다.**

이 초안을 만들며 같은 시도를 했고 같은 벽을 만났습니다 — FIU 신고현황 페이지는 404,
금융투자협회는 방화벽 차단, 거래소 사이트는 자바스크립트로 그려져 본문이 비어 옵니다.
**유형마다 공식 등록부 한 페이지를 사람이 열어 확인하고 옮겨 적는 것**이 맞습니다.
은행 19곳이 은행연합회 한 페이지를 공유하듯, **유형마다 URL 하나면 됩니다.**

### 자리가 다른 셋

초안에 **안 넣은 것**이 있습니다. 평가셋에는 나오는데 `org` 표가 아닙니다.

| | 왜 |
| --- | --- |
| 금융감독원 · 서울중앙지검 · 서초경찰서 | [04 §8](04-기관정보.md) — *"`org` 테이블이 아니라 3순위 공통 KB 항목"* |

**못 덮은 것이 정확히 이 셋뿐입니다.** 90.9% 의 나머지 9.1% 가 전부 이들이고,
`org` 표에 들어갈 것 중에는 **빠진 것이 없습니다.**

> **처음에는 여섯이라고 적었습니다.** 신한카드와 다날을 「유형이 없어 못 넣는다」고
> 함께 묶었는데, 둘 다 틀렸습니다 — 다날은 처음부터 `CH-carrier` 안이었고
> (매트릭스가 요청처를 「통신사 + **결제대행사**」로 적고 있습니다), 카드는
> [ADR-055](../../decisions/055-channel-card.md)로 자리를 만들었습니다.

## 9. 넓혀서 다시 쟀습니다 — 덮이지만, 오탐도 큽니다

2026-08-26, [ADR-055](../../decisions/055-channel-card.md) 로 `CH-card` 가 서면서
초안에 카드사 아홉·결제대행사 둘이 더해졌습니다(27 → 38곳). 사전과 합치면
**57곳 · 표기 162가지**입니다.

### ① 커버리지 — `org` 표에 들어갈 것 중에는 빠진 것이 없습니다

| | 기관 | 상품권사 | 통신사 | 합 |
| --- | --- | --- | --- | ---: |
| 전사(40발화) | 21/24 | 5/5 | 4/4 | **30/33 · 90.9%** |
| 화면(20장) | 16/18 | 2/2 | 2/2 | **20/22 · 90.9%** |

**못 덮은 3곳·2곳은 전부 금융감독원·서울중앙지검·서초경찰서입니다** — [04 §8](04-기관정보.md)이
`org` 표가 아니라 공통 KB 항목이라고 정해 둔 것들입니다. 그걸 빼면 **100%** 입니다.

§7 에서 「85%·86%」로 예측했던 값인데, 다날과 신한카드가 들어가면서 그보다 올랐습니다.

### ② 그런데 오탐이 같이 컸습니다 — §2 의 결론이 깨집니다

| 거리 | 전사 회수 | 전사 오탐 | 화면 회수 | 화면 오탐 |
| ---: | --- | ---: | --- | ---: |
| 0 | **5/9** | **0** | 0/10 | **0** |
| 1 | 5/9 | 17 | **5/10** | **5** |
| 2 | 7/9 | 457 | 9/10 | 246 |

19곳일 때와 나란히 놓으면 이렇습니다.

| | 19곳 | 57곳 |
| --- | ---: | ---: |
| 전사 거리 1 오탐 | 6 | **17** |
| 화면 거리 1 오탐 | **0** | **5** |
| 거리 2 오탐 | 200 · 133 | **457 · 246** |

**「화면은 거리 1 이 안전하다(오탐 0)」가 더는 참이 아닙니다.** 사전이 커질수록
비슷한 이름이 늘어 아무 데나 걸립니다 — 임계값은 사전 크기와 **같이 움직입니다.**

### ③ 임계값은 거리가 아니라 **표기 길이**로 정합니다

오탐을 낸 것이 전부 세 글자 표기였으므로(§2), **짧은 표기만 정확일치로 묶어** 봤습니다.
`dict_probe.py` 의 `fuzzy_from` 이 그것입니다 — 「이 길이 이상인 표기에만 거리를 허용한다」.

| 규칙 | 전사 회수 | 전사 오탐 | 화면 회수 | 화면 오탐 |
| --- | --- | ---: | --- | ---: |
| 거리 0 | 5/9 | 0 | **0/10** | 0 |
| 거리 1 | 5/9 | 17 | 5/10 | 5 |
| **거리 1 · 4자 이상만** | **5/9** | **0** | **5/10** | **0** |
| 거리 1 · 5자 이상만 | 5/9 | 0 | **3/10** | 0 |
| 거리 2 | 7/9 | 457 | 9/10 | 246 |

**「거리 1 · 4자 이상만」이 회수를 하나도 잃지 않고 오탐을 0 으로 만듭니다.**
거리 1 과 회수가 같고(5/9 · 5/10), 오탐만 17·5 에서 0 으로 떨어집니다.

- **5자로 올리면 손해입니다** — 화면 회수가 5/10 → 3/10 으로 떨어집니다.
  「케이뱅크」·「토스뱅크」가 넉 자라 문턱 밖으로 밀립니다.
- **32곳에서도 57곳에서도 오탐 0 입니다** — 사전이 커져도 버팁니다. §2 의
  「임계값이 사전 크기와 같이 움직인다」는 **표기 길이를 안 봤기 때문**이었습니다.
- **경로를 나눌 필요가 없어졌습니다.** 전사는 거리 0, 화면은 거리 1 로 따로 두려던 것을
  **한 규칙으로 묶을 수 있습니다.**

> **표본이 작다는 것은 그대로입니다.** 화면 20장·전사 40발화이고, 회수 모수가
> 9·10 건입니다. 「4자」가 다른 데이터에서도 최적이라는 뜻은 아닙니다 —
> **길이를 봐야 한다는 것**까지가 이 측정이 말하는 것입니다.

> **모수가 바뀌었습니다.** 회수 모수가 전사 2 → 9, 화면 7 → 10 으로 늘었습니다 —
> 사전에 없어 세지도 못하던 것들이 이제 세어지기 때문입니다. 19곳 표의 「2/2」와
> 57곳 표의 「5/9」는 **같은 것을 재고 있지 않습니다.**

### 요약시키지 않았습니다 — 방향을 뒤집었습니다

`org.json` 의 `_note` 가 기록한 사고는 **모델에게 이름을 뽑아 달라고 한 것**입니다.
그 방향에서는 없는 이름이 만들어집니다 — 「한국산업은행」이 「국민은행」으로,
「신한은행」이 「우리은행」으로 밀렸습니다.

**우리가 아는 이름이 원문에 있는지만 보면 만들어질 이름도, 밀릴 이름도 없습니다.**
[verify_source.py](../../assets/datasets/08-26-org-dict/verify_source.py) 가 그 방향이고,
전부 찾혀야 그 URL 을 `source_url` 로 씁니다.

> 그 김에 등록부 표기가 「**비씨카드**」인 것을 알았습니다 — `name` 을 거기 맞추고
> 「BC카드」를 별칭으로 뒀습니다. `source_url` 이 말하는 것과 `name` 이 어긋나면
> 출처가 출처 구실을 못 합니다.

### 걸린 것 둘 — 다음 사람을 위해

**① 압축.** `curl` 에 `--compressed` 를 빼면 압축본이 와서 어떤 인코딩으로도 안 풀립니다.

**② 인코딩을 「먼저 성공한 것」으로 고르면 안 됩니다.** 은행연합회 페이지는 meta 가
UTF-8 이라 적혀 있는데 실제로는 cp949 이고, 게다가 셋 다 엄격 디코드에 실패합니다.
utf-8/replace 로 떨어지면 **한글이 57자만 남고 1,342자리가 뭉개집니다.**
한글이 가장 많이 나오는 인코딩을 고릅니다.

## 14. 모델을 붙이면 어디까지 오르나 — ADR-056 을 처음 걸어 봤습니다

> 2026-08-27. `src/scripts/probe-org-repair.ts` · `gemini-3.6-flash` · 사전 51곳.
> **§2~§9 는 사전만으로 잰 것**이고, 여기는 그 앞에 모델을 한 겹 붙인 값입니다.

[ADR-056](../../decisions/056-transcript-org-normalization.md)이 정한 구조는
**문맥은 모델이 보고, 확정은 사전이 한다**입니다. 코드는 `lib/org-repair.ts` 에
있고 `flows/read-evidence.ts` 가 토큰화 뒤에 부릅니다.

### 왜 재야 했나 — 실패가 실패로 안 보이는 자리입니다

`repairOrgs` 는 **실패해도 던지지 않습니다.** 던지면 전사 결과를 통째로 잃기
때문이고, 그건 옳은 설계입니다(불변 규칙 5). **그런데 그래서 모델이 형식을 못
지키면 영영 조용히 안 됩니다.**

챗에서 실제로 그랬습니다 — `gemini-2.5-flash` 가 200 을 내면서 `ref` 로
`"history"` 를 냈고, 걸어 보기 전까지 몰랐습니다.

### 결과

**§8 의 그 전사문입니다** — 기관을 잃은 아홉 건.

```

```

### 못 잡은 하나는 **모델 탓이 아닙니다**

`신세계상품권` — 모델은 「신세계 상품권」으로 **정확히 들었습니다.** 사전에

**§13 「남은 여섯이 막힌 지점」 표의 세 번째 줄이 바로 이것입니다.** 사전을 넓히면
그대로 풀립니다 — 모델 쪽에 손댈 것이 없습니다.

### ⚠️ 오탐 세는 법 — 처음에 틀리게 셌습니다

첫 실행에서 **「오탐 2」**가 나왔습니다(업비트·페이코). 그런데 둘 다
**그 글에 실제로 있던 기관**이었습니다. 「잃은 것」만 정답으로 잡았더니,
**안 잃은 기관을 함께 찾아낸 맞는 동작**이 오탐으로 잡힌 것입니다.

> **그 글의 기관 전체**로 재야 합니다. 「회수해야 할 것」과 「내도 되는 것」은
> 다릅니다.

`verifyOrgRepair` 가 전사문에 없는 표기를 버리므로(§11.4.4 ①) 이 자리에서
**모델이 지어낸 이름은 애초에 못 올라옵니다.** 그래서 「오탐이 나왔다」를 봤을 때
모델을 의심하기 전에 **정답 기준부터** 봐야 합니다.

### ⛔ 걸린 것 — 열쇠 한도

아홉 건을 두 번 돌리는 동안 `503`(모델 혼잡)과 `429`(한도 초과)를 모두 만났고,
**세 번째 실행은 아홉 중 일곱이 429** 였습니다.

조용히 건너뜁니다** — 한도가 차면 **교정이 안 되는 줄도 모르고 지나갑니다.**

## 15. 공공기관 — **사전만으로 풀립니다.** 처음 결론이 틀렸습니다

> 2026-08-27. **한 번 틀리게 적었다가 고친 절입니다.** 고친 과정을 남깁니다 —
> 왜 틀렸는지가 다음 사람에게 더 쓸모 있습니다.

[PII 경계](../../spec/common/08-14-pii-boundary.md)의 「토큰화 제외 목록」에는
**「공공기관·수사기관명 — 수법 판별(F-04)의 입력. 사칭 기관을 특정해야 함」**이
들어 있습니다. `org` 표에는 못 넣습니다 — `org` 행은 `channel_id` 가 필수인데
이들은 **돈이 지나간 경유 서비스가 아닙니다**(§8 이 「3순위 공통 KB 항목」으로 가른 것).

### ⛔ 처음에 이렇게 적었습니다 — 그리고 틀렸습니다

「모델이 「금융감독원 보이스피싱 지킴이」를 **통째로** 집는다」고 보고 쟀습니다.
그 전제 위에서 *「부분 등재가 무의미하니 고정 목록으로는 못 푼다」*는 결론이 나왔고,
**`isAllowed` 에 기관 접미사 규칙이 필요하다**고 적었습니다.

**그 전제를 측정하지 않았습니다.** 옆 세션이 실모델에서 받은 span 은 다릅니다.

| 문장 | 실제 span |
| --- | --- |
| 「금융감독원에 전화해서 …」 | `금융감독원` — 통째 |
| 「서초경찰서에 전화해서 …」 | `서초경찰서` — 통째 |
| 「금융감독원 보이스피싱 지킴이에 신고했습니다」 | **`보이스피싱 지킴이`** — 금융감독원은 안 집음 |
| 「보이스피싱 지킴이에 전화해서 …」 | **`지킴이`** — 잘림 |

### 실측 span 으로 다시 재면 — **규칙을 안 건드려도 됩니다**

| 사전에 넣는 것 | 살아나는 수 |
| --- | --- |
| 아무것도 | 0/4 |
| 기관 이름 셋(금융감독원·서초경찰서·서울중앙지검) | **2/4** |
| ＋ 서비스명(`보이스피싱 지킴이`) | **3/4** |
| ＋ 잘린 꼬리(`지킴이`) | **4/4** |

`isAllowed` 가 「허용어로 시작 + 뒤는 조사만」이라, **모델이 낸 span 과 사전 표기가
맞기만 하면 살아납니다.** 통째로 집을 때도, 조각으로 집을 때도 마찬가지입니다 —
**그 조각을 사전에 넣으면** 됩니다.

> **접미사 규칙은 필요 없습니다.** 「덜 가리는」 방향으로 경계를 푸는 안은
> **근거가 사라졌으므로 버립니다.**

### 남는 것은 규모와 모양입니다

    경찰서 약 250곳 · 지검·지청 수십     넣을 수는 있지만 사전이 커집니다
    「지킴이」 같은 **잘린 꼬리**          사전에 그 조각을 넣는 것이 맞는 모양인가

### 안 넣으면 어디가 어떻게 되나 — **세 칸이 다릅니다**

| 어디 | 지금 사전에 안 넣으면 |
| --- | --- |
| **사용자 화면** | ✅ 복원돼 보입니다 — `transcript-viewer` 가 **전체 복원**입니다(`read.ts` §`site: "transcript"`). **단 그 브라우저에서만** — *"다른 기기에서 열면 매핑이 없어 토큰이 그대로 남습니다"* |
| **서버 처리** | ⛔ **영구히 `[이름-1]`** — 아래 |
| **외부 LLM(챗)** | ⬜ 프롬프트에 `[이름-1]` 로 갑니다. 절차는 **서버 조건으로 고르므로** 인용은 안 흔들립니다 |

**서버 칸이 제일 무겁고, 되돌릴 수 없습니다.**

`F-04`(수법 판별)의 입력이라고 경계 문서가 적었는데, **`case-reader` 는 아직
아무도 안 부릅니다** — `app/c/[token]/evidence.tsx` 가 *"`case-reader`(층 1)가
미구현이고 §3.3 에도 자리가 없어"* 라고 적어 뒀습니다. 그래서 지금 기관명이
가려져도 **고르는 절차는 안 바뀝니다.** 유형 분기의 입력은 **경유 서비스**이지
경찰서·검찰청이 아닙니다.

⚠️ **다만 전사문은 가려진 채로 저장됩니다.** 데이터 모델 §3 이 *"전사·OCR 원문을
저장하지 않습니다"* 로 못 박았고 `evidence.transcript_masked` 만 남습니다.
복원 매핑의 열쇠는 **브라우저에만** 있습니다(ADR-009·ADR-027) —
**서버에서 도는 F-04 는 나중에도 못 되살립니다.**

> **지금 안 넣으면 「나중에 F-04 를 붙일 때」가 아니라 「그 뒤에 들어온 사건부터」
> 입니다.** 그 전 사건은 서버 쪽에서 영영 가려진 채입니다.

### ⛔ 넣으려면 **둘 곳을 먼저 정해야 합니다**

`org` 표에는 못 넣습니다 — 스키마가 못 박고 있습니다.

    0001_initial_schema.sql:274   channel_id  VARCHAR(32)  NOT NULL

그리고 제외 목록은 `createAllowedTermSource` 가 **`org` 표에서만** 만듭니다.
그래서 「사전에 넣자」가 바로 되지 않습니다. 길이 셋입니다.

| | 무엇 | 대가 |
| --- | --- | --- |
| (가) | `org.channel_id` 를 nullable 로 | 마이그레이션. **「이 표는 경유 서비스」라는 뜻이 흐려집니다** — §8 이 일부러 가른 것을 되돌리는 셈 |
| (나) | 별도 표·파일 + 제외 목록의 **둘째 출처** | 코드가 조금 늡니다. **§8 의 가름을 지킵니다** |
| (다) | 코드 상수 (`patterns.ts` 선례) | KB 릴리스와 따로 놉니다 — **제도가 바뀌어도 배포해야 고쳐집니다** |

**여기서 고르지 않습니다** → 05 U-35.

### 사전을 만들 때 — **KB 본문에 이미 쓰인 표기부터 훑습니다**

공통 KB 본문에는 기관명이 **자유 텍스트**로만 있습니다. 사전을 새로 만들면
그 본문과 어긋날 수 있어서(사전에 「금융감독원」이 있는데 본문이 「금감원」이면
그 표기는 안 걸립니다), **본문에 실제로 쓰인 것**을 먼저 셌습니다.

| 표기 | 본문에 나오는 곳 |
| --- | --- |
| `금융감독원` | 6 — `ch-card`·`ch-carrier`·`common` 의 `debt-extinction-notice` 등 |
| `금융위원회` | 6 — `ch-crypto` 의 `legal_basis`(보도자료 출처) |
| `경찰청` | 3 · `112` 4 · `수사기관` 4 · `수사관` 1 |
| `한국소비자원` | 3 · **`소비자원` 단독 1** (「소비자원이 사업자에게 사실을 확인」) |
| `소비자상담센터` | 1 |
| **`경찰서`** | **단독 2** — 「경찰서에서 사건사고사실확인원을」·「경찰서 사이버수사팀에」 |

⚠️ **`금감원`·`검찰`·`지검` 류는 본문에 한 번도 안 나옵니다.** 별칭에 넣을지는
「사기범이 그렇게 말하는가」로 정할 일이지 본문에서 근거가 나오지 않습니다.

⚠️ **부분문자열을 조심하세요.** 처음에 「`금융위` 단독 7곳」으로 셌는데 **전부
「금융위원회」의 일부**였습니다 — 회피 로직이 틀렸습니다. §12 의 「KT 가 SKT 안에서
걸린다」와 같은 함정이 여기서도 났습니다.

### ⛔ 곁가지 — **04 §8 의 공통 창구가 KB 에 하나도 안 들어가 있습니다**

§8 이 *"`org` 테이블이 아니라 **3순위 공통 KB 항목에 들어갑니다**"* 로 적었는데,
`src/kb/*.json` 본문을 훑으면 **하나도 없습니다.**

    1332 · 1394 · 통합대응단 · 어카운트인포 · 엠세이퍼 · 1577-5500 · 1670-1382
    → 전부 ⛔ 없음

`금융감독원`이라는 **이름**은 본문에 나오지만 그건 「금융감독원이 공고합니다」처럼
**절차 설명**이고, **「여기로 거세요」로 쓰이는 창구는 없습니다.**

**이것도 「문서가 어디로 간다고 적어 뒀는데 아무도 안 넣은」 자리입니다.**
U-35 와 붙어 있습니다 — 창구를 KB 에 넣으면 그 본문 표기가 사전의 별칭 근거가 됩니다.

### 오늘 나는 해는 **표시**입니다 — 다만 그 표시가 저장됩니다

`F-04`(수법 판별)의 입력이라고 경계 문서가 적었는데, **`case-reader` 는 아직
아무도 안 부릅니다** — `app/c/[token]/evidence.tsx` 가 *"`case-reader`(층 1)가
미구현이고 §3.3 에도 자리가 없어"* 라고 적어 뒀습니다. 그래서 지금 기관명이
가려져도 **고르는 절차는 안 바뀝니다.** 유형 분기의 입력은 **경유 서비스**이지
경찰서·검찰청이 아닙니다.

⚠️ **다만 전사문은 가려진 채로 저장됩니다.** `evidence.transcript_masked` 가
토큰화된 것이고 원문은 안 남습니다(규칙 2). 복원 매핑은 **브라우저에만** 열쇠가
있습니다(ADR-009·ADR-027) — **서버에서 도는 F-04 는 나중에도 못 되살립니다.**

> **지금 안 넣으면 「나중에 F-04 를 붙일 때」가 아니라 「그 뒤에 들어온 사건부터」
> 입니다.** 그 전 사건은 이미 가려진 채입니다.
