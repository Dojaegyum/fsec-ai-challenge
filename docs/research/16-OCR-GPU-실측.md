# OCR GPU 실측 — 37배, 그리고 잃는 것은 전부 이름과 기관이다

> 2026-08-26 측정. 측정 원본은 [assets/datasets/08-26-ocr-gpu/](../../assets/datasets/08-26-ocr-gpu/),
> 하네스는 [services/transcriber/bench_ocr.py](../../services/transcriber/bench_ocr.py),
> 화면은 [make_screens.py](../../assets/datasets/08-21-local-ocr-pii/make_screens.py) 로 그렸습니다.
>
> [15](15-STT-GPU-실측.md) 가 전사에서 한 것을 화면에서 한 것입니다. 평가셋은
> [11](11-로컬OCR-PII인식-실측.md)·[12](12-OCR-실측-방법론.md) 의 것을 그대로 썼습니다 —
> 화면 20장 · 라벨-값 쌍 81 · `pii` 36 · `keep` 70.

## 결론 — 셋

**① 장치만 바꾸면 37배입니다.** 장당 4.76초 → **0.13초**. 그리고 **품질 지표가 한
자리도 안 움직였습니다**(PII 손상 5/36 · keep 손상 11/70 동일) — 15 §2 와 같은 그림입니다.

**② 열화가 속도에도 품질에도 거의 영향이 없습니다.** 회전·조명·블러를 먹인
`photo` 도 0.12초이고 PII 손상은 그대로 5건입니다.

**③ 잃는 것은 전부 한글입니다.** **숫자류 개인정보 20건(계좌 14·전화 5·주민번호 1)
을 한 건도 안 잃습니다.** 분기에 쓰는 숫자 맥락(금액 19·일시 15·대표번호 6)도
**40건 전부 살아남습니다.** 11 의 결론 ①(*"계좌번호는 화면에서 읽는 게 압도적"*)이
재현됐습니다.

**다만 기관명은 26건 중 9건(35%)을 잃습니다** — 8유형 분기가 걸린 자리라 §3.

---

## 1. 잰 것

```
RunPod SECURE · RTX 4090 24GB · 호스트 CUDA 13.0 · CPU 128코어
EasyOCR ko+en · torch 2.8.0+cu128 · detail=1 + 좌표 행 복원
엔진은 services/transcriber/engines/easyocr_reader.py 를 그대로 부릅니다
```

**벤치용으로 EasyOCR 을 따로 부르지 않았습니다.** 그러면 좌표 행 복원이 빠져
[11 R-2·R-3](11-로컬OCR-PII인식-실측.md) 이 권고한 구성과 다른 것을 재게 됩니다.
**실제로 붙일 물건을 그대로 재는 것**이 이 하네스의 전제입니다.

## 2. 결과

| | 장치 | 열화 | 장당 | 20장 합계 | PII 손상 | keep 손상 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| `C1` | cpu | clean | **4.76초** | 95.2초 | 5/36 | 11/70 |
| `G1` | cuda | clean | **0.13초** | 2.6초 | **5/36** | **11/70** |
| `G2` | cuda | lowres | 0.10초 | 2.0초 | 6/36 | 11/70 |
| `G3` | cuda | photo | 0.12초 | 2.4초 | 5/36 | 12/70 |

**`C1` 과 `G1` 은 장치만 다릅니다.** 같은 화면·같은 엔진·같은 후처리이고
`EasyOcrReader(device=...)` 한 인자만 바뀝니다 — 그래서 4.76 → 0.13초가
**온전히 GPU 의 몫**입니다.

**품질이 안 움직였다는 것이 이 표의 두 번째 값입니다.** GPU 는 속도만 사고
정확도는 안 건드립니다. 15 §2 에서 전사가 보인 것과 같습니다.

### ⚠️ 「37배」를 ADR-043 의 87초와 곧바로 잇지 마세요

[ADR-043](../../decisions/043-gpu-hosting.md) 은 **OCR 장당 87초**를 전제로 GPU 필요성을
논증했습니다. 여기 CPU 값은 **4.76초**로 18배 차이가 납니다 — **이 팟의 CPU 가
128코어**이기 때문입니다. 11 의 측정은 노트북 CPU 였습니다.

즉 **37배는 이 기계 안에서의 장치 차이**이고, 실제 배포할 CPU 를 기준으로 하면
**더 큽니다.** 두 숫자를 나눠서 쓰지 마세요.

## 3. 무엇을 잃나 — 숫자는 하나도 안 잃습니다

`G1` 기준으로 종류별로 세면 이렇습니다.

| | 종류 | 전체 | 잃음 | |
| --- | --- | ---: | ---: | --- |
| **개인정보** | 계좌 | 14 | **0** | |
| | 전화 | 5 | **0** | |
| | 주민번호 | 1 | **0** | |
| | 이름 | 16 | **5** | 31% |
| **분기 입력** | 금액 | 19 | **0** | |
| | 일시 | 15 | **0** | |
| | 대표번호 | 6 | **0** | |
| | **기관** | 26 | **9** | **35%** |
| | 상품권사 | 2 | 1 | |
| | 통신사 | 2 | 1 | |

**숫자는 한 줄도 안 깨집니다.** 개인정보 쪽 숫자 20건도, 분기에 쓰는 금액·일시·
대표번호 40건도 전부 살아남습니다.

**전사와 정반대입니다.** [15 §6](15-STT-GPU-실측.md) 에서 전사는 계좌번호를 날짜로
읽어 자리표기를 무너뜨렸는데, 화면에서는 **숫자가 그대로 남고 한글이 깨집니다.**
11 의 결론 ①·②가 그대로입니다.

### 기관명이 또 걸립니다 — 그리고 전사보다 나쁩니다

**기관 26건 중 9건(35%)이 사라집니다.** [15 §7](15-STT-GPU-실측.md) 의 전사가
19% 였으니 **화면 쪽이 더 나쁩니다.**

잃은 것들이 이렇습니다 — 농협은행 · 토스뱅크 · 카카오뱅크 · 케이뱅크 · 빗썸 ·
금융감독원. **`케이뱅크`·`카카오뱅크` 처럼 붙여 쓴 긴 한글**이 EasyOCR 에서
낱자로 흩어지거나 오독됩니다(11 §4).

**두 입력 경로가 같은 자리에서 샙니다.** 그래서 이건 엔진 문제가 아니라
**사전 문제**로 보입니다 — [09 §5.5](09-로컬모델-PII인식-실측.md) 가 말한
「허용 목록에 기관명 사전이 있어야 한다」와 같은 결론이고, 원천은
[04-기관정보](04-기관정보.md) 와 `src/kb/org.json` 입니다.

## 4. 사건 하나가 이렇게 됩니다

[ADR-043](../../decisions/043-gpu-hosting.md) 의 예(녹음 7분 + 화면 3장 + 진술 12발화)에
이번 두 실측을 넣으면 이렇습니다.

| | ADR-043 (CPU) | 지금 (GPU) |
| --- | ---: | ---: |
| 전사 7분 | 20분 | **8초** |
| OCR 3장 | 4.4분 | **0.4초** |
| NER 12발화 | 5.5분 | **안 쟀습니다** |

**STT·OCR 몫은 사실상 사라졌습니다.** 남은 것은 NER 이고, 그 값은 아직 CPU
기준입니다 — 다음에 잴 자리입니다.

## 5. 이 실측이 답하지 못한 것

- **NER 을 GPU 에서 안 쟀습니다.** 위 표의 빈칸입니다. `gemma3:4b` 는 로컬에서
  발화당 18초였고([15 §8](15-STT-GPU-실측.md) 의 이름 측정), GPU 값은 모릅니다.
- **화면이 12 의 그것과 픽셀 단위로 같지는 않습니다.** 12 §5 가 하네스를 안 남겨
  **다시 그렸습니다**(§6). 절차는 같지만 글꼴 렌더링이 기계마다 다릅니다 —
  **이 표 안에서 조건끼리** 비교하고 11 의 절대값과 나란히 놓지 마세요.
- **여전히 합성 화면입니다.** 실제 은행 앱은 글꼴·자간·배경이 다릅니다 → 11 §2.4.
- **짝짓기·자형 혼동은 안 쟀습니다.** 11 이 따로 둔 지표들이고, 이번 물음(속도)에
  필요하지 않아 「값이 살아남았나」만 셌습니다.
- **표본이 작습니다** — 화면 20장. 백분율 한 칸이 한 건에 가깝습니다.

## 6. 다시 재려면

**11·12 는 하네스를 안 남겨 OCR 엔진을 다시 못 돌렸습니다**(12 §5). 이번에 그
자리를 메웠습니다.

```bash
# 화면 그리기 (맑은 고딕 필요 · 12 §1 절차)
python assets/datasets/08-21-local-ocr-pii/make_screens.py \
    assets/datasets/08-21-local-ocr-pii/screens

# 재기 — ⚠️ 모듈로 부릅니다(engines 가 ..config 를 참조하는 패키지입니다)
python -m services.transcriber.bench_ocr \
    assets/datasets/08-21-local-ocr-pii/screens \
    assets/datasets/08-21-local-ocr-pii/eval-set.json \
    results-ocr.json C1,G1,G2,G3
```

GPU 가 없는 곳에서 `G1`~`G3` 을 부르면 **돌리지 않고 건너뜁니다.**
그린 화면은 [screens/](../../assets/datasets/08-21-local-ocr-pii/screens/) 에 그대로
넣어 뒀습니다 — 글꼴이 없는 기계에서도 재현할 수 있게.
