## 이 폴더가 왜 있나

`spec/backend/08-16-data-model.md`의 `kb_entry`·`org` 테이블에는 **근거 없는 행을 넣을 수 없습니다.** `legal_basis`·`source_url`·`effective_from`이 전부 `NOT NULL`입니다.

`CLAUDE.md` 불변 규칙 1이 이렇게 정하고 있습니다.

> **LLM은 절차를 창작하지 않는다.** 신고·지급정지 절차는 전부 버전드 KB에서 인용하며, 답변에는 근거와 시행일이 붙습니다.

**그 근거를 채우려면 원천 자료가 있어야 합니다.** 이 폴더가 그것입니다.

## 다른 폴더와의 관계

| 폴더 | 무엇 | 이 폴더와의 관계 |
| --- | --- | --- |
| `research/` | **사실과 출처** | 여기가 원천 |
| `spec/` | 구현 계약 | 여기서 스키마를 정의 |
| `docs/plans/` | 사람이 보는 기획서 | 서비스 설계. 절차 사실은 여기가 아님 |

```
research/  →  KB 릴리스  →  kb_entry · org 테이블  →  LLM 이 인용
(사실·출처)   (사람 검수)     (spec/09)              (spec/07)
```

**여기 있는 내용을 그대로 코드나 프롬프트에 넣지 마세요.** KB 데이터로 만들어 넣습니다.

## 기록 규칙

**1. 출처 없는 사실을 쓰지 않습니다.** 모든 항목에 출처 URL과 확인 날짜를 붙입니다.

```markdown
| 항목 | 내용 | 출처 | 확인일 |
| --- | --- | --- | --- |
| 피해구제 신청 기한 | 3영업일 | https://www.law.go.kr/... | 2026-08-16 |
```

**2. 확인 못 한 것은 `TODO(근거 필요)`로 남깁니다.** 추측으로 채우지 않습니다.

`CLAUDE.md` 작업 규칙이 이렇게 정했습니다.

> **모르는 절차·수치를 지어내지 마세요.** 이 서비스는 잘못된 안내가 곧 피해자의 금전 손실입니다.

**3. 논리적 추론은 사실과 구분해 표시합니다.** 법 조문에서 도출한 것과 문헌에 직접 적힌 것은 다릅니다.

**4. 확인 날짜가 90일이 지나면 다시 봅니다.** 은퇴한 `kb-operations` 의 Staleness Guard 기준을 이어받은 것입니다 — 자동 재검증은 없고 사람이 봅니다(대회 중에는 1회 확인, [18](18-KB-소스-주소-실측.md)).

## 신뢰도 표기

각 항목에 붙습니다.

| 표기 | 뜻 |
| --- | --- |
| **확인** | 1차 출처(법령·기관 공지)에서 직접 확인 |
| **보도** | 언론 보도로만 확인. 1차 출처 미확인 |
| **추론** | 조문에서 논리적으로 도출. 명시 문헌 없음 |
| **미확인** | 확인 못 함. 사용 금지 |

**`추론`과 `미확인`은 사용자 응답에 쓰지 않습니다.**
