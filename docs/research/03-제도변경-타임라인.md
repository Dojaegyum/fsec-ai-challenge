# 03 · 제도 변경 타임라인

`spec/backend/08-16-data-model.md`의 `kb_entry.effective_from` / `effective_until`을 채우는 근거입니다.

## 왜 이 문서가 있나

`spec/backend/08-14-kb-operations.md`가 이렇게 정했습니다.

> 도메인 지식에는 **시간성**이 있습니다. 가상자산 환급(2026.10.1 시행)이 살아있는 예시입니다 — 시행일 메타 덕분에 **같은 질문에도 10월 전후로 다른 답**이 나갑니다.

**시행일을 틀리면 안내 전체가 틀립니다.** 9월에 "거래소에 지급정지를 요청하세요"라고 하면 아직 의무가 없어서 거절당하고, 10월에 "환급 대상이 아닙니다"라고 하면 받을 수 있는 걸 포기하게 만듭니다.

## 2. 항목별 상세

### 2.1 대면편취형 포함 — 2023-11-17

**바뀐 것** — 현금을 직접 건넨 경우도 환급법 적용을 받게 됐습니다. 다만 **피해자가 직접 지급정지를 요청할 수 없고** 112 신고로 수사기관이 계좌를 특정합니다.

**출처** — 금융위원회 보도자료 https://www.fsc.go.kr/no010101/81090 (확인 2026-08-16) · 신뢰도 **확인**

**KB 반영** — `CH-facetoface` 항목의 `effective_from = 2023-11-17`

### 2.2 은행권 자율배상 — 2024-01-01

**바뀐 것** — 비대면 금융사고 책임분담기준 시행. 은행이 피해액 일부를 분담합니다.

**다만 실적이 극히 적습니다.**

| 항목 | 수치 |
| --- | --- |
| 기간 | 2024-01 ~ 2025-04 (1년 4개월) |
| 은행권 상담 | 2,244건 |
| **실제 배상** | **41건** |
| 배상액 | 1억 6,891만원 |
| 피해액 대비 | **0.1%** |
| 평균 처리 기간 | **116일** |

**제외 대상** — 직접 송금, 로맨스스캠, 중고거래 사기는 심사 대상에서 빠집니다. 악성 링크를 눌렀거나 비밀번호를 입력했으면 과실로 평가될 수 있습니다.

**신뢰도 보도** — 1차 출처(금감원 자료) 미확인. `CLAUDE.md` 불변 규칙 8이 이 수치를 근거로 삼고 있으므로 **원문 확인이 필요합니다.**

**KB 반영** — 공통 항목. `effective_from = 2024-01-01`. **`caveat`에 위 수치를 넣어 기대치를 먼저 낮춥니다** → `CLAUDE.md` 불변 규칙 8

> ⬜ **[근거 필요]** 자율배상 표준처리기한. 평균 116일이 걸린다는 것과 별개로, 은행이 지켜야 할 기한이 정해져 있는지 확인해야 합니다.

### 2.3 통장묶기 이의제기 표준화 — 2026-05

**바뀐 것** — 소명자료를 제출하면 **5영업일 안에 결과를 통보**하도록 표준화됐습니다. 소액이거나 이력이 없거나 생계와 관련되면 접수 즉시 나머지 금액이 풀립니다.

**출처** — https://www.newsis.com/view/NISX20260430_0003614017 (확인 2026-08-16) · 신뢰도 **보도**

**KB 반영** — `track = 'frozen_account'` 항목. `effective_from = 2026-05-01`

> ⬜ **[근거 필요]** 정확한 시행일(5월 중 어느 날인지)과 금융감독원 원문. 현재 언론 보도로만 확인.
> 2026-09-03 진전 — 금감원 자료 이름이 **「지급정지 계좌 관련 이의제기 업무처리 절차」**,
> 발표일이 **2026-05-03** 이고, **보완 시 +5영업일 · 추가 보완 시 +3영업일**이
> 붙는다는 것까지 확인했습니다 → [21 §4](21-통장묶기-이의제기.md).

**`track = 'frozen_account'` 항목을 쓰려면** 제도 변경만으로는 부족합니다 — 절차의
근거(법 제7조 · 시행령 제7조)와 제출처·서식은 [21](21-통장묶기-이의제기.md)에 있습니다.

### 2.4 피해구제 비대면 신청 — 2026-07

**바뀐 것** — 은행 앱에서 비대면으로 피해구제를 신청할 수 있게 됐습니다. **계좌번호와 거래내역이 자동으로 채워집니다.**

`spec/backend/08-14-channel-matrix.md`가 이렇게 경고했습니다.

> ⚠️ **"서면"이라고 쓰지 마세요.** 2026년 7월부터 **은행 앱에서 비대면으로 신청**하며, 계좌번호와 거래내역은 자동으로 채워집니다. 기획서 v1.2의 "서면 신청" 표현은 낡았습니다.

> ⬜ **[미확정]** **시행일이 출처마다 7월 1일 / 8월 1일로 엇갈립니다.** 단계적 시행으로 보이나 확정하지 못했습니다. 금융위·금감원 보도자료 원문으로 확인해야 합니다.
>
> **이게 `effective_from` 값을 결정합니다.** 잘못 넣으면 그 한 달 사이 사건에 틀린 절차가 나갑니다.

### 2.5 개정법 시행 — 2026-08-04

> ⬜ **[미확인]** 조사 과정에서 "8월 4일 개정법 시행"이 언급됐으나 **무엇이 바뀌었는지 확인하지 못했습니다.**
>
> 간편송금 정보공유·지급정지 연계 의무화가 이것일 가능성이 있으나 확인 전입니다. **확인 전까지 KB에 넣지 않습니다.**

### 2.6 가상자산 환급 대상 포함 — 2026-10-01

**이것이 시행일 분기의 대표 사례입니다.**

| | 2026-09-30까지 | 2026-10-01부터 |
| --- | --- | --- |
| 환급법 적용 | 없음 | **있음** |
| 거래소 지급정지 | 임의 협조 | **의무** |
| 반환 방식 | — | 코인 종류·수량 단위 반환 **또는** 전담기관 매도 후 금전 지급 |
| 평가 기준 시점 | — | **지급정지 시점** |

**출처** — 금융위원회 보도자료 https://www.fsc.go.kr/no010101/86446 (확인 2026-08-16) · 신뢰도 **확인**

**KB 반영** — 항목을 두 벌 둡니다.

```
kb_entry_id             channel_id   effective_from   effective_until
crypto-no-relief        CH-crypto    2020-01-01       2026-09-30
crypto-freeze-request   CH-crypto    2026-10-01       NULL
```

**배포 없이 10월 1일부터 답이 바뀝니다.** 이 동작이 `spec/backend/08-14-kb-operations.md`가 말한 "KB 설계의 살아있는 증거"입니다.

> ⬜ **[근거 필요]** 시행령 세부 규정이 입법예고 단계입니다. 시행 전에 실제 요청 절차를 확인해 `crypto-freeze-request`의 단계 내용을 채워야 합니다. **지금은 "제도가 바뀐다"는 사실만 확인됐고 "어떻게 하면 되는지"는 모릅니다.**

## 3. 데모에서 쓸 수 있는 장면

`spec/backend/08-14-kb-operations.md`가 시행일 분기를 발표 소재로 지목했습니다.

같은 질문에 날짜만 바꿔 두 번 물으면 다른 답이 나옵니다.

```
질문: "업비트로 500만원 보냈어요. 돌려받을 수 있나요?"

오늘이 2026-09-30 이면:
  "현재는 환급 제도 대상이 아닙니다. 112 신고와 거래소 신고를 먼저 하시고,
   형사 절차로 진행하셔야 합니다.
   다만 2026년 10월 1일부터 제도가 바뀌어 거래소도 지급정지 의무를 집니다.
   ── 출처: 통신사기피해환급법 개정 · 시행 2026-10-01"

오늘이 2026-10-01 이면:
  "거래소에 지급정지를 요청하실 수 있습니다. …
   ── 출처: 통신사기피해환급법 개정 · 시행 2026-10-01"
```

**코드를 배포하지 않고 시스템 날짜만 바꿔서 시연할 수 있습니다.**

---

## 4. 갱신 규칙

**제도가 바뀌면 기존 항목을 고치지 않습니다.** `effective_until`을 채우고 새 항목을 추가합니다.

이유는 `spec/backend/08-16-data-model.md` §8의 `deadline.rule_snapshot`과 같습니다. **이미 계산해 안내한 기한이 어느 시점 규정에서 나왔는지 추적할 수 있어야** 합니다.

`verified_at`이 90일 지나면 재검증 대상입니다 → `spec/backend/08-14-kb-operations.md` Staleness Guard.
