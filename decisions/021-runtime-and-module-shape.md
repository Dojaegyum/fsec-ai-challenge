# ADR-021. 백엔드를 Next.js 안에 TypeScript로 두고, 모듈은 필요한 것을 인터페이스로 선언한다

- 상태: **채택**
- 날짜: 2026-08-17
- 결정: @kth9245
- 관련: [ADR-019](019-module-code-sync.md) (`src/modules/` 를 못 박은 결정 — 이 ADR이 그 안의 언어를 채웁니다) ·
  [ADR-014](014-module-names.md) **부분 대체** (이름 목록에 `pii-masker` 추가) ·
  [ADR-009](009-restore-mapping-location.md) (`pii-restorer` 가 브라우저인 근거) ·
  [ADR-016](016-retention-and-datastore.md) (저장소 제품) · [ADR-020](020-adr-threshold.md) (이 문턱을 넘어 쓰는 것)

## 맥락

**백엔드 구현 언어가 어느 문서에도 정해진 적이 없습니다.**

- `spec/` 전체에서 코드 블록은 SQL 19개·JSON 27개·Python 1개입니다. TypeScript는 **0개**입니다.
- 유일한 Python은 [10-errors.md](../spec/backend/08-16-errors.md) §1의 예외 계층 14개입니다.
- [`ARCHITECTURE.md`](../ARCHITECTURE.md) §2 기술 스택 표에 **언어 칸이 없습니다.** 「백엔드 런타임: Vercel 서버리스 함수」까지만 있습니다.
- 같은 문서 §10이 **「모듈의 물리 배치 — Next.js 라우트 핸들러 안인가, 별도 백엔드인가」**를 미결로 세워 두었습니다.

한편 **결정을 이미 반쯤 내려놓은 것들**이 있습니다.

- [ADR-019](019-module-code-sync.md)가 도메인 모듈 코드를 `src/modules/{module-name}/`에 두라고 못 박았습니다. 그 폴더는 Next.js 앱 내부입니다.
- `src/`는 `create-next-app` 프로젝트이고 `package.json` 이름이 `fin-ally`입니다. shadcn/ui와 FinAlly 도메인 토큰까지 들어가 있습니다.
- [ADR-009](009-restore-mapping-location.md)에 따라 `pii-restorer`는 **브라우저에서만** 돕니다. 브라우저는 JavaScript·TypeScript 외의 선택지가 없습니다.

[ADR-014](014-module-names.md)가 재검토 트리거로 **「구현에 착수해 폴더 구조를 잡을 때」**를 적어 두었는데, 지금이 그 시점입니다.

**동시에 두 가지가 드러났습니다.** 모듈 이름 정본을 코드에 옮기려다 발견한 것입니다.

- [08-16-module-boundaries.md](../spec/common/08-16-module-boundaries.md)가 클라이언트 책임으로 **「1차 PII 마스킹」**을 굵게 적고 있는데, [12-module-names.md](../spec/common/08-16-module-names.md)의 이름 목록에 없습니다. **이름이 없으면 [ADR-019](019-module-code-sync.md) 규칙상 폴더를 만들 수 없습니다** — PII 경계의 절반이 갈 곳이 없는 상태였습니다.
- **송출 직전 잔여 PII 검사에 담당이 없습니다.** `EgressBlockedError`(422)와 `X-Pii-Egress-Residual` 헤더가 이 검사의 결과인데, 어느 모듈이 하는지 어느 문서에도 없었습니다.

## 결정

### 하나 — TypeScript로 쓰고, 백엔드를 Next.js 밖으로 빼지 않는다

별도 백엔드 서버를 두지 않습니다. 화면·API·도메인 로직이 **한 프로젝트 안의 TypeScript**입니다.

| 무엇 | 어디 | 어디서 도나 |
| --- | --- | --- |
| 화면 | `src/app/**/page.tsx` | 브라우저 |
| API 진입점 | `src/app/api/**/route.ts` | 서버 (Vercel 함수) |
| 도메인 모듈 | `src/modules/{module-name}/` | 대부분 서버. `pii-masker`·`pii-restorer` 는 브라우저 |
| 자원 접근 구현 | `src/lib/` | 서버 |

폴더 배치는 Next.js 기본을 따릅니다. Route Group으로 화면을 따로 묶지 않습니다.

**[10-errors.md](../spec/backend/08-16-errors.md) §1의 예외 계층을 TypeScript로 옮깁니다.** 값(코드·HTTP 상태·재시도 여부)은 하나도 바꾸지 않습니다.

### 둘 — 진입점은 얇게, 판단은 모듈에

`route.ts`는 HTTP만 압니다 — 요청 파싱·인증·속도 제한·상태 코드·계측 헤더. **도메인 판단을 담지 않습니다.**

모듈은 반대로 **자기가 HTTP로 불렸는지 모릅니다.** 그래야 파기 배치·리마인더 같은 다른 경로에서 같은 모듈을 부를 수 있고, HTTP 없이 테스트할 수 있습니다.

### 셋 — 모듈은 필요한 것을 인터페이스로 선언하고 구현을 주입받는다

각 모듈은 **자기가 필요로 하는 외부 자원을 자기 폴더 안에서 타입으로 선언**하고, 실제 구현은 밖에서 받습니다.

```
src/modules/{name}/
├── index.ts       공개 계약. 밖에서 쓰는 것만 내보낸다
├── contract.ts    입출력 타입 + 이 모듈이 요구하는 인터페이스
├── errors.ts      이 모듈이 던지는 예외 (공용 AppError 상속)
└── README.md      책임·금지·근거 문서 링크
```

**인터페이스는 쓰는 쪽이 소유합니다.** `planner` 가 필요한 저장 기능은 `modules/planner/contract.ts` 에 적히고, SQL을 쓰는 구현만 `src/lib/store/` 에 갑니다.

**저장소 접근과 LLM 호출에 모듈 이름을 만들지 않습니다.** 둘 다 도메인 판단을 하지 않는 자원 접근이라 [12-module-names.md](../spec/common/08-16-module-names.md)의 「동작 단위」가 아닙니다. `src/modules/` 밖은 [ADR-019](019-module-code-sync.md)가 자유로 둔 영역입니다.

### 넷 — 이름 하나를 추가하고, 검사 하나에 주인을 준다

| 무엇 | 결정 |
| --- | --- |
| 1차 PII 마스킹 | **`pii-masker`** 로 이름을 세웁니다. 층 1·층 2 양쪽에서 돌고, 브라우저 모듈입니다 |
| 송출 직전 잔여 PII 검사 | **`pii-tokenizer` 의 책임**입니다. 새 이름을 만들지 않습니다 |

**검사를 `pii-tokenizer` 에 붙인 이유**는 경계를 지키는 일이 한 모듈에 모여야 우회 경로가 생기지 않기 때문입니다. 토큰화하는 자리와 나가기 직전 확인하는 자리가 다르면, 한쪽만 지나는 경로를 만들 수 있게 됩니다.

### 다섯 — 브라우저·서버 경계를 빌드가 강제한다

`pii-restorer` 는 **서버에 존재하는 것 자체가 [ADR-009](009-restore-mapping-location.md) 위반**입니다. 규칙을 문서로만 두지 않고, 잘못 부르면 **빌드가 실패하도록** 각 모듈에 `server-only` · `client-only` 표시를 답니다.

## 근거

- **선택지가 이미 하나로 좁혀져 있었습니다.** [ADR-019](019-module-code-sync.md)가 `src/modules/` 를 못 박았고, `pii-restorer` 는 브라우저 전용이라 어차피 TypeScript입니다. Python을 고르면 18개 중 하나는 여전히 TypeScript라 **언어가 둘로 갈립니다.**
- **서버리스 제약이 이미 계약에 반영돼 있습니다.** presigned 업로드·폴링·스트리밍 없음·재시도 2회에 전체 예산 20초는 전부 Vercel 함수 한계에서 나온 값입니다 → [`ARCHITECTURE.md`](../ARCHITECTURE.md) §2. 런타임을 바꾸면 이 계약들의 근거가 사라집니다.
- **지금이 가장 싼 시점입니다.** 화면 코드가 아직 `create-next-app` 기본 상태라 API 호출 경로가 어디에도 박혀 있지 않습니다. [ADR-019](019-module-code-sync.md)가 *"`src/` 에 도메인 코드가 하나도 없는 지금이 가장 싼 시점"*이라고 한 것과 같은 논리입니다.
- **인터페이스 선언이 미정 항목을 우회하는 수단입니다.** NER 모델·볼트 제품·공휴일 출처·마이그레이션 방식이 전부 미정인데, 그것들을 인터페이스로 두면 **미정인 채로 계약이 완결됩니다.** 정해질 때 모듈은 바뀌지 않습니다.
- **순수해 보이는 모듈도 의존이 있습니다.** `date-checker` 는 공휴일 목록을 읽어야 하고([기한 계산 규칙](../spec/common/08-16-deadline-rules.md)이 *"하드코딩한 공휴일 배열을 코드에 굽지 마세요"*라고 못 박았습니다), `retry-checker` 는 대기에 ±20% 흔들림을 줍니다. **전부 같은 모양으로 두는 편이 판단할 것이 없습니다.**

### 검토한 대안

| 대안 | 사유 |
| --- | --- |
| Python 별도 백엔드 (FastAPI 등) | NER·STT 자체 호스팅에 유리하고 [10-errors.md](../spec/backend/08-16-errors.md)를 그대로 쓸 수 있습니다. 그러나 [ADR-019](019-module-code-sync.md)를 뒤집어야 하고, 배포가 둘로 갈리며, `pii-restorer` 는 여전히 TypeScript입니다. **한 모듈의 사정으로 전체 구조를 나누는 셈입니다** |
| TypeScript 기본 + 무거운 처리만 Python | 위의 이점을 살리면서 갈래를 줄이지만, **서비스 간 통신 규약·배포·인증이 지금 범위에 들어옵니다.** 필요해지면 그때 `pii-tokenizer` 만 떼는 편이 낫습니다 (아래 재검토 트리거) |
| 언어를 정하지 않고 폴더에 계약 문서만 | 결정을 미루는 대신 **타입 검사를 받는 것이 아무것도 없습니다.** 계약이 서로 맞는지 확인할 방법이 사라집니다 |
| 클래스 기반 모듈 | 익숙하지만 테스트용 가짜 구현을 넣기가 번거롭고, Next.js 쪽 코드와 모양이 달라집니다 |
| 저장소 접근을 모듈 이름으로 세우기 (`case-store` 등) | [08-api.md](../spec/common/08-14-api.md)가 「Case Store」를 **"동작 단위가 아니라 저장소"**라며 목록에서 이미 뺐습니다. 같은 이름을 모듈로 되살리면 두 뜻이 생깁니다 |
| Route Group으로 화면을 `(screens)/` 에 묶기 | `app/` 아래에서 화면과 API가 갈려 보이는 이점이 있으나, **URL과 파일 경로의 1:1 대응이 한 겹 흐려집니다.** 기본을 따르기로 했습니다 |

## 결과

**얻는 것**

- **배포가 하나입니다.** 대회 배포 URL 요건을 `git push` 한 번으로 만족합니다.
- **미정 항목에 막히지 않고 모듈을 만들 수 있습니다.** NER·볼트·공휴일 출처가 정해지지 않아도 그 자리를 인터페이스로 두고 나머지를 완성합니다.
- **PII 경계 두 단계에 모두 이름이 생겼습니다.** `pii-masker` 와 `pii-tokenizer` 로 어느 단계에서 샜는지 지목할 수 있습니다.
- **`pii-restorer` 를 서버에서 부르면 빌드가 깨집니다.** 불변 규칙 3이 문서가 아니라 구조가 됩니다.

**잃는 것 · 감수하는 것**

- **NER을 자체 호스팅하기 어려워집니다.** Vercel 서버리스 함수에 모델을 띄울 수 없어, `pii-tokenizer` 는 당분간 외부 API를 부르게 됩니다. **그 호출은 격리 경계 이전 단계라 원문이 나갑니다** — [`ARCHITECTURE.md`](../ARCHITECTURE.md) §6이 *"경계의 가장 약한 고리"*라고 적은 자리이고, 이 결정으로 해소되지 않습니다.
- **폴더마다 파일이 서넛으로 늘어납니다.** 모듈 18개면 파일 60개 이상입니다.
- **구현체를 조립해 주입하는 자리가 한 군데 필요합니다.** 그 자리가 커지면 그것대로 관리 대상이 됩니다.
- **상시 배치가 없다는 제약이 그대로입니다.** 파기·리마인더 실행 수단은 이 결정으로 풀리지 않습니다 → [`ARCHITECTURE.md`](../ARCHITECTURE.md) §10.

## 재검토 트리거

- **`pii-tokenizer` 가 자체 호스팅 모델을 요구하게 되면** 그 모듈만 별도 서비스로 뗍니다. 인터페이스로 선언해 두었으므로 나머지 모듈은 바뀌지 않습니다. **전체 구조를 나누는 결정으로 번지지 않게 합니다.**
- `src/lib/` 에 도메인 판단이 쌓이기 시작하면 경계를 다시 봅니다. 자원 접근이 아닌 것이 거기 들어가고 있다는 신호입니다.
- 모듈 조립부가 읽기 어려워지면 조립 방식을 다시 정합니다.
