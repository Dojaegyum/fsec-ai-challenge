# ADR-039. 링크 토큰을 `case_id` 와 분리하고, 경로 이름을 `{case_token}` 으로 바꾼다

## 맥락

**[ADR-021](021-reentry-and-identity.md)이 「추측 불가능한 토큰이 박힌 URL」로 정했습니다.**
계정도 비밀번호도 없고, **주소를 아는 사람이 곧 주인**입니다.

그런데 규격을 「남은 것」으로 미뤄 뒀고, 그 사이에 **API 계약이 경로를
`/api/cases/{case_id}` 로 적었습니다.** `case`의 기본키는 **ULID**입니다.

```
01J8XKR5...  ← 3시 02분에 만든 사건
01J8XKR6...  ← 3시 03분에 만든 사건   ← 앞자리가 거의 같습니다
```

**ULID 는 앞자리가 생성 시각입니다** — 정렬하려고 일부러 그렇게 만든 형식입니다.
그대로 URL 토큰이 되면 **하나를 알 때 이웃을 좁혀서 찔러볼 수 있습니다.**

**아무도 「`case_id` 를 토큰으로 쓰자」고 정한 적이 없습니다.** 다만 경로 이름이
그렇게 하도록 유도하고 있었고, 라우트가 아직 안 붙어서 드러나지 않았을 뿐입니다.

**털리면 무엇이 보이나** — 복호화 키가 클라이언트에만 있어 원문 개인정보까지는 아니지만,
**진행 상황과 토큰화된 전사 전문**이 보입니다. ADR-021이 이미 그렇게 적어 뒀습니다.
그리고 이건 한 사람이 아니라 **열거 가능한 전체**의 문제입니다.

## 결정

### ① 토큰은 `case_id` 와 별개의 칼럼입니다

`case` 표에 **`link_token`** 을 둡니다. `case_id` 는 **내부 식별자로만** 씁니다 —
외래키·응답 본문·로그.

**`case_id` 에서 토큰을 파생하지 않습니다.** 해시를 씌워도 원본이 시간순이면
탐색 공간이 그만큼 좁습니다.

### ② 128비트 · Crockford Base32 · 26자

| | |
| --- | --- |
| 생성 | **CSPRNG 128비트.** 열거가 계산적으로 불가능합니다 |
| 표기 | **Crockford Base32** — `0-9A-Z` 에서 **`I`·`L`·`O`·`U` 를 뺀** 32글자 |
| 길이 | 26자 |

**혼동 문자를 뺀 이유**는 사용자가 고령일 수 있고 패닉 상태이기 때문입니다.
`1`/`I`/`l`, `0`/`O` 를 구분하게 만들면 링크를 옮겨 적다 잃습니다.

> ⚠️ **ULID 와 길이가 같습니다(26자).** 겉으로 구분이 안 되니 **코드에서 섞지 마세요** —
> 다른 점은 길이가 아니라 **시간 정보가 없다**는 것입니다.

### ③ 평문으로 저장합니다 — 해시하지 않습니다

**`link_token` 을 그대로 저장하고 고유 인덱스를 겁니다.**

**해시가 추가로 지키는 것이 좁습니다.** DB 가 털리면 사건 데이터가 함께 털리므로,
공격자는 링크를 재구성할 이유가 없습니다.

**그리고 메일이 유일한 복구 경로입니다.** 해시로 두면 서버가 링크를 다시 만들 수 없어
**리마인더 메일에 링크를 넣을 수 없고**, 링크를 잃은 사용자는 **사건을 통째로 잃습니다.**
브라우저 기록을 지우거나 기기를 바꾸는 일은 실제로 자주 일어납니다.

> 이것은 [ADR-021](021-reentry-and-identity.md)이 미정으로 남긴 **「링크를 메일 본문에
> 넣을지」를 앞질러 닫지 않으려는 것**이기도 합니다. 해시로 가면 그 선택지가 사라집니다.

### ④ 열거 방어는 **404 를 IP 로 셉니다**

[API 계약](../spec/common/08-14-api.md) §1.3 의 카운터는 **사건당**입니다.
**없는 사건을 찌르는 공격에는 무의미합니다** — 매번 다른 사건을 부르니까요.

**`CASE_NOT_FOUND`(404) 를 IP당 분당 10회로 제한합니다.** 정상 사용자는 404 를
거의 만들지 않습니다.

### ⑤ 경로 파라미터 이름을 `{case_token}` 으로 바꿉니다

**이름이 함정이었습니다.** `{case_id}` 라고 적혀 있으면 라우트를 짜는 사람이
`case_id` 를 넣습니다 — ADR-021을 안 읽으면 어길 수밖에 없습니다.

```
이전   POST /api/cases/{case_id}/messages
지금   POST /api/cases/{case_token}/messages
```

**주석으로 막지 않고 이름으로 막습니다.** 주석은 놓칠 수 있지만 이름은 못 놓칩니다.

### ⑥ 재발급 경로는 만들지 않습니다 (P2)

**「가족에게 링크 보내기」가 설계된 기능입니다** — 공유가 전제인 서비스에서
무효화 버튼은 반대 방향입니다. 대회 범위에서는 만들지 않습니다.

## 근거

**막는 비용이 가장 쌉니다.** 칼럼 하나와 이름 바꾸기이고, **라우트가 붙기 전인 지금이
가장 쌉니다.** 붙은 뒤에는 이미 나간 링크를 회수할 방법이 없습니다.

**되돌릴 수 없는 쪽으로 기웁니다.** 토큰이 추측 가능한 채로 나가면 **회수가 불가능**합니다.
반대로 토큰을 넉넉하게 잡아서 손해 보는 것은 URL 이 조금 길어지는 것뿐입니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| `case_id` 를 그대로 토큰으로 | **ADR-021 위반.** 시간순이라 추측 가능합니다 |
| `case_id` 를 해시해서 토큰으로 | 원본이 시간순이면 **탐색 공간이 그대로 좁습니다** |
| 토큰을 해시로 저장 | 위 ③ — 메일 복구 경로가 막히고, DB 유출 시 지키는 것이 좁습니다 |
| 경로는 `{case_id}` 두고 주석으로 경고 | **주석은 놓칩니다.** 이름이 함정이면 이름을 고칩니다 |
| 짧은 토큰(64비트) | 짧아서 얻는 것이 없습니다. 사용자는 복사해서 씁니다 |
