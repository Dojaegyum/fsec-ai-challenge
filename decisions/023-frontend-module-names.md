# ADR-023. 브라우저에서 도는 것에 층 C를 만들고 열한 개 이름을 붙인다

- 상태: **채택**
- 날짜: 2026-08-17
- 결정: @Dojaegyum
- 관련: [ADR-014](014-module-names.md) **보완** · [ADR-019](019-module-code-sync.md) ·
  [ADR-021](021-reentry-and-identity.md) · [ADR-022](022-chat-turn-boundaries.md) ·
  [모듈 명칭](../spec/common/08-16-module-names.md) 층 C ·
  [모듈 경계](../spec/common/08-16-module-boundaries.md) 클라이언트 구역 ·

## 맥락

서버는 동작 단위 열여덟에 전부 이름이 있는데, **브라우저는 네 덩어리가 한국어 서술로만 있었습니다.**

> 업로드 · **1차 PII 마스킹** · **복호화 키 보유** · 실행 보드
> — [모듈 경계](../spec/common/08-16-module-boundaries.md) 클라이언트 구역 (2026-08-17 이전)

[모듈 명칭](../spec/common/08-16-module-names.md)은 이 상태를 알고 TODO로 남겨 두었습니다.

> TODO(미정): 화면·프론트 구성의 명칭 — 이번 범위에서 제외했습니다.

**세 가지가 겹쳐 미룰 수 없게 됐습니다.**

**하나. [ADR-019](019-module-code-sync.md)가 `src/modules/{정본 이름}/`을 CI로 강제합니다.**
이름이 없으면 브라우저 코드를 어디에 둘지가 규약 밖이고, 폴더를 만드는 순간 검사기가 막습니다.

**둘. [워크스페이스 패널](../spec/frontend/08-17-workspace-panels.md)이 새 책임을 만들었습니다.**
어느 단계를 할 차례인지 판정하고 유형별 패널을 렌더하는 일이 생겼는데, 「실행 보드」 안에 들어가면
**서버가 `slot-extractor`(뽑기)와 `slot-checker`(판정)를 나눈 이유가 브라우저에서만 사라집니다.**

**셋. [ADR-021](021-reentry-and-identity.md)이 없던 책임을 하나 만들었습니다.**
계정이 없어 **URL 토큰이 인증을 통째로 대신**하는데, 그 자리를 부를 말이 없었습니다.

## 결정

### 하나 — 층 C를 만듭니다

브라우저에서 도는 것을 **층 C**로 묶고 열한 개에 이름을 붙입니다.
`pii-restorer`는 챗 한 턴의 마지막 단계라 **층 2에 그대로 둡니다** — 두 표에 있으면 인벤토리가 두 번 셉니다.

| 구역 | 이름 |
| --- | --- |
| 원문을 다루는 자리 | `pii-masker` · `key-handler` |
| 사건에 접속하는 자리 | `case-opener` |
| 서버와 이야기하는 자리 | `poll-checker` |
| 재료를 넣고 보는 자리 | `file-sender` · `transcript-viewer` |
| 사건을 보여주는 자리 | `plan-viewer` · `deadline-viewer` · `chat-handler` |
| 작업하는 자리 | `work-handler` · `doc-filler` |

### 둘 — 층 C만 시간축을 쓰지 않습니다

[ADR-014](014-module-names.md)가 **「언제 도는가」**로 층을 갈랐습니다. 층 C는 그러지 않습니다.

**브라우저는 화면이 열려 있는 동안 여러 가지가 동시에 돕니다.** 시간축으로 가르면
`plan-viewer`·`deadline-viewer`·`chat-handler`·`work-handler`·`poll-checker`가 한 칸에 몰려,
**"어디서 막혔나를 한마디로 지목한다"는 이름 체계의 목적이 그 칸 안에서 사라집니다.**

**대신 「절대 하지 않는 것」이 다른가로 가릅니다.** 금지가 없는 덩어리는 이름이 없어도 되지만,
금지가 걸린 자리는 이름이 없으면 **어겼을 때 짚을 데가 없습니다.**

### 셋 — `work-handler`는 판정과 렌더를 함께 맡습니다

나누는 안(판정 / 렌더)을 검토하고 **합쳤습니다.**

**대신 [모듈 경계](../spec/common/08-16-module-boundaries.md)에 금지 한 줄을 넣습니다** —
「판정을 렌더 안에 섞지 않는다」. 이 표에서 **유일하게 모듈 안쪽을 향한 금지**입니다.

## 근거

### 왜 이름이 필요한가 — 규칙을 붙일 자리

브라우저 쪽에는 **서버에 없는 금지가 몰려 있습니다.** 복호화 키가 여기에만 있고, 원문이 여기서만 펼쳐지고,
사건의 열쇠가 URL이기 때문입니다. 이름이 없으면 그 금지들이 **문서의 산문에만 존재합니다.**

| 금지 | 지금은 붙을 자리가 |
| --- | --- |
| 키를 서버·로그·DB로 보내지 않는다 | `key-handler` |
| 마스킹 전 원문을 네트워크로 보내지 않는다 | `pii-masker` · `file-sender` |
| **날짜를 계산하지 않는다** | `deadline-viewer` |
| 서버가 만든 완성 문서를 그대로 받지 않는다 | `doc-filler` |
| T0를 다른 것에 종속시키지 않는다 | `plan-viewer` |

### 왜 `key-handler`와 `case-opener`를 갈랐나 — 같은 말의 두 뜻

처음 후보는 `key-handler`(복호화 키)와 **`key-register`**(사건 URL 토큰)였습니다.
**둘 다 "열쇠"인데 하나는 절대 클라이언트를 떠나지 않고 하나는 URL에 박혀 돌아다닙니다.**

[ADR-014](014-module-names.md)가 정확히 이 이유로 `orchestrator`를 버렸습니다.

> 두 문서가 같은 「오케스트레이터」라는 말을 서로 다른 뜻으로 쓰고 있었습니다.
> **그래서 이 이름에 `orchestrator`를 쓰지 않습니다.**

같은 판단을 적용해 사건 쪽을 `case-opener`로 바꿨습니다.

### 왜 `transcript-viewer`인가 — 이름이 사실과 달랐습니다

후보는 `ocr-handler`였습니다. **실제 OCR은 서버 `transcriber`가 하고 이 모듈은 표시만 합니다.**
이름대로 읽으면 "브라우저가 OCR을 한다"가 되고, 게다가 **녹음 전사(STT)도 같은 화면에 뜨는데**
이름에는 OCR만 있었습니다.

### 왜 `-handler`를 여덟 개 쓰지 않았나

후보 열두 개 중 여덟이 `-handler`였습니다. [ADR-014](014-module-names.md) 명명 원칙 2가
**「하는 일이 이름에 드러나되」**인데 `-handler`는 "다룬다"라 드러나지 않습니다.
서버 쪽은 전부 드러납니다 — `tokenizer`(토큰화) `finder`(찾기) `builder`(조립) `checker`(판정) `extractor`(뽑기).

특히 **`file-sender`와 `file-handler`가 나란히 있으면 PII 규칙이 정반대인 둘이 같은 접두를 씁니다**
— 하나는 가려서 올리고 하나는 펼쳐서 완성합니다. 그래서 뒤쪽을 `doc-filler`로 바꿨습니다.

`key-handler`·`chat-handler`·`work-handler` 셋은 남겼습니다. 이 셋은 **하는 일이 하나로 안 좁혀지는 자리**라
`-handler`가 오히려 정직합니다.

### 왜 `deadline-viewer`를 `plan-viewer`에서 갈랐나

합치자는 안이 있었고, **기한 기능의 크기를 재서 판단했습니다.**
[기한 규칙](../spec/common/08-16-deadline-rules.md)과 [API 계약](../spec/common/08-14-api.md) §3.7 기준으로
**화면이 지켜야 할 규칙이 일곱이고 그중 넷이 금지**입니다.

여기에 [research/06](../docs/research/06-경로별-실측조사.md)이 둘을 더했습니다 —
**사용자 기한이 셋**이고(3영업일 · 잔액 1만원 이하 통지 후 30일 · 공고 후 2개월),
그중 카드 부정사용 보상 60일은 **신고일에서 과거로 셉니다.**

> 조사한 10경로 중 유일하게 과거를 향해 세는 기한이라,
> **기한 계산이 전방향만 가정하면 표현할 자리가 없습니다.**

작지 않아 갈랐습니다. 무엇보다 **「날짜를 계산하지 않는다」가 독립된 이름을 가져야 어길 때 짚힙니다.**

### 왜 `work-handler`는 반대로 합쳤나

같은 논리라면 판정과 렌더도 갈라야 합니다. **합친 것은 판단이 달라서가 아니라 비용이 달라서입니다.**

**모듈은 책임의 단위이지 파일 개수가 아닙니다** → [모듈 경계](../spec/common/08-16-module-boundaries.md).
`deadline-viewer`의 금지(날짜 계산)는 **다른 모듈이 어길 수 있는 것**이라 이름으로 막아야 하지만,
`work-handler`의 금지(판정을 렌더에 섞기)는 **한 모듈 안에서만 일어나는 것**이라 모듈 안의 규칙으로 족합니다.

**대가는 정직하게 적습니다** — 경계가 이름에서 사라져 **코드 리뷰에서만 지켜집니다.**
[ADR-022](022-chat-turn-boundaries.md)의 `chat-receiver`가 「절대 하지 않는 것」으로만 지켜지는 것과 같은 상태입니다.

### 탈락한 후보

| 후보 | 사유 |
| --- | --- |
| `key-register` (사건 URL) | `key-handler`와 **같은 말이 두 뜻**. ADR-014의 `orchestrator` 선례 |
| `ocr-handler` | **사실과 다름** — OCR은 서버가 하고 STT도 같은 화면에 뜸 |
| `chat-response-handler` | **세 단어.** 명명 원칙 4는 두 단어까지 허용 |
| `file-handler` (서류 완성) | `file-sender`와 접두가 같은데 **PII 규칙이 정반대** |
| `process-handler` · `date-handler` · `pii-handler` | 하는 일이 안 드러남. 각각 `plan-viewer`·`deadline-viewer`·`pii-masker` |
| `work-router` (판정) + `work-handler` (렌더) | 위 「왜 반대로 합쳤나」 |
| 층 C를 시간축으로 가르기 | 대부분이 「화면이 열려 있는 동안」 한 칸에 몰림 |

## 결과

**얻는 것**

- **브라우저 쪽 금지에 붙일 자리가 생겼습니다.** 다섯 개 규칙이 산문에서 이름으로 옮겨갔습니다.
- `src/modules/`에 프론트 코드를 둘 수 있습니다 — [ADR-019](019-module-code-sync.md)의 CI를 통과합니다.
- **인벤토리 스킬이 프론트도 답합니다.** 정본을 읽는 도구라 문서만 고치면 따라옵니다.
- 워크스페이스 패널이 어느 모듈의 것인지 지목됩니다.

**잃는 것 · 감수하는 것**

- **층의 뜻이 하나가 아니게 됐습니다.** 1~4는 「언제」, C는 「무엇을 책임지는가」입니다.
  문서에 명시했지만, 처음 읽는 사람은 한 번 걸립니다.
- **`work-handler`의 판정·렌더 경계가 이름에서 사라졌습니다.** 코드 리뷰에서만 지켜집니다.
- **모듈이 열한 개 늘었습니다.** 2인 팀에 이름이 서른 개가 됩니다 — 인벤토리 도구가 없으면 감당하기 어렵습니다.
- `-handler` 셋이 남아 있어 **명명 원칙 2를 완전히 지키지는 못했습니다.**

## 남은 것

- **`chat-receiver`·`chat-publisher`가 정본에 없습니다.** [ADR-022](022-chat-turn-boundaries.md)로 이름은
  정해졌는데 [모듈 명칭](../spec/common/08-16-module-names.md) 층 2 표에 반영되지 않았습니다.
  **등재 전에는 `src/modules/`에 폴더를 만들 수 없습니다** — 백엔드 담당의 일입니다.
- **리마인더 발송과 파기 실행의 이름.** 층 4에 자리가 비어 있고, 선행 조건이던
  재진입·연락처([ADR-021](021-reentry-and-identity.md))와 상시 배치([ADR-016](016-retention-and-datastore.md))가 **둘 다 풀렸습니다.**
- **`work-handler`가 얇게 유지되는지 볼 방법.** 지금은 금지 조항뿐입니다 → TODO(미정).
- **화면 ID(`S-xx`)와 모듈의 대응.** [화면 설계](../spec/frontend/08-14-screens.md)가 아직 3-패널 시절이라
  다시 쓸 때 함께 맞춥니다.

## 재검토 트리거

- **`work-handler`가 커질 때** — 판정 규칙이 늘거나 패널 유형이 일곱을 넘으면 쪼갤 시점입니다.
- **층 C가 시간축으로도 갈리는 것이 드러날 때** — 예를 들어 백그라운드 동기화가 생기면 다시 봅니다.
- `-handler` 셋의 이름이 실제로 헷갈리는 것이 관측되면 다시 봅니다.
