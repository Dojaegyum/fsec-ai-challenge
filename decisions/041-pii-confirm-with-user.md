# ADR-041. PII 판정을 기계가 혼자 하지 않는다 — 사용자가 보고 있는 자리에서는 물어본다

- 상태: **채택**
- 날짜: 2026-08-21
- 결정: @Dojaegyum
- 관련 문서: [ADR-040](040-write-path-boundary.md) 「1차 정규식 게이트」 (**③을 좁힙니다**) ·
  [ADR-038](038-transcript-confirm.md) `WS-confirm` (**여는 조건을 넓힙니다**) ·
  [ADR-011](011-pii-boundary-hardening.md) 토큰화 제외 목록 ·

  [CLAUDE.md](../CLAUDE.md) 불변 규칙 2 · 5

## 맥락

**어제까지 우리는 「기계가 PII 를 다 골라낸다」를 전제하고 있었습니다.**
[ADR-040](040-write-path-boundary.md)이 「1차 정규식 게이트를 지금 세우면 된다」고 했고,
[ADR-038](038-transcript-confirm.md)은 검수 패널을 「**신뢰도가 낮을 때만**」 열기로 했습니다.

**실측이 둘 다 흔들었습니다** — 합성 평가셋 40발화로 잰 결과입니다
(`docs/research/09-로컬모델-PII인식-실측.md` · 별도 브랜치).

| | 누출 | 과차단 |
| --- | --- | --- |
| 정규식만 (현행 `pii-masker`) | **39.4%** | 0% |
| 정규식 + 로컬 LLM + 허용 목록 | 0.0% | 0% |

**그리고 전사문에서 정규식이 무너집니다.** 깨끗한 텍스트에서 숫자류 **20/20** 을 잡던 것이
전사문에서는 **6~10건**입니다. `"공이 9876543"` 을 전화번호로 읽는 것은 정규식이 못 합니다.

**검수 패널의 트리거도 틀렸습니다.** `3333-01-2345678` 이 「**3333년 1월 23일**」로 전사됐는데,
**자연스러운 날짜라 신뢰도가 낮게 나올 이유가 없습니다.** 「신뢰도가 낮을 때만 연다」로는
**가장 위험한 오독을 정확히 놓칩니다.**

## 결정

**기계가 확신하지 못하는 자리에서, 사용자가 그 값을 보고 있으면 물어봅니다.**

### ① 경로마다 다릅니다 — 기준은 「지금 보고 있나」

| 어디 | 어떻게 | 왜 |
| --- | --- | --- |
| **전사문** | **확인하고 씁니다** | 파일을 막 올린 참이고, 값이 몇 개뿐입니다 |
| **슬롯 입력**(`PATCH …/slots`) | **확인하고 씁니다** | 지금 타이핑 중이라 즉시 물을 수 있습니다 |
| **챗 발화** | **가리고 진행합니다** | 발화마다 물으면 **대화가 성립하지 않습니다** |

**[ADR-040](040-write-path-boundary.md)이 챗과 쓰기 경로를 가른 것과 같은 선입니다.**
우연이 아니라 **기준이 같기 때문**입니다 — 사용자가 그 값을 지금 보고 있는가.

**챗에서 가린 것은 사후에 보여줍니다** → `S-11`(이 답변에 무엇이 나갔나).

### ② 확인 대기가 플랜을 막지 않습니다

**기다리는 것은 「전사에서 뽑은 슬롯에 기반한 절차」뿐입니다.**

| | 기다리나 |
| --- | --- |
| **T0** (112 신고 · 지급정지 요청) | **아니오** — 슬롯이 없습니다. 진입 즉시 나갑니다 |
| 유형 기본 절차 | **아니오** — 유형을 모르면 슈퍼셋 플랜이 나갑니다 |
| 전사 기반 슬롯에 걸린 단계 | 예 |

**골든타임에 나가야 하는 것은 T0 인데, 그것은 애초에 전사와 무관합니다.**

**사용자가 확인 없이 떠나도 됩니다.** 그 슬롯이 `unconfirmed` 로 남고 플랜은 T0 + 유형 기본인데,
**「모름」일 때와 같은 상태**입니다. 새로 나빠지는 것이 없습니다.

> **불변 규칙 5 는 여기 걸리지 않습니다.** 그 규칙은 「**모르는 것을 내놓으라고 요구해서 막지 마라**」이고,
> 이 확인은 **이미 우리가 가진 것을 보여주고 맞는지 묻는 것**입니다. 사용자가 새로 알아야 할 것이 없습니다.

### ③ `WS-confirm` 을 여는 조건이 **둘**이 됩니다

```
① 신뢰도가 낮다        기계가 자신 없어함        (ADR-038)
② PII 후보다          **신뢰도와 무관하게**      (이 결정)
```

**두 축은 독립입니다.** 「자연스러운 날짜라 확신한다」와 「주민번호였을 수 있다」는 다른 말이고,
축이 하나면 **후자를 영영 못 잡습니다.**

### ④ 확인은 **분류 정정**이지 개인정보 포기가 아닙니다

| 사용자가 할 수 있는 것 | |
| --- | --- |
| 「`[기관-1]` 은 국민은행이에요」 | ✅ [허용 목록](011-pii-boundary-hardening.md) 종류로 되돌리는 것 |
| 「제 계좌번호 그냥 보내세요」 | ❌ **불변 규칙 2 는 사용자가 원해도 깨지 않습니다** |

**푸는 것은 「이건 개인정보가 아니다」이지 「개인정보지만 괜찮다」가 아닙니다.**

## 근거

**NER 에 요구하는 수준이 내려갑니다.** 「정확히 골라내는 NER」이 아니라
**「후보를 넉넉히 던지는 NER」**이면 됩니다 — 과차단은 사용자가 풀어주니까요.
[ARCHITECTURE.md](../ARCHITECTURE.md) §10의 모델 선택이 그만큼 쉬워집니다.

**틀리는 방향이 안전해집니다.** 가렸는데 아니었으면 사용자가 풉니다.
안 가렸는데 맞았으면 **이미 나갔습니다.**

**그리고 이 화면은 이미 있어야 하는 것이었습니다.** [ADR-038](038-transcript-confirm.md)이
`WS-confirm` 을 만들어 뒀고, **여는 조건 하나만 넓히면 됩니다.**

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| 기계가 다 판정 (어제까지) | **전사문에서 39.4% 가 샙니다.** 실측이 있습니다 |
| 전 경로에서 되묻기 | **챗이 성립하지 않습니다** — 발화마다 확인창 |
| 확인이 올 때까지 플랜을 멈추기 | **골든타임을 놓칩니다.** T0 는 전사와 무관하게 나가야 합니다 |
| 의심되면 무조건 가리고 확인도 안 받기 | 과차단이 남고, **기관명이 가려지면 8유형 분기가 무너집니다** ([ADR-011](011-pii-boundary-hardening.md)) |

## 결과

**[ADR-040](040-write-path-boundary.md) ③이 좁혀집니다.** 「1차 정규식 게이트를 지금 세운다」는
**타이핑된 값에 대해서만** 참입니다. **전사문에 같은 게이트만 걸고 끝내면 안 됩니다.**

**[ADR-038](038-transcript-confirm.md)의 트리거가 넓어집니다.** 「신뢰도 낮은 필드 목록」에
**PII 후보**가 더해집니다. ADR-038 자체는 고치지 않습니다 — 이 결정이 잇습니다.

**화면이 늘어납니다.** `WS-confirm` 이 이제 두 가지를 묻습니다 —
「이 값이 맞나요」와 **「이건 개인정보인가요」**. 시안을 받을 때 둘을 같이 그려야 합니다.

**⬜ 남은 것**

- **PII 후보를 무엇으로 판정하나.** 정규식 히트 + NER 후보인데, **NER 이 아직 없습니다.**
  그 전까지는 정규식 히트만이고, **전사문에서는 그것으로 부족하다는 것을 알면서 갑니다.**
- **슬롯 입력에서 되묻는 화면.** [ADR-040](040-write-path-boundary.md)이 남긴
  「422 를 받으면 무엇을 하나」가 여기로 옮겨 왔습니다 — **되묻기가 답이지만 문구가 없습니다.**
- **확인 대기 중인 슬롯의 표시.** `unconfirmed` 와 「PII 확인 대기」는 다른 상태인데
  [데이터 모델](../spec/backend/08-16-data-model.md) §5.2의 슬롯 상태 넷에 자리가 없습니다.

**재검토 트리거** — NER 이 붙고 **과차단율을 실제로 재고 나면** ①의 「챗은 가리고 진행」을 다시 봅니다.
과차단이 드물면 챗에서도 `S-11` 대신 즉시 되묻는 것이 나을 수 있습니다.
