# ADR-053. 채권소멸공고의 기산일은 통지문에서 온다

- 상태: **채택**
- 날짜: 2026-08-26
- 결정: @Dojaegyum
- 관련 문서: [기한 계산 규칙](../spec/common/08-16-deadline-rules.md) ·
  [데이터 모델](../spec/backend/08-16-data-model.md) §5.1 (슬롯 표) · §8 (기한) ·
  [완수 검증](../spec/backend/08-14-completion-hook.md) (부산물이 기산점) ·
  [API 계약](../spec/common/08-14-api.md) §3.7 (`starts_at`·`elapsed`) ·
  [ADR-048](048-horizon-carries-meaning.md) (공고 대기 카드가 달력 앵커를 그린다)

## 맥락

[ADR-048](048-horizon-carries-meaning.md)이 공고 대기 카드에 **달력 앵커**를 그리기로
정했습니다 — 「8월 30일 공고 시작 · **지금** · 10월 30일 만료」. §3.7 이 그에 맞춰
`starts_at`·`elapsed` 두 칸을 확정했고, 서버가 그것을 싣게 됐습니다.

**그런데 그 값을 만들 근거가 없었습니다.**

기한 하나가 서려면 셋이 필요합니다 — 세는 규칙, 기산점, 그리고 그 기산점을
채우는 길. 셋 다 없었습니다:

| | 상태 |
| --- | --- |
| 세는 규칙 | `date-checker` 에 `months` 가 없었습니다 (민법 제160조 역법 계산) |
| KB 항목 | `kb/` 어디에도 채권소멸공고 단계가 없었습니다 |
| 기산 슬롯 | 슬롯 표 §5.1 에 공고 시작일을 담을 칸이 없었습니다 |

앞의 둘은 만들면 되지만, **셋째는 「무엇을 그 날짜로 삼는가」를 정해야 합니다.**
법이 정한 것은 *"최초의 채권소멸절차 개시의 **공고일**부터 2개월"*
(통신사기피해환급법 제9조)인데, 그 공고를 하는 것은 금융감독원이고 **우리는
그 날짜를 모릅니다.**

## 결정

**공고 통지문을 부산물로 받고, 거기 적힌 공고일을 기산일로 씁니다.**

- 슬롯 `notice_started_at` 을 §5.1 에 더합니다 (T2 · `datetime`).
- 채권소멸공고 KB 항목의 기한은 `{ kind: 'months', amount: 2, from: 'notice_started_at' }`
  이고 주인은 기관이라 `kind: "info"` 입니다 — **사용자가 지킬 기한이 아닙니다.**
- **그 슬롯이 비면 카드를 그리지 않습니다.** 화면도 서버도 대신 만들지 않습니다.

### 왜 「신청일로부터 추정」이 아닌가

피해구제 신청 접수일(`relief_applied_at`)에 며칠을 더해 추정할 수도 있었습니다.
그러면 카드가 **늘** 뜹니다. 두 가지 이유로 버렸습니다.

**① 더할 며칠의 근거가 없습니다.** 법은 금융회사가 지급정지 후 *"지체 없이"*
공고를 요청하고 금감원이 *"지체 없이"* 공고한다고만 합니다(같은 법 제5조).
「지체 없이」는 날수가 아닙니다. 우리가 숫자를 고르면 그것은 **지어낸 것**이고,
`CLAUDE.md` 가 금지합니다 — *"모르는 절차·수치를 지어내지 마세요."*

**② 틀리는 방향이 나쁩니다.** 추정이 실제 공고일보다 **늦으면** 만료일도 늦게
잡히고, 사용자는 아직 시간이 있다고 믿습니다. 이 서비스가 막으려는 실패가
정확히 그것입니다.

기한 규칙이 이미 같은 것을 말하고 있습니다 —
*"부산물이 아직 없으면 기한을 확정하지 말고 「미확인」 배지와 함께 추정만
보여줍니다. 추정 날짜를 확정 기한처럼 보여주면, 사용자는 틀린 날짜를 믿고
권리를 잃습니다."* 우리는 여기서 **추정조차 하지 않기로** 합니다. 근거가 없는
추정은 「미확인」 배지를 붙여도 여전히 날짜입니다.

### 무엇을 잃나

**통지문을 못 받았거나 안 올린 사용자에게는 카드가 안 보입니다.** 그 사람은
공고가 진행 중인지 화면에서 알 수 없습니다.

받아들입니다. 이 카드가 하는 일은 *"제도가 흐르는 시간 · 은행과 금융감독원이
진행합니다"* 를 보여주는 것이고, **사용자가 할 일은 없습니다.** 없는 정보를
지어내 보여주는 것보다 안 보이는 편이 낫습니다.

대신 카드가 없어도 **절차 안내는 그대로 나갑니다** — 공고 단계 자체는 플랜에
서고, 「금융감독원이 진행합니다」라는 설명도 붙습니다. 사라지는 것은 날짜뿐입니다.

## 이 결정이 기대는 것

**부산물이 슬롯을 채우는 길은 이미 열려 있습니다** — `PATCH /api/cases/{token}/slots/{slot_key}`
가 슬롯 표의 모든 칸을 받고, 답이 저장되면 `answer-slot` 이 플랜과 기한을 다시
만듭니다. 화면은 통지문을 올린 뒤 「공고일이 언제로 적혀 있나요」를 한 번 더
물으면 됩니다.

⬜ **화면의 그 자리는 아직 없습니다.** 부산물 업로드와 날짜 묻기를 잇는 것은
층 C 작업으로 남습니다.

## 함께 드러난 것 — `actor` 와 `owner` 의 목록이 어긋납니다

공고 단계를 적으면서 **금융감독원을 행위자로 고를 수 없다**는 것을 알았습니다.

| | 목록 | `agency` |
| --- | --- | --- |
| `plan_step.actor` | `victim`·`police`·`bank`·`prosecutor`·`carrier`·`issuer` | **없습니다** |
| `deadline.owner` | `user`·`bank`·`agency` | 있습니다 |

기한의 주인은 `agency` 로 적을 수 있는데(그래야 `kind: "info"` 가 됩니다) **그 일을
하는 단계의 행위자로는 적을 수 없습니다.** 지금은 `actor: "bank"` 로 두었습니다 —
공고를 *요청*하는 것이 금융회사(제5조제1항)라 아주 틀리지는 않지만, **공고를 내고
2개월을 세는 주체는 금융감독원**(제5조제2항·제9조제1항)입니다.

⬜ `actor` 에 `agency` 를 더하려면 `plan_step` 의 CHECK 제약을 바꾸는 마이그레이션이
필요합니다 → [데이터 모델](../spec/backend/08-16-data-model.md) §6. 이 ADR 은 그것을
정하지 않습니다.

## 대안

| 안 | 왜 안 골랐나 |
| --- | --- |
| 부산물을 **올린 시각**을 기산일로 | 사용자가 며칠 뒤 올리면 기한이 그만큼 늦게 잡힙니다. 틀리는 방향이 나쁩니다(위 ②) |
| 신청일 + N일로 추정 | N 의 근거가 없습니다(위 ①) |
| §3.8 에 날짜 칸을 더해 부산물과 함께 받기 | 계약을 넓히지 않고도 됩니다 — 슬롯 경로가 이미 그 일을 합니다 |
| 접수번호에서 날짜를 뽑기 | 기관별 형식의 정본이 없어 `format_unknown` 입니다 |
