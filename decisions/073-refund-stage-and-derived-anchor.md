# ADR-073. 공고 2개월 뒤의 결과를 절차로 둔다 — 결정 14일·지급·절차 정지, 기산점은 규칙이 파생한다

- 날짜: 2026-09-06

- 관련 문서: [사용자 여정](../spec/common/08-21-user-journeys.md) 여정 5 (「결과 확인 — 없음」) ·

## 맥락

플랜은 채권소멸공고 2개월에서 끝났습니다. 그 뒤 — 채권이 소멸하고, 금융감독원이 환급금을 결정하고, 금융회사가
지급하는 — 는 「기관이 하는 일이라 KB 에 단계가 없다」는 이유로 비워 두었고, 레일의 「환급」 칸은 앞 칸을
따라오기만 했습니다(§S-07). 사용자 여정 5 「결과 확인」은 **없음**이었습니다.

빈 이유는 둘이었습니다. 하나는 「받을 수 있다고 말하지 않는다」([불변 규칙 8](../CLAUDE.md)) — 환급 칸이 있으면
「기다리면 환급이 온다」로 읽힐 위험. 다른 하나는 기산점 — 법이 정한 결정 기한은 「채권이 소멸된 날부터 14일」인데,
채권 소멸일은 슬롯도 부산물도 아니라 **공고일 + 2개월**로만 나오고, `deadline.from` 은 슬롯 이름과 `artifact:{kind}` 만 받았습니다.

2026-09-06 에 국가법령정보 API 로 받은 본문(법률 제21320호 · 시행 2026-08-04)에서 제8조·제9조·제10조·제11조를
그대로 읽었습니다([ADR-072](072-law-collection-wired.md)의 첫 수집).

## 결정

### ① 결과 단계 셋을 `common.json` 에 둔다 — 전부 기관의 일이고, 사용자가 할 것은 통지문을 올리는 것뿐

| `step_key` | 누가 | 무엇 | 기한 |
| --- | --- | --- | --- |
| `refund-decision` | 금융감독원 | 채권 소멸(제9조제1항) 뒤 **14일 안에** 환급 대상·금액 결정·통지(제10조제1항). 결정 통지문이 부산물 | `calendar_days 14 · from debt_extinct_at · owner agency` → `info` |
| `refund-payment` | 금융회사 | 결정 통지를 받으면 **지체 없이** 지급(제10조제1항 후단). 입금 내역이 부산물 | 없음 — 「지체 없이」에는 숫자가 없습니다 |
| `procedure-stopped` | 금융감독원 | 이의제기·소송이 있으면 절차 종료·통지(제8조). 읽는 단계 | 없음 — 이의제기 통보일을 담을 슬롯이 없습니다 |

셋 다 `after: [debt-extinction-notice]`(지급은 결정 뒤)라 **공고 통지문이 올라온 뒤에야 플랜에 붙습니다.** 그 전에는
레일의 「환급」이 지금처럼 앞 칸을 따라옵니다 — 절차가 「해당 없음」인 사건에서 환급만 「미시작」으로 서는 일은
그대로 없습니다(`plan.tsx` 의 `railTones` 가 「이름만 있고 단계가 없는 칸」을 걸리지 않은 칸으로 봅니다).

문구는 불변 규칙 8 을 지킵니다. 「결정되면」이지 「받습니다」가 아니고, 안분(제10조제2항)과 지급받을 수 없는 자(제11조)를
caveat 에 적었습니다. 대상인지와 금액은 말하지 않습니다.

### ② 기산점을 규칙이 파생한다 — `debt_extinct_at`

`deadline.from` 에 파생 기산점 하나를 더합니다 — `debt_extinct_at` = `notice_started_at` + 2개월(제9조제1항 · 채권 소멸일).
`flows/compute-deadlines.ts` 의 `DERIVED` 표가 코드의 정본이고, **같은 `date-checker` 로 셉니다** — 달 셈이 두 곳에 있으면
어긋납니다. 공고일이 추정이면 파생 기한도 추정입니다. `kb-load.ts` 가 같은 이름을 받습니다. LLM 은 여기 없습니다(불변 규칙 7).

이의제기 통보일부터 2개월(제8조제2항제2호)은 파생하지 않습니다 — 통보일을 담을 슬롯이 없고, 지어내면 하루가 틀려
권리가 사라집니다. 통지문이 오면 자료 추출로 채우는 길을 나중에 엽니다.

### ③ KB 릴리스는 사람 검수 뒤에

이 ADR 과 함께 들어가는 것은 파일(`src/kb/common.json`)과 코드입니다. 배포본이 이 단계를 내는 것은 사람이 항목 셋을
검수하고 `kb:load` 로 새 버전을 찍어 `KB_VERSION` 을 올린 뒤입니다(RFC-002). `verified_at` 은 본문을 API 로 읽은 날이고,
사람이 다시 눈으로 보는 것이 릴리스 조건입니다.

## 근거

**결과가 없는 사건 관리는 반쪽입니다.** 「몇 달을 대신 관리한다」가 골자인데 2개월 뒤에 무엇이 오는지, 안 오면 어디에
물어야 하는지가 비어 있었습니다. 제10조는 금융감독원의 14일을 못박고 있어 「통지가 없으면 확인하라」는 안내에 근거가 있습니다.

**기산점을 파생하는 것이 추정보다 정확합니다.** 채권 소멸일은 법이 공고일에서 셈하라고 정한 날입니다. 슬롯으로 따로 묻거나
통지로 받을 값이 아니라 규칙의 결과이고, 그 규칙은 이미 공고 기한을 세는 그 규칙입니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| **환급 칸을 계속 비워 둔다** | 여정 5 가 영영 없습니다. 「받을 수 있다」를 안 말하는 것과 「무엇이 오는지」를 안 말하는 것은 다릅니다 |
| **결정 기한을 공고일 + 2개월 + 14일 한 규칙으로** | `date-checker` 의 규칙은 한 단위(일·영업일·달)입니다. 규칙에 다리를 둘 두면 스냅샷 계약(§8.2)이 바뀝니다. 파생 기산점이 더 작습니다 |
| **채권 소멸일을 슬롯으로 묻는다** | 사용자가 모르는 값입니다. 금융감독원의 통지(제9조제2항)로 오지만, 안 와도 날짜는 법으로 정해져 있습니다 |
| **지급에도 기한을 둔다** (「지체 없이」를 며칠로) | 숫자를 지어내는 것입니다 |
