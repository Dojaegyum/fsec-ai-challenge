# ADR-069. 증거에서 뽑은 값은 한 번의 탭으로 확인한다 — 자동 추출을 배선하고, 임계값은 0.7

## 맥락

[서비스 골자](../spec/common/08-17-service-concept.md)는 **「증거가 있으면 슬롯이 자동 추출돼 플랜이
정밀해진다」**고 약속했고, [슬롯 티어링](../spec/backend/08-14-slot-tiering.md)은 *"T2 는 증거 자동 추출이
우선이므로 실제 질문은 보통 1~2개로 끝나야 합니다"* 라고 적었습니다. 그 몫의 모듈
`src/modules/slot-extractor/`(F-05b 의 앞 절반)도 2026-08 에 만들어졌습니다.

그런데 **어느 흐름도 그 모듈을 부르지 않았습니다.** 전사 흐름(`flows/read-evidence.ts`)이 토큰화 뒤에
하는 일은 [ADR-056](056-transcript-org-normalization.md) 의 기관명 사전 대조 하나였고, 금액·시각·상대 계좌는
전부 문진으로 왔습니다. 이체 내역 캡처에 「32,000,000원 · 2026.09.01 14:22:41 · 받는 계좌 …」가 다 적혀
있어도 챗은 「얼마를 보내셨나요」부터 물었습니다. 시연 자료 셋(`assets/demo/09-01-mock-evidence/`)이 정확히
그 자리를 보여줍니다 — 올린 자료가 대화에 아무 영향도 못 미치는 것으로 보였습니다.

배선이 없던 이유 둘이 스펙에 남아 있었습니다.

1. **임계값이 미정이었습니다** — *"얼마나 확신해야 질문 생략인지"* (슬롯 티어링 TODO).
2. **`extracted` 의 되묻기가 기관명에만 있었습니다.** 상태의 정의는 *"LLM 이 뽑았고 확인 전 — 묻는 것은
   「이 값이 맞나요」"*(`slot-checker/types.ts`)인데, 실제로 되묻는 코드는 `org_name` 의 사전 선택지뿐이었고
   나머지 슬롯은 `extracted` 면 **확인 없이 채워진 것으로** 셌습니다(`tierStatus`). 그대로 배선하면 모델이
   잘못 읽은 금액이 피해구제 신청서 기재 안내에, 잘못 읽은 날짜가 기한 계산에 들어갑니다.

## 결정

### ① 전사·판독이 끝나면 다섯 값을 뽑아 `extracted` 로 둔다

`flows/read-evidence.ts` 가 토큰화 뒤 기관명 대조 다음에 `slot-extractor` 를 부릅니다. 받는 이름은
**금액 · 보낸 시각 · 상대 계좌 · 사칭 기관 · 연락 수단** 다섯(`slot-checker` 의 `CONFIRMABLE_KEYS`)입니다.

| 안 받는 것 | 왜 |
| --- | --- |
| `org_name` | [ADR-056](056-transcript-org-normalization.md) 의 사전 대조가 따로 둡니다. 사전 밖 이름이 슬롯에 들어오면 안 됩니다 |
| `transferred` · `channel` (T1) | 분기를 정하는 값이라 사람의 답으로만. `channel` 은 `case_channel` 을 함께 적어야 해서 슬롯만 채우면 갈래가 빗나갑니다 |
| 확신도 **0.7 미만** | 아래 ③ |
| 다듬어지지 않는 모양 | 아래 ② |
| 이미 `confirmed` 인 슬롯 | 덮지 않습니다 — ADR-056 이 2026-09-03 에 겪은 것과 같은 그물. `unknown`(모름)은 채웁니다 |

모델이 보는 것은 토큰화된 전사문입니다 — 계좌번호는 `[계좌-1]` 로만 보이고, 뽑힌 상대 계좌도 그 토큰입니다.
[불변 규칙 2](../CLAUDE.md)를 넘지 않습니다.

### ② 값은 절대 표기만 받는다 — 셈은 하지 않는다

`slot-extractor` 는 값을 다듬지 않습니다(*"이 모듈에는 시계가 없다"*). 그 값을 슬롯 모양으로 옮기는
`lib/extracted-value.ts` 에도 시계가 없습니다. `2026.09.01 14:22:41` 은 `2026-09-01T14:22:41+09:00` 으로,
`3,200만원` 은 `32000000` 으로 옮기지만, **「어제」·「삼천이백만 원쯤」은 버립니다** — 그 슬롯은 비어 있는
채로 남고 문진이 그대로 묻습니다. 여기서 「어제」를 날짜로 바꾸면 시계가 둘이 됩니다
([불변 규칙 7](../CLAUDE.md)).

### ③ 확신도 임계값은 0.7

슬롯 티어링의 TODO 를 여기서 정합니다. `flows/read-evidence.ts` 의 `CONFIDENCE_MIN = 0.7` 입니다.
**실측으로 고른 값이 아닙니다** — ②의 모양 검증과 ④의 확인 탭이 뒤에 있어, 임계값이 하는 일은
「모델이 스스로 자신 없다고 한 것을 굳이 되묻지 않는다」뿐입니다. 시연 자료로 돌려 본 뒤 옮길 수 있고,
옮기는 것은 이 ADR 을 대체할 일이 아닙니다(상수 하나).

### ④ 뽑힌 값은 한 번의 탭으로 확인받는다 — 되묻기를 `org_name` 밖으로 넓힌다

`slot-checker` 가 `extracted` 인 다섯 슬롯을 **문진 순서 그 자리에서** 버튼으로 되묻습니다.

```
올린 자료에서 찾은 보낸 금액입니다: 32,000,000원. 맞나요?
[맞아요]  [아니에요, 다시 적을게요]  [모름·기억 안 남]
```

| 답 | 무엇이 되나 |
| --- | --- |
| 「맞아요」 | 값 그대로 `confirmed`. `source` 는 `auto` 그대로 — 기한 계산이 「증거에서 온 날짜」를 확정으로 보는 근거가 이 칸입니다(`compute-deadlines.ts`) |
| 「아니에요, 다시 적을게요」 | 슬롯을 비웁니다(`empty`). 다음 턴에 그 문항이 **원래 형식**(금액 입력·날짜 입력)으로 나옵니다 |
| 「모름·기억 안 남」 | 지금까지처럼 `unknown` |
| 버튼 밖의 글 | 일반 답입니다 — 뽑힌 값을 갈아끼웁니다. 고치는 길을 막지 않습니다 |

두 선택지의 **글자가 곧 계약**입니다 — `slot-checker` 가 내고(`CONFIRM_YES`·`CONFIRM_NO`) `flows/answer-slot.ts`
가 같은 글자로 가릅니다. 그 갈래는 **토큰화보다 앞**에 있습니다 — 아니면 「맞아요」가 금액이 됩니다.

문구는 `lib/questions.ts` 의 `confirmFor` 가 냅니다(값을 사람이 읽는 모양으로 — 쉼표와 원, 날짜와 시·분).
계좌 토큰은 그대로 둡니다 — 원문은 브라우저만 압니다. 문구 소스가 `confirmFor` 를 안 주면 되묻지 않고
지금까지처럼 채워진 것으로만 셉니다 — 어떤 입력에도 사용자를 막지 않는다는 `slot-checker` 의 계약입니다.

## 근거

**문진이 짧아지는 것이 이 서비스의 약속입니다.** 「진술만 하면」이 골자이고, 자료를 올린 사람에게 자료에
있는 것을 다시 묻는 것은 그 약속의 반대입니다. 다섯 값 중 셋(금액·시각·계좌)이 이체 내역 캡처 한 장에
다 있습니다.

**확인 없이 채우지 않는 이유는 그 값이 가는 자리입니다.** 금액과 계좌는 피해구제 신청서 기재 안내에,
시각은 기한 계산에 갑니다. 모델이 잘못 읽은 값이 거기 들어가면 잘못된 안내가 곧 금전 손실입니다
(CLAUDE.md 「모르는 절차·수치를 지어내지 마세요」). 한 번의 탭은 입력 한 번보다 싸고, 틀린 값이 서류에
가는 것보다 훨씬 쌉니다.

**되묻기를 `org_name` 하나에 두지 않는 이유.** 상태의 정의가 이미 「이 값이 맞나요」였고, 코드가 정의를
못 따라가고 있었습니다. 정의를 코드에 맞추는 대신 코드를 정의에 맞춥니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| **확인 없이 채운다** (`extracted` 를 그대로 `confirmed` 처럼) | 문진은 가장 짧아지지만, 모델이 잘못 읽은 금액·날짜가 서류와 기한에 들어갑니다. 기한 계산은 `extracted` 를 없는 값으로 보므로(`compute-deadlines.ts`) 날짜는 어차피 확인이 필요합니다 |
| **한 문항으로 셋을 한꺼번에 확인** | 탭 하나로 끝나 더 짧지만, `next_question` 이 슬롯 하나를 가리키는 계약(§3.4)을 깨야 합니다. 세 탭이면 충분히 짧습니다 |
| **T1 도 뽑는다** (`transferred`·`channel`) | 이체 캡처는 「돈이 나갔다」의 강한 근거이지만, `channel` 은 `case_channel` 배선이 함께 필요하고 두 문항은 버튼이라 이미 한 탭입니다. 얻는 것이 적습니다 |
| **모델이 값을 다듬게 한다** (「어제」→ 날짜) | 시계가 둘이 됩니다. 불변 규칙 7 |
| **정규식만으로 뽑는다** (모델 없이) | 이체 캡처의 「받는 계좌」와 「보낸 계좌」를 가르는 것은 문맥입니다. 정규식은 어느 토큰이 상대인지 모릅니다. 모델이 고르고 규칙이 검증하는 지금 구조(ADR-014 의 층 나눔)가 맞습니다 |

## 결과

- `flows/read-evidence.ts` 에 `extractSlots` — `repairOrgs` 다음. 실패는 삼킵니다(전사 결과를 잃지 않게).
- `lib/extracted-value.ts` (새 파일) — 금액·시각·계좌 토큰·글 값의 다듬기. 못 다듬으면 `null`.
- `slot-checker` — `CONFIRMABLE_KEYS` · `CONFIRM_YES` · `CONFIRM_NO` · `QuestionSource.confirmFor` · `SlotSnapshot.valueMasked`.
  `CasePlanStore.readSlots` 가 값을 함께 읽습니다(`db-plan.ts`).
- `lib/questions.ts` 의 `confirmFor` · `flows/answer-slot.ts` 의 「맞아요/아니에요」 갈래.
- 슬롯 티어링 「구현 상태」·TODO 갱신 · API 계약 §3.3·§3.4·§3.5 · `slot-extractor`·`slot-checker` README.
- **화면은 바뀌지 않습니다** — 되묻기는 이미 있는 버튼 질문 형식(§3.4)이고, 사건 파일 패널은 `extracted` 를
  채워진 것으로 그리고 있었습니다.
