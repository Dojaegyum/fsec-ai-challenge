# ADR-019. 코드 폴더를 모듈 이름에 묶고, 스키마가 바뀌면 마이그레이션을 함께 받는다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @Dojaegyum
- 관련: [ADR-014](014-module-names.md) **부분 대체** · [ADR-018](018-inventory-skill.md) (같은 스크립트가 검사기) ·
  [ADR-008](008-structure-gate-ci.md) · [ADR-017](017-doc-integrity-ci.md) (같은 자리에서 같은 방식으로 강제)

## 맥락

[ADR-014](014-module-names.md)가 모듈 이름 19개를 정하면서 **코드 구조에는 묶지 않기로** 했습니다.

> **정하지 않습니다** — 코드 폴더 구조 (구현 시 자유롭게)

당시 판단은 타당했습니다. 이름은 용어집이고, 폴더는 구현의 사정이라는 것이었습니다.
그런데 **이름을 정한 목적이 "문제 난 자리를 한마디로 지목하는 것"**이었는데,
코드가 그 이름을 따르지 않으면 `slot-checker`는 문서에만 있는 말이 됩니다.
"슬롯 체커에서 막혔다"고 말해도 **열어볼 파일이 없습니다.**

`src/`에는 아직 create-next-app 스캐폴딩뿐이고 도메인 코드가 하나도 없습니다 —
ADR-014가 *"이름을 정하기에 가장 비용이 싼 시점"*이라고 적었던 것과 같은 이유로,
**지금이 코드 구조를 이름에 묶기에 가장 싼 시점**입니다. 나중에 하면 폴더를 옮겨야 합니다.

스키마도 같은 문제가 있습니다. `spec/backend/08-16-data-model.md`의 DDL이 정본인데,
**바꿔도 이미 만들어진 DB를 옮길 방법이 함께 오지 않으면** 정본과 실제가 갈라집니다.

## 결정

### 하나 — 도메인 모듈 코드는 `src/modules/{module-name}/`

폴더 이름이 [모듈 명칭](../spec/common/08-16-module-names.md)의 이름과 **글자 그대로 같아야** 합니다.

```
src/modules/slot-checker/     ← 정본에 있는 이름
src/modules/slotChecker/      ← 막힘 (정본에 없음)
src/modules/slot-validator/   ← 막힘 (지어낸 이름)
```

**정본에 없는 이름으로 폴더를 만들 수 없습니다.** 새 모듈이 필요하면
`spec/common/08-16-module-names.md`에 먼저 추가하고(ADR-014도 함께 갱신), 그다음 폴더를 만듭니다.

반대 방향은 강제하지 않습니다 — **정본에 있는데 아직 코드가 없는 것은 정상**입니다(구현 전).

`src/modules/` 밖은 자유입니다. 공용 유틸·UI 컴포넌트·라우트는 모듈이 아니므로 이 규칙 밖입니다.

### 둘 — DDL이 바뀌면 `src/migrations/`가 함께 온다

`spec/backend/08-16-data-model.md`의 `CREATE TABLE`·`ALTER TABLE`·컬럼 정의가 바뀐 변경에는
마이그레이션 파일이 동반돼야 합니다. **산문만 고친 변경은 해당하지 않습니다** — 검사기가 DDL 줄만 봅니다.

### 셋 — CI가 검사하되, 조건이 갖춰지기 전에는 건너뛴다

`.github/workflows/module-sync.yml`이 **스킬과 같은 스크립트**를 호출합니다.

```bash
python .claude/skills/module-inventory/scripts/inventory.py --check
```

| 검사 | 언제 켜지나 |
| --- | --- |
| 옛 표기 잔존 | 항상 |
| 정본 모듈이 `ARCHITECTURE.md` 연결구조에 다 있는지 | 항상 |
| DDL 파싱 가능 여부 | 항상 |
| **코드 폴더 ↔ 정본 이름** | `src/modules/`가 생긴 뒤부터 |
| **DDL 변경 ↔ 마이그레이션** | `src/migrations/`가 생긴 뒤부터 |

## 근거

- **이름이 코드에 닿지 않으면 용어집은 장식입니다.** ADR-014의 목적("문제 난 자리를 한마디로 지목")은
  코드가 그 이름을 쓸 때 비로소 달성됩니다. 이 ADR은 ADR-014를 뒤집는 것이 아니라 **끝까지 미는 것**입니다.
- **모듈화가 강제되면 피처 하나가 한 폴더로 모입니다.** 지금처럼 층이 다르면 도는 시점도 다른 구조에서는,
  파일이 기능별로 흩어지면 "언제 도는가"를 코드에서 읽을 수 없게 됩니다.
- **검사기가 스킬과 같은 스크립트입니다.** 사람이 손으로 돌리는 명령과 CI가 돌리는 명령이 같아야
  게이트가 문지기가 아니라 안전망이 됩니다 — [ADR-017](017-doc-integrity-ci.md)에서 세운 원칙입니다.
- **조건부 활성이 핵심입니다.** 지금 마이그레이션 검사를 켜면 스키마를 다듬는 커밋이 전부 막힙니다.
  마이그레이션 방식이 아직 미정이라([ARCHITECTURE.md](../ARCHITECTURE.md) §10) 낼 것이 없기 때문입니다.
  **자주 걸리는 게이트는 꺼집니다** — [ADR-008](008-structure-gate-ci.md)의 재검토 트리거가 그것입니다.
  폴더가 생기는 순간 저절로 켜지므로, 잊어버릴 수도 없습니다.

### 검토한 대안

| 대안 | 사유 |
| --- | --- |
| 폴더 구조를 계속 자유롭게 (현행 ADR-014) | 이름이 문서에만 남습니다. "슬롯 체커에서 막혔다"고 해도 열어볼 파일이 없습니다 |
| 코드에서 모듈 이름을 **추출**해 정본을 자동 갱신 | 방향이 반대입니다. 정본이 코드를 따라가면 **이름을 지어 쓰는 것을 막을 수 없습니다** |
| 파일 단위로 강제 (`src/modules/slot-checker.ts`) | 모듈 하나가 파일 하나로 끝나지 않습니다. 폴더여야 테스트·타입·하위 파일이 함께 모입니다 |
| 마이그레이션 검사를 지금부터 무조건 | 낼 마이그레이션이 없어 정당한 커밋이 전부 막힙니다 |
| 경고만 하고 막지 않기 | 경고는 읽히지 않습니다 — ADR-017에서 같은 판단을 했습니다 |

## 결과

**얻는 것**

- **"어디서 막혔다"가 파일 경로가 됩니다** — `slot-checker`라고 말하면 `src/modules/slot-checker/`입니다.
- 이름을 지어 쓰는 것이 **구조적으로 막힙니다.** 정본에 먼저 추가해야 폴더를 만들 수 있습니다.
- 스키마 정본과 실제 DB가 갈라지지 않습니다.

**잃는 것 · 감수하는 것**

- **폴더 구조의 자유를 잃습니다.** ADR-014가 명시적으로 남겨둔 여지를 회수하는 것이라,
  구현 중에 "이 코드는 어느 모듈인가"를 매번 판단해야 합니다. 애매하면 `src/modules/` 밖에 둡니다.
- **모듈을 만들기 전에 문서를 고치는 한 단계가 늘어납니다.** 그것이 이 결정의 값이기도 합니다.
- **검사기가 `.claude/`에 있습니다.** CI가 스킬 스크립트에 의존하므로, 그 파일을 지우면 CI가 깨집니다.
- DDL 판정은 **정규식 근사**입니다. 컬럼 정의처럼 보이는 산문이 있으면 오탐이 납니다.

## 재검토 트리거

- 구현이 진행돼 `src/modules/` 밖에 도메인 코드가 쌓이기 시작하면, 경계를 다시 정합니다.
- 마이그레이션 도구를 고를 때(`src/migrations/`의 파일 형식) 검사 조건을 그 도구에 맞춥니다.
- 오탐이 반복되면 그 검사만 끕니다 — 게이트 전체를 끄지 않습니다.
