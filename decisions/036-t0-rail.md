# ADR-036. 셸을 세 열로 하고, T0 안전 절차를 왼쪽 고정 레일에 둔다

- 상태: **채택**
- 날짜: 2026-08-20
- 결정: @Dojaegyum
- 관련 문서: [슬롯 티어링](../spec/backend/08-14-slot-tiering.md) 「T0 · 없어도 시작」 ·
  [모듈 명칭](../spec/common/08-16-module-names.md) `plan-viewer` ·
  [화면 설계](../spec/frontend/08-14-screens.md) (이 결정으로 개정됨) ·
  [ADR-035](035-screen-state-axes.md) (본문·오른쪽 열 두 축) ·
  [RFC-003](../rfc/003-design-handoff.md) (시안과 갈릴 때)

## 맥락

**T0 안전 절차가 챗 본문 안에 있었습니다.** 그래서 본문이 플랜이나 증거함으로 바뀌면
**같이 사라졌습니다.**

이건 계약 위반입니다. 두 문서가 이미 반대로 적고 있었습니다.

| 어디 | 무엇이라 적혀 있나 |
| --- | --- |
| [슬롯 티어링](../spec/backend/08-14-slot-tiering.md) | 「T0 공통 안전 절차는 인입 즉시, **슬롯과 무관하게 실행 보드에 상시 노출**」 |
| [모듈 명칭](../spec/common/08-16-module-names.md) | 「`plan-viewer` — 타임라인·단계·상태 배지를 그린다. **T0 안전 절차를 상시 노출한다**」 |

**「상시」가 「챗을 보고 있는 동안만」이 되어 있었습니다.**

동시에 화면에는 남는 자리가 있었습니다. 본문이 챗일 때 스트림은
`max-w-[700px]`로 가운데 정렬되는데, 셸은 `1408px`이고 오른쪽 열이 `350px`이라
**왼쪽에 300px 가까이가 비어 있었습니다.**

## 결정

**셸을 세 열로 만들고, 맨 왼쪽 `288px`를 T0 전용 고정 레일로 씁니다.**

```
┌──────────────┬───────────────────────────┬──────────────────┐
│ T0 안전 절차   │  본문                      │  오른쪽 열        │
│ (288px·고정)  │  챗 · 플랜 · 증거함         │  (350px)         │
└──────────────┴───────────────────────────┴──────────────────┘
```

- **T0는 본문 밖에 있습니다.** `focus`가 무엇이든 자리를 지킵니다.
- **넓은 폭에서는 접히지 않습니다.** 자리가 남으니 접을 이유가 없고,
  접는 순간 「급하면 안 보이는 것」이 됩니다. **접기는 좁은 폭 전용**입니다.
- **좁은 폭에서는 맨 위에 쌓이고 요약 한 줄 + 접기**로 돌아갑니다.
- 흡수 모션의 대상은 **본문 열뿐**입니다. T0 레일은 빨려들지 않습니다.

## 근거

**「상시」는 화면 구조로 지켜야 합니다.** 본문 안에 두면 국면이 바뀔 때마다
「이 화면에도 T0를 넣었나」를 사람이 기억해야 하고, 한 번 빠뜨리면 아무도 모릅니다.
**열을 따로 주면 빠뜨릴 수가 없습니다.**

**패닉 상태에서 스크롤해서 찾게 하면 안 됩니다.** T0는 「틀릴 수 없는 절차」라
가장 급한 사람이 가장 먼저 봐야 하는 것인데, 챗 위에 있으면 대화가 길어질수록
위로 밀려 올라갑니다.

**빈 자리를 채우는 것이 아니라, 빈 자리가 있어서 가능한 것입니다.** 순서가 거꾸로면
안 됩니다 — 자리가 없었다면 다른 방법을 찾았을 겁니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| 본문 안 유지 (기존) | 플랜·증거함에서 사라집니다. 계약 위반입니다 |
| 세 본문에 각각 T0를 넣기 | 같은 것을 세 군데 두면 **언젠가 하나가 어긋납니다** |
| 헤더에 칩으로 축약 | 112·1332는 **번호를 읽어야** 하는 정보입니다. 칩에 안 들어갑니다 |
| 오른쪽 열 아래에 붙이기 | 그 자리는 워크스페이스·미니 챗이 씁니다. 셋이 겹칩니다 |

## 결과

**시안 셋과 갈립니다.** `S-06`·`S-07`·`S-08` 핸드오프는 전부 **2열**(본문 + 350px)이고,
T0는 챗 본문 맨 위에 있습니다. 이 결정으로 **세 화면 모두 셸이 달라집니다** —
캔버스를 나중에 보는 사람이 「왜 다르지」 할 자리라 여기 적어 둡니다
([RFC-003](../rfc/003-design-handoff.md) 「시안이 spec과 어긋나면」).

**본문이 좁아집니다.** `1408 − 288 − 350 = 770px`. 챗(`max-w-[700px]`)은 그대로 들어가고,
플랜(`max-w-[860px]`)과 증거함은 그만큼 줄어듭니다. 셋 다 상한이라 깨지지 않습니다.

**시안을 새로 받을 때 이 열을 전제해야 합니다.** 2열로 그려 오면 옮길 때마다
같은 판단을 다시 하게 됩니다.

**재검토 트리거** — 좁은 폭에서 T0가 「먼저 읽어야 하는 벽」이 되면
(스크롤해야 본론이 나오는 상태), 좁은 폭에서만 접힌 채로 시작하는 것을 봅니다.
넓은 폭에서 접는 쪽으로는 돌아가지 않습니다.
