# ADR-033. 워크스페이스 패널을 챗과 같은 화면에 두고, 단계 상세 화면을 없앤다

- 상태: **채택**
- 날짜: 2026-08-19
- 결정: @Dojaegyum

## 맥락

`spec/frontend/` 안에서 **두 문서가 서로 다른 그림을 들고 있었습니다.**

| 문서 | 무엇이라 적혀 있었나 |
| --- | --- |
| [화면 설계](../spec/frontend/08-14-screens.md) `S-09` | 단계 상세 `/c/{token}/step/{id}` — **「`WS-*` 일곱이 여기 붙고」** |
| [워크스페이스 패널](../spec/frontend/08-17-workspace-panels.md) 「배치」 | 한 화면에 네 열. **「워크스페이스와 챗이 같은 열에 있습니다」** |

이력을 보면 원인이 분명합니다. 둘은 같은 커밋(`19c2572`)에서 **3-패널 상황실 전제로** 태어났고,
그날 `90274a8`이 「3-패널 상황실 폐기, 화면 일곱」으로 **화면 설계만 재작성**하면서 `S-09`가
갈라져 나왔습니다. **워크스페이스 문서의 배치 절은 따라가지 못했습니다.**

그런데 **버려진 쪽 문서에 담긴 논거가 더 강했습니다.** 같은 문서의 시그널 규칙이 이렇습니다.

> 남은 것이 없음 → **패널을 그대로 둔다. 닫지 않습니다.**
> 「감사합니다」 같은 발화에서 패널이 사라지면 **사용자가 적고 있던 접수번호를 잃습니다.**

**이것은 챗과 패널이 한 화면에 있어야만 성립하는 걱정입니다.** 패널이 별도 주소에 있으면
챗이 그것을 「닫을」 일 자체가 없습니다. 즉 그 규칙은 `S-09` 전제와 앞뒤가 맞지 않았습니다.

S-06 챗 시안이 들어오면서 **핸드오프가 이 자리를 「제품 결정 확정」으로 넘겨** 왔고,
[RFC-003](../rfc/003-design-handoff.md)대로 사람이 정했습니다.

## 결정

**워크스페이스 패널은 `S-06` 챗 국면과 같은 화면, 챗 옆 열에 붙습니다.
`S-09` 단계 상세 화면과 `/c/{token}/step/{id}` 주소를 없앱니다.**

| | 이전 | 지금 |
| --- | --- | --- |
| 패널이 사는 곳 | `S-09` `/c/{token}/step/{id}` | **`S-06` `/c/{token}` 우측 열** |
| 단계를 누르면 | 다른 주소로 이동 | **같은 화면에서 패널만 바뀜** |
| 화면 개수 | 여덟 | **일곱** (`S-09` 폐기) |
| `S-09` 번호 | — | **재사용하지 않습니다** |

**바뀌지 않는 것 셋을 못박습니다.**

1. **어느 패널을 여는지는 서버가 정합니다.** `body.action` 일곱 값 그대로이고
   ([ADR-024](024-step-action-and-url.md)), `work-handler`가 규칙으로 고릅니다.
   **이 결정은 「어디에 그리나」만 바꿉니다.**
2. **완료는 부산물이 판정합니다.** 「완료가 판정되는 유일한 자리」였던 `S-09`의 역할은
   패널이 그대로 가져갑니다 — 체크만으로 완료되는 경로는 여전히 없습니다.
3. **「나중에」를 막지 않습니다.** 미룬 단계는 「미확인」으로 남아 기한 추적이 계속됩니다.

**좁은 폭에서는 위아래로 쌓이고 워크스페이스가 맨 위로 옵니다** — 지금 할 일이 먼저입니다.

## 근거

**시그널 규칙이 이미 같은 화면을 전제하고 있었습니다.** 위의 「닫지 않습니다」가 그 증거입니다.
별도 주소를 유지하려면 그 규칙을 버려야 하는데, 그건 **적던 접수번호를 잃는** 실제 손해입니다.
통화 중에 그 일이 일어납니다.

**「말한 곳」과 「하는 곳」이 갈라지면 안 됩니다.** 챗이 "은행에 전화하세요"라고 말하고
대본은 다른 주소에 있으면, 사용자는 전화를 걸면서 화면을 오갑니다.
**전화는 관측 불가한 블랙박스**라 그 순간 이탈하면 우리가 알 방법이 없습니다.

**주소가 하나 줄어드는 것이 이 서비스에서는 이득입니다.** 계정이 없어 **링크가 유일한 열쇠**인데
([ADR-021](021-reentry-and-identity.md)), 사용자가 들고 있어야 할 주소가 둘이면
「어느 걸 저장해야 하나」가 생깁니다. `/c/{token}` 하나로 끝나는 편이 낫습니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| `S-09` 별도 주소 유지 (기존 계약) | 「패널을 닫지 않는다」가 성립하지 않고, 통화 중 화면 이동이 생깁니다 |
| 둘 다 두기 — 화면 안 패널 + 딥링크용 주소 | **정본이 둘이 됩니다.** 같은 패널을 두 곳에서 렌더하면 「완료 판정이 어디서 일어나나」가 갈립니다 |
| 패널을 모달로 | 모달은 [접근성 기준](../spec/frontend/design-system/08-16-accessibility.md)이 **포커스를 가두지 않는다**고 정한 자리이고, 통화 중 오래 떠 있어야 하는 것을 모달로 두면 뒤의 챗을 못 봅니다 |

## 결과

**쉬워지는 것** — 라우팅이 하나 줄고, `work-handler`의 판정 결과가 **곧바로 옆 열**이 됩니다.
「보드에서 단계를 눌렀을 때」와 「챗이 언급했을 때」가 원래 한 곳으로 들어오게 설계돼 있었는데
([시그널](../spec/frontend/08-17-workspace-panels.md)), 이제 그 「한 곳」이 실제로 한 곳입니다.

**잃는 것** — **단계 하나를 가리키는 주소가 없어집니다.** 기한 알림 이메일이
「3영업일 마감 D-1」을 보낼 때 사건 전체로만 보낼 수 있고, 그 단계로 바로 열어줄 수 없습니다.
`reminder-sender`가 붙을 때 다시 필요해지면, **주소를 되살리는 게 아니라
`/c/{token}?step=…` 같은 질의 문자열로** 같은 화면을 여는 쪽을 먼저 봅니다.

**재검토 트리거** — 좁은 폭(폰)에서 세 덩이가 위아래로 쌓였을 때 「지금 할 일」에 닿기까지
스크롤이 길어지면, 그때는 화면을 나누는 게 아니라 **폰에서 무엇을 접을지**를 정합니다.
