# ADR-017. 문서 간 참조가 규약과 어긋나면 CI로 막는다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @Dojaegyum
- 관련: [RFC-001](../rfc/001-repo-structure.md) (규약 본문 · 「CI가 강제합니다」) ·
  [ADR-008](008-structure-gate-ci.md) (폴더 구조 게이트 — 같은 자리에서 같은 방식으로 강제합니다)

## 맥락

[ADR-008](008-structure-gate-ci.md)은 **폴더**가 규약과 어긋나는 것을 막았습니다.
그런데 이 저장소가 실제로 어긋나는 지점은 폴더보다 **문서 사이의 참조**입니다.

문서 57개가 서로를 307번 가리킵니다. 그리고 규약이 그 참조를 어렵게 만들어 두었습니다 —
의도한 대가입니다.

- 파일명이 `MM-dd-{slug}`라 **읽는 순서를 알려주지 않습니다.** 그래서 RFC-001은
  *"목차에 없는 문서는 사실상 없는 문서"*라고 정했는데, **지키지 않아도 아무 일도 없었습니다.**
- `ADR-003`·`F-05b` 같은 ID가 문서·커밋·코드를 잇는데, **없는 번호를 가리켜도 아무도 모릅니다.**
- ADR은 고치지 않는 것이 원칙이지만, **고쳐도 막히지 않았습니다.**

이 저장소는 사람과 에이전트가 함께 씁니다. **에이전트는 문서를 그대로 믿기 때문에,
틀린 링크와 빠진 목차의 비용이 사람일 때보다 큽니다.** 사람은 링크가 깨지면 검색이라도 하지만,
에이전트는 "없는 문서"를 없는 것으로 취급하고 그대로 진행합니다.

## 결정

**문서 간 참조가 규약과 어긋나면 CI가 막습니다.** `.github/workflows/doc-integrity.yml` ·
`.github/scripts/doc-integrity.py` — PR과 `main` 푸시 모두에 걸립니다.

| 검사 | 무엇을 막나 |
| --- | --- |
| 링크 | 없는 파일을 가리키는 상대링크 |
| 앵커 | 대상 문서에 없는 `#절` |
| ID | 정의되지 않은 `ADR-NNN`·`RFC-NNN`·`F-xx`·`S-xx`·`CH-xxx` |
| 파일명 | 폴더별 규약 위반 (`NNN-{slug}` · `MM-dd-{slug}`) |
| 번호 | RFC·ADR 번호 중복 |
| 목차 | 폴더 `README.md`에 등록되지 않은 문서 |
| ADR | 결정 내용의 사후 수정 · 삭제 · 번호 변경 |
| 대체 | `대체됨(→ ADR-NNN)`의 상대가 없거나, 대체한 쪽이 그 사실을 안 적은 것 |

**검사기는 표준 라이브러리만 씁니다.** 설치가 없으므로 로컬에서도 그대로 돕니다 —
`python .github/scripts/doc-integrity.py`. CI가 문지기가 아니라 안전망이 되려면
**커밋 전에 사람이 먼저 돌려볼 수 있어야** 합니다.

## 근거

- **규약은 어겨도 아프지 않으면 지켜지지 않습니다.** ADR-008에서 이미 확인한 것이고,
  문서 참조는 폴더보다 훨씬 자주 어긋납니다.
- **결정론만 넣었습니다.** 문서끼리 **모순**되는 것(예: 한쪽은 "24시간 파기", 다른 쪽은 "몇 달 관리")은
  정규식으로 잡을 수 없고 LLM이 필요합니다. 판단이 필요한 것을 차단 게이트에 넣으면
  오탐으로 게이트가 꺼집니다. **모순 탐지는 넣지 않았습니다** — 필요해지면 차단이 아니라
  리뷰 코멘트로 따로 답니다.
- **순환참조는 검사하지 않습니다.** 도입 전 실측에서 문서 간 링크 사이클이 270개 넘게 나왔는데,
  **전부 정상이었습니다** — `ADR-005`↔`ADR-006`, `pii-boundary`↔`domain-model`처럼
  서로를 가리키는 것은 문서에서 미덕입니다. 사이클을 결함으로 보면 오탐 270건으로 시작합니다.
- **코드블록 안은 보지 않습니다.** RFC-001이 출처 줄 형식을 예시로 보여주며 쓴
  `<상대경로>` 같은 것은 참조가 아니라 설명입니다.

### ADR 불변성을 어떻게 판정했나

여기만 판정이 까다로웠습니다. RFC-001은 *"오탈자 정도는 되지만 결정 내용은 그대로 둡니다"*라고
적었는데, **기계는 오탈자와 내용 변경을 구별하지 못합니다.**

그래서 **"결정 내용"을 구조로 정의**했습니다 — **H1의 결정 문장**과 **「## 결정」 절**.
이 둘이 바뀌면 막고, 맥락·근거·결과·링크·상태 줄은 통과시킵니다.

이 기준을 도입 시점의 실제 변경에 걸어 확인했습니다. 그때 진행 중이던
`# 0003.` → `# ADR-009.` 같은 **번호 표기 정규화는 통과**합니다(번호 접두를 떼고 비교하므로).
`## 결정` 절을 고치는 변경은 막힙니다.

### 검토한 대안

| 대안 | 사유 |
| --- | --- |
| 링크 검사만 (markdown-link-check 등 기성 액션) | ID·목차 등록·ADR 불변성은 이 저장소만의 규약이라 기성 도구가 모릅니다 |
| ADR 본문 수정을 전부 차단 | 도입 시점에 진행 중이던 정당한 번호 표기 정규화가 막힙니다. 규약도 오탈자 수정은 허용합니다 |
| ADR 수정을 경고만 | 경고는 읽히지 않습니다. 판정 기준을 구조로 좁혀서 차단할 수 있게 만드는 편이 낫습니다 |
| 순환참조 탐지 | 실측 결과 오탐 270건. 문서에서 양방향 링크는 결함이 아닙니다 |
| LLM 모순 탐지를 게이트에 | 판단이 필요한 것은 차단하면 안 됩니다. 오탐 한 번에 게이트가 꺼집니다 |
| 라벨로 우회 허용 | ADR-008과 같은 이유 — 우회가 기본값이 됩니다 |

## 결과

**얻는 것**

- 파일을 옮기거나 이름을 바꿀 때 **깨진 링크가 머지되지 않습니다.**
- 새 문서를 만들면 **목차 등록을 강제로 한 번 생각하게** 됩니다.
- ADR이 조용히 고쳐지지 않습니다 — 이력이 이력으로 남습니다.
- 검사기가 곧 규약의 실행 가능한 사본이라, **규약과 검사가 어긋나면 CI가 먼저 말합니다.**

**잃는 것 · 감수하는 것**

- **ID 정의처가 검사기에 하드코딩돼 있습니다** (`ID_SOURCES`). `features.md`·`screens.md`·
  `channel-matrix.md`를 옮기면 검사기도 같이 고쳐야 합니다. 안 고치면 검사기가 그렇다고 말합니다.
- **앵커 검사는 GitHub 규칙의 근사**입니다. 렌더링 규칙이 바뀌면 오탐이 생길 수 있습니다.
- **기준 커밋이 없으면(브랜치 첫 푸시·force push) ADR 불변성만 건너뜁니다.** 나머지는 그대로 돕니다.
- 도입 시점에 `docs/research/`의 파일 6개가 파일명 규약(`MM-dd-{slug}`)을 어기고 있었습니다.
  → [RFC-001](../rfc/001-repo-structure.md) 「파일명 규약」에서 조사 자료의 이름 규칙을 따로 정해 해소했습니다.

## 재검토 트리거

- 오탐이 반복되면 그 검사만 끕니다 — 게이트 전체를 끄지 않습니다.
- 문서 **모순**이 실제로 사고를 내면, 차단이 아닌 리뷰 코멘트로 LLM 검사를 따로 답니다.
- `spec/` 문서가 늘어 목차 관리가 병목이 되면, 목차를 생성하는 쪽으로 바꿉니다.
