# 0009. 근거를 문장마다 붙이고, 근거가 없으면 에러 대신 되묻는다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @kth9245
- 관련: [RFC-0007](../rfc/0007-인용-검증과-되묻기.md) · `spec/11-chat-context.md` §5 §6 §9 · `spec/10-errors.md` §4.1 · `spec/08-api.md` §3.9

## 결정

**결정 A — 「절차를 언급했는지」를 판정하지 않습니다.**

모델이 자유 문장을 낼 때는 근거가 **하나 이상 반드시** 있어야 합니다. 되묻기라는 예외를 두지 않습니다.

**결정 B — 근거를 문장 단위로 붙이고, 항목마다 가리킨 이유를 씁니다.**

**번호는 절차 항목만이 아니라 프롬프트에 넣는 자료 전체에 붙입니다.**

| 접두 | 무엇 |
| --- | --- |
| `kb-` | 절차 항목 |
| `case-` | 사건 정보 — 슬롯·단계·기한·부산물 |
| `t-` | 전사 한 줄 |

```jsonc
{
  "insufficient": false,
  "citations": [
    { "ref": "kb-2", "label": "피해구제 신청서 제출",
      "kb_entry_id": "relief-application", "kb_version": "2026.08.1",
      "why": "지급정지를 이미 걸었으므로, 다음 단계가 신청서 제출이라고
              안내하는 데 썼습니다" },
    { "ref": "case-3", "label": "피해구제 신청 기한",
      "why": "8월 20일이라는 날짜를 문장에 그대로 옮기는 데 썼습니다" }
  ],
  "reply": "다음은 피해구제 신청서 제출입니다. 8월 20일까지 하셔야 하고, …"
}
```

**`why`에 「왜」가 아니라 「어떻게 썼는지」를 씁니다.** 답변의 어느 대목에 썼는지가 드러나야 합니다. 이 자리가 **과잉 인용을 막는 유일한 장치**입니다 — 번호 대조만으로는 프롬프트에 있는 항목을 전부 넣어도 통과하고, 실제로 안 쓴 항목은 여기 쓸 말이 없습니다.

**답변을 문장 단위로 쪼개는 안은 버렸습니다.** 조각마다 `ref`를 달면 과잉 인용을 기계적으로 잡을 수 있지만, 문장을 얼마나 잘게 나눌지를 또 정해야 하고 한국어에서 `"~하고,"` 로 이어지는 문장을 끊으면 어색해집니다. **얻는 것에 비해 비용이 큽니다.**

**`ref`와 `label` 모두 서버가 붙입니다.** 모델은 그 번호로만 가리킵니다.

**결정 C — 모델이 근거를 못 찾으면 에러가 아니라 되묻기로 갑니다.**

| 원인 | 처리 |
| --- | --- |
| KB 조회 결과 0건 | **현행 유지.** 절차를 말하지 않고 1332 안내 |
| 조회는 됐는데 모델이 `insufficient: true` | **슬롯 한 개를 버튼으로 질문** → 채우면 다시 답변 → 채울 슬롯이 없으면 1332 |

## 왜 결정 A인가

**판정 방법을 잘 만드는 것보다 판정을 없애는 것이 낫습니다.**

두 가지를 검토하고 버렸습니다.

**서버가 응답 문장을 규칙으로 검사하는 방식** — "3영업일", "신청하세요" 같은 표현 목록에 근거가 없습니다. 한국어 표현은 다양해서 빠뜨리면 못 잡고 과하게 넣으면 정상 응답이 막힙니다. `CLAUDE.md` 작업 규칙이 가장 강하게 막는 것이 **근거 없는 규칙을 지어내는 일**입니다.

**모델이 스스로 표시하는 방식** — 불변 규칙 1의 확인 장치를 모델 판단에 맡기게 됩니다. 모델이 틀리거나 업로드 문서에 심어진 문장에 넘어가면 검증이 통째로 비켜갑니다.

### 판정이 필요 없는 이유는 구조에 있습니다

**되묻는 것은 원래 모델의 일이 아닙니다.**

`spec/02-slot-tiering.md`가 빠진 정보를 물을 때 **서버가 버튼 한 문항으로 만든다**고 정해뒀습니다. 그래서 **모델이 자유 문장을 쓰는 자리는 절차를 설명하는 자리뿐**입니다.

## 왜 결정 B인가

**허용 집합 대조만으로는 과잉 인용을 못 막습니다.** 조회된 항목을 전부 넣어도 통과합니다.

**왜 가리켰는지를 쓰게 하면 관련 없는 항목은 쓸 이유가 없어 스스로 걸러집니다.** 그리고 선언한 근거를 어느 문장에도 안 붙이면 서버가 잡을 수 있습니다.

### 절차 항목에만 번호를 붙이면 두 가지가 샙니다

**첫째, 사건 정보를 지어내는 것을 못 막습니다.** 모델이 없는 계좌번호를 말해도 절차 검사에 걸리지 않습니다.

**둘째, 정상 응답이 규칙 위반이 됩니다.** `"그 계좌는 국민 ****7890입니다"`에는 인용할 절차 항목이 존재하지 않습니다. 근거가 비었다는 이유로 되묻기가 발동하면, **계좌를 확인한 사용자에게 엉뚱한 슬롯 질문이 뜹니다.**

**둘째가 [ADR-0007](0007-챗-컨텍스트-조립.md)의 부분 복원과 정면으로 부딪혔습니다.** 계좌가 여럿일 때 어느 건인지 알아보게 하려고 만든 기능인데, 그 기능이 쓰이는 턴마다 위반이 되는 상태였습니다.

**번호 대상을 자료 전체로 넓히면 둘 다 해소됩니다.** 절차를 말하면 `kb-`를, 사건 정보를 말하면 `case-`를, 통화 내용을 말하면 `t-`를 가리키면 됩니다.

### 대괄호 충돌이 구조로 없어집니다

`spec/04-pii-boundary.md`의 토큰이 `[계좌-1]` 형식입니다. 근거 표시를 같은 대괄호로 본문에 넣으면 두 표기가 겹치는데 **처리 방향이 정반대**입니다.

| | 최종 답변 본문에 |
| --- | --- |
| PII 토큰 | **남아야 합니다** — 브라우저가 부분 복원 ([ADR-0007](0007-챗-컨텍스트-조립.md)) |
| 근거 표시 | **없어야 합니다** — 내부 식별자 노출 금지 |

**문장 단위 구조에서는 근거 번호가 본문 밖 별도 칸에 붙어 둘이 만나지 않습니다.**

## 왜 결정 C인가

**근거를 못 붙였다는 것은 사건 정보가 부족하다는 신호이지 시스템 실패가 아닙니다.**

조회 조건은 사건 정보에서 나옵니다. 인용을 못 붙였다는 것은 **지금 조회된 절차가 이 질문에 안 맞는다**는 뜻이고, 조회 조건을 좁힐 정보가 더 있으면 맞는 절차가 나올 수 있습니다.

`CLAUDE.md` 불변 규칙 5가 **"모름은 실패가 아니다. 정보 요구로 사용자를 막지 마라"**입니다. 충격 상태의 사용자에게 "안내를 만들지 못했습니다"라는 화면을 띄우면, **사용자는 무엇을 더 알려줘야 하는지 모른 채 막힙니다.**

`spec/10-errors.md` §4의 「에러가 아닌 실패」 분류와 결이 맞습니다. 그 표에 이미 "슬롯 자동 추출 실패 → 질문으로 흘려보냅니다"가 있습니다.

### 원인을 가르는 이유

**조회 결과가 0건이면 되물어도 소용없습니다.** 해당 절차가 지식 베이스에 아예 없다는 뜻이라, 슬롯을 아무리 채워도 나오지 않습니다. 이때 질문을 던지면 사용자만 헛수고합니다.

## 결과

**얻는 것**

- **인용 강제를 구현할 수 있게 됐습니다.** 미정으로 남아 있던 판정 방법이 필요 없어졌습니다
- 과잉 인용이 줄고, 어느 문장이 어느 근거에서 나왔는지 추적됩니다
- **오류 화면 대신 질문이 나갑니다.** 사용자가 무엇을 더 알려주면 되는지 알게 됩니다
- 관리자 조회가 "왜 하필 이 절차를 골랐나"에 항목 단위로 답합니다
- 근거 표시와 개인정보 토큰의 표기 충돌이 생기지 않습니다

**잃는 것**

- **모델 출력이 복잡해집니다.** 문장 분할과 항목별 이유를 함께 내야 합니다. 형식 오류로 인한 재시도가 늘 수 있습니다
- 응답 스키마가 바뀌어 화면 쪽도 문장 단위로 그려야 합니다
- **되묻기 경로에서 사용자가 답을 못 받고 질문을 받습니다.** 화면에서 이걸 어떻게 보여줄지가 새 과제입니다

## 탈락한 후보

| 후보 | 사유 |
| --- | --- |
| 서버가 문장을 규칙으로 검사 | **표현 목록에 근거가 없습니다.** 규칙을 지어내는 것이 됩니다 |
| 모델이 절차 언급 여부를 표시 | 불변 규칙 1의 확인 장치를 **모델 판단에 맡기게 됩니다** |
| 조회 결과가 있으면 항상 인용 요구 | 판정은 없어지지만 `"네, 접수 문자 오면 올려주세요"` 에도 법령 근거가 달립니다 |
| 근거 표시를 본문에 `[태그]` 로 넣기 | **개인정보 토큰과 표기가 겹칩니다.** 처리 방향이 정반대라 섞이면 안 됩니다 |
| 인용 실패를 502로 끝내기 (현행) | 불변 규칙 5와 어긋납니다. **사용자가 막힙니다** |
