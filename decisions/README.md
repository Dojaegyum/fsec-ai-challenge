# 의사결정 기록 (ADR)

되돌리기 어렵거나 나중에 "왜 이렇게 했더라"가 나올 결정을 한 건에 한 파일로 남깁니다.
주제 확정, 기술 스택, MVP 범위 컷 같은 것들이 대상입니다.

여기는 **왜 그렇게 정했나**를 남기는 곳입니다(과거형·이력). 그래서 **지금 지켜야 할 규칙**은
[rfc/](../rfc/)에 따로 있습니다(현재형·현행).

**한 결정이 둘 다 낳는 것이 정상입니다** — 판단은 여기, 그 결과 지킬 규칙은 `rfc/`,
제품이 만족해야 할 계약은 [spec/](../spec/). 셋을 같이 갱신하는 것까지가 한 작업입니다.

**ADR은 지우지도 고치지도 않습니다** — 뒤집을 때는 새 번호를 쓰고 기존 것을 `대체됨`으로 표시합니다.

## 파일명과 번호

**파일명은 `MM-dd-{slug}.md`** (저장소 전체 공통 → [RFC-0001](../rfc/08-16-repo-structure.md)),
**문서 안 ID는 `ADR-NNNN`** 으로 따로 붙입니다. 파일명에는 번호를 넣지 않습니다.

```
파일   decisions/08-16-topic-selection.md
문서   # ADR-0001. 출전 주제를 보이스피싱 사후 대응으로 한다
참조   "ADR-0001 참조"
```

번호로 파일을 찾을 수는 없으므로 **아래 「목록」이 번호↔파일 대응표**입니다.
새 ADR을 쓰면 반드시 목록에 넣으세요.

- `MM-dd`는 **결정한 날**이며 나중에 바꾸지 않습니다.
- 번호는 순번이며 **재사용하지 않습니다.**
- 같은 날 여러 결정이 나오는 것은 정상입니다 — slug으로 구분됩니다.

## 템플릿

```markdown
# ADR-NNNN. <결정 한 문장>

- 상태: 제안 | 채택 | 폐기 | 대체됨(→ ADR-NNNN)
- 날짜: YYYY-MM-DD
- 관련 문서: <../spec/..., ../rfc/..., ../docs/... 등>

## 맥락

무엇을 정해야 했고, 그때 무엇을 알고 있었는지. 제약(시간·인원·데이터 접근)도 여기.

## 결정

무엇으로 정했는지.

## 근거

왜 그것인지. 탈락한 대안과 탈락 사유를 함께.

## 결과

이 결정으로 무엇이 쉬워지고 무엇이 어려워지는지. 나중에 재검토할 트리거가 있으면 명시.
```
