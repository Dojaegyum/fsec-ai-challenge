# ADR-003. spec을 common·backend·frontend로 나누고 파일명을 `MM-dd-{title}.md`로 한다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @Dojaegyum
- 관련: [spec/README.md](../spec/README.md) · [CLAUDE.md](../CLAUDE.md) 「spec 폴더와 파일명」

## 맥락

`spec/`은 기획서 v1.2에서 추출할 당시 `10-`, `20-`… 십 단위 번호로 만들었고,
그 뒤 `01`~`08` 연번으로 한 번 바꿨습니다. 이 시점에 두 가지가 드러났습니다.

- **번호가 순서를 약속해 버립니다.** 사이에 문서를 하나 넣으려면 뒤를 다 밀거나 소수점을 붙여야 합니다.
  실제로 파일명만 `01~08`로 바꾸고 본문 H1은 `# 10 · 기능명세`로 남아 하루 만에 어긋났습니다.
- **읽는 사람이 갈립니다.** 화면 계약(S-01~S-03)과 KB 운영 파이프라인은 볼 사람이 다른데
  한 폴더에 나란히 있어, 백엔드 작업자가 화면 문서까지 훑어야 자기 계약을 찾습니다.

구현 착수를 앞두고 백엔드 모듈 경계를 정하는 중이라, 계약 문서부터 갈라둘 시점이었습니다.

## 결정

**폴더 — "누가 지키는 계약인가"로 셋으로 나눕니다.**

| 폴더 | 무엇 |
| --- | --- |
| `common/` | 양쪽이 함께 지키는 것 — 용어, 기능명세(F-xx), PII 경계, API 계약 |
| `backend/` | 서버의 판단·데이터 계약 — 슬롯 티어링, 경유 서비스 매트릭스, 완수 검증, KB 운영 |
| `frontend/` | 화면·상호작용 계약 — 화면 설계(S-xx) |

**파일명 — `MM-dd-{title}.md`.** `MM-dd`는 **최초 작성한 월-일이며, 개정해도 바꾸지 않습니다.**
제목은 영문 kebab-case, 문서 안 H1은 한국어로 씁니다.

## 근거

- **날짜는 순서를 약속하지 않습니다.** 그래서 새 문서를 아무 때나 추가해도 기존 파일을
  건드릴 일이 없습니다. 번호 체계가 겪던 재배치 압력이 사라집니다.
- **날짜를 고정하는 것이 이 규약의 핵심입니다.** 개정할 때마다 날짜를 갱신하면 파일명이 바뀌고,
  그 문서를 가리키는 링크와 `CLAUDE.md`의 ID 표가 한꺼번에 깨집니다. 날짜는 최신성 표시가 아니라
  **출생기록**입니다. 최신성은 문서 안에 적습니다.
- **`common/`을 둔 이유** — 용어·기능명세·API는 어느 한쪽의 것이 아닙니다. 특히 PII 경계는
  클라이언트가 토큰화하고 서버가 그 상태를 유지하는 규칙이라 **한쪽만 지키면 규칙이 깨집니다**
  (`CLAUDE.md` 불변 규칙 2·3). 어느 한쪽 폴더에 넣으면 반대쪽이 읽지 않게 됩니다.
- **ID 체계는 건드리지 않습니다.** `F-xx`·`S-xx`·`CH-xxx`는 기획서 번호를 따르는 것이라
  파일명과 독립입니다. 파일이 옮겨가도 ID는 그대로입니다.

### 검토한 대안

| 대안 | 사유 |
| --- | --- |
| 연번 `NN-{title}.md` 유지 | 위 재배치 문제가 그대로 남습니다 |
| `YYYY-MM-DD-` 전체 날짜 | 파일명이 길어지고, 대회 기간(단년)에는 연도가 정보를 더하지 않습니다 |
| `common/` 없이 둘로만 | PII 경계·기능명세를 한쪽에 밀어넣으면 반대쪽이 안 읽습니다 |

## 결과

- **얻는 것** — 새 spec 문서를 기존 파일을 건드리지 않고 추가할 수 있습니다. 백엔드·프론트가
  자기 폴더만 봐도 되고, 양쪽이 같이 지켜야 하는 것은 `common/` 하나로 모입니다.
- **잃는 것** — 파일명 정렬이 **읽는 순서를 알려주지 않습니다.** 읽는 순서는
  [spec/README.md](../spec/README.md)의 목차가 담당합니다. 목차 갱신을 빠뜨리면 새 문서는 사실상 안 보입니다.
- **연도가 없습니다.** 다른 해 같은 날짜에 같은 제목을 만들면 충돌합니다 —
  그때는 제목을 더 구체적으로 씁니다(`08-14-api.md` → `08-14-api-case.md`).
- 옮기면서 본문 H1의 옛 번호(`# 10 · 기능명세`)를 걷어냈고, 문서 간 상호 링크와
  `CLAUDE.md`·`AGENDA.md`·`src/README.md`의 경로를 새 위치로 갱신했습니다.
- **재검토 트리거** — spec 문서가 20개를 넘어 폴더 안에서 찾기 어려워지면, 폴더를 더 쪼갤지
  다시 봅니다. 날짜 접두는 그때도 유지하는 편이 링크가 안전합니다.
