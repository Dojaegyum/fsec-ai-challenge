# ADR-034. 브라우저 화면에는 원문을 보여준다 — 토큰은 경계 밖으로 나갈 때만

- 상태: **채택**
- 날짜: 2026-08-19
- 결정: @Dojaegyum
- 관련 문서: [ADR-013](013-chat-context.md) **결정 B를 대체합니다** ·
  [PII 격리 경계](../spec/common/08-14-pii-boundary.md) 「복원 범위」 (이 결정으로 개정됨) ·
  [ADR-009](009-restore-mapping-location.md)·[ADR-027](027-session-key-storage.md) (키의 자리 — **안 바뀝니다**) ·
  [CLAUDE.md](../CLAUDE.md) 불변 규칙 2·3 (**안 바뀝니다**)

## 맥락

**경계해야 할 것은 하나입니다 — 외부 LLM API(Claude·GPT·Grok 등)에 PII가 나가는 것.**
그 경계는 [불변 규칙 2](../CLAUDE.md)와 `pii-tokenizer`가 이미 지키고 있고,
**이 결정은 그 경계를 조금도 건드리지 않습니다.**

문제는 **경계 안쪽**이었습니다. [ADR-013](013-chat-context.md) 결정 B가 챗 답변의 토큰을
**종류별 부분 복원**으로 정해 두었습니다.

| 종류 | 화면에 뜨던 것 |
| --- | --- |
| 계좌 | `국민 ****7890` |
| 이름 | `김O수` |
| 전화 | `010-****-5678` |
| 주민번호 | `[주민번호-1]` — 복원 안 함 |

**같은 문서 안에서 이미 갈라져 있었습니다.** [PII 격리 경계](../spec/common/08-14-pii-boundary.md)의
「복원 범위」 표를 보면 **슬롯 확인 화면 · 서류 초안 · 사용자가 직접 입력한 값 ·
전사 뷰**는 전부 **전체 복원**이고, **챗 답변만** 부분 복원이었습니다.

**그래서 사용자가 보는 화면이 자리마다 다릅니다.** 증거함에서는 자기 계좌번호를 온전히 보다가,
챗으로 오면 같은 번호가 `국민 ****7890`이 됩니다. **자기가 준 정보를 자기가 못 보는 것**이고,
가려진 이유가 「우리가 못 믿어서」로 읽힐 수 있습니다.

## 결정

**브라우저 화면에는 원문을 보여줍니다. 토큰은 경계를 넘어갈 때의 형태이지, 사용자가 볼 형태가 아닙니다.**

| | 이전 | 지금 |
| --- | --- | --- |
| **외부 LLM API로 나가는 것** | 토큰만 | **토큰만.** 그대로입니다 |
| **복호화가 일어나는 곳** | 브라우저 | **브라우저.** 그대로입니다 |
| **키의 자리** | 브라우저에만 (`extractable: false`) | **그대로입니다** |
| 챗 답변 문장 | 종류별 **부분** 복원 | **전체 복원** |
| `F-04` 분석 결과 · `F-05` 플랜 설명 | 복원 안 함 | **전체 복원** |
| 슬롯·서류·전사·직접 입력 | 전체 복원 | **그대로** |

**「복원 범위」 표가 한 줄로 줄어듭니다** — *브라우저가 보여주는 것은 전부 원문.*
자리마다 다르던 규칙이 사라집니다.

**주민번호는 예외가 아닙니다.** 애초에 [ADR-026](026-raw-upload-retention.md)이
**주민등록번호를 수집하지 않기로** 했으므로, 복원할 주민번호가 우리에게 없습니다.
있다면 그건 다른 문제(수집이 새고 있다는 뜻)이고, 표시 규칙으로 덮을 일이 아닙니다.

### 바뀌지 않는 것 — 이게 결정의 절반입니다

1. **`pii-tokenizer`는 그대로 돕니다.** 나가는 텍스트는 여전히 토큰뿐입니다
2. **`chat-publisher`의 잔여 PII 검사(`EGRESS_BLOCKED`)도 그대로**입니다
3. **서버는 여전히 원문을 보지 못합니다.** 매핑은 암호문으로 볼트에 있고 키는 브라우저에만
4. **`pii-restorer`는 없어지지 않습니다.** 하는 일이 「부분이냐 전체냐 심사」에서
   **「이 자리가 브라우저인가」 확인**으로 단순해집니다

## 근거

**가리는 것의 목적은 사용자에게서 숨기는 게 아니라 외부로 새지 않게 하는 것입니다.**
그런데 부분 복원은 **사용자에게서 숨기는 쪽**으로만 작동했습니다.
외부로 나가는 것은 어차피 토큰이라 화면 표시와 무관합니다.

**한 화면 안에서 규칙이 갈리면 사용자는 규칙을 못 배웁니다.** 증거함에서 온전히 보이던 값이
챗에서 별표가 되면, 그건 「보안」이 아니라 **버그처럼 읽힙니다.**

**「모름은 실패가 아니다」와 같은 방향입니다.** 자기가 말한 내용을 자기가 확인하지 못하면
진술이 맞는지 검토할 수 없고, 틀린 계좌번호로 서류가 나가도 알아차릴 방법이 없습니다.
**오독이 곧 권리 상실인 서비스**에서 이건 실제 손해입니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| 부분 복원 유지 (기존) | 자리마다 규칙이 달라 사용자가 못 배웁니다. 가리는 이유도 설명되지 않습니다 |
| 전부 토큰으로 통일 (더 가리기) | **자기 정보를 자기가 못 봅니다.** 서류가 틀려도 검토가 불가능합니다 |
| 기본은 가리고 **눌러서 펼치기** | 어깨너머 위험은 줄지만, 매번 누르게 만드는 것은 고령 사용자에게 관문입니다. **다만 아래 「재검토」 참고** |

## 결과

**쉬워지는 것** — 「복원 범위」 규칙이 한 줄이 됩니다. `pii-restorer`가 종류별 분기를 들지 않고,
화면마다 「여기는 어디까지」를 묻지 않아도 됩니다.

**잃는 것 — 파란 토큰이 신뢰 장치였습니다.** S-06·S-08 시안이 「**파란 토큰 = 서버로 안 갔다는 뜻**」을
카피로 여러 곳에서 말하고 있고, 「AI가 뭘 하는지 투명한 것」을 심사 차별점으로 삼고 있었습니다.
**그 장치를 다른 방식으로 대신해야 합니다** — 예컨대 전사 화면에서 **가려지는 순간을 보여주고
(업로드 직후) 그 뒤에는 원문으로 두는** 식으로. 시안 갱신 때 정합니다.

**새로 생기는 위험 — 어깨너머로 보입니다.** 피해자가 은행 창구나 지구대에서 화면을 열면
계좌번호가 그대로 보입니다. 전에는 부분 마스킹이 이걸 우연히 막고 있었습니다.
**의도한 방어가 아니었지만 효과는 있었습니다.**

**기기를 바꾸면 원문을 못 봅니다.** [ADR-027](027-session-key-storage.md)이 감수한 제약인데,
전에는 **서류 작성만** 영향을 받았고 이제는 **화면 대부분**이 그렇습니다.
링크만 있고 매핑이 없는 브라우저에서는 토큰이 그대로 보이게 되므로,
**그 상태를 「고장」이 아니라 「이 기기에는 열쇠가 없다」로 설명해야** 합니다.

**재검토 트리거** — 어깨너머 노출이 실제 문제로 드러나면, 부분 복원으로 되돌리는 게 아니라
**화면 단위 가리기**(예: 「가리기」 토글 하나로 그 화면 전체)를 봅니다.
자리마다 규칙이 다른 상태로는 돌아가지 않습니다.
