# 0002. 프로젝트 이름을 FinAlly로 한다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @Dojaegyum · @kth9245
- 관련: [ADR-001](001-topic-selection.md) (출전 주제)

## 결정

서비스 이름은 **FinAlly**, 슬러그는 **`fin-ally`** 입니다.

**Fin**(금융) + **Ally**(동행자·우군)의 합성이면서, 읽으면 **Finally**(마침내)가 겹쳐 들립니다.
피해자가 여기저기 헤매다 마침내 만나는 곳이라는 뜻이 이름 안에 들어갑니다.

이전 명칭 **골든30**은 폐기합니다.

## 왜 바꿨나

골든30은 "피해 직후 30분"을 이름에 박은 것인데, [ADR-001](001-topic-selection.md)에서 확정된 서비스 성격과 어긋납니다.

이 서비스는 112·1332 상담이 끝난 뒤 링크로 들어와 **며칠에서 몇 달에 걸친 절차를 대신 관리**합니다. 최종 보드의 표현대로 "전화로 안내를 받아도 **진짜 함정은 그 뒤 몇 주에 있다**"가 출발점입니다. 이름이 30분을 가리키면 서비스를 실제보다 좁게 만듭니다.

동시에 **긴급 진입은 유지**합니다 — 진입점에서 사용자의 진술을 받아 가장 적절한 매뉴얼을 고르는 것이 핵심 동작이고, 거기서 사건 관리로 넘어갑니다. `Ally`(동행자)는 이 두 축을 다 담습니다.

## 표기 규칙

| 쓰임 | 표기 |
| --- | --- |
| 브랜드·문서·발표 | **FinAlly** |
| 슬러그·패키지·폴더·저장소 | `fin-ally` |
| 코드 식별자 | `finAlly` (카멜) / `FinAlly` (파스칼) |
| 한국어 병기가 필요할 때 | FinAlly (핀얼라이) |

**`finally`를 식별자나 패키지명으로 쓰지 마세요** — JavaScript·TypeScript 예약어라 `import`·변수명에서 충돌합니다. 하이픈을 넣은 `fin-ally`가 예약어를 피하면서 어원(Fin + Ally)도 드러냅니다.

## 결과

- 이름에 "보이스피싱"이나 "사기"가 들어가지 않습니다. **의도한 것입니다** — 피해자가 링크를 열었을 때 화면에 그 단어가 크게 떠 있으면 수치심을 건드리고, 고령 사용자일수록 그렇습니다. 무엇에 관한 서비스인지는 이미 알고 들어옵니다.
- 나중에 다른 금융 사고 대응으로 넓혀도 이름을 바꿀 필요가 없습니다.
- `docs/plans/`의 기획서 v1.2는 골든30 이름으로 작성된 문서입니다. 포지셔닝 전환과 함께 개정될 때 이름도 반영합니다 — **그 전까지 파일명과 본문의 "골든30"은 이 결정 이전의 기록**으로 읽으세요.
