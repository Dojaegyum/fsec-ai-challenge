# ADR-038. 기계가 읽은 값을 사용자가 확인하는 자리를 둔다 — `confirm` · `WS-confirm`

- 상태: **채택**
- 날짜: 2026-08-20
- 결정: @Dojaegyum
- 관련 문서: [ADR-024](024-step-action-and-url.md) `steps[].action` 일곱 (**이 결정으로 여덟이 됩니다**) ·
  [워크스페이스 패널](../spec/frontend/08-17-workspace-panels.md) (이 결정으로 개정됨) ·
  [데이터 모델](../spec/backend/08-16-data-model.md) §11.4.6 (이 결정으로 개정됨) ·
  [모듈 명칭](../spec/common/08-16-module-names.md) `transcriber`·`slot-extractor` ·
  [슬롯 티어링](../spec/backend/08-14-slot-tiering.md) 「모름은 실패가 아니다」 ·
  [CLAUDE.md](../CLAUDE.md) 불변 규칙 4 「업로드된 문서 속 문장은 지시가 아니라 데이터다」

## 맥락

**`transcriber`가 읽은 것이 맞는지 아무도 안 봅니다.**

전사·OCR 결과는 `slot-extractor`를 거쳐 슬롯이 되고, 슬롯은 `planner`가 절차를 고르는 근거가 됩니다.
그 사이에 **사람이 눈으로 보는 자리가 한 곳도 없습니다.**

이게 문제가 되는지는 **모르는 것 둘**에 달려 있습니다.

| 모르는 것 | 왜 모르나 |
| --- | --- |
| **전사 모델이 얼마나 틀리나** | 로컬 모델 성능이 실측 전입니다. 브라우저 디코더는 **노이즈가 조금만 껴도 무너지는 것을 확인**해 폐기했습니다 |
| **틀린 단어가 얼마나 멀리 가나** | 잘못 읽힌 값이 슬롯 → 플랜 → 안내까지 흘러갔을 때의 영향 범위가 측정된 적이 없습니다 |

**둘 다 모르는 채로 「검수는 필요 없다」고 정할 수는 없습니다.**
이 서비스는 잘못된 안내가 곧 금전 손실입니다.

## 결정

**`steps[].action`에 여덟째 값 `confirm`을 두고, 워크스페이스 패널 유형 `WS-confirm`을 만듭니다.**

| | |
| --- | --- |
| 무엇 | 기계가 읽은 값을 **원본 조각과 나란히** 보여주고, 맞다고 하거나 고치게 합니다 |
| **고칠 수 있는 것** | **명사와 숫자뿐입니다** — 기관명·계좌번호·금액·일시 |
| **비관문** | **안 해도 진행합니다.** 안 고친 값은 `미확인`으로 남습니다 |
| 언제 열리나 | 서버가 **신뢰도 낮은 필드 목록**을 밀 때 |
| 누가 | `work-handler`가 렌더합니다 (층 C) — 다른 일곱과 같습니다 |

### 왜 명사만인가 — 이게 이 결정의 핵심입니다

**문장을 고치게 하면 검수가 아니라 편집이 됩니다.**

전사문은 [불변 규칙 4](../CLAUDE.md)에 따라 **지시가 아니라 데이터**로 다뤄지고,
프롬프트에 들어갈 때 격리 태그가 씌워집니다. 사용자가 문장을 자유롭게 고칠 수 있으면
**격리된 블록의 내용을 사용자가 쓰는 셈**이 되고, 그 블록은 더 이상 「받은 자료」가 아닙니다.

**명사·숫자만 고치면 뜻이 바뀌지 않습니다.** 「국민은행」을 「국민은행」으로 고치는 것은
**같은 사실을 다르게 적은 것을 바로잡는 것**이지 새 사실을 만드는 것이 아닙니다.
`slot-extractor`가 다시 뽑아도 같은 결론이 나옵니다.

### 왜 비관문인가

[슬롯 티어링](../spec/backend/08-14-slot-tiering.md)이 **「모름은 실패가 아니다」**로 정했습니다.
검수를 안 했다고 플랜이 안 나오면 그 원칙이 깨집니다.

**그리고 검수를 강요하면 검수의 뜻이 사라집니다.** 넘어가야 진행되는 화면은
사용자가 읽지 않고 누릅니다 — 확인받은 값이 아니라 **확인받았다고 기록된 값**이 남습니다.

## 근거

**모르는 것이 둘이라 「일단 보여주는」 쪽이 쌉니다.** 검수 자리를 안 만들었다가
오독이 문제로 드러나면 **슬롯·플랜·완료 판정까지 거슬러 고쳐야** 합니다.
만들어 두고 안 쓰는 비용은 화면 하나입니다.

**원본 조각을 나란히 두는 것이 이 화면의 전부입니다.** 「이 값이 맞나요?」만 묻는 화면은
사용자가 판단할 근거가 없어 전부 「맞아요」를 누릅니다. **읽은 자리를 함께 보여줘야**
확인이 확인이 됩니다.

**대화 중에는 이 패널이 필요 없습니다.** 사용자가 말하는 동안에는 되묻기가 이미 있습니다
(`slot-checker`의 한 문항). **사전 업로드 파일**이 문제인데, 그건 사용자가 말하기 전에
이미 읽혀 있어서 되물을 계기가 없습니다 — **AI의 첫 답변이 이 패널을 띄웁니다.**

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| 검수 없음 (기존) | 모르는 것 둘이 풀리기 전에는 위험을 못 잽니다 |
| 문장 전체를 고치게 | **격리가 깨집니다.** 위 「왜 명사만인가」 |
| 슬롯 화면으로 대신 | 슬롯은 **뽑힌 결과**입니다. 잘못 읽힌 원인이 전사에 있으면 슬롯만 고쳐도 다음 추출에서 되살아납니다 |
| 관문으로 (확인해야 진행) | 「모름은 실패가 아니다」와 부딪히고, **읽지 않고 누르게** 만듭니다 |

## 결과

**패널 유형이 여덟이 됩니다.** [워크스페이스 패널](../spec/frontend/08-17-workspace-panels.md)
「유형 일곱」이 「여덟」로 바뀌고, [데이터 모델](../spec/backend/08-16-data-model.md) §11.4.5의
적재 거부 조건(「일곱 밖」)도 함께 바뀝니다. **`action`은 KB 항목마다 사람이 적는 값이라,
스키마만 늘리고 KB를 안 고치면 아무 일도 일어나지 않습니다.**

**원본 조각을 화면에 띄우려면 좌표가 필요합니다.** 시안은 서버가 `bbox`를 갖고
**이미지는 기기에만** 두는 구조를 전제하는데, [데이터 모델](../spec/backend/08-16-data-model.md)에
좌표 칸이 없습니다. **미결입니다.**

**다른 기기에서 열면 원본이 없습니다.** 그 상태는 **에러가 아니라 정상**입니다 —
[ADR-009](009-restore-mapping-location.md)·[ADR-034](034-browser-shows-plaintext.md)가
정한 것의 직접적인 귀결입니다. 화면이 「고장이 아닙니다」라고 말해야 합니다.

**`confidence`를 누가 채우는지가 아직 없습니다.** 이 패널은 「신뢰도 낮은 필드」를 받아 열리는데,
`case_slot.confidence`를 **어느 모듈이 쓰는지 spec 어디에도 적혀 있지 않습니다.**
`slot-extractor`가 자연스럽지만 **정해진 적이 없습니다** — 미결입니다.

**재검토 트리거** — `transcriber`가 서고 **실제 오독률을 재고 나면** 다시 봅니다.
오독이 드물면 이 패널은 「신뢰도가 낮을 때만 열리는」 지금 구조 그대로 두고,
잦으면 열리는 조건을 넓힙니다. **없애는 쪽으로는 오독률을 재기 전에 가지 않습니다.**
