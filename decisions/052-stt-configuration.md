## 맥락

[ADR-043](043-gpu-hosting.md) 이 GPU 를 쓰기로 하면서 전제로 삼은 숫자는
**「전사 = 음성 길이의 2.9배」**(CPU · `medium`) 였습니다. 실제로 GPU 를 빌려 재 보니
**0.019배**입니다 — 150배 차이입니다.

속도가 이만큼 남으면 **모델을 무엇으로 할지가 다시 열립니다.** `medium` 은 CPU 에서
현실적인 최대치라 고른 것이지 정확도로 고른 것이 아니었습니다.

그런데 모델을 올리면 **정확도가 한 방향으로만 좋아지지 않습니다.** 잃는 값은
줄어드는 대신, **날짜로 둔갑한 계좌번호**가 늘어납니다.

## 결정

### ① 모델은 `large-v3`

| | 벽시계 | PII 보존 | keep 손상 |
| --- | ---: | ---: | ---: |
| `medium` (지금) | 33.3초 | 22/33 | 21/80 |
| `large-v3-turbo` | 16.6초 | 26/33 | 15/80 |
| **`large-v3`** | **32.2초** | **28/33** | **11/80** |

**`medium` 과 같은 시간에 절반 이하로 잃습니다.** GPU 에서 `medium` 을 유지할 이유가
없습니다.

### ② `large-v3-turbo` 는 탈락 — 이유를 남깁니다

**나중에 다시 제안될 것이라 여기 적습니다.** 벤치마크 표에서 `turbo` 는 매력적입니다 —
두 배 빠르고 배치 없이 재면 `medium` 보다도 좋습니다.

**그런데 배치를 켜면 무너집니다.**

| `large-v3-turbo` · 긴 녹음 | PII 손상 | 전사문 글자 수 |
| --- | ---: | ---: |
| 배치 없음 | 9/33 | 2,274 |
| 배치 16 | **12/33** | **1,973** |

글자가 13% 줄었고 **줄어든 몫이 계좌번호였습니다.** 같은 조건에서 `large-v3` 는
글자가 줄어도(2,412 → 2,230) `keep` 손상이 29 → 13 으로 **좋아졌습니다** — 그쪽은
줄어든 것이 환각이었습니다.

**평균 WER 로 골랐으면 이걸 놓쳤습니다.** 모델 선택은 벤치마크 숫자가 아니라
**우리 채점**(값이 살아남았나)으로 합니다.

### ③ 배치 16 · VAD 켬 · 낱말 시각 켬

긴 녹음에서 **4배**입니다(30.7 → 7.6초). 32 로 올려도 더 안 벌립니다.

**VAD 는 취향이 아니라 전제 조건입니다.** 무엇을 묶을지 정하는 것이 VAD 라,
30초를 넘는 파일에 끄고 배치를 걸면 라이브러리가 거절합니다. 14 §4 의
「VAD 는 속도로는 켤 이유가 없다」는 **CPU 에 한정된 이야기**로 좁혀집니다.

낱말 시각은 배치에서 공짜입니다(7.6 vs 8.0초). 모듈 계약의 `pieces` 가 요구하므로
켭니다.

### ④ `DEFAULT_DIGIT_RULE.gapJoin` 을 5 에서 8 로 넓힌다

**이 항목이 이 ADR 에서 유일하게 경계를 건드립니다.**

모델을 올리면 **「자리표기 변형」이 2 → 4건으로 늘어납니다.** `medium` 이 아예 못
듣던 계좌번호를 `large-v3` 는 듣고 **날짜로 적습니다.**

```
3333-01-2345678  ->  "3333년 1월 23일 45678"
880312-2345678   ->  "88만 312-2345678"
```

**여기서 이 결정의 전제가 한 번 뒤집혔습니다.** 처음에는 「토큰화 앞에 자리표기를
되돌리는 단계를 새로 만들자」로 갔는데, **이미 있는 것을 못 보고 한 판단이었습니다.**

`pii-tokenizer/transcript-digits.ts` 가 이 문제를 **이미 다릅니다.** 그것도 더 나은
방식으로 — 되돌려서 알아보는 게 아니라 **기본값을 가리는 쪽으로 뒤집어**, 안전한
형태로 확인된 것만 통과시킵니다([ADR-011](011-pii-boundary-hardening.md)).
그 파일의 주석은 `"3333년 5월 11일 임한 2334로"` 를 **예로 이미 적어 두고** 있었습니다.

그래서 물음이 바뀝니다 — **「무엇을 새로 만들까」가 아니라 「있는 것이 늘어난 몫까지
버티나」** 입니다. 재 봤습니다.

| 전사 | `gapJoin` 5 (기존) | **`gapJoin` 8** | 과차단 |
| --- | ---: | ---: | ---: |
| medium · CPU | 2건 | 1건 | 0건 |
| medium · GPU | 2건 | **0건** | 0건 |
| large-v3-turbo | 1건 | **0건** | 0건 |
| large-v3 | 1건 | **0건** | 0건 |

**버팁니다 — 한 곳만 빼고.** 그 한 곳이 이것입니다.

```
7777-01-9988776  ->  "7777년 1월 마이너스 9988776"
                             └── "월 마이너스 " = 7자
```

`withdrawSafe` 는 「단위가 붙었어도 바로 뒤에 정체불명 숫자가 이어지면 안전을
거두는」 장치인데, **보는 거리가 5자였습니다.** 전사가 하이픈을 `마이너스` 로 읽으면
그 거리를 못 건넙니다. 안전이 안 거둬지니 `9988776` 이 홀로 남고, 7자리는
`minDigits` 9 미만이라 안 가려집니다 — **계좌번호 뒷자리 7개가 그대로 나갔습니다.**

**8 로 넓히면 잡히고 과차단은 그대로 0 입니다.** 10·12 도 결과가 같아 8 이 하한입니다.

`medium · CPU` 에 남는 1건은 성격이 다릅니다 — `5501234567` 이 `"501-34567"` 로
읽혀 **8자리만 남은** 것이라 `minDigits` 아래로 떨어집니다. 값이 새로 샌 게 아니라
전사가 깨진 것이고, `large-v3` 에서는 사라집니다. **전사 품질을 올리는 것이 이
규칙의 누출도 줄입니다** — [09 §5.4](../docs/research/09-로컬모델-PII인식-실측.md) 가
「전사 개선은 누출 대책이 아니다」라고 한 것에, **숫자 규칙 쪽에서는 조금 다르다**는
단서가 붙습니다.

회귀는 `transcript-digits.leak.test.ts` 가 지킵니다 — 손으로 고른 문장이 아니라
**저장된 전사문 40발화를 통째로** 넣고, 가리고 남은 글에 정체불명 숫자가 있는지
봅니다.

> ⚠️ **판정 기준을 조심하세요.** 「가려진 숫자가 원래 값과 같은가」로 세면 안 됩니다 —
> 자리표기가 깨졌으니 애초에 다릅니다. 그렇게 세면 **가려진 것을 누출로 오인합니다**
> (실제로 처음에 그렇게 셌습니다). **남은 글에 뭐가 보이나**로 세야 합니다.

## 그래서 무엇이 바뀌나

```
FINALLY_DEVICE=cuda  FINALLY_STT=large-v3  FINALLY_COMPUTE=float16  FINALLY_VAD=1
```

env 로 되는 것은 여기까지입니다. **코드는 둘입니다.**

| | 어디 | 상태 |
| --- | --- | --- |
| `gapJoin` 5 → 8 | `src/modules/pii-tokenizer/transcript-digits.ts` | **이 PR 에서 했습니다.** 기존 테스트 1,138개 그대로 통과 |
| 배치 배선 | `services/transcriber/engines/faster_whisper_stt.py` | **안 했습니다.** 지금 `WhisperModel` 을 직접 부릅니다 — `BatchedInferencePipeline` 으로 감싸야 4배가 나옵니다 |

## 탈락시킨 것

| | 왜 |
| --- | --- |
| **토큰화 앞에 「자리표기 되돌리기」 단계 신설** | **이미 있는 것으로 됩니다.** `transcript-digits.ts` 가 가리는 쪽을 기본값으로 두어 같은 문제를 더 안전하게 답니다. 되돌리기는 「알아본 것만 가린다」로 되돌아가는 셈이라 [ADR-011](011-pii-boundary-hardening.md) 과 어긋납니다 |
| `large-v3-turbo` | 위 ② — 배치에서 PII 9 → 12 |
| `beam_size=1` | 14% 를 벌고 개인정보 2건을 더 잃습니다 ([14 §4](../docs/research/14-STT-전처리-실측.md)) |
| 우리가 직접 청크 쪼개기 | 라이브러리가 이미 합니다. 밖에서 또 쪼개면 경계만 늘어납니다 |
| CPU 에서 모델만 올리기 | **안 쟀습니다.** `medium` 이 이미 실시간 1.77배라 더 느려질 뿐입니다 |

## 아직 안 잰 것

- **이름은 이 규칙이 안 잡습니다.** 형태가 없어 규칙으로 못 잡고 `NerModel` 몫입니다.
  이번 측정은 **숫자류만** 본 것이라, `large-v3` 에서 이름 누출이 어떤지는 따로
  재야 합니다([09](../docs/research/09-로컬모델-PII인식-실측.md) 은 `medium` 기준).
- **`gapJoin` 8 이 옳은 값이라는 근거는 없습니다.** 이 평가셋에서 10·12 와 결과가
  같아 하한으로 고른 것입니다. 실제 통화에는 `마이너스` 보다 긴 삽입이 있을 수
  있습니다.
- **합성 음성 기준의 낙관적 하한값입니다.** 표본이 40발화(계좌 8건)라 「0」이
  「앞으로도 0」은 아닙니다.

## 되돌리려면

①\~③ 은 env 와 배선이라 마이그레이션이 필요 없습니다.
④ 는 **경계의 값**이라 되돌리면 그때까지 쌓인 전사문의 위험 상태가 달라집니다 —
되돌리기 전에 그 사이 들어온 사건을 다시 훑어야 합니다.
