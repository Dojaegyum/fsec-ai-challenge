# ADR-052. 전사는 large-v3 로 하고, 자리표기를 되돌린 뒤 토큰화한다

- 상태: **채택**

- 결정: @Dojaegyum

## 맥락

[ADR-043](043-gpu-hosting.md) 이 GPU 를 쓰기로 하면서 전제로 삼은 숫자는
**「전사 = 음성 길이의 2.9배」**(CPU · `medium`) 였습니다. 그 뒤 실제로 GPU 를 빌려
재 보니 **0.019배**입니다 — 150배 차이입니다.

속도가 이만큼 남으면 **모델을 무엇으로 할지가 다시 열립니다.** `medium` 은 CPU 에서
현실적인 최대치라 고른 것이지 정확도로 고른 것이 아니었습니다.

그런데 모델을 올려 보니 **정확도가 한 방향으로만 좋아지지 않았습니다.**

## 결정

### ① 모델은 `large-v3`

| | 벽시계 | PII 보존 | keep 손상 |
| --- | ---: | ---: | ---: |
| `medium` (지금) | 33.3초 | 22/33 | 21/80 |
| `large-v3-turbo` | 16.6초 | 26/33 | 15/80 |
| **`large-v3`** | **32.2초** | **28/33** | **11/80** |

**`medium` 과 같은 시간에 절반 이하로 잃습니다.** GPU 에서 `medium` 을 유지할 이유가
없습니다.

### ② `large-v3-turbo` 는 탈락 — 이유를 남깁니다

**나중에 다시 제안될 것이라 여기 적습니다.** 벤치마크 표에서 `turbo` 는 매력적입니다 —
두 배 빠르고 평균 WER 도 나쁘지 않습니다. 실제로 배치 없이 재면 `medium` 보다도
좋습니다.

**그런데 배치를 켜면 무너집니다.**

| `large-v3-turbo` · 긴 녹음 | PII 손상 | 전사문 글자 수 |
| --- | ---: | ---: |
| 배치 없음 | 9/33 | 2,274 |
| 배치 16 | **12/33** | **1,973** |

글자가 13% 줄었고 **줄어든 몫이 계좌번호였습니다.** 같은 조건에서 `large-v3` 는
글자가 줄어도(2,412 → 2,230) `keep` 손상이 29 → 13 으로 **좋아졌습니다** — 그쪽은
줄어든 것이 환각이었습니다.

**평균 WER 로 골랐으면 이걸 놓쳤습니다.** 모델 선택은 벤치마크 숫자가 아니라
**우리 채점**(값이 살아남았나)으로 합니다.

### ③ 배치 16 · VAD 켬 · 낱말 시각 켬

긴 녹음에서 **4배**입니다(30.7 → 7.6초). 32 로 올려도 더 안 벌립니다.

**VAD 는 취향이 아니라 전제 조건입니다.** 무엇을 묶을지 정하는 것이 VAD 라,
30초를 넘는 파일에 끄고 배치를 걸면 라이브러리가 거절합니다. 14 §4 의
「VAD 는 속도로는 켤 이유가 없다」는 **CPU 에 한정된 이야기**로 좁혀집니다.

낱말 시각은 배치에서 공짜입니다(7.6 vs 8.0초). 모듈 계약의 `pieces` 가 요구하므로
켭니다.

### ④ 토큰화 앞에 자리표기 되돌리기를 둔다 — 이게 이 ADR 의 핵심입니다

**모델을 좋게 하면 위험이 옮겨 갑니다.**

whisper 는 하이픈 낀 숫자를 날짜로 정규화합니다.

```
3333-01-2345678  ->  "3333년 1월 23일 45678"
880312-2345678   ->  "88만 312-2345678"
```

`pii` 33건을 셋으로 갈라 세면 이렇습니다.

| 모델 | 보존 | **자리표기 변형** | 소실 |
| --- | ---: | ---: | ---: |
| `medium` | 22 | **2** | 9 |
| `large-v3` | 28 | **4** | 1 |

**변형이 2 → 4 로 늘었습니다.** `medium` 이 아예 못 듣던 계좌번호를 `large-v3` 는
듣고 날짜로 적습니다. 소실이 변형으로 옮겨 간 것입니다.

**변형은 소실보다 나쁩니다.**

| | 무슨 일이 일어나나 |
| --- | --- |
| 소실 | 확인 화면에 빈칸으로 보입니다. 사용자가 고칩니다 → [ADR-038](038-transcript-confirm.md) |
| **변형** | **그럴듯한 텍스트로 남아 아무도 이상함을 못 느낍니다.** 탐지기가 날짜로 읽고 지나치면 **원문 계좌번호가 경계를 넘습니다** |

[09 §5.4](../docs/research/09-로컬모델-PII인식-실측.md) 가 「전사문에서 정규식이
20/20 에서 6\~10건으로 떨어진다」고 한 것이 바로 이 자리입니다.

**그래서 `pii-tokenizer` 로 들어가기 전에 자리표기를 되돌립니다.** 변형 4건이 전부
회수되어 28 → **32/33 (97.0%)** 이 됩니다. 참조 구현은
[notation.py](../assets/datasets/08-25-stt-gpu/notation.py) 입니다.

⚠️ **되돌리기는 전체에 적용하고 처음부터 다시 세야 합니다.** 「잃은 것만 다시
보기」로 하면 안 됩니다 — 첫 판에서 `"56만 7,890"` 의 **자리쉼표** 때문에 멀쩡하던
`110-234-567890` 이 깨졌습니다. 쉼표를 먼저 떼도록 고쳐 지금은 0건입니다.

## 그래서 무엇이 바뀌나

```
FINALLY_DEVICE=cuda  FINALLY_STT=large-v3  FINALLY_COMPUTE=float16  FINALLY_VAD=1
```

env 로 되는 것은 여기까지입니다. **코드가 필요한 것이 둘 남습니다.**

| | 어디 | 왜 |
| --- | --- | --- |
| 배치 배선 | `services/transcriber/engines/faster_whisper_stt.py` | 지금 `WhisperModel` 을 직접 부릅니다. `BatchedInferencePipeline` 으로 감싸야 4배가 나옵니다 |
| 자리표기 되돌리기 | `pii-tokenizer` 앞 | **모듈이 아직 없습니다.** 참조 구현만 데이터셋에 있습니다 |

## 탈락시킨 것

| | 왜 |
| --- | --- |
| `large-v3-turbo` | 위 ② — 배치에서 PII 9 → 12 |
| `beam_size=1` | 14% 를 벌고 개인정보 2건을 더 잃습니다 ([14 §4](../docs/research/14-STT-전처리-실측.md)) |
| 우리가 직접 청크 쪼개기 | 라이브러리가 이미 합니다. 밖에서 또 쪼개면 경계만 늘어납니다 |
| CPU 에서 모델만 올리기 | **안 쟀습니다.** `medium` 이 이미 실시간 1.77배라 더 느려질 뿐이고, GPU 없이 정확도만 사는 길이 아닙니다 |

## 이 결정이 기대는 미검증 전제

**⚠️ 탐지기가 「자리표기 변형」을 실제로 놓치는지는 안 쟀습니다.** 형태가 날짜와
같으니 놓칠 수 있다고 본 것입니다.

[09](../docs/research/09-로컬모델-PII인식-실측.md) 의 하네스와 평가셋이 그대로
있으므로 **변형 4건을 `gemma3:4b` 와 정규식에 넣어 보면 바로 확인됩니다.**
놓치지 않는 것으로 나오면 ④ 는 정확도 개선일 뿐이고, 놓치는 것으로 나오면
**경계의 일부**입니다 — 그때 이 ADR 을 잇는 새 ADR 로 격을 올립니다.

## 되돌리려면

①\~③ 은 env 와 배선이라 되돌리는 데 마이그레이션이 필요 없습니다.
④ 는 토큰화 앞단이라, 빼면 **이미 저장된 전사문의 위험 상태가 달라집니다** —
빼기 전에 그때까지 쌓인 사건을 다시 훑어야 합니다.
