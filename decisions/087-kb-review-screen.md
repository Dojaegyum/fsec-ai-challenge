# ADR-087. KB 검수 큐 화면을 만든다 — 관리자 계정 하나와 문지기를 살리고, 사건 조회 화면은 계속 두지 않는다

- 날짜: 2026-09-06

## 맥락

법령 수집이 어제([ADR-072](072-law-collection-wired.md)) 돌기 시작했고, 첫 회차에 조문 58개(법 31 · 시행령 27)가
「최초 수집」으로 `source_change` 큐에 올랐습니다. 그것을 보고 판단하는 자리는 명령줄 `npm run kb:review`
하나입니다. 팀에서 *"긁어와서 업데이트하는 페이지가 없다"* 는 말이 나왔고, 「KB 를 바꿀 수 있는 UI」가
제안됐습니다.

두 가지를 갈랐습니다.

- **검수 큐를 보고 판단하는 화면**은 원칙에 걸리지 않습니다. `kb-reviewer` 위에 화면을 얹는 것이고,
  데이터 모델 §12.2·[ADR-044](044-review-deferral.md)·`kb-reviewer` README 가 「검수 화면이 그때 조회한다」며
  자리를 비워 두었습니다.
- **KB 본문을 화면에서 고치는 것**은 [RFC-002](../rfc/002-kb-authoring.md)(원본은 파일, DB 는 사본)와
  [ADR-045](045-kb-release-pin.md)(나간 버전은 덮지 않는다)에 정면으로 부딪힙니다. 화면에서 `kb_entry` 를
  고치는 순간 원본이 둘이 되고 릴리스 고정이 깨집니다.

그런데 [ADR-068](068-no-admin-screen.md) 이 이틀 전에 **관리자 화면을 만들지 않기로** 정했습니다. 근거는
「대회 안에 그 화면을 열 사람이 없다」였고, 그 화면은 **사건 조회**(어느 턴의 프롬프트·판단 근거)였습니다.
검수 큐는 다릅니다 — 열 사람이 팀이고, 지금 58건이 기다리고 있으며, 조문이 바뀔 때마다 계속 쌓입니다.

그리고 웹 페이지 변경 감지 스파이크(2026-09-06)가 기관 페이지도 같은 큐로 들어올 수 있음을 보였습니다
(텍스트 정규화 해시 6/6 안정 · 은행연합회 한 페이지에서 은행 19곳 추출). 큐에 오는 것이 법령만이 아니게 되면
명령줄 하나로는 버겁습니다.

## 결정

### ① 화면 하나 — `S-12` KB 검수 큐, `/admin/kb`

컨셉 방향 셋(받은편지함 · 두루마리 · 매뉴얼 기준) 가운데 **받은편지함(목록 + 상세)에 매뉴얼 기준 렌즈를
얹은 것**을 골랐습니다. 왼쪽 목록은 「조문 기준」과 「매뉴얼 기준」 둘 중 하나로 보고, 조문 상세의
「닿는 매뉴얼」 행을 누르면 그 항목 기준으로 문맥이 넘어갑니다. 판단(승인 · 거절 · 미룸)은 조문 단위입니다.

**피해자 화면 어디서도 링크하지 않습니다.** 관리자 헤더에만 「고객 화면 열기」를 둡니다. 피해자 화면에
Customer · Admin 탭을 두는 안은 탈락시켰습니다(아래 「검토한 대안」).

### ② 문 — 비밀번호 하나, 값은 환경변수, 형식은 scrypt

§5.1 이 정해 둔 계정 하나 · 세션 쿠키 8시간 · `__Host-fin_ally_admin` 을 그대로 씁니다. 잠들어 있던
`session-cookie.ts` 의 발급·검증 코드가 그대로 살아납니다. ADR-068 이 「정본에 없어 못 만들었다」고 적은
**해시 형식**을 여기서 정합니다.

| 무엇 | 값 |
| --- | --- |
| `ADMIN_PASSWORD_HASH` | `scrypt$N$r$p$<salt base64>$<hash base64>` — `node:crypto` 의 `scryptSync`, 새 의존성 없음 |
| 만드는 법 | `npm run admin:hash -- <비밀번호>` (`src/scripts/admin-hash.ts`) — 출력을 Vercel 환경변수에 넣습니다 |
| 로그인 경로 | `POST /api/admin-login` — 문지기 **밖**입니다. `/api/admin/` 접두사에 안 걸리는 이름을 일부러 골랐습니다 |
| 로그아웃 | `POST /api/admin/logout` — 문지기 안. 세션이 있어야 부를 수 있으니 그대로 맞습니다 |
| 값 | **무작위 문자열.** 저장소가 공개이고 배포 주소도 공개라 `admin` 같은 고정값은 문을 여는 것과 같습니다 |

`ADMIN_USERNAME` 은 되살리지 않습니다 — 계정이 하나라 이름을 대조할 일이 없습니다(2026-09-06 에 이미 뺐습니다).

### ③ API — `/api/admin/kb/*` 다섯, 전부 문지기 뒤

[API 계약 §7](../spec/common/08-14-api.md) 에 적었습니다. 큐 · 변경 상세 · 판단 · 매뉴얼 목록 · 판단 이력.
라우트는 얇게 `handleRoute` 를 지나고, 판단은 있는 `kb-reviewer` 가 합니다([ADR-028](028-runtime-and-module-shape.md)).
`kb_entry` 를 통째로 읽는 조회가 없어 `KbStore` 에 `listEntries(kbVersion)` 하나를 더합니다.

### ④ 조문 ↔ 매뉴얼 연결은 규칙으로, 「추정」이라고 씁니다

`kb_entry.legal_basis` 는 글입니다(*"통신사기피해환급법 제3조제1항 · 제4조제1항제1호 …"*). `source_key`
(`law:011359:3` = 법 제3조 · `law:011359:2:2` = 제2조의2, 데이터 모델 §12.1)의 법령 번호와 조 번호를 그 글에서 뽑은 「법 제N조」「시행령 제N조」와 대조하는 순수 함수
`kb-reviewer/link.ts` 를 둡니다. F-11 이 계획한 LLM 영향 분석의 자리이지만 **모델을 쓰지 않습니다** —
규칙이면 시험이 되고, 틀리면 사람이 봅니다. 화면에는 「닿는 매뉴얼(추정)」으로 표시하고, 못 잇는 조문은
「닿는 항목 없음 · 새 조문」으로 따로 보입니다.

### ⑤ ADR-068 에서 무엇이 대체되나

| ADR-068 | 이 결정 |
| --- | --- |
| 「관리자 조회 화면을 만들지 않는다」 | **검수 큐 화면 하나를 만든다.** 사건 조회 화면(§5 의 엔드포인트 둘 · `admin.message_viewed`)은 **계속 만들지 않는다** |
| `ADMIN_PASSWORD_HASH` 는 「더 이상 필요한 값이 아니다」 | **다시 필요한 값이다** — 형식을 정하고 만드는 명령을 둔다 |
| 문지기 유지 · `session-cookie.ts` 는 잠든 코드 | 문지기 **그대로** · 잠든 코드를 **깨운다** (로그인 경로가 붙는다) |
| 기록(`reasoning_masked` · 감사 로그)은 DB 를 직접 본다 | **그대로** — 이 화면은 사건 데이터를 보지 않는다 |

## 근거

**검수의 산출물은 판단 기록이고, 그 기록이 원칙 4 의 증거입니다.** 명령줄은 기록을 남기지만 큐가 얼마나
쌓였는지 아무도 보지 않으면 썩습니다. 화면은 신뢰도를 더하는 것이 아니라 **검수가 실제로 일어나게** 합니다.

**KB 편집 화면이 아니라 검수 화면입니다.** 반영은 지금처럼 파일을 고쳐 릴리스합니다. 승인 단추 문구는
「승인」이고, 그 아래 「승인해도 매뉴얼에 자동 반영되지 않습니다」가 받칩니다 — 「승인 완료 및 반영」처럼
읽히는 문구는 파이프라인과 다른 말을 하는 것이라 쓰지 않습니다.

**문지기 뒤에 두면 인증을 빠뜨릴 수 없습니다.** §5.1 이 「경로 접두사로 일괄 처리하고 엔드포인트마다
개별로 확인하지 않는다」고 정해 둔 것이 그대로 쓰입니다. 로그인 경로만 밖에 두고, 그 하나는 상한을 빡빡하게 겁니다.

**피해자 화면은 손대지 않습니다.** 충격 상태의 사용자를 위해 여백을 깎아 온 화면에 관리자 입구는 소음이고,
심사위원 눈에도 「왜 Admin 이 있지」로 읽힙니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| **검수 화면을 계속 만들지 않는다** (ADR-068 유지) | 58건이 큐에 있고 매일 더 쌓입니다. 명령줄만으로는 「무엇이 닿나」를 원문을 뒤져 알아내야 합니다 |
| **KB 항목을 화면에서 편집한다** | RFC-002·ADR-045 위반. 원본이 둘이 되고 릴리스 고정이 깨집니다. 하려면 화면이 JSON 파일에 커밋을 만드는 구조여야 하고 그건 다른 규모입니다 |
| **피해자 화면에 Customer · Admin 탭** | 피해자에게 뜻 없는 소음 · 「모든 페이지」의 색인이 성립하지 않음(`/c/{token}` 은 링크로만) · 관리자 입구를 모든 방문자에게 드러냄 |
| **비밀번호 `admin`** | 공개 저장소 · 공개 배포에서 고정값은 문을 여는 것. 환경변수 값만 다르므로 작업량 차이가 0 입니다 |
| **링크 토큰** (`/admin/kb?key=…`) | 로그인 화면이 없어 가장 빠르지만 링크 자체가 상시 자격증명이라 채팅에 남는 순간 샙니다 |
| **Vercel 배포 보호** | 배포 전체를 잠가 피해자 화면까지 막힙니다 |
| **조문 ↔ 매뉴얼을 LLM 으로 잇는다** | 시험이 안 되고, 틀리면 검수자가 엉뚱한 항목을 봅니다. 규칙으로 뽑고 「추정」이라 씁니다 |
| **두루마리(한 열 카드) · 매뉴얼 기준(항목 단위)** 방향 | 각각 직전/이번 diff 를 못 놓음 · 영향 표시부터 만들어야 함. 매뉴얼 기준의 장점은 렌즈로 흡수했습니다 — 캔버스 둘째 페이지에 남김 |

## 어떻게 지키나

- `proxy.ts`·`request.ts` 의 문지기 시험이 `/api/admin/*` 401 을 그대로 봅니다. 새 라우트는 그 아래에만 둡니다.
- `route-contract` 검사기가 `handleRoute` 통과와 POST 의 상한 갈래를 강제합니다. `change_id` 는 보호 세그먼트 목록에 올려 `ulidParamOf` 로만 읽게 합니다.
- `kb-reviewer/link.test.ts` 가 실제 `src/kb/*.json` 항목으로 연결 규칙을 봅니다 — 제3조는 셋, 제13조의4 는 없음.
- 승인 단추 문구를 시험이 봅니다 — 「반영」이라는 말이 판단 단추에 없어야 합니다.
