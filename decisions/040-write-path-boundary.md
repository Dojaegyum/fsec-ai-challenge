## 맥락

**불변 규칙 2는 「`pii-tokenizer` 를 통과하지 않는 LLM 호출 경로를 만들지 마세요」입니다.**
그런데 **지금 토큰화를 지나는 것은 챗 발화 하나뿐**입니다.

```
챗 발화        →  [ pii-tokenizer ]  →  저장  ✅
슬롯 입력      →  ─────────────────→  저장  ⚠️
부산물 제출    →  ─────────────────→  저장  ⚠️
                                       │
                                       ↓  나중에 prompt-builder 가 사건 상태를 넣을 때
                                  외부 모델로 나감
```

**스키마는 이미 원문을 금지하고 있습니다** — `case_slot.value_masked`(「토큰화된 값. 원문 금지」) ·
`artifact.value_masked`(「토큰화 후 저장」). **그런데 아무도 확인하지 않습니다.**

`PATCH /slots` 와 `POST /artifacts` 는 「클라이언트가 이미 가렸다」를 믿고 값을 그대로 받습니다.
**브라우저 코드는 우리 손을 떠난 코드입니다** — 마스킹 버그 하나, 또는 API 직접 호출이면
검사가 아예 없고, **샜다는 사실조차 남지 않습니다.** 저장은 성공하고 사고는 몇 턴 뒤에 납니다.

## 결정

### ① 값을 받는 모든 경로가 경계를 지납니다

챗만이 경계가 아닙니다. **`PATCH /slots` · `POST /artifacts` 도 같은 검사를 받습니다.**

### ② 잡히면 **거부**합니다. 서버가 대신 토큰화하지 않습니다

**이것이 이 결정의 핵심입니다.**

서버가 원문을 발견했을 때 「토큰화해서 저장」하면 편해 보이지만, 그러려면
**서버가 토큰↔원문 매핑을 만들어야** 합니다. 그 순간 둘이 깨집니다.

| 깨지는 것 | 왜 |
| --- | --- |
| [ADR-009](009-restore-mapping-location.md) | **매핑은 브라우저가 만들어 암호화해 맡깁니다.** 서버가 만들면 서버가 원문을 압니다 |
| **그 값의 쓸모** | 브라우저가 모르는 토큰은 **복원되지 않습니다** → [복원 전 검사 2번](../spec/common/08-14-pii-boundary.md) |

**두 번째가 실질적입니다.** `counterpart_account` 가 서버제 토큰이 되면,
**서류 기재 안내(S-10)에서 그 칸이 영영 빈칸**입니다. 안전해 보이는 처리가
그 슬롯을 통째로 못 쓰게 만듭니다.

> **챗 발화는 다릅니다.** 거기서 2차(NER)가 잡는 것은 문장 안의 낱말 하나이고,
> 복원이 안 되면 토큰 그대로 보일 뿐 문장은 남습니다. **값 하나가 통째로 토큰이 되는
> 쓰기 경로와 같이 다루면 안 됩니다.**

**그래서 `EGRESS_BLOCKED`(422) 로 돌려보냅니다.** 이미 있는 코드이고 문구도 맞습니다 —
「개인정보가 남아 있어 요청을 중단했습니다」.

### ③ 1차 게이트는 **지금 섭니다** — NER 을 안 기다립니다

`pii-tokenizer` 는 NER 모델 미선택으로 비어 있지만, **1차 정규식은 이미 있습니다.**

`pii-masker/patterns.ts` 의 **`findHits(text): Hit[]` 는 순수 함수**입니다 —
`window`·`document`·`crypto` 를 하나도 쓰지 않아 **서버에서 그대로 돕니다.**

```
값이 들어옴 → findHits(value) → 히트가 있으면 422
                              → 없으면 저장
```

**막을 수 있는 것부터 막습니다.** NER 이 붙으면 같은 자리에 2차를 더합니다.

> ⛔ **이 게이트는 「타이핑된 값」용입니다** → [ADR-041](041-pii-confirm-with-user.md).
> **전사문에서는 정규식이 무너집니다** — 실측에서 숫자류가 **20/20 → 6~10건**으로 떨어졌습니다.
> `"공이 9876543"` 을 전화번호로 읽는 것은 정규식이 못 합니다.
> **`transcriber` 뒤쪽에 같은 게이트만 걸고 끝내지 마세요.**

### ④ 패턴은 **한 곳**입니다 — 복사하지 않습니다

**`pii-tokenizer` 가 `pii-masker/patterns` 를 그대로 씁니다.**

[PII 격리 경계](../spec/common/08-14-pii-boundary.md)가 이미 같은 말을 하고 있습니다 —
「패턴 목록의 정본은 `pii-masker/patterns.ts`. **문서에 정규식을 옮겨 적지 않습니다** —
두 곳에 두면 반드시 어긋나고, **어긋난 쪽이 조용히 새는 쪽**이 됩니다.」

**코드도 마찬가지입니다.**

> ⚠️ **층을 넘는 import 입니다.** `pii-masker` 는 층 C 인데 `pii-tokenizer` 는 층 1입니다.
> **`patterns.ts` 만 예외로 둡니다** — 순수한 정규식 표와 순수 함수이고, 브라우저 동작을
> 들여오지 않습니다. `key-handler` 처럼 **키를 다루는 것은 여전히 못 가져옵니다.**

## 근거

**믿는 것과 확인하는 것은 다릅니다.** 클라이언트 1차는 **네트워크를 타기 전에 줄이는 것**이지
보증이 아닙니다. 경계는 서버에 있어야 경계입니다.

**그리고 새면 모릅니다.** 이 종류의 사고는 저장이 성공하고 몇 턴 뒤에 조용히 납니다 —
**422 로 시끄럽게 실패하는 것이 낫습니다.**

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| 지금처럼 클라이언트를 믿기 | **경계가 챗 하나뿐**입니다. 불변 규칙 2 위반 |
| 서버가 발견하면 토큰화해서 저장 | 위 ② — ADR-009 가 깨지고 **그 값이 영영 복원되지 않습니다** |
| NER 이 설 때까지 미루기 | **1차 정규식은 지금 있습니다.** 막을 수 있는 것부터 막습니다 |
| `pii-tokenizer` 가 패턴을 복사 | **어긋나면 새는 쪽이 생깁니다.** 문서에 정규식을 안 적는 이유와 같습니다 |

## 결과

**`pii-tokenizer` 가 처음으로 할 일이 생겼습니다.** NER 없이도 설 수 있고,
[착수 순서](../docs/plans/08-18-backend-baseline.md) ③이 「NER 을 기다리지 않는다」고
한 것과 맞습니다.

**422 를 받은 클라이언트가 무엇을 하는지 정해야 합니다.** 다시 가려 보내는 것은
답이 아닙니다 — **1차가 이미 놓친 값이라 재시도해도 같습니다.**

> ⬜ **TODO(미정)** — 화면 동작. 슬롯 값에 계좌번호가 섞여 들어온 경우라면
> 「이 칸에는 계좌번호를 적지 마세요」가 맞고, 클라이언트 버그라면 사용자가 할 일이
> 없습니다. **둘을 구분할 방법이 없어 문구를 아직 못 정했습니다.**

**토큰화 제외 목록이 게이트를 지나야 합니다.** 금액·기관명·시각은 원문 그대로가 정상이고
([ADR-011](011-pii-boundary-hardening.md)), 1차 패턴은 이들을 잡지 않도록 이미 짜여
있습니다 — 대표번호(`15xx`·`16xx`·`18xx`)를 빼고 화폐 단위가 붙은 수를 거르는 것이 그것입니다.
**게이트를 붙일 때 이 동작을 시험으로 고정해야 합니다.**

**재검토 트리거** — NER 이 붙으면 ③의 「1차만」을 「1·2차」로 올립니다.
그때도 ②(거부이지 토큰화가 아님)는 그대로입니다.
