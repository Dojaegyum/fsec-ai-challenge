# ADR-080. KB 행의 `steps`·`caveat`·`legal_basis`·완료 증거를 적용 절차의 프롬프트 본문에 넣는다 — 참고 절차는 요약만

- 상태: **채택**
- 날짜: 2026-09-06
- 결정: @kth9245 (사용자 결정 — *"이런것들 넣으면 좋을거같음"*)
- 관련 문서: [챗 문맥](../spec/backend/08-16-chat-context.md) §2.5(이 결정으로 신설) · §2.3 ·
  [데이터 모델](../spec/backend/08-16-data-model.md) §11.4 · §11.4.4 · [RFC-002](../rfc/002-kb-authoring.md) 「적재 전 자기점검」 ·
  [ADR-015](015-citation-and-reask.md)(근거가 없으면 되묻는다) · [ADR-022](022-chat-turn-boundaries.md)(변환은 부르는 쪽) ·
  `src/lib/adapters.ts` · `src/lib/adapters.test.ts`

## 맥락

**모델이 보는 KB 본문은 `summary` 한 칸이었습니다.** `kb_entry` 행에는 `steps[]`(무엇을 어떻게 하나)·`caveat`(기대치를
낮추는 말)·`required_artifact`(끝나면 남는 것)·`legal_basis`(조문)가 있지만, 행을 프롬프트용 문자열로 바꾸는
`kbRowToPromptEntry`(`src/lib/adapters.ts`)가 2026-08-20 부터 `summary` 만 옮겼습니다. 그 함수의 주석과 `chat-receiver`
README 에 *"누가 옮기는지 정본에 없다"* 는 미결 표시가 그대로 있었습니다 — 어느 칸이 모델에게 가는지를 계약이 정한 적이 없습니다.

2026-09-06 배포본(시중은행 계좌이체 · 112 신고 전)에서 확인한 것입니다.

| 물음 | 같은 행에 있던 것 | 챗의 답 |
| --- | --- | --- |
| 서류는 뭘 내야 하나요? 수수료도 있어요? | `steps`: 별지 제1호서식 · 신분증 사본 1부 · 수수료 없음 | 「어떤 서류를 내야 하는지와 수수료 여부는 제 안내에 없습니다」 |
| 자율배상 신청하면 보통 얼마나 받고 얼마나 걸려요? | `caveat`: 1년 4개월 41건 · 피해액의 0.1% · 평균 116일 | 「구체 수치가 없습니다」 |
| 이 단계 끝나면 뭘 올려야 완료로 되나요? | `required_artifact`: 사건접수번호 | 112 항목은 `summary` 가 우연히 말해 답함 — 다른 단계는 모름 |

**작업 패널은 같은 칸을 그대로 그립니다**(`work-handler`). 심사위원은 화면에는 적혀 있는데 챗은 모른다고 하는 장면을 봅니다.
그리고 `caveat` 의 숫자는 이 서비스가 불변 규칙 8(「받을 수 있다고 말하지 않는다」)의 근거로 내세우는 바로 그 값인데
챗이 쓸 수 없었습니다. 시스템 지시문 §4 3항 *"자료에 그것이 적혀 있으면 「OO이 오면 올려주세요」"* 는 `required_artifact` 가
프롬프트에 없어 `summary` 가 우연히 말한 단계에서만 작동했습니다.

같은 날 [PR #80](https://github.com/Dojaegyum/fsec-ai-challenge/pull/80) 이 「3영업일이 무슨 뜻이냐」를 KB 문장 쪽에서 고쳤는데,
그것은 KB 행 어디에도 글자로 없던 지식(기한 단위 세는 법)의 문제였고, 이 결정은 **행에는 있는데 모델에게 안 가는** 지식의 문제입니다.

## 결정

### ① 적용 절차는 다섯 줄로 간다

`applied` 묶음의 항목은 본문을 이 순서로 붙입니다. 없는 칸은 줄을 만들지 않습니다.

```
{summary}
할 일: 1) {steps[0].text} 2) {steps[1].text} …
남기는 것: {required_artifact.label}
주의: {caveat}
근거: {legal_basis}
```

`label` 은 그대로 `title` 입니다. 태그 모양(`<entry ref label channel>`)은 바뀌지 않습니다 — 본문만 길어집니다.

### ② 참고 절차는 `summary` 만

`reference` 묶음은 다른 유형의 절차라 조건 라벨을 붙여 한 줄로 안내하는 자리입니다(§2.3). 스무 개가 넘어 넉넉히 넣으면
크기가 다시 두 배 넘게 늘고, 서류 목록을 읊을 자리도 아닙니다.

### ③ 글자로 가지 않는 것

- `steps[].contact_ref`·`url` — 연락처는 [§11.4.4](../spec/backend/08-16-data-model.md) 가 **막혔을 때만** 주기로 했습니다. 이 결정은 그것을 바꾸지 않습니다.
- `deadline` — 계산기의 것입니다(불변 규칙 7). 기한을 말로 하는 것은 `summary` 의 몫이고 [RFC-002 자기점검](../rfc/002-kb-authoring.md)과 `kb-load.test.ts` 가 지킵니다.
- `kb_entry_id`·`kb_version` — 모델이 되받지 않습니다(§5).

## 근거

**크기는 감당할 만합니다.** 실패한 턴의 프롬프트에 적용 절차 일곱을 ①로 그려 넣으면 적용 절차 블록이 935 → 3,401자,
입력 토큰이 **4,827 → 6,785**(grok-4.5 실측 · 약 40%)입니다. 참고 절차 스무 개까지 넣으면 글자수가 4,500자 더 늘어 그쪽은 뺐습니다.

**같은 프롬프트로 다시 물었을 때** — 넷 다 해당 항목을 인용해 답했습니다.

| 물음 | 답 |
| --- | --- |
| 서류는 뭘 내야 하나요? 수수료도 있어요? | 「별지 제1호서식 피해구제신청서와 신분증 사본 1부입니다. … 수수료는 없습니다」(kb-25) |
| 자율배상 신청하면 보통 얼마나 받고 얼마나 걸려요? | 「1년 4개월 동안 배상은 41건·피해액의 0.1% 수준이었으며 처리에 평균 116일 … 기대를 낮춰 두시는 편이」(kb-28) |
| 이 단계 끝나면 뭘 올려야 완료로 되나요? | 「끊기 전에 사건접수번호를 받아 적어 두세요. … 확인되면 올려 주세요」(kb-22) |
| 이거 무슨 법에 근거한 거예요? | 「통신사기피해환급법과 그 시행령에 따른 절차입니다」(kb-23·24) |

**KB 문장을 고치는 것으로는 안 됩니다.** `summary` 는 작업 패널 카드의 첫 줄이라 짧아야 하고, `steps`·`caveat` 에 이미 있는 말을
다시 적으면 같은 사실이 두 칸에 있어 어느 쪽이 정본인지 사라집니다. 사람이 이미 써 둔 칸을 그대로 보내는 편이 맞습니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| **지금처럼 `summary` 만** | 위 표의 물음에 챗이 「자료에 없다」고 답합니다. 패널과 챗의 지식이 다릅니다 |
| **`summary` 에 서류·수수료·수치를 다시 적기** | 패널 카드가 길어지고 `steps`·`caveat` 와 중복됩니다 — 정본이 둘이 됩니다 |
| **참고 절차에도 다섯 줄** | 입력이 다시 두 배 가까이 늘고, 참고 절차는 한 줄 조건 라벨의 자리입니다(§2.3) |
| **`deadline` 도 문장으로 렌더** | 계산기의 구조를 코드가 말로 풀면 「영업일이 무엇인가」같은 지식이 코드에 박힙니다. KB 문장 쪽 규칙(RFC-002)으로 이미 해결 |
| **연락처도 넣기** | §11.4.4 의 「막혔을 때만」결정을 뒤집는 일이라 별도 ADR 의 몫입니다 |

## 결과

**얻는 것**

- 사람이 KB 에 써 둔 서류·수수료·기대치·완료 증거·조문을 챗이 그대로 씁니다. 패널과 챗이 같은 것을 압니다.
- 지시문 §4 3항(「OO이 오면 올려주세요」)이 모든 적용 단계에서 근거를 갖습니다 — 완료를 부산물로 판정하는 흐름(불변 규칙 6)이 챗에서도 이어집니다.
- 불변 규칙 8 의 숫자가 답변에 실립니다.

**잃는 것**

- 한 턴 입력이 약 2,000 토큰 늘어납니다. 캐싱 경계(§3.2)는 그대로라 적용 절차 블록은 사건 안에서 거의 안 바뀝니다.
- 답이 길어질 수 있습니다. 지시문의 「한 번에 한 단계만」「짧고 분명하게」가 그대로 억제합니다 — 위 네 답은 두 문단을 넘지 않았습니다.

## 정하지 않은 것

- **연락처의 「막혔을 때」안내**(§11.4.4 2단계)는 챗에 배선되지 않아 *"은행 전화번호가 뭐예요"* 는 여전히 「자료에 없다」입니다. 별도 결정.
- 참고 절차의 `caveat`(「10월부터 대상이 된다는 것이 곧 돌려받는다는 뜻은 아니다」류)를 넣을지 — 유형이 정해지기 전 사건에서만 의미가 있어 미룹니다.
- 세는 법을 글자로 주면 모델이 예시 날짜를 스스로 세는 것을 봤습니다(PR #80). 지시문에 「예시 날짜도 만들지 마라」를 더할지는 지시문 쪽 결정입니다.
