# ADR-042. 신청서를 내는 길은 하나가 아니다 — 앱과 영업점을 함께 내놓고, 순서는 KB가 정한다

- 상태: **채택**
- 날짜: 2026-08-21
- 결정: @Dojaegyum
- 관련 문서: [데이터 모델](../spec/backend/08-16-data-model.md) §11.1 `org.contact` (**④를 대체합니다**) ·
  [기관 조사 §0.1](../docs/research/04-기관정보.md) ·
  [워크스페이스 패널](../spec/frontend/08-17-workspace-panels.md) `WS-visit` ·
  [사용자 여정](../spec/common/08-21-user-journeys.md) 「어긋난 자리」 (**이 결정이 닫습니다**) ·
  [ADR-037](037-doc-guidance-not-generation.md) 서류를 만들지 않는다

## 맥락

**두 화면이 사용자를 서로 다른 곳으로 보내고 있었습니다.**

| 어디 | 무엇이라 쓰여 있었나 |
| --- | --- |
| `plan.tsx` (08-19) | 「피해구제 신청서를 **국민은행 앱에서** 제출하세요」 |
| `doc.tsx` (08-20) | 「국민은행 — **가까운 영업점에 서면 제출**」 |

**기한이 3영업일 안쪽인 구간이라 헛걸음이 그대로 손해입니다.**

**그리고 근거가 우리가 믿던 것과 반대였습니다.**
`spec/` 세 곳이 「**서면 신청은 낡은 표현이고 앱 비대면 신청이다**」라고 적고 있었는데,
2026-08-20 에 1차 출처로 훑어 보니 이렇습니다 ([조사 §0.1](../docs/research/04-기관정보.md)).

| 은행 | 앱 피해구제 신청 |
| --- | --- |
| KB국민 · NH농협 | **아니오** — 공식 안내가 **영업점 서면 제출** |
| 신한 · 우리 · 하나 · 카카오뱅크 · 토스뱅크 | **확인 실패** |

**앱 신청 경로가 확인된 은행이 한 곳도 없습니다.** 「낡은 표현」이라던 쪽이
지금 확인되는 유일한 경로입니다.

**그런데 「그럼 전부 영업점」도 틀립니다.** [채널 매트릭스](../spec/backend/08-14-channel-matrix.md)가
`CH-neobank`(인터넷은행)에 대해 **창구가 앱 중심**이라고 이미 적어 뒀고, 토스뱅크에는
찾아갈 영업점이 사실상 없습니다. **은행마다 답이 다른데 화면이 하나로 말하고 있었습니다.**

> **2026-08-20 에 제가 반대로 정했습니다.** [데이터 모델](../spec/backend/08-16-data-model.md) §11.1 ④가
> 「`app_path` 를 두지 않는다 — 앱으로 되면 `submit_place` 가 「앱 → …」이 되고
> 안 되면 「영업점 …」이 된다. **키 하나면 된다**」였습니다.
> **둘 중 하나만 참이라는 전제가 틀렸습니다.**

## 결정

### ① `submit_place` 문자열을 **`submit` 배열**로 바꿉니다

```jsonc
"contact": {
  "report_tel": "1588-9999",
  "submit": [
    { "how": "branch", "text": "가까운 영업점에 서면 제출", "url": "…지점 찾기…" },
    { "how": "app",    "text": "앱 → 고객센터 → 피해구제 신청", "url": "…" }
  ]
}
```

| 필드 | 무엇 |
| --- | --- |
| `how` | **`"branch"` 또는 `"app"`** 둘뿐입니다. 화면이 아이콘·문구를 이걸로 고릅니다 |
| `text` | 사용자에게 보이는 **한 줄**. 기관이 쓰는 말 그대로 |
| `url` | 그 경로로 가는 **공식 주소**. 선택 — 없으면 링크 없이 글자만 |

### ② **배열 순서가 곧 권장 순서입니다. 화면이 정렬하지 않습니다**

**「앱이 먼저」를 코드에 박지 않습니다.** 지금 데이터로 그렇게 하면
KB·NH 사용자가 앱을 뒤지다 3영업일을 씁니다.

**기관마다 무엇이 먼저인지가 다르고, 그건 KB 가 압니다** —
[불변 규칙 1](../CLAUDE.md)이 절차를 KB 로 내린 것과 같은 자리입니다.

### ③ 확인 못 한 경로는 **배열에 없습니다**

§11.1 ①이 이미 정한 규칙 그대로입니다 — **`null` 을 넣지 않습니다.**

```
KB국민 · NH농협    →  [ branch ]        앱은 「아니오」라 넣지 않습니다
나머지 다섯        →  [ ]               둘 다 확인 실패
```

**빈 배열이면 제출처 카드를 아예 그리지 않습니다.** 「모른다」를 「없다」로 그리지 마세요.

> ⚠️ **KB·NH 의 앱이 빠진 것과 신한의 앱이 빠진 것은 뜻이 다릅니다** —
> 전자는 **아니오**, 후자는 **모름**입니다. 그 구분은 `research/04` 가 갖고 화면은 안 봅니다.
> **화면에서는 둘 다 「말하지 않는다」로 같습니다.**

### ④ 지도를 우리 화면에 **임베드하지 않습니다** — 밖으로 내보냅니다

「가까운 영업점」이 필요하다는 것은 맞습니다. 다만 **우리가 계산하지 않습니다.**

| | |
| --- | --- |
| **왜 안 하나** | 「가까운」을 우리가 정하려면 **사용자 위치**가 필요합니다. 지금 안 받는 개인정보가 하나 늘고, 그 대가로 얻는 것이 은행 공식 지점찾기보다 **못합니다** — 영업시간·업무 취급 여부를 우리는 모릅니다 |
| **대신** | `submit[].url` 이 **은행 공식 지점 찾기**를 가리킵니다. 그 페이지가 이미 지도입니다 |
| **어느 패널** | `WS-visit` — 「외부 이동」이 이미 있는 유형입니다 |
| **위치** | **우리 서버로 오지 않습니다.** 사용자가 은행 페이지에서 직접 씁니다 |

## 근거

**둘 다 내놓는 것이 불확실성에 대한 정답입니다.** 지금 우리는 다섯 은행에 대해 모릅니다.
하나만 고르라면 **틀릴 확률이 반**인데, 둘을 나란히 놓으면 사용자가 되는 쪽을 씁니다.

**그리고 이 구조는 확인이 끝나도 그대로 씁니다.** 앱이 되는 은행이 나오면
`submit` 에 한 줄을 더할 뿐이고, **화면은 안 고칩니다.**

**순서를 데이터로 내린 것이 핵심입니다.** 제도가 바뀌면(비대면 신청이 실제로 열리면)
KB 한 줄이 바뀌고 끝납니다 — 코드를 고치는 일이 없습니다.

### 검토한 대안

| 대안 | 왜 아닌가 |
| --- | --- |
| `submit_place` 문자열 하나 (2026-08-20) | **둘 중 하나만 참이라는 전제가 틀렸습니다.** 인터넷은행은 영업점이 없고, 시중은행은 앱이 확인 안 됩니다 |
| 「앱 먼저, 안 되면 영업점」을 화면에 박기 | **KB·NH 는 공식 안내가 아니오입니다.** 헛걸음이 3영업일 안에서 일어납니다 |
| 전부 영업점으로 통일 | 토스뱅크에 **찾아갈 영업점이 없습니다** |
| 지도를 화면에 임베드 | **사용자 위치라는 개인정보가 새로 생깁니다.** 얻는 것은 은행 페이지보다 못합니다 |
| 확인될 때까지 제출처를 아예 안 보여주기 | KB·NH 는 **확인됐습니다.** 아는 것까지 감추는 것은 손해입니다 |

## 결과

**`spec/` 의 「서면 신청은 낡은 표현」이 틀렸습니다.** 세 곳을 고칩니다 —
[채널 매트릭스](../spec/backend/08-14-channel-matrix.md) · [컴포넌트](../spec/frontend/design-system/08-16-components.md) ·
[spec/README](../spec/README.md). **「낡은 표현」이 아니라 「기관마다 다른 것」입니다.**

**화면 둘의 문구가 바뀝니다** — `plan.tsx` 히어로와 `doc.tsx` 제출처 카드.
**둘 다 같은 값(`org.contact.submit`)을 봅니다.** 그래야 다시 갈라지지 않습니다.

**`org` 데이터가 아직 비어 있습니다.** 구조만 서고 값은 조사에서 옵니다 —
**지점 찾기 URL 은 아직 아무 은행도 확인 안 했습니다** → `research/05` `U-31`.

**재검토 트리거**
- **은행 하나라도 앱 신청이 공식 확인되면** — ②의 순서를 그 기관 행에서 뒤집습니다. ADR 은 안 씁니다
- **지도 임베드가 다시 논의되면** ④를 봅니다. 그때 새로 생기는 것은 **위치 정보**이고, [PII 경계](../spec/common/08-14-pii-boundary.md)에 항목이 하나 늘어납니다
