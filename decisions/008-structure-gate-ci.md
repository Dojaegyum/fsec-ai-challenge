# ADR-008. 폴더 구조가 바뀌면 RFC 수정을 CI로 강제한다

- 상태: **채택**
- 날짜: 2026-08-16
- 결정: @Dojaegyum
- 관련: [RFC-001](../rfc/001-repo-structure.md) (규약 본문 · 「CI가 강제합니다」)

## 맥락

[RFC-001](../rfc/001-repo-structure.md)은 "무엇을 어디에 두는가"의 현행 규약이고,
바뀌면 문서를 고치도록 정해두었습니다. 그런데 **지키지 않아도 아무 일도 일어나지 않았습니다.**

실제로 어긋난 적이 있습니다. `2bf61f3`(브랜드 자산 등록)에서 `assets/brand/logo`·`icon`·`favicon`
세 폴더가 생겼지만 `rfc/`는 그대로였습니다. 규약이 실제 저장소보다 뒤처지면,
**다음 사람이 잘못된 지도를 보고 파일을 엉뚱한 곳에 둡니다.** 이 저장소는 사람과 에이전트가 함께 쓰고,
에이전트는 규약 문서를 그대로 믿기 때문에 비용이 더 큽니다.

## 결정

**폴더가 생기거나 사라지거나 이름이 바뀌면, 같은 변경에 `rfc/` 수정이 없으면 CI가 막습니다.**
`.github/workflows/repo-structure-gate.yml` — PR과 `main` 푸시 모두에 걸립니다.

- 판정 기준은 **추적되는 파일의 폴더 집합**입니다(git은 빈 폴더를 추적하지 않습니다).
- `src/`·`.github/`의 **내부** 폴더는 제외합니다. `src`·`.github` 자체의 생성·삭제는 감시합니다.

## 근거

- **규약은 어겨도 아프지 않으면 지켜지지 않습니다.** 문서에 "고치세요"라고 적는 것과,
  안 고치면 머지가 안 되는 것은 다릅니다.
- **폴더 변화는 드물고 명확합니다.** 매일 걸리는 게이트가 아니라 몇 주에 한 번 걸리는 것이라
  마찰이 작습니다. 대신 걸릴 때는 반드시 판단이 필요한 순간입니다.
- **코드 내부 구조는 제외해야 실용적입니다.** `src/` 밑은 구현이 진행되며 계속 늘어납니다.
  거기까지 강제하면 게이트를 끄게 되고, 그러면 정작 중요한 최상위 구조도 못 지킵니다.

### 검토한 대안

| 대안 | 사유 |
| --- | --- |
| pre-commit 훅 | 로컬 설정이라 사람마다 다르고, 클론한 사람이 안 깔면 없는 것과 같습니다 |
| 라벨로 우회 허용 | 우회가 기본값이 됩니다. 급하면 관리자 권한으로 머지하면 되므로 별도 장치를 두지 않습니다 |
| 전 폴더 감시(`src/` 포함) | 구현 중 마찰이 커서 게이트 자체가 꺼집니다 |
| 감시하지 않음 | 이미 한 번 어긋났습니다 |

## 결과

**얻는 것**

- 규약과 실제 저장소가 어긋난 채로 머지되지 않습니다.
- 폴더를 만들 때 "이게 규약에 걸리나"를 **강제로 한 번 생각하게** 됩니다.

**잃는 것 · 감수하는 것**

- 정당한 폴더 추가에도 `rfc/` 수정이 필요합니다. 대개 폴더 지도 한 줄이면 끝나지만, 한 단계가 늘어납니다.
- **기준 커밋이 없는 경우(브랜치 첫 푸시·force push)는 검사를 건너뜁니다.** 이때는 게이트가 없는 것과 같습니다.
- `src/` 내부는 감시하지 않으므로, 코드 구조 규약은 이 게이트로 지켜지지 않습니다.

## 재검토 트리거

- 게이트가 자주 걸려 우회가 잦아지면 감시 범위를 좁힙니다.
- `src/` 하위 구조 규약이 RFC에 생기면, 제외 범위를 다시 판단합니다.
