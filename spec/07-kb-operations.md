# 07 · 매뉴얼 KB와 운영 파이프라인 (F-05, F-11)

기획서 §4.

> **설계 원칙: LLM은 절차를 외우지 않는다 — 버전드 KB를 인용할 뿐이다.**
>
> 절차 지식을 프롬프트에 굽지 않고 구조화 KB(JSON + 출처·시행일 메타)로 분리하면,
> 제도 변경이 **코드 배포 없이 KB 릴리스로** 반영됩니다.

## 왜 이게 핵심인가

도메인 지식에는 **시간성**이 있습니다. 가상자산 환급(2026.10.1 시행)이 살아있는 예시입니다 —
시행일 메타 덕분에 **같은 질문에도 10월 전후로 다른 답**이 나갑니다.

이 구조 자체가 발표에서 **'환각 방지 설계'** 로 어필하는 지점입니다.

## KB 원칙

1. 모든 절차 항목은 **출처(법령·기관 공지) 링크**와 **시행일**을 메타데이터로 갖습니다.
2. **LLM은 KB 근거 없이 절차를 창작하지 않습니다** (근거 인용 강제).
3. 원본 데이터는 경유 서비스 8유형 매트릭스 → [03](03-channel-matrix.md).
4. 런타임 KB는 **운영 파이프라인으로만** 갱신됩니다. 코드에서 직접 쓰지 않습니다.

## 운영 파이프라인 (F-11)

```
소스 (공개) — 4층
  · 국가법령정보 API      — 공포된 법령·시행령
  · 법제처 입법예고 API   — 공포 전 예고 중인 개정
  · 금융위 게시판         — 정책 발표·해설
  · 기관 실무 정보        — 은행·페이 콜센터 (자동 감시 불가)
      ↓
Watcher (주기 수집, 하루 1회)
      ↓
변경 감지 (내용 해시) ── 변경 없음 → 대기
      ↓ 변경
LLM 영향 분석 — 어떤 유형·단계에 영향? 개정 초안 생성
      ↓
👤 사람 검수 큐  ← 절차 지식은 자동 반영 금지
      ↓ 승인
KB 버전 릴리스 vX.Y (+ 시행일 메타 + 출처 링크)
      ↓
런타임 KB → 모든 답변에 근거 인용
```

- **사람 검수는 생략 불가**입니다. 절차 지식이 자동으로 런타임에 들어가면 안 됩니다.
- **Staleness Guard** — 90일 재검증. **단 층마다 의미가 다릅니다 → 아래 「감시되지 않는 층」**
- **MVP 범위**: KB는 수동 구축하고, 파이프라인은 **시연**합니다 (F-11은 P2).

저장 구조는 [09-data-model.md](09-data-model.md) §12, 설계 근거는 [RFC-0005](../rfc/0005-절차지식-수집과-저장.md).

### 소스 주소 — 실측 확인 (2026-08-16)

**1. 국가법령정보 Open API**

```
검색  https://www.law.go.kr/DRF/lawSearch.do?OC=<키>&target=law&type=XML&query=<법령명>
본문  https://www.law.go.kr/DRF/lawService.do?OC=<키>&target=law&MST=<일련번호>&type=XML&efYd=<시행일>
이력  https://www.law.go.kr/DRF/lawSearch.do?OC=<키>&target=eflaw&type=XML&query=<법령명>
```

| 확인한 것 | 값 |
| --- | --- |
| 통신사기피해환급법 법령ID | `011359` |
| 조문 수 | 법률 31개 · 시행령 27개 |
| 응답 크기 | 법률 47KB · 시행령 223KB |
| 이력 조회 | 2011년 제정부터 22건 전부 |

**`efYd`로 시행일 기준 본문을 조회할 수 있습니다.** 과거 시점 조문을 그대로 재현할 수 있습니다.

**`<조문시행일자>`가 조문마다 따로 있습니다.** 법령 하나 안에서도 조문별 시행일이 다를 수 있습니다.

**2. 법제처 입법예고 API** — 공공데이터포털 `data.go.kr/data/15090734`

**법령 API만 보면 예정된 개정을 놓칩니다.** 실측에서 법령 이력 22건에 **가상자산 2026-10-01 개정이 없었습니다.** 공포 전이라 안 뜹니다. 우리가 그걸 아는 건 보도자료를 봤기 때문입니다.

**3. 금융위원회 게시판**

| 게시판 | RSS |
| --- | --- |
| 보도자료 | `https://www.fsc.go.kr/about/fsc_bbs_rss/?fid=0111` |
| 보도설명자료 | `…?fid=0112` |
| 공지사항 | `…?fid=0114` |

**RSS는 최근 10건만 주고, 그 10건이 4일치입니다.** 수집이 며칠만 멈춰도 그 사이 게시물이 밀려나 사라집니다.

**그래서 RSS는 감지에만 쓰고 실제 수집은 목록 페이지에서 합니다.** 이전 수집 지점과 겹칠 때까지 쪽을 넘깁니다 → [09-data-model.md](09-data-model.md) §12.5

**4. 기관 실무 정보** — 자동 경로 없음. 사람이 확인 → [research/04-기관정보.md](../research/04-기관정보.md)

### 감시되지 않는 층

**「전부 감시한다」고 말할 수 없습니다.**

| 순위 | 내용 | 근거의 출처 | 자동 감시 |
| --- | --- | --- | :---: |
| 3순위 공통 | 112 신고, 명의도용 점검 | 법률 | **가능** |
| 2순위 유형 기본 | 3영업일·14일 기한 | **시행령** | **가능** |
| **1순위 기관 전용** | **콜센터 번호, 앱 메뉴 경로** | **은행 재량** | **불가능** |

법령은 "금융회사에 요청한다"까지만 정하고, **어느 번호로 어떤 메뉴에서 하는지는 법령·보도자료 어디에도 없습니다.**

**Staleness Guard 90일은 1순위에만 의미가 있습니다.** 2·3순위는 자동으로 잡히므로 90일을 기다릴 이유가 없고, 1순위는 90일이 길 수 있습니다.
