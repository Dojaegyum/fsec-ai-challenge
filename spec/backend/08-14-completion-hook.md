# 완수 검증 Completion Hook (F-06b)

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §5

> **문제** — 체크리스트는 "체크는 됐는데 행위는 안 된 상태"를 막지 못합니다.
> 은행·경찰 시스템 API가 없으므로 완수를 직접 조회할 수도 없습니다.
>
> **원리** — 모든 공식 절차는 완수 시 반드시 **부산물**(접수번호·통지 문자·접수증)을 남깁니다.
> 이 부산물을 완료 조건이자 **다음 단계의 필수 입력**으로 삼으면,
> 인위적 잠금이 아니라 **절차 자체의 의존관계**로 완수가 강제됩니다.

## ① 증거 연쇄 (Evidence-Chained Workflow)

각 단계의 완료 = 부산물 입력/업로드.

| 단계 | 부산물 | 다음 단계에서의 쓰임 |
| --- | --- | --- |
| 112 신고 | 사건접수번호 | **피해구제신청서의 필수 필드** |
| 지급정지 | 은행 접수 문자 캡처 | 진행 상태 근거 |
| 피해구제 신청 (앱·비대면) | 접수증 | **환급 타임라인의 기산점** — `relief_applied_at` (3영업일 서류 제출 기한이 여기서 섭니다) |
| 이의제기 제출 (통장묶기 · `frozen_account`) | 접수증 | **결과 통보의 기산점** — `objection_submitted_at`. 5영업일 자체는 시행일이 미확인이라 KB 본문에만 있습니다 ([ADR-066](../../decisions/066-track-fixed-new-case.md) 「결과」) |

**부산물이 없으면 다음 산출물이 물리적으로 완성되지 않는 구조가 가장 강한 훅입니다.**

> **기산점을 실제로 채우는 자리 (2026-09-04)** — 어느 단계의 부산물이 어느 슬롯을 남기는지의 정본은
> `src/flows/anchor-from-artifact.ts` 의 `ANCHOR_BY_STEP` 입니다 (지금 둘 — 위 표의 셋째·넷째 행).
> 검증을 통과해 `done_verified` 가 된 부산물(L1·L2)이 들어온 **그날**을 `source: 'system'` 으로 채우고,
> 이미 확정된 값은 덮지 않습니다 — 부산물을 두 번 내도 기산점이 뒤로 밀리지 않습니다.
> `notice_started_at`(채권소멸공고 2개월)은 여기서 채우지 **않습니다** — 통지문에 적힌 날이라 통지문에서
> 와야 하고([ADR-054](../../decisions/054-notice-anchor.md)), 그 배선은 아직 없습니다(ADR-066 「결과」).

## ② 검증 3단계

| 레벨 | 방식 | 결과 상태 |
| --- | --- | --- |
| **L1 자동 검증** | **접수번호를 받아 적었는지**([ADR-057](../../decisions/057-receipt-number-l1.md)), 접수증 OCR로 이름·날짜·사건 정보 대조(사건 파일과 일관성 검사) — ⬜ **이름·날짜 대조는 구현 전**(2026-09-06): 올린 접수증(`receipt_doc`)은 L2 로 판정하되, 아래처럼 **판독 결과**를 봅니다 | 완료(증빙됨) |
| **L2 증빙 확인** | 캡처·서류 업로드 (**PII 스크러버 통과**) — **올린 것 자체는 증빙이 아닙니다** ([ADR-077](../../decisions/077-upload-is-not-proof.md)). 전사·OCR 이 낸 **판독 글에 「접수번호」 자리와 번호가 있어야** 통과합니다. **공공기관 이름만 있으면 미확인이고 접수번호를 적는 길을 냅니다**([ADR-083](../../decisions/083-receipt-number-required-for-l2.md)) — 사기 문자에도 수사기관 이름은 거의 늘 들어 있습니다. 은행 이름은 근거가 아닙니다 — 이체 캡처에도 있습니다. 통화 녹음은 서류가 아닙니다 | 완료(증빙됨) |
| | 공공기관 이름만 있고 접수번호가 없음 → **「기관 이름은 보이지만 접수번호가 없습니다」** (`verify_detail.reason: org_only`). 통지문·확인원처럼 번호를 갖지 않는 서류가 여기 걸립니다. 화면은 접수번호를 적는 길(L1)·자기 신고(L3)를 냅니다 (ADR-083) | **미확인** |
| | 판독 글에 접수번호도 기관 이름도 없음 · 읽기 실패 · 통화 녹음 → **「올렸지만 확인 못 함」** (`verify_result: failed`). 화면은 이유와 함께 접수번호를 적는 길(L1)·자기 신고(L3)를 냅니다 | **미확인** |
| | 아직 읽는 중 → `reading_pending` 으로 미뤄 두고, **읽기가 끝난 자리**(`flows/read-evidence.ts` → `flows/settle-artifacts.ts`)가 같은 규칙으로 판정을 마칩니다 | **미확인** (판정 뒤 바뀜) |
| **L3 자기 신고** | 최후 수단 — 허용하되 상태가 '완료'가 아님 | **미확인** |

### 상태 머신

```
미시작 → 진행중 → 완료(증빙됨)
                ├→ 미확인   (L3 자기신고)
                └→ 미확인   (L2 올렸지만 확인 못 함 · 읽는 중)  → 판독이 끝나면 완료로 바뀔 수 있음
```

`미확인`은 종결 상태가 아닙니다 — 리마인더 추적 대상으로 남습니다.

**단계가 완료(증빙됨)가 되면 그 단계의 사용자 기한(`primary`·`grace`)은 `met` 으로 닫힙니다**
([ADR-077](../../decisions/077-upload-is-not-proof.md) · [09 §8](08-16-data-model.md)). 안내용 기한(`info` · 공고 2개월)은
기관이 하는 일이라 단계가 끝나도 그대로 흐릅니다.

> **자료함과 단계 증빙은 다른 일입니다.** 자료함(S-08)의 「+ 올리기」는 **증거**를 올리는 자리이고
> 어느 단계에도 붙지 않습니다. 단계의 부산물은 **워크스페이스 패널의 자리**(「접수증·캡처 올리기」·접수번호 입력·
> 「번호 없이 접수했다고 표시」)에서만 받습니다 — 그 올리기도 파일을 자료함에 두고 §3.8 로 **그 단계에** 붙입니다.

## ③ 통화 동반 모드

전화는 웹이 관측할 수 없는 블랙박스이므로 **관측 가능한 앞뒤를 잡습니다.**

1. 발신 버튼 클릭 → 통화 스크립트 + 예상 질문 표시
2. 통화 타이머 작동
3. 종료 직후 → **"접수번호를 지금 받아적으세요" 캡처 프롬프트 즉시 표시**

부산물 확보를 통화 경험 안에 심는 설계입니다.

## ④ 소프트 게이트 + 리마인더 + 사회적 훅

패닉 사용자를 막아 세우면 이탈합니다.

- **"나중에 입력"은 항상 허용**합니다.
- 단, `미확인` 상태를 **3영업일 D-day 트래커와 연동**해 리마인더(웹 알림·이메일)가 계속 추적합니다.
- **보호자 공유** — 진행 현황을 가족이 열람. 완수 책임을 사회화하는, 완수율을 올리는 가장 강한 비기술적 훅.

## 구현 주의

- 사용자의 체크만으로 `완료(증빙됨)`가 되는 경로를 만들지 마세요 — 이 기능의 존재 이유가 사라집니다.
- 업로드된 접수증도 PII 스크러버를 통과해야 합니다 → [04](../common/08-14-pii-boundary.md).
- 플랜이 재생성되어도(슬롯 보완 시, [02](08-14-slot-tiering.md)) **이미 확보한 부산물과 완료 상태는 보존**해야 합니다.
- L1 자동 검증이 실패했다고 사용자를 막지 마세요. L2 → L3으로 내려가는 경로가 항상 열려 있어야 합니다.

## L1 이 접수번호에서 보는 것 → [ADR-057](../../decisions/057-receipt-number-l1.md)

**형식 정본이 없습니다** — 112·은행·금감원 어디에도 공개된 규격이 없고, 흔히 인용되는
`2025-000000` 꼴은 사설 안내에만 나옵니다 ([U-18](../../docs/research/05-미확인-목록.md)).
**기다리지 않기로 했습니다.** 기다리는 동안 L1 이 죽어 있었고, **은행에 전화해
접수번호를 받아 적은 사람이 실패 화면**을 봤습니다.

| 무엇 | 어떻게 |
| --- | --- |
| **① 모양** | 구분자를 뗀 **영숫자 6자 이상 + 숫자 하나 이상**. 형식 규격이 아니라 오타·빈칸 거르개입니다 — 자릿수도 접두어도 주장하지 않습니다 |
| **② 형식** | **아는 기관만** 대조합니다. 모르면 `format_unchecked` 를 남기고 **통과**시킵니다 |

`verify_detail.reason` 은 실패 전용 칸이 아닙니다 — `format_unchecked` 는 **통과에
붙고**, 나중에 형식 정본이 생기면 그 표시로 **재검증 대상을 셉니다**.
