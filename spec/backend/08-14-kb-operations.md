# 매뉴얼 KB와 운영 파이프라인 (F-05, F-11)

> **출처** — [서비스 기획서 v1.2](../../docs/plans/08-13-service-plan.html) §4

> **설계 원칙: LLM은 절차를 외우지 않는다 — 버전드 KB를 인용할 뿐이다.**
>
> 절차 지식을 프롬프트에 굽지 않고 구조화 KB(JSON + 출처·시행일 메타)로 분리하면,
> 제도 변경이 **코드 배포 없이 KB 릴리스로** 반영됩니다.

## 왜 이게 핵심인가

도메인 지식에는 **시간성**이 있습니다. 가상자산 환급(2026.10.1 시행)이 살아있는 예시입니다 —
시행일 메타 덕분에 **같은 질문에도 10월 전후로 다른 답**이 나갑니다.

이 구조 자체가 발표에서 **'환각 방지 설계'** 로 어필하는 지점입니다.

## KB 원칙

1. 모든 절차 항목은 **출처(법령·기관 공지) 링크**와 **시행일**을 메타데이터로 갖습니다.
2. **LLM은 KB 근거 없이 절차를 창작하지 않습니다** (근거 인용 강제).
3. 원본 데이터는 경유 서비스 8유형 매트릭스 → [03](08-14-channel-matrix.md).
4. 런타임 KB는 **운영 파이프라인으로만** 갱신됩니다. 코드에서 직접 쓰지 않습니다.

## 운영 파이프라인 (F-11)

```
소스 (공개)
  · 국가법령정보 API — 통신사기피해환급법·시행령
  · 금융위·금감원·경찰청 보도자료 (RSS/크롤)
  · 기관 실무 정보 — 은행·페이 콜센터/절차 공지
      ↓
Watcher (주기 수집, 일 1회)
      ↓
변경 감지 (diff) ── 변경 없음 → 대기
      ↓ 변경
LLM 영향 분석 — 어떤 유형·단계에 영향? 개정 초안 생성
      ↓
👤 사람 검수 큐  ← 절차 지식은 자동 반영 금지
      ↓ 승인
KB 버전 릴리스 vX.Y (+ 시행일 메타 + 출처 링크)
      ↓
런타임 KB → 모든 답변에 근거 인용
```

- **사람 검수는 생략 불가**입니다. 절차 지식이 자동으로 런타임에 들어가면 안 됩니다.
- **Staleness Guard** — 90일 재검증.
- **MVP 범위**: KB는 수동 구축하고, 파이프라인은 **시연**합니다 (F-11은 P2).
