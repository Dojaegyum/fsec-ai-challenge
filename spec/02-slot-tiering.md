# 02 · 슬롯 티어링 (F-05b)

기획서 §2.

> **설계 원칙: 미확정 슬롯이 있어도 절대 멈추지 않는다.**
> 패닉 사용자는 정보를 못 주는 게 정상입니다. 정보 요구로 사용자를 막지 말고,
> T0부터 시작해 슬롯이 채워질 때마다 플랜을 점진적으로 구체화합니다.

## 3티어

| 티어 | 슬롯 | 없을 때의 동작 |
| --- | --- | --- |
| **T0 · 없어도 시작** | (없음 — 진입 자체로 충분) | **공통 안전 절차 즉시 제공**: 112 신고 + 1332 상담 + 추가 송금 금지 + 악성앱 의심 시 비행기모드. 어떤 분기에서도 틀리지 않는 슈퍼셋 |
| **T1 · 분기 결정** | 송금 여부 / 송금 수단(8유형) | 버튼 1문항으로 질문. **"모름·기억 안 남" 선택지 상시 제공** → 보수적 슈퍼셋 플랜(해당 없으면 건너뛰기 표시)으로 진행 |
| **T2 · 정밀화** | 기관명·금액·시각·경과시간·상대 연락수단 | **증거에서 자동 추출 우선** (이체내역 OCR → 은행명·금액·시각). 실패 시에만 질문. 미확정은 플랜에 '미확인' 배지로 명시, 나중에 채우면 **플랜 자동 재생성** |

## 흐름

```
인입(파일/텍스트/문진)
  → 슬롯 자동 추출 (전사·OCR에서 LLM 추출)
  → 슬롯 체커: T1 충족?
       ├ 미충족 → 우선순위 최상 슬롯 1개만 버튼 질문 ("모름" 포함)
       │            ├ 응답 → 다시 추출
       │            └ 모름 → 보수적 슈퍼셋 플랜
       └ 충족   → 유형별 맞춤 플랜 생성 (KB 근거 인용)
  → 실행 보드
       └ 증거 추가·슬롯 보완 시 → 추출부터 다시 (플랜 재생성)

T0 공통 안전 절차는 인입 즉시, 슬롯과 무관하게 실행 보드에 상시 노출
```

## 규칙

### 최소 질문 원칙

- **한 번에 한 슬롯만**, 전부 버튼으로 답할 수 있게.
- 질문 순서는 **플랜을 가장 크게 바꾸는 슬롯부터** (정보 이득 순).
- T2는 증거 자동 추출이 우선이므로 실제 질문은 보통 1~2개로 끝나야 합니다.

### "모름"의 처리

"모름"은 실패가 아니라 **정상 상태**입니다.

- 슈퍼셋 플랜은 모든 분기의 안전 단계를 포함하되, 조건부 단계에는 `"카카오페이로 보냈다면"` 식 라벨을 붙입니다.
- **낫게 안내하지 못할 바에 넓게 안내하고, 절대 창작하지 않습니다.**

### 재생성

슬롯이 나중에 채워지면 플랜을 다시 만듭니다. 이때 **이미 완료된 단계의 상태(부산물 포함)는 보존**해야 합니다 → [05](05-completion-hook.md).

## 구현 주의

- 슬롯 미충족을 이유로 실행 보드 진입을 막는 흐름을 만들지 마세요 — T0가 있는 이유입니다.
- 모달로 정보를 강제 입력받는 UI는 이 원칙에 어긋납니다.
- 자동 추출 실패는 정상 경로입니다. 예외로 처리하지 말고 질문 경로로 흘려보내세요.
