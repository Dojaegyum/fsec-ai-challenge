## 레이아웃 — 3-패널 상황실

"사건 파일(Case)" 중심 구조. 업로드된 증거·분석 결과·체크리스트·서류·기한이 하나의 사건 폴더로 묶입니다.
관제 콘솔(후보 13번)에서 검증한 3-패널 레이아웃을 **소비자 문법으로 번역**한 것입니다.

상단에는 항상 **대응 경과 타이머**가, 플랜 단계부터는 **3영업일 D-day**가 함께 붙습니다.

## S-01 · 사건 생성 — `/case/new`

요건 ⓪①②를 **한 화면에서** 보여주는 것이 목적입니다.

| 패널 | 내용 |
| --- | --- |
| 좌 · 사건 증거함 | 업로드된 파일 목록과 처리 상태 (전사 중 74%, OCR 완료 + 감지 요약). 드래그&드롭 추가 |
| 중 · 텍스트화 & PII 보호 | 전사 결과에 **PII가 파란 토큰으로 치환되는 것이 실시간으로 보임**. 하단에 수법 판별·위험도·근거 건수 |
| 우 · 대응 비서 챗 | 분석이 도는 동안 T1 슬롯을 버튼 1문항으로 질문 (F-05b) |

**데모 포인트** — 전사가 흐르고, PII가 토큰으로 바뀌고, 경유 서비스 감지가 배지로 뜨는 것. *"AI가 뭘 하고 있는지"가 투명한 것 자체가 심사 차별점.*

## S-02 · 대응 플랜 — `/case/{id}/plan`

| 패널 | 내용 |
| --- | --- |
| 좌 · 진행 타임라인 | 수법 판별 → 지급정지 → 서면 신청(D-3) → 채권소멸 공고(2개월) → 환급 결정(3~6개월). **환급 기대치 관리가 목적** |
| 중 · 맞춤 대응 플랜 | 경유 서비스 감지 배지 + 번호 매겨진 실행 단계. 완료된 단계는 부산물과 함께 표시(예: "사건접수번호 기록됨") |
| 우 · 서류 도우미 | 피해구제신청서 초안, 다운로드 시 PII 복원 안내. 아래에 대응 비서 챗 |

경유 서비스가 `CH-easypay`인 경우 **선불업자와 연계 은행 양쪽**이 단계로 나옵니다 → [03](../backend/08-14-channel-matrix.md).

## S-03 · 피싱 백신 — `/vaccine` (F-09, P1)

평시 훈련 모드. 가족 등록·동의 상태, 훈련 결과와 취약 패턴, 가족 안전 리포트.

- 동의는 **미리** 받되 시점은 **예고 없이** (향후 2주 내 무작위)
- 목표는 "속이기"가 아니라 **대응 리허설** — 끊기 → 공식번호 확인 → 절차 말하기
- 훈련 종료 즉시 **"훈련이었습니다" 해제 고지** 필수
- 발신은 사전 동의된 **웹 링크 기반 — 실제 전화망 미사용**
- 훈련 데이터는 가족 계정에만 보관

## 화면 전반 원칙

기획서 §0·§2에서 이어지는 것:

- 사용자는 **패닉 상태**입니다. 한 화면에서 요구하는 판단을 최소화합니다.
- 질문은 **한 번에 하나, 전부 버튼**으로 (F-05b).
- **"모름" 선택지가 상시 존재**합니다.
- 미확정 정보는 숨기지 말고 **'미확인' 배지**로 드러냅니다.
- 파이프라인의 각 단계가 **눈에 보이게** 합니다 (숨기지 않는 것이 신뢰 장치).
