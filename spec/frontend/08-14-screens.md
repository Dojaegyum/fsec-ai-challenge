## 화면 일곱

| ID | 화면 | 경로 | 어느 국면에서 | 층 C 모듈 |
| --- | --- | --- | --- | --- |
| `S-04` | 랜딩 | `/` | 국면 0·1 — 발견 | — |
| `S-05` | 동의 · 선택 제공 | `/start` | 국면 1 — 첫 10분 | `pii-masker` · `file-sender` |
| `S-06` | 사건 · **본문이 챗** (+ 워크스페이스) | `/c/{token}` | 국면 1~4 | `chat-handler` · `poll-checker` · `pii-restorer` · `work-handler` |
| `S-07` | 사건 · **본문이 플랜** | `/c/{token}` | 국면 2~5 | `plan-viewer` · `deadline-viewer` |
| `S-08` | 증거함 | `/c/{token}` | 국면 1~3 | `transcript-viewer` · `file-sender` |
| `S-10` | 서류 초안 (P1) | `/c/{token}/doc/{id}` | 국면 3 | `doc-filler` · `key-handler` |
| `S-03` | 피싱 백신 (부가) | `/vaccine` | 평시 | — |

**`S-06`·`S-07`·`S-08`은 경로가 같습니다.** 화면 ID가 가리키는 것은 경로가 아니라
**무엇을 보여주는 상태인가**입니다. 셋 사이의 이동은 내비게이션이 아니라 **본문이 바뀌는 것**이고,
`case-opener`가 링크를 열 때 어느 상태로 들어갈지 정합니다 →
[모듈 명칭](../common/08-16-module-names.md) 층 C.

```
/                     랜딩
/start                동의 · 선택 제공 → 링크 발급
/c/{token}            사건 — 챗 · 플랜 · 증거함 + 워크스페이스 패널
  /doc/{id}             서류 초안 (P1)
/vaccine              피싱 백신 (부가)
```

## 셸은 세 열입니다

`/c/{token}`은 **T0 레일 · 본문 · 오른쪽 열** 세 칸으로 돼 있습니다
([ADR-036](../../decisions/036-t0-rail.md)).

```
┌──────────────┬───────────────────────────┬──────────────────┐
│ T0 안전 절차   │  본문                      │  오른쪽 열        │
│ (288px·고정)  │  챗 · 플랜 · 증거함         │  (350px)         │
└──────────────┴───────────────────────────┴──────────────────┘
```

**T0는 본문 밖에 있습니다.** 본문이 무엇이든 자리를 지킵니다 —
[슬롯 티어링](../backend/08-14-slot-tiering.md)이 「슬롯과 무관하게 **실행 보드에 상시 노출**」이라
했고, [모듈 명칭](../common/08-16-module-names.md)도 `plan-viewer`가 T0를 상시 노출한다고
적고 있습니다. **본문 안에 두면 국면이 바뀔 때 같이 사라집니다.**

| | |
| --- | --- |
| 접기 | **넓은 폭에서는 접히지 않습니다.** 접기는 좁은 폭 전용입니다 |
| 좁은 폭 | 맨 위에 쌓이고 **요약 한 줄 + 접기**로 돌아갑니다 |
| 흡수 모션 | 대상은 **본문 열뿐**입니다. T0 레일은 빨려들지 않습니다 |
| 금지 | 여기에 절차를 **넷보다 많이** 두는 것 — 넷을 넘기면 T0가 아닙니다 |

> ⚠️ **핸드오프 시안 셋은 전부 2열입니다.** T0가 챗 본문 맨 위에 있습니다.
> 세 열은 우리가 정한 것이고, **새 시안을 받을 때도 이 열을 전제**합니다.

## 화면 상태는 두 축입니다

`/c/{token}`의 상태는 **한 줄로 늘어놓는 단계가 아니라 독립된 두 축**입니다
([ADR-035](../../decisions/035-screen-state-axes.md)).

```ts
focus: 'chat' | 'plan' | 'evidence'   // 본문이 무엇을 보여주나
side:  'casefile' | 'work'             // 오른쪽 열이 무엇을 보여주나
```

| `focus` | 본문 | 화면 ID |
| --- | --- | --- |
| `chat` | 챗 스트림 + 컴포저 | `S-06` |
| `plan` | 단계 · 기한 · 진행 타임라인 | `S-07` |
| `evidence` | 전사 · 자료 레일 | `S-08` |

| `side` | 오른쪽 350px | 언제 |
| --- | --- | --- |
| `casefile` | 사건 파일 — 슬롯이 채워지는 것이 보입니다 | 진술을 받는 동안 |
| `work` | 워크스페이스 패널 — 지금 할 일 하나 | 챗이 단계를 가리킨 뒤 |

**두 축은 독립이라 「다음」이 없습니다.** 며칠 뒤 링크를 열면 곧장 `focus: 'plan'`부터
시작합니다 — 챗을 거치지 않습니다. `case-opener`가 어느 조합으로 열지 정합니다.

> ⚠️ **「국면」은 화면 상태를 가리키는 말이 아닙니다.** 국면은 사건의 일생(0~5)이고,
> 정의는 [서비스 골자](../common/08-17-service-concept.md) 「여정 — 여섯 국면」에 있습니다.
> 화면은 **본문**과 **오른쪽 열**로 부릅니다.

**핸드오프 번들은 옛 어휘로 적혀 있습니다.** 받은 그대로 두는 스냅샷이라
고치지 않았습니다([RFC-003](../../rfc/003-design-handoff.md)) — 읽을 때 이렇게 대응시키세요.

| 번들의 `phase` | 지금 |
| --- | --- |
| `chat` | `{ focus: 'chat', side: 'casefile' }` |
| `chat_panel` | `{ focus: 'chat', side: 'work' }` |
| `board` | `{ focus: 'plan', side: 'work' }` |
| `evidence` | `{ focus: 'evidence', side: 'work' }` |

**모션은 바뀐 축을 따릅니다** — 번들의 전환 ①은 `side`만, ②·④는 `focus`만 바뀝니다.

## S-04 · 랜딩 — `/`

**검색으로 온 사람에게 「여기는 신고 다음을 맡는 곳」이라는 것 하나를 이해시킵니다.**
설명을 늘리면 실패합니다 — 진입은 검색·직접 접속이 전제입니다
([ADR-021](../../decisions/021-reentry-and-identity.md)).

| | |
| --- | --- |
| 행동 | **[지금 시작하기] 하나.** 스크롤 아래에도 두 번째 행동을 두지 않습니다 |
| 폭 | **셸 폭**(`--container-shell`). 랜딩만 예외이고, 국면 1 이후는 좁은 폭입니다 |
| 첫 화면 | 스크롤 없이 보이는 곳에서 **3초 안에** 납득시킵니다. 아래는 그다음 몫입니다 |
| 금지 | 기능 목록·메뉴·앵커 내비게이션·요금 링크 |

### 스크롤 네 마디 (→ [ADR-029](../../decisions/029-scroll-landing.md))

**스크롤은 허용하되, 아래로 갈수록 요구가 줄어야 합니다.** 읽어야 이해되는 것을
아래에 쌓으면 「읽어야 하는 페이지」가 되고, 패닉 상태에서는 안 읽힙니다.

| 마디 | 무엇 | 계약 |
| --- | --- | --- |
| ① 히어로 | 심볼 · 헤드라인 · 서브카피 · **[지금 시작하기]** | 스크롤 없이 **여기까지가 보입니다.** 행동이 접히면 안 됩니다 |
| ② 하는 일 셋 | 진술→절차 · 기한 계산 · 서류 | 훑고 지나가도 「뭘 해주는지」가 남아야 합니다 |
| ③ 화면 소개 | `/start` · 챗 · 보드 · 증거함·서류 | **보여주는 것**이지 읽히는 것이 아닙니다 — 미니 목업 + **한 줄** |
| ④ 고지 | **112 우선** · 환급 비보장 | 페이지 끝에 한 줄. 문구를 줄이지 않습니다 |

**③은 기능 목록이 아닙니다.** 화면 넷이 각각 무엇을 하는 자리인지를 그림으로 보여주는
것이고, 각 화면당 설명은 **한 줄을 넘기지 않습니다.** 항목이 늘어나거나 줄글이 붙으면
그 순간 금지된 「기능 목록」이 됩니다.

**④의 112 안내는 뺄 수 없습니다.** 전환율을 깎는 자리지만, 빼면 아직 신고 전인 사람을
우리 화면에 붙잡습니다. ①에 두면 첫 화면이 두 갈래가 되므로 **끝에 둡니다** —
스크롤이 생기면서 이 자리가 생겼습니다.

**히어로의 장식(오비트 링·글로우)은 뜻을 싣지 않습니다.** `--horizon` 규칙 그대로이고
전부 `aria-hidden`입니다. 회전은 `prefers-reduced-motion`이 멈춥니다
([design-system/08-16-tokens.md](design-system/08-16-tokens.md)).

## S-05 · 동의 · 선택 제공 — `/start`

**관문은 동의 하나뿐입니다.** 동의는 법적 필수라 관문이지만,
**증거와 기본 정보는 줄 수 있는 사람만 줍니다** — 폼을 통과해야 다음으로 가는 구조를 만들면
「모름은 실패가 아니다」 위반입니다 ([02-slot-tiering.md](../backend/08-14-slot-tiering.md)).

| | |
| --- | --- |
| 관문 | **동의만.** 「건너뛰고 바로 시작」이 **같은 화면**에 **같은 크기로** 있습니다 |
| 이메일 | **선택.** 안 주면 알림이 없고 일회성으로 끝난다는 것을 **같은 크기로 옆에** 씁니다 |
| 증거 | 선택. 올리면 `pii-masker`가 브라우저에서 가린 뒤 `file-sender`가 보냅니다 |
| API | `POST /api/cases` ([08-api.md](../common/08-14-api.md) §3.1) · `POST …/evidence` §3.2 |
| 층 C | `pii-masker` · `file-sender` |

### 한 주소에 두 단계입니다

**`/start`는 화면을 옮기지 않고 단계만 바꿉니다.** 발급 전으로 되돌아갈 수 없으므로
뒤로 가기로 되짚는 구조를 만들지 않습니다.

| 단계 (`phase`) | 무엇 | 끝나는 조건 |
| --- | --- | --- |
| **intake** | 동의 → 무슨 일이 있었는지(Q1) → 자료(선택) | 동의 완료 + [다음] |
| **issued** | 발급된 **사건 주소**가 화면의 주인. 이메일(선택) | `/c/{token}` 으로 이동 |

여기는 `/c/{token}` 과 달리 **되돌아갈 수 없는 한 방향**이라 축이 하나입니다.

**왼쪽에 단계 레일(동의 → 무슨 일 → 링크 발급)이 상시 보입니다.** 몇 걸음 남았는지를
숨기지 않는 것이 패닉 상태에서 이탈을 막습니다.

### 동의 — 전문은 모달, 요약은 그 앞에

**동의는 법적 필수라 유일하게 관문이 될 수 있습니다.** 다만 전문을 읽어야만 넘어가는 구조는
아닙니다 — 요약을 먼저 보여주고, 전문은 같은 모달 안에 둡니다.

| | |
| --- | --- |
| 파기 | **마지막 활동일부터 180일** ([ADR-016](../../decisions/016-retention-and-datastore.md)) |
| 주민등록번호 | **수집하지 않습니다.** 못 가리면 그 파일만 빼고 진행 ([ADR-026](../../decisions/026-raw-upload-retention.md)) |
| 토큰화 | 계좌·전화·이름은 **전송 전 브라우저에서** 치환됩니다 |
| 학습 | **AI 학습에 쓰지 않습니다.** 이 사건 처리에만 |
| 포커스 | **모달로 포커스를 가두지 않습니다** ([접근성](design-system/08-16-accessibility.md) 「키보드」) |

**조항 다섯을 모두 확인해야 동의가 성립합니다**
([ADR-031](../../decisions/031-consent-clause-ack.md)). 그 전에는 [동의하고 계속하기]가
열리지 않고, **몇 개가 남았는지를 항상 보여줍니다**(`확인 N / 5` · 「N개 항목 확인 남음」) —
왜 못 누르는지 모르게 두는 것이 진짜 이탈 원인입니다.

**이것은 관문을 하나 더 세우는 것이 아닙니다.** 체크는 사용자에게서
**정보를 받아내지 않고**, 우리가 고지한 것을 읽었다는 표시일 뿐입니다 —
관문은 여전히 **동의 하나**이고, 체크는 그 관문을 통과하는 절차입니다.

### 무슨 일이 있었는지 (Q1)

**첫 문항은 진술의 축을 가릅니다.** `F-05b`의 규칙 그대로 **한 번에 하나 · 전부 버튼 ·
「모름」 상시**입니다.

- 선택지는 **「내 돈이 나갔어요」 · 「내 계좌가 갑자기 묶였어요」 · 「잘 모르겠어요」** 셋.
- **「잘 모르겠어요」는 같은 크기·같은 자리**에 둡니다. 글자색만 `ink-3`으로 내리고,
  **그보다 더 낮추지 않습니다** — 고르기 부끄러운 선택지로 만들면 「모름은 실패가 아니다」가 깨집니다.
- **기본 선택을 두지 않습니다.** 아무것도 안 고른 상태가 시작점입니다 —
  미리 골라두면 화면이 답을 유도하고, 그 답이 그대로 사건 축이 됩니다.

### 자료 — 종류가 곧 안내입니다

**빈 업로드 상자 하나 대신 종류별 슬롯 넷**을 둡니다. 무엇을 올려야 할지가 슬롯 이름에
적혀 있어야 하고, 올린 것이 무엇인지도 그 순간 정해집니다.

| 슬롯 | 무엇 |
| --- | --- |
| 통화 녹음 | 사기범과의 통화 파일 |
| 문자·메신저 캡처 | 받은 문자, 카톡 대화 화면 |
| 이체 내역 | 은행 앱의 보낸 기록 캡처 |
| 은행·기관에서 받은 통지 | 지급정지 문자, 우편 통지 |

- **없어도 진행됩니다.** 「없어도 괜찮습니다 — 진술만으로 시작할 수 있습니다」를 같은 자리에 씁니다.
- **「신분증·주민등록증은 올리지 마세요」를 업로드 자리에 씁니다** — 받은 뒤 거르는 것보다
  안 받는 것이 낫습니다 ([ADR-026](../../decisions/026-raw-upload-retention.md)).

### 링크 발급 — 되돌릴 수 없는 갈림길

**발급 즉시 복사할 수 있어야** 하고, 잃으면 복구 경로가 없다는 것을 **그 자리에서** 알립니다 —
계정이 없어 되찾아 줄 방법이 없습니다 ([ADR-021](../../decisions/021-reentry-and-identity.md)).

| | |
| --- | --- |
| 주소 | **화면의 주인입니다.** 줄바꿈해서라도 **전부 보입니다** — 복사가 실패해도 손으로 옮길 수 있게 |
| 복사 | 버튼 하나. 눌린 것이 **눈에 보여야** 합니다 |
| 이메일 | **검증하지 않습니다.** 오타는 알림이 안 갈 뿐이고, 여기서 사용자를 막지 않습니다 |
| 경고 | 「이메일을 안 주시면 …」을 **입력칸 옆 같은 크기로**. 아래에 작게 붙이지 않습니다 |
| 거절 버튼 | **「이메일 없이 시작하기」** — 무엇을 포기하는지가 버튼 이름에 있습니다 |

## S-06 · 사건 · 챗 — `/c/{token}`

**진술을 받아 가장 적절한 매뉴얼을 고르는, 이 서비스의 핵심 동작입니다.**

| | |
| --- | --- |
| 규칙 | 질문은 **한 번에 하나 · 전부 버튼 · 「모름」 상시** (`F-05b`) |
| T0 | 안전 절차는 **셸의 왼쪽 레일**에 있습니다 — 이 화면이 그리지 않습니다 ([ADR-036](../../decisions/036-t0-rail.md)) |
| API | `POST …/messages` §3.9 · `GET …/slots` §3.4 · `GET …/plan` §3.6 |
| 금지 | **응답을 스트리밍하지 않습니다.** 근거 검증(`citation-checker`)이 끝난 뒤 한 번에 나갑니다 |
| 층 C | `chat-handler` · `poll-checker` · `pii-restorer` · `work-handler` |

**답변의 토큰은 브라우저에서 원문으로 복원됩니다** — `pii-restorer`가 합니다
([ADR-034](../../decisions/034-browser-shows-plaintext.md)). 화면이 보여주는 것은 전부 원문이고,
**토큰은 경계를 넘어갈 때의 형태**입니다.

### 두 열, 그리고 오른쪽 열이 바뀌는 것

```
┌───────────┬──────────────────────┬──────────────────┐
│ T0 (상시)  │ 챗 스트림              │  사건 파일        │  side: casefile
│           │ 컴포저                 │   → 워크스페이스   │  side: work
└───────────┴──────────────────────┴──────────────────┘
```

**오른쪽 열은 자리가 하나이고 내용이 바뀝니다.** 진술을 받는 동안에는
「사건 파일」이 채워지는 것이 보이고, 챗이 단계를 가리키면 **같은 자리**가
워크스페이스 패널로 바뀝니다 ([ADR-033](../../decisions/033-ws-panel-placement.md)).

### 좁은 폭 순서 — 지금 할 일이 먼저입니다

세 열이 위아래로 쌓입니다. 순서는 **오른쪽 열이 무엇이냐**로 갈립니다.

| `side` | 순서 | 왜 |
| --- | --- | --- |
| `work` | **워크스페이스 → 본문 → T0** | 할 일이 있으면 그게 먼저입니다 |
| `casefile` | **T0 → 본문 → 사건 파일** | 아직 진술을 받는 중이라 할 일이 없고, **그때가 T0가 가장 급한 때**입니다 |

**`side-in`(오른쪽 열이 옆에서 밀고 들어오는 것)은 넓은 폭 전용입니다.** 좁은 폭에서는
이 열이 옆이 아니라 위아래로 쌓이므로 들어올 자리가 없고, 도는 동안 308px이 화면 밖으로
나가 **가로 스크롤이 생깁니다**.

### 스트리밍을 안 하는 대신 무엇을 하는지 말합니다

검증이 끝나야 답이 나가므로 **기다리는 구간이 생깁니다.** 그 자리를 비워두지 않습니다.

- **점 3개·스켈레톤·타자기를 쓰지 않습니다.** 무엇을 하고 있는지 **문장으로** 씁니다
  ([컴포넌트 규칙](design-system/08-16-components.md) 「로딩」).
- 단계 목록은 **`poll-checker`가 내준 값 그대로**입니다. **화면이 추측하거나 세지 않습니다.**
- 답이 오면 **같은 자리에서 본문으로 바뀝니다** — 새로 등장하지 않습니다.

### 사건 파일 — 채워지는 것이 보입니다

진술에서 파악한 슬롯을 실시간으로 보여줍니다. **「AI가 뭘 하고 있는지 투명한 것」이
심사 차별점**이라, 이 자리를 숨기지 않습니다.

| 상태 | 어떻게 | 왜 |
| --- | --- | --- |
| 채워짐 | 값 그대로 | |
| PII | **파란 토큰** | 서버로 안 갔다는 뜻입니다. 흐리지 마세요 |
| 지금 묻는 중 | 앰버 배경 | **사용자 기한이 아니라 「여기 답하는 중」**입니다 |
| 아직 | 흐리게 + 「모름이어도 진행」 | 빈 칸이 실패로 보이면 안 됩니다 |

**「모름도 답입니다 — 빈 칸이어도 진행됩니다」를 이 카드 안에 씁니다.**

### 워크스페이스 — 유형별 패널 일곱

계약은 [워크스페이스 패널](08-17-workspace-panels.md)이고, **어느 패널을 여는지는
서버의 `body.action`**이 정합니다 ([ADR-024](../../decisions/024-step-action-and-url.md)).
`work-handler`가 판정과 렌더를 함께 맡습니다.

- **언급이 없으면 닫지 않습니다.** 「감사합니다」 같은 발화에서 패널이 사라지면
  **적고 있던 접수번호를 잃습니다.**
- **한 번에 하나**입니다. 챗이 여러 단계를 언급해도 `seq` 앞의 것 하나만.
- **완료는 부산물이 판정합니다** ([완수 검증](../backend/08-14-completion-hook.md)).

## S-07 · 사건 · 플랜 — `/c/{token}`

**며칠 뒤 링크를 열었을 때 「지금 뭘 해야 하나」가 첫 줄이어야 합니다.**
빈 챗창이 뜨면 관리 서비스가 아닙니다.

| | |
| --- | --- |
| 무엇 | 단계 · 기한 · 진행 타임라인 |
| API | `GET …/plan` §3.6 · `GET …/deadlines` §3.7 |
| 기한 | **서버가 계산한 값만 표시합니다. 화면은 날짜를 세지 않습니다** ([10-deadline-rules.md](../common/08-16-deadline-rules.md)) |
| 색 | 기한 임박은 **앰버**. **빨강을 쓰지 않습니다** — 패닉 상태를 더 밀어붙이지 않습니다 |

**할 일이 없는 국면에도 플랜은 비지 않습니다.** 채권소멸 공고 2개월 구간에도
**사용자 기한이 둘 살아 있습니다**(1만원 이하 통지 후 30일, 공고 후 2개월) →
[research/06](../../docs/research/06-경로별-실측조사.md). 그 자리의 일은 **통지 해독**입니다.

### 히어로 스트립 — 첫 줄이 답입니다

**맨 위는 「지금 하실 일은 하나」와 D-day 하나**입니다
(시안 「Board S-07 Options」 1c 골격 + 1b 히어로).

| | |
| --- | --- |
| 무엇 | 할 일 한 줄(21px) + D-day 박스(26px) + [지금 하기] · [서류 초안 열기] |
| 색 | 앰버 6% 배경 + 45% 테두리. **빨강 금지** |
| 보조 | 「넘기면 9월 3일까지 유예」 — **놓쳐도 끝이 아니라는 것**을 같은 자리에 |

### 단계 상태 어휘 — 여섯

**색 하나로 가르지 않습니다.** 기호·라벨·색 셋이 함께 갑니다.

| 상태 | 기호 | 태그 | 언제 |
| --- | --- | --- | --- |
| `done` | `✓` | 증빙됨 | 부산물(`◆`)이 완료를 판정한 뒤 |
| `now` | `→` | D-2 | 지금 할 차례. 이 행만 앰버 8% 배경 |
| `todo` | `○` | 미시작 | |
| `anytime` | `◇` | 언제든 | 기한이 없는 일 (명의도용 점검 등) |
| `na` | `—` | 해당 없음 | **지우지 않고 흐리게** 둡니다 — 왜 없는지가 정보입니다 |

### 공고 대기 카드 — 앰버를 쓰지 않습니다

기다리는 두 달은 **사용자 기한이 아니라 제도가 흐르는 시간**입니다.
카운트다운으로 만들면 매일 실망을 줍니다 — 그 자리의 일은 **통지 해독**이고,
「기다리는 동안 할 수 있는 것」을 함께 적습니다.

## S-08 · 증거함 — `/c/{token}`

**전사가 흐르고 PII가 파란 토큰으로 바뀌는 것이 눈에 보이는 자리입니다.**
「AI가 뭘 하고 있는지 투명한 것」 자체가 심사 차별점입니다.

| | |
| --- | --- |
| 상태 | `pending` · `processing` · `done` · `failed` |
| API | `POST …/evidence` §3.2 · `GET …/evidence/{id}` §3.3 |
| 의미 | **파란 토큰 = 「서버로 안 갔다」.** 이 대응을 화면에서 흐리지 마세요 |
| 금지 | 업로드를 관문으로 만드는 것. 증거가 없어도 T0는 그대로 돕니다 |

**주민등록번호가 든 파일은 올라가지 않습니다.** `pii-masker`가 가리지 못하면
**그 파일만 빼고 진행**합니다 — 막는 것이 아니라 갈림길입니다
([ADR-026](../../decisions/026-raw-upload-retention.md)). 그때도 **앰버이고 빨강이 아닙니다** —
사용자가 뭘 잘못한 게 아닙니다.

### 두 칸 — 자료 레일과 전사 (시안 1d)

```
┌──────────────┬───────────────────────────┬──────────────────┐
│ 자료 레일     │  전사 본문                 │  워크스페이스     │
│ (220px)      │   파일 헤더 · 발화 · 푸터   │   + 미니 챗       │
└──────────────┴───────────────────────────┴──────────────────┘
```

**오른쪽 350px 은 다른 본문과 같은 자리**입니다 — 그래서 흡수 모션의 착지점이
세 본문에서 모두 같습니다. 그게 1d 를 고른 이유입니다.

| 상태 | 점 | 한 줄 |
| --- | --- | --- |
| `pending` | 아웃라인 | 대기 중 |
| `processing` | 파랑 + 맥동 | 가리는 중 74% · **「원본은 아직 이 브라우저 안에 있습니다」** |
| `done` | 파랑 | 전사 완료 |
| `failed` | 앰버 | 제외 — 주민번호를 못 가렸습니다 + **[다른 파일 올리기]·[없이 진행]** |

**점은 색뿐이라, 아래 한 줄이 항상 말로 같은 것을 말합니다.**

### 전사 본문 — 화면은 원문입니다

**값은 원문이고, 화면이 다시 가리거나 풀지 않습니다**
([ADR-034](../../decisions/034-browser-shows-plaintext.md)).

- **사칭 정황 구간** — 화자 라벨에 앰버 표기 + 본문 왼쪽 2px 앰버 보더
- **미확인** — 대시 앰버 언더라인 + `미확인` 배지. **서류에 자동으로 들어가지 않습니다**

> 보여주게 되면서 **그 장치가 사라졌습니다.** 지금은 헤더에 「서버로는 이름 1 · 계좌 1 을

## S-09 · 단계 상세 · 부산물 — **폐기됨**

**이 화면과 `/c/{token}/step/{id}` 주소는 없습니다.** 워크스페이스 패널 일곱은
[S-06](#s-06--사건--챗--ctoken)의 오른쪽 열로 들어갔습니다
([ADR-033](../../decisions/033-ws-panel-placement.md)).

**번호는 재사용하지 않습니다.** 「완료가 판정되는 자리」라는 역할은 패널이 그대로 가져갑니다 —
체크만으로 완료되는 경로는 여전히 없습니다.

## S-10 · 서류 초안 — `/c/{token}/doc/{id}` (P1)

피해구제신청서·자율배상 신청 초안. **내려받을 때 PII가 브라우저에서만 복원됩니다.**

| | |
| --- | --- |
| 누가 | `doc-filler` — 값을 채우는 것은 브라우저입니다 |
| 금지 | **서버가 완성 문서를 내려주는 구조** ([04-pii-boundary.md](../common/08-14-pii-boundary.md) 규칙 6) |
| 기대치 | 자율배상은 **대상인지 진단해주는 것**까지입니다. 「받을 수 있다」고 쓰지 않습니다 |

## S-03 · 피싱 백신 — `/vaccine` (F-09, 부가)

평시 훈련 모드. 가족 등록·동의 상태, 훈련 결과와 취약 패턴, 가족 안전 리포트.

- 동의는 **미리** 받되 시점은 **예고 없이** (향후 2주 내 무작위)
- 목표는 "속이기"가 아니라 **대응 리허설** — 끊기 → 공식번호 확인 → 절차 말하기
- 훈련 종료 즉시 **"훈련이었습니다" 해제 고지** 필수
- 발신은 사전 동의된 **웹 링크 기반 — 실제 전화망 미사용**
- 훈련 데이터는 가족 계정에만 보관

## 화면 전반 원칙

- 사용자는 **패닉 상태**입니다. 한 화면에서 요구하는 판단을 최소화합니다.
- 질문은 **한 번에 하나, 전부 버튼**으로 (`F-05b`). **「모름」 선택지가 상시 존재**합니다.
- 미확정 정보는 숨기지 말고 **「미확인」 배지**로 드러냅니다.
- 파이프라인의 각 단계가 **눈에 보이게** 합니다 — 숨기지 않는 것이 신뢰 장치입니다.
- **기한을 화면에서 세지 않습니다.** 서버가 계산한 값을 그대로 표시합니다.

### 화면마다 「폰용」·「데스크톱용」을 정하지 않습니다

**반응형 하나입니다.** 제출물이 배포 주소라 심사위원이 임의 기기로 엽니다.
국면별 **좁은 폭 / 넓은 폭**은 「그 시점에 그 폭에서 열릴 가능성이 높다」는 뜻이지,
**그 폭에서만 동작한다는 뜻이 아닙니다.**
