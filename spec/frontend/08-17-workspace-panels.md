# 워크스페이스 패널 — 단계를 실제로 수행하는 자리

> **출처** — [API 계약](../common/08-14-api.md) §3.6 `steps[]` · §3.9 `referenced_steps` ·
> [완수 검증](../backend/08-14-completion-hook.md) ①③ · [경로별 실측조사](../../docs/research/06-경로별-실측조사.md).
> 화면 배치는 [화면 설계](08-14-screens.md), 재료는 [디자인 시스템](design-system/)입니다.

## 왜 이 계층이 필요한가

플랜은 단계 목록을 주지만, **단계마다 사용자가 하는 행동이 다릅니다.**

| | |
| --- | --- |
| 은행에 전화를 건다 | 스크립트를 보며 말하고, 끊기 전에 접수번호를 받아적어야 합니다 |
| 은행 앱에서 신청한다 | 우리 화면을 떠났다가 **무언가를 들고 돌아와야** 합니다 |
| 신청서 초안을 받는다 | 내려받는 순간 **가려진 개인정보가 브라우저에서 복원**됩니다 |
| 공고를 기다린다 | **할 일이 없습니다.** 할 일이 있는 것처럼 보이면 안 됩니다 |

**이걸 한 가지 모양으로 렌더하면 전부 「읽고 체크하는 목록」이 됩니다.** 그러면
[완수 검증](../backend/08-14-completion-hook.md)이 막으려던 **"체크는 됐는데 행위는 안 된 상태"**로 돌아갑니다.

## 유형 일곱

**`WS-*`는 화면 계약의 ID입니다.** 재사용·재정렬하지 않습니다.

| ID | 유형 | 사용자가 하는 일 | 실제 단계 예 |
| --- | --- | --- | --- |
| `WS-call` | **통화** | 전화를 걸어 말하고, 끊기 전에 값을 받아온다 | 은행 콜센터 지급정지 요청(24시간) · 1332 상담 |
| `WS-visit` | **외부 이동** | 다른 앱·사이트에서 처리하고 돌아온다 | 은행 앱 피해구제 신청 · 정부24 사건사고사실확인원 · 어카운트인포·엠세이퍼 |
| `WS-write` | **받아적기** | 짧은 값을 입력한다 | 112 사건접수번호 · 은행 접수번호 |
| `WS-upload` | **제출** | 파일을 올린다 | 접수 문자 캡처 · 접수증 · **받은 통지문** |
| `WS-download` | **서류 기재 안내** | 무엇을 어느 칸에 적는지 값과 함께 본다 | 피해구제신청서 기재 항목 (F-08) |
| `WS-wait` | **기다리기** | 없다 | 채권소멸 공고 2개월 · 환급금 결정 14일 |
| `WS-read` | **읽기** | 알고만 있으면 된다 | 사각지대 고지 · 자율배상 기대치 |

### 유형별로 다른 것

| | 완료 판정 | 나가는 곳 | 특이사항 |
| --- | --- | --- | --- |
| `WS-call` | 통화 뒤 `WS-write`로 이어짐 | 전화 | **타이머가 도는 동안 받아적기 칸이 이미 떠 있어야** 합니다 |
| `WS-visit` | 돌아와서 `WS-upload` | 외부 URL | **무엇을 들고 돌아와야 하는지**를 나가기 전에 보여줍니다 |
| `WS-write` | `L1` 포맷 검증 | — | 형식이 틀려도 막지 않습니다. 저장하고 표시만 |
| `WS-upload` | `L2` 증빙 | — | **`pii-tokenizer` 통과 필수** |
| `WS-download` | 다음 단계의 입력이 됨 | — | 값 복원은 **브라우저에서만**. **문서를 조판하지 않습니다** → [ADR-037](../../decisions/037-doc-guidance-not-generation.md) |
| `WS-wait` | 사용자가 하지 않음 | — | **카운트다운을 만들지 않습니다** |
| `WS-read` | 없음 | — | 완료 개념이 없습니다. 체크박스를 두지 마세요 |

## 누가 맡나 — `work-handler`

**판정도 렌더도 [`work-handler`](../common/08-16-module-names.md) 하나가 맡습니다**
(층 C · 브라우저) → [ADR-023](../../decisions/023-frontend-module-names.md).

> ⚠️ **모듈 안에서 판정을 렌더와 섞지 마세요.** 둘을 한 모듈로 합친 대가라,
> 경계가 이름이 아니라 **모듈 안의 규칙**으로만 남습니다. 섞이면 "왜 이 패널이 떴나"를 짚을 수 없습니다
> → [모듈 경계](../common/08-16-module-boundaries.md).

패널이 쓰는 재료는 **전부 이미 있는 모듈에서 옵니다** — `WS-write`·`WS-upload`의 완료 판정은
`completion-checker`, `WS-wait`의 기한은 `date-checker`, `WS-download`의 초안은 `doc-builder`가 만들고
`doc-filler`가 브라우저에서 채웁니다. **패널은 원자 모듈 위의 추상화이지 새 동작이 아닙니다.**

## 시그널 — 어느 패널을 여는가

**모델이 패널을 고르지 않습니다.** 모델은 이미 내고 있는 `referenced_steps`만 내고,
**`work-handler`가 규칙으로** 패널을 정합니다 → [ADR-013](../../decisions/013-chat-context.md) ·
[ADR-022](../../decisions/022-chat-turn-boundaries.md)가 정한 "모델은 도구를 부르지 않는다"를 그대로 지킵니다.

```
챗 응답의 referenced_steps
   ↓  아직 안 끝난 것만 남긴다 (done_verified · skipped 제외)
   ↓  그중 seq 가 가장 작은 것 하나
   ↓
그 step 의 유형으로 워크스페이스를 연다
```

| 조건 | 동작 |
| --- | --- |
| 남은 것이 있음 | 그 단계로 **패널을 바꾼다** |
| **남은 것이 없음** | **패널을 그대로 둔다.** 닫지 않습니다 |
| 사용자가 보드에서 단계를 직접 누름 | 같은 패널이 열립니다 — **두 경로가 한 곳으로 들어옵니다** |

> **왜 안 닫는가** — `referenced_steps`는 "감사합니다" 같은 발화에서 비어 있습니다.
> 그때 작업 패널이 사라지면 **사용자가 적고 있던 접수번호를 잃습니다.**
> 패널은 사용자가 닫거나 다른 단계로 바뀔 때만 바뀝니다.

**여러 단계를 언급해도 패널은 하나입니다.** "지급정지를 걸고 3영업일 안에 신청하세요"는
두 단계를 가리키지만, 지금 할 것은 앞의 하나입니다.

## 유형은 어디서 오는가 — 서버가 줍니다

> 2026-08-18 확정 → [ADR-024](../../decisions/024-step-action-and-url.md).
> **프론트가 추론하지 않습니다.** 이전 초안은 `actor`·`channel`·`required_artifact`를 조합해
> 파생하는 안이었고, 근거가 세 필드에 흩어져 절차가 늘면 어긋나는 문제가 있었습니다.

`GET /api/cases/{case_id}/plan`의 `steps[].body.action` 하나로 정해집니다
→ [API 계약](../common/08-14-api.md) §3.6 · [데이터 모델](../backend/08-16-data-model.md) §11.4.6.

| `body.action` | 패널 |
| --- | --- |
| `call` | `WS-call` |
| `visit` | `WS-visit` |
| `write` | `WS-write` |
| `upload` | `WS-upload` |
| `download` | `WS-download` |
| `wait` | `WS-wait` |
| `read` | `WS-read` |

**KB 항목마다 사람이 적고, 비면 릴리스가 거부됩니다** → [데이터 모델](../backend/08-16-data-model.md) §11.4.5.
「LLM은 절차를 창작하지 않는다」와 같은 자리입니다 — 유형도 절차의 일부라 모델이 정하지 않습니다.

### 나갈 곳은 두 갈래입니다

`WS-visit`이 사용자를 밖으로 내보낼 때, 주소가 **기관별인지 아닌지**로 갈립니다.

| | 어디서 | 예 |
| --- | --- | --- |
| **기관별** | `body.contact` — 서버가 `contact_ref`를 푼 값 | 국민은행 앱 신청 경로 |
| **기관 무관** | `body.url` · `body.url_label` | 정부24 확인원 · 어카운트인포 · 엠세이퍼 |

**둘 다 `null`일 수 있습니다.** 기관을 특정 못 했거나 번호·경로가 아직 확인 안 된 경우이고,
**그때도 절차는 나갑니다** — 「어느 은행인지」를 화면이 되물으면 됩니다
→ [데이터 모델](../backend/08-16-data-model.md) §11.4.3.

> ⬜ **아직 없는 것 — `WS-download`가 가리킬 초안.** `doc-builder`(F-08)가 P1이라 엔드포인트 계약 자체가
> 없습니다. `action: "download"`인 단계는 **KB에 아직 넣지 않습니다** → TODO(미정).

## 배치 — 본문이 챗일 때의 오른쪽 열

(T0 안전 절차는 이 그림 **왼쪽 바깥**, 셸의 고정 레일에 있습니다 →
[화면 설계](08-14-screens.md) 「셸은 세 열입니다」 · [ADR-036](../../decisions/036-t0-rail.md))

**패널은 챗과 같은 화면에 있습니다** ([ADR-033](../../decisions/033-ws-panel-placement.md)).
별도 주소(`/c/{token}/step/{id}`)는 없앴습니다.

```
/c/{token}
┌──────────────────────────────┬──────────────────┐
│ 챗 스트림                     │  사건 파일        │  side: casefile
│ 컴포저                        │   → 워크스페이스   │  side: work
│ 컴포저                        │                  │
└──────────────────────────────┴──────────────────┘
```

**오른쪽 열은 자리가 하나이고 내용만 바뀝니다.** 챗이 "이걸 하세요"라고 말하면
**바로 옆에서** 패널이 바뀝니다 — 시선이 화면을 건너지 않습니다.
다른 주소에 두면 「말한 곳」과 「하는 곳」이 갈라지고, **통화 중에 그 일이 일어납니다.**

**좁은 폭에서는** 위아래로 쌓이고 **워크스페이스가 맨 위**로 옵니다. 지금 할 일이 먼저입니다.

> **왜 같은 화면이어야 하는지는 아래 「시그널」이 이미 말하고 있습니다** —
> 「언급이 없으면 닫지 않는다」는 규칙은 챗과 패널이 함께 떠 있어야 성립합니다.
> 패널이 다른 주소에 있으면 챗이 그것을 닫을 일 자체가 없습니다.

## 지켜야 할 것

- **`WS-read`에 체크박스를 두지 마세요.** 완료 개념이 없는 유형입니다.
- **`WS-wait`에 진행률 막대를 D-day처럼 쓰지 마세요.** 환급은 카운트다운이 아니라 **진행 단계 설명**입니다
  → [기한 계산 규칙](../common/08-16-deadline-rules.md).
- **`WS-call`의 받아적기 칸은 통화 시작과 함께 뜹니다.** 끊고 나서 띄우면 늦습니다
  → [완수 검증](../backend/08-14-completion-hook.md) ③.
- **`WS-download`가 PII 전체 복원이 허용된 유일한 작업 패널입니다.** 다른 패널에서 원문을 펼치지 마세요
  → [PII 격리 경계](../common/08-14-pii-boundary.md).
- **어느 패널에서도 「나중에 하기」를 막지 마세요.** 미확인 상태로 남고 기한 추적이 계속됩니다.
- **패널이 열려 있다고 단계가 완료되는 것은 아닙니다.** 완료는 부산물이 판정합니다.
