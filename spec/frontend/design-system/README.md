# design-system — 화면이 지키는 디자인 계약

색·타이포·컴포넌트를 **무엇을 뜻하는가**로 정의합니다. 취향이 아니라 계약입니다 —
예를 들어 파란 토큰은 "안전하게 가려졌다"는 뜻이고, 그 색이 틀리면 제품이 틀립니다
(→ [PII 격리 경계](../../common/08-14-pii-boundary.md)).

## 값의 정본은 여기가 아닙니다

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| **토큰 값** (색상값·크기) | `src/app/globals.css` | 두 곳에 적으면 반드시 어긋납니다. 코드가 유일한 정본 |
| **의미·규칙** | 이 폴더 | "이 색은 무엇을 뜻하고, 언제 쓰는가" |
| **로고·아이콘 원본** | `assets/brand/` | 자산 원본 |
| 눈으로 보는 팔레트·컴포넌트 | `src/app/styleguide/` (미생성) | 문서보다 화면이 정확합니다 |

이 폴더의 문서에 **색상 코드(`#hex`·`oklch()`)를 적지 마세요.** 토큰 이름으로 부릅니다.

## 전제

- 기반은 **shadcn/ui**(`radix-nova` 스타일, `neutral` 베이스) + Tailwind v4입니다.
  바닥부터 만들지 않습니다 — 대회 일정에 맞지 않고, 접근성도 이미 검증된 것을 쓰는 편이 낫습니다.
- 우리가 정할 것은 **shadcn이 정해주지 않는 것**입니다: 위험도·기한·완료 상태를 무엇으로 보여줄지,
  PII 토큰을 어떻게 드러낼지, 고령 사용자에게 몇 pt까지 허용할지.
- 화면 구조는 [08-14-screens.md](../08-14-screens.md)가 정본입니다. 여기는 그 화면을 채우는 재료입니다.
