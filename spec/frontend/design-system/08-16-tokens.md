## 표면 사다리 — 어디에 놓인 것인가

깊이를 색으로 구분합니다. 테두리 대신 **표면 밝기와 inset 하이라이트**로 층을 만듭니다.

| 토큰 | 뜻 | 쓰이는 곳 |
| --- | --- | --- |
| `--color-ground` | 페이지 바닥 | 랜딩 배경 |
| `--color-stage` | 작업이 일어나는 무대 | 챗 콘솔 영역 |
| `--color-surface-low` | **stage 와 surface 사이.** 카드가 얹히는 낮은 면 | 랜딩 카드 그라데이션 끝, 화면 소개 카드 |
| `--color-surface` | 떠 있는 카드 | 사건 보드, 입력 카드 |
| `--color-panel-top` · `--color-panel-bottom` | **WS 액티브 패널 전용** 그라데이션 두 끝 | 통화·외부이동·받아적기·제출·받기 패널 |
| `--color-hairline` | 표면끼리 맞닿는 경계 | 카드 테두리, 셀 구분선 |
| `--color-chip` | 눌러지거나 상태를 나타내는 알약 | 배지, 선택 버튼, 입력 필드 |

### 저채도 표면은 색상(hue) 268로 모읍니다

`ground`를 뺀 표면 값은 전부 **hue 268**입니다. 계열이 갈리면 화면마다 다른 회색이 됩니다.

- **채도 0.004 대에서는 hue가 안 보입니다.** 285.9 → 268로 옮겼을 때 실제 변화는
  **R 채널 1단계**(255 중)였습니다. 그래서 랜딩·stage를 옮기는 비용이 없었습니다.
- **채도 0.02 대에서는 보입니다.** WS 액티브 패널이 그 자리라
  268(`#1c202a`, 파랑)과 285.9(`#1f1f2a`, R=G라 보라로 읽힘)가 눈에 갈립니다.
  **파랑 쪽을 골랐습니다** — 무채색 배경과 다른 축이라 「의도된 면」으로 읽힙니다.

**WS 액티브 패널이 수동 패널(`--surface` 평면)과 갈리는 것은 넷이 함께 합니다** —
그라데이션 · 밝기(0.245 > 0.231) · `--pii` 34% 테두리 · 채도. 넷 중 하나만 빼도 됩니다.

**칩은 배경색이 아니라 반투명 흰색 + inset 하이라이트입니다.**
어느 표면 위에 얹혀도 같은 재질로 보이게 하려는 것이라, 불투명 색으로 바꾸지 마세요.

> ⚠️ **대비의 최악 배경은 「칩 위」입니다.** 칩이 표면을 살짝 밝히기 때문에,
> 대비를 볼 때는 표면이 아니라 **칩을 얹은 표면**을 기준으로 봐야 합니다 →
> [접근성](08-16-accessibility.md)의 실측표.

## 텍스트 사다리 — 얼마나 중요한가

| 토큰 | 뜻 | 쓰이는 곳 | 최악 배경 대비 |
| --- | --- | --- | --- |
| `--color-ink-1` | 사용자가 반드시 읽어야 하는 것 | 헤드라인, 금액, 기한 숫자 | 15.11:1 · AAA |
| `--color-ink-2` | 본문 | 단계 설명, 칩 라벨 | 9.40:1 · AAA |
| `--color-ink-3` | 보조 설명 | 부연, 힌트 | 5.96:1 · AA |
| `--color-ink-4` | 가장 약한 것 | placeholder, 부연 중의 부연 | 4.67:1 · AA |
| `--color-icon` | 아이콘 선 | 입력창 아이콘 | 3.97:1 · **비텍스트 3:1** |

**`--color-ink-4`의 값을 올렸습니다.** 초안 값은 최악 배경에서 2.03:1이라 기준 미달이었습니다.
고령 사용자가 주 대상인데 "못 읽어도 치명적이지 않은 자리"를 남겨 두는 것은 앞뒤가 안 맞습니다.

**비활성 상태는 색으로 표현하지 않습니다.** 흐린 색으로 비활성을 나타내던 자리는
**불투명도와 `aria-disabled`** 로 바꿉니다 — 토큰을 하나 더 파면 뜻을 외울 것이 늘어납니다.

**`--color-icon`은 아이콘 전용입니다.** 비텍스트 3:1 기준으로 통과합니다.

> ⚠️ **글자에 쓰지 마세요.** 실측하면 카드 위 **4.43:1**, 워크스페이스 패널 위 **4.27:1**로
> 본문 기준 4.5:1에 **미달**합니다. 12.5px 캡션에 쓰면 눈에 띄게 안 읽힙니다 —
> 실제로 S-06~S-08 구현에서 **텍스트 45곳**에 쓰였다가 되돌렸습니다.
> 캡션·설명문은 `--color-ink-3`, 눈썹 라벨·메타는 `--color-ink-4`를 쓰세요.

| 배경 | `icon` | `ink-4` | `ink-3` |
| --- | --- | --- | --- |
| `--surface` | 4.43 ✗ | 5.21 | 6.64 |
| `--panel-top` | 4.27 ✗ | 5.02 | 6.41 |
| `--pii-bg` | 4.43 ✗ | 5.22 | 6.66 |

> **그리고 아이콘 세트는 `--color-icon` 을 쓰지 않습니다.** 34종은 전부 `currentColor` 라
> **감싸는 글자의 색을 따라옵니다** (→ [components](08-16-components.md) 「공통 재질 — 아이콘」).
> `--color-icon` 이 남아 있는 자리는 **입력창 안의 장식 글리프**처럼 곁에 글자가 없는 곳뿐입니다.
> 아이콘에 색을 직접 주지 마세요 — 글자 토큰을 고르면 아이콘이 따라옵니다.
**아이콘에 정보를 실으면 라벨을 함께 답니다** — 색과 모양만으로 뜻을 전달하지 않습니다.

## 상태 색 — 무엇을 뜻하는가

| 토큰 | 뜻 | 쓰이는 곳 | 최악 배경 대비 |
| --- | --- | --- | --- |
| `--color-pii` | **가려진 개인정보.** 이 색이 보이면 "서버로 안 갔다"는 뜻 | 전사 뷰 토큰, 토큰화 배지 | 5.54:1 · AA |
| `--color-pii-bg` | 위의 배경 | 토큰 칩 | — |
| `--color-deadline-urgent` | **법정 기한 임박.** 놓치면 권리가 사라지는 것 | D-day, 3영업일 경고 | 7.16:1 · **AAA** |
| `--color-horizon` | 브랜드 분위기(장식) **+ 「제도가 흐르는 시간」** — 사용자 기한이 아니고, 할 일이 없고, 날짜를 세지 않는 자리 | 랜딩 히어로 글로우, 랜딩·`/start`·사건 화면 바닥의 호라이즌(`HorizonGlow`), 공고 대기 카드의 달력 앵커 | 8.18:1 |

### `--color-horizon` 에 뜻을 실어도 되는 자리 — 셋을 다 만족할 때만

2026-08-23 에 뜻을 넓혔습니다 → [ADR-048](../../../decisions/048-horizon-carries-meaning.md).
**앰버를 피하려고 고른 색**입니다 — 두 달짜리 제도 절차를 `--color-deadline-urgent` 로
칠하면 매일 급한 일로 보입니다.

1. **사용자가 지켜야 할 기한이 아닐 것** — 놓칠 수 있는 것이 아니라 기다리는 것
2. **사용자가 할 일이 없을 것** — 기관이 진행합니다
3. **날짜를 세지 않을 것** — D-n 도 퍼센트도 붙이지 않습니다

지금 해당하는 것은 **채권소멸공고 대기** 하나입니다.

**조건 둘이 따라붙습니다.**

- **그래픽(막대·점·글로우)은 전부 `aria-hidden`.** 뜻은 곁의 글자가 싣습니다.
- **글자에 쓸 때는 그 글자가 스스로 뜻을 말할 것.** 「지금」은 색이 없어도 「지금」입니다 —
  색은 위치를 찾게 하는 것이지 뜻을 만드는 것이 아닙니다.

> **셋 중 하나라도 어긋나면 다른 색입니다.** 특히 「사용자가 할 일이 없다」가 자주 틀립니다 —
> 기다리는 것처럼 보여도 중간에 제출·확인이 끼면 그건 사용자 기한이고, **앰버**입니다.

**`--color-deadline-urgent`의 값도 미세하게 올렸습니다.** 초안 값은 칩 위에서 6.93:1이라
AAA(7:1)에 아슬아슬하게 못 미쳤는데, **기한 숫자가 정확히 칩 위에 얹히는 자리**입니다.

**빨강을 쓰지 않습니다.** 기한 임박은 앰버(`--color-deadline-urgent`)입니다.
사용자는 방금 사기를 당해 이미 각성 상태이고, 빨간 경보를 더하면 판단을 돕는 게 아니라 굳게 만듭니다.
빨강은 `--destructive`(파괴적 동작 확인)에만 남겨 둡니다.

### 위험도 전용 색을 만들지 않습니다

**`--color-risk-high/mid/low`를 신설하지 않기로 했습니다.** 이유가 셋입니다.

1. **위험도는 절차를 가르지 않습니다.** 분기축은 경유 서비스 하나이고,
   `case-reader`의 판정은 화면 표시와 관리자 조회에서만 소비됩니다 → [12-module-names](../../common/08-16-module-names.md).
2. **색이 하나 늘 때마다 외울 것이 늡니다.** 완료·미확인에 전용 색을 만들지 않은 것과 같은 이유입니다.
3. **색만으로 구분하지 않는다는 원칙**([접근성](08-16-accessibility.md))에 어차피 라벨이 필요합니다.

**위험도는 텍스트 라벨 + 아이콘으로 표시하고**, 강조가 필요하면 텍스트 사다리를 씁니다.

[S-09](../08-14-screens.md)의 단계 상태 다섯입니다. **전용 색을 만들지 않습니다.**

## 타이포

### 크기 사다리 — 고령 사용자 기준

| 토큰 | 크기 | 행간 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `text-xs` | 13px | 1.6 | 라벨·캡션. **읽지 않아도 되는 것만** |
| `text-sm` | 15px | 1.7 | 보조 설명 |
| **`text-base`** | **17px** | **1.75** | **본문 — 최소 크기** |
| `text-lg` | 20px | 1.6 | 강조 문장·단계 제목·**기한 숫자** |
| `text-xl` | 24px | 1.45 | 화면 제목 |
| `text-2xl` | 30px | 1.35 | 절 제목 |
| `text-3xl` | 40px | 1.25 | 랜딩 히어로 |

- **12.5px 미만을 쓰지 않습니다** (→ [ADR-032](../../../decisions/032-text-floor.md)).
  Tailwind 기본 `text-xs`(12px)를 그대로 쓰면 이 선을 넘습니다.
  **이 숫자는 WCAG 요건이 아니라 우리가 정한 선입니다** — WCAG에는 최소 글꼴 크기 규정이 없습니다.
- **사다리와 하한은 다른 것입니다.** 위 표는 **권장 단**이고 12.5px는 **넘지 말 선**입니다.
  사다리의 최소 단은 13px 그대로이고, 12.5px는 사다리에 없으므로 필요한 자리에만 직접 적습니다.
- **본문은 17px입니다.** 기본값 16px보다 한 단 올렸습니다 — 고령 사용자가 주 대상입니다.
- **행간이 라틴 기준보다 넉넉합니다.** 한글은 글자가 네모라 같은 행간에서 더 빽빽해 보입니다.
- **기한 숫자는 `text-lg` 이상**입니다. 오독이 곧 권리 상실인 자리라 본문 크기로 두지 않습니다.

| 결정 | 내용 |
| --- | --- |
| 한국어 줄바꿈 | **`word-break: keep-all` 필수.** 없으면 "동/행합니다"처럼 어절이 쪼개집니다 |
| 넘침 처리 | `overflow-wrap: break-word`를 함께 걸어 긴 URL·계좌번호가 레이아웃을 밀지 않게 |

| 문서 언어 | **`<html lang="ko">`.** 낭독기의 발음과 줄바꿈 규칙이 여기서 갈립니다 |
| 광학 중앙 | 가운데 정렬한 줄이 **마침표로 끝나면 왼쪽으로 밀려 보입니다** — 아래를 보세요 |

#### 가운데 정렬 + 마침표 — 광학 보정

정렬은 **글자폭(advance width)** 기준인데, 마침표는 폭을 차지하면서 잉크는 점 하나입니다.
그 빈 폭이 오른쪽에 남아 **글자 뭉치가 왼쪽으로 밀려 보입니다.** 물음표·느낌표로 끝나는 줄은
폭을 거의 채우므로 이 현상이 없습니다.

**보정은 `position: relative` + `left` 로 합니다.**

```jsx
<span className="relative left-[0.21em]">그다음부터 저희가 맡습니다.</span>
```

- ⚠️ **음수 `margin` 으로 하지 마세요.** 부모가 `flex` + `items-center` 면 자식이
  **내용 폭에 맞춰 줄어드는데**, 음수 margin 이 그 폭 계산에 섞여 상자가 글자보다 좁아지고
  **없던 줄바꿈이 생깁니다.** `relative` 오프셋은 레이아웃 폭을 건드리지 않습니다.
- **마침표를 지우거나 `aria-hidden` 으로 감추지 마세요.** 낭독기 억양에 쓰이는 내용입니다.
- 보정값은 `em` 으로 씁니다 — 제목이 `clamp()` 으로 커지고 작아져도 비율이 유지됩니다.

| 토큰 | 값 | 뜻 |

| `--container-shell` | 1408px | **앱 셸의 바깥 폭** — 헤더와 본문이 같이 씁니다 |
| `--container-narrow` | 720px | **좁은 폭** 상한 |
| `--container-wide` | 1120px | **넓은 폭** 상한 |
| `--container-prose` | 54ch | 본문 측정 폭 |
| `--container-title` | 26ch | 제목 측정 폭 |

- **브레이크포인트는 `md`(768px) 하나만 씁니다.** 늘리면 그만큼 확인할 조합이 늘어납니다.
- **셸이 「넓은 폭」보다 큽니다.** 목업은 1180px 창 안에 그려졌지만 실제 브라우저는 더 넓어,
  목업 값을 그대로 쓰면 **콘텐츠가 화면 가운데 작게 뭉칩니다.** 좌우 여백은 고정값이 아니라
  `clamp(20px, 4.2vw, 72px)`처럼 화면에 비례시킵니다.
- **`ch`는 라틴 기준이라 한글에서 좁게 잡힙니다.** 54ch가 한글로는 대략 30자 안팎입니다.
- **화면마다 「폰용」·「데스크톱용」을 정하지 않습니다** → [screens](../08-14-screens.md).

| `--size-touch` | 44px | 터치·클릭 목표 최소 크기 |

권장치를 맞추려는 것입니다.

### 장식 keyframes — 뜻을 싣지 않습니다

`globals.css`의 `@layer base` 안에 있습니다. **전부 장식이라 `aria-hidden`이 붙은 요소에만**
쓰고, 상태·진행·경고를 이걸로 표현하지 않습니다.

| 이름 | 무엇 | 어디서 |
| --- | --- | --- |
| `spin-slow` | 시계 방향 회전 | 랜딩 히어로 오비트 링 — 파랑 스윕 9초 · 점선 링 46초 |
| `spin-rev` | 반시계 회전 | 같은 링의 앰버 스윕 14초 |
| `pulse-dot` | 점 맥동 (불투명도 1 ↔ 0.35) | 헤더 PII 배지의 점 2.6초 |
| `breathe` | 글로우 호흡 (0.5 ↔ 0.85) | 랜딩 히어로 글로우 6초 · `/start` 발급 단계 글로우 6초 |
| `bloom-in` | 피어남 (불투명도 0 → 1 · 0.94 → 1 배) | 랜딩 히어로 링·글로우 묶음의 **첫 렌더** 1.2초 — 글자의 `rise`(0.5초)보다 길어 글이 다 올라온 뒤에도 잠깐 더 밝아집니다 |
| `appear` | 밝기만 (불투명도 0 → `--appear-to`, 기본 1) | `HorizonGlow` 첫 렌더 1.4초. 사건 화면은 끝값 0.7 — 오래 머무는 화면이라 |
| `row-flash` | 행이 채워질 때 한 번 훑고 사라짐 (`--pii` 12% → 투명) | S-06 「사건 파일」의 새·변경 행 1.2초 |
| `icon-spin` | 시계 방향 회전 | 아이콘 `working` 「진행 중」 1.4초 |

- **`icon-spin` 은 `spin-slow` 와 몸통이 같습니다. 합치지 마세요.**
  `spin-slow` 는 랜딩 오비트 링(장식·9~46초)이고 `icon-spin` 은 **「진행 중」 표시(1.4초)**입니다.
  한쪽 속도를 만지다 다른 쪽이 딸려가면 히어로가 팽이가 되거나 스피너가 멈춘 것처럼 보입니다.
  **`pulse-dot` 이 duration 만 바꿔 쓰는 것과 다른 판단인 이유**는 그쪽은 둘 다 「점 맥동」이라
  뜻이 같고, 이쪽은 **장식과 상태 표시**로 뜻이 다르기 때문입니다.
- **`pulse-dot` 은 속도가 둘입니다** — 배지는 2.6초, **챗 안은 1.6초**.
  keyframes 는 하나를 쓰고 `animation-duration` 만 바꿉니다. **세 번째 값을 만들지 마세요.**
- **`row-flash` 는 행 단위로만 씁니다.** 표를 다시 정렬하거나 스크롤을 튀게 하지 않습니다 —
  값이 채워지는 것을 보여주려다 읽던 자리를 잃게 만들면 안 됩니다.
- **`border-beam` 은 컴포저 전용입니다.** 작업 패널에 두르지 마세요.
- **`@layer base` 밖에 두지 마세요.** 같은 레이어 안에 있어야 위의 감속 모드 블록이 함께 끕니다.
  컴포넌트 파일이나 인라인 `<style>`에 애니메이션을 만들지 않습니다
  (→ [RFC-003](../../../rfc/003-design-handoff.md)).
- **회전은 전정 장애가 있는 사용자에게 증상을 유발합니다.** 감속 모드에서 멈추는 것이
  이 넷의 사용 조건입니다.

### 전환 — 화면 상태의 두 축이 움직일 때

값의 출처는 핸드오프 「Phase Transition Motion」 **v2**
(`assets/artifacts/handoff/08-19-s08-evidence/`)이고, 축의 뜻은
[ADR-035](../../../decisions/035-screen-state-axes.md)입니다.
**이 셋은 장식이 아닙니다** — 「같은 것이 자리를 옮겼다」를 말합니다.

| 토큰 | 값 | 무엇 |
| --- | --- | --- |
| `--motion-ease` | `cubic-bezier(0.65, 0, 0.35, 1)` | **전환의 유일한 이징.** 다른 곡선을 새로 만들지 마세요 |
| `--motion-panel-in` | `0.9s` | 오른쪽 열이 밖에서 들어오는 시간 |
| `--motion-absorb` | `1500ms` | 챗이 우하단 슬롯으로 빨려드는 총 길이 |

| 이름 | 무엇 | 어디서 |
| --- | --- | --- |
| `view-in` | 본문 등장 (불투명도 0→1 + `translateY` 22→0) | `focus` 가 바뀔 때, 0.8초 · 0.5초 지연 |
| `view-out` | 본문 퇴장 (역방향) | 같은 전환의 **나가는 쪽**, 0.7초 · 0.3초 지연 |
| `side-in` | 오른쪽 열이 밖에서 (`translateX` 308→0) | `side` 가 바뀔 때, 0.9초 · 0.15초 지연. **`md` 이상 전용** |
| `mini-take` | 미니 챗이 유령 챗을 이어받음 (68% 까지 투명) | 흡수 중, `absorb.ts` 의 `CROSSFADE.in` 과 같은 값 |

- **들어오는 것과 나가는 것이 겹칩니다.** 퇴장(0.3s)이 등장(0.5s)보다 먼저 시작해
  **빈 화면이 생기지 않습니다.** 지연 값을 줄여 순차로 만들지 마세요 — 그 순간 한 박자 깜빡입니다.
- **나가는 본문은 `fixed` 유령으로 띄웁니다** (`page.tsx`). 레이아웃을 밀지 않고
  `pointer-events: none` 이라 클릭을 막지도 않습니다.
- ⚠️ **유령의 크기는 「바뀌기 직전」 본문에서 잽니다.** 바뀐 뒤 것으로 재면 플랜이 챗보다
  길어서 유령이 화면 아래로 늘어나고, **맨 아래 컴포저가 잘려 나갑니다** —
  챗이 떨어져 나가는 동안 입력창이 사라져 보입니다.
- **`side-in` 은 좁은 폭에서 돌면 안 됩니다.** 그 폭에서는 열이 위아래로 쌓여
  옆에서 들어올 자리가 없고, 308px 이 화면 밖으로 나가 가로 스크롤이 생깁니다.

#### 흡수는 CSS 에 없습니다 — `absorb.ts`

챗이 우하단 슬롯으로 빨려드는 전환은 **끝점이 레이아웃에서 나오므로** CSS 로 못 적습니다.
시안은 1280×720 고정 캔버스라 픽셀이 박혀 있지만 우리는 반응형입니다.
`src/app/c/[token]/absorb.ts` 가 **같은 곡선을 30점으로 표본을 떠서** keyframes 를 만들고
Web Animations API 로 돌립니다.

| 상수 | 값 | 무엇 |
| --- | --- | --- |
| 가로 핀치 | `0.16` | 중간에서 가로로 눌립니다 |
| 세로 늘어짐 | `0.09` | 동시에 세로로 늘어납니다 |
| `skewY` · `rotate` | `3.2°` · `−2.2°` | 진행 방향으로 기울어짐 |
| `rotateX` · `rotateY` | `7°` · `−15°` | 판이 기울며 앞 모서리가 먼저 딸려 들어감 |
| `perspective` | `1400px` | 위 기울기가 원근으로 보이게 |
| 둥글기 | `+26px` | 중간에서만 더해집니다 |

- **변형은 `d = sin(진행률·π)` 를 탑니다** — 중간에서 최대, **양 끝점은 0**.
  그래서 시작과 끝은 정형이고, 중간에서만 휩니다.
- **축이 따로 움직입니다.** 흡수는 x → y → 스케일 순, **복귀는 역재생이 아니라**
  y 먼저(위로 떠오른 뒤) → x 나중(왼쪽으로 펼쳐짐)입니다.
#### 옮기면서 밟은 함정 넷 — 다시 밟지 마세요

| 무엇 | 증상 | 어떻게 |
| --- | --- | --- |
| **WAAPI 는 `oklch()` 색을 보간하지 못합니다** | 유령이 투명한 채로 아래 화면 위에 겹쳐 글자가 뒤엉킵니다 | 카드 겉모습(배경·테두리·그림자)은 **CSS `ghost-card`** 가 합니다. `absorb.ts` 는 위치·크기·둥글기만 |
| **`transform-origin` 이 양쪽 다 `top left` 여야 합니다** | 복귀할 때 챗이 **화면 어디에도 안 보입니다** | 좌표를 왼쪽 위 기준으로 계산하므로, 유령과 본문 **둘 다** 지정 |
| **변형된 요소가 문서를 넓힙니다** | 전환 중 **레이아웃이 통째로 오른쪽으로 밀립니다** | 유령을 `fixed inset-0 overflow-hidden` 겹 안에 가둡니다 |
| **감속 모드는 CSS 만 멈춥니다** | WAAPI 가 그대로 돕니다 | `prefersReducedMotion()` 없이 `element.animate()` 를 쓰지 마세요 |

- **헤드리스 크롬으로 확인할 때는 `prefers-reduced-motion` 을 꺼야 합니다.**
  기본값이 `reduce` 라, 그냥 찍으면 **모션이 전부 꺼진 화면**만 나옵니다.

## 다크 전용입니다

**2026-08-18 확정 — 라이트 모드를 만들지 않습니다.**
랜딩은 기존 테마(다크 + 오렌지 호라이즌 글로우)를 그대로 유지하고, 나머지 화면도 다크입니다.

**고령 사용자에게는 밝은 배경이 읽기 쉽다는 근거가 있습니다** — 백내장·난시가 있는 눈에서는
검정 바탕의 흰 글자가 번져 보입니다(halation). **이 결정은 그 사실을 부정하지 않습니다.**
대신 **글자 크기·대비·행간으로 보완**했고, 그것이 완전한 대체가 아니라는 것을 여기 적어 둡니다.
