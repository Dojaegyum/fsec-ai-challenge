## 핵심 개념

| 용어 | 뜻 | 코드 식별자 |
| --- | --- | --- |
| **사건 (Case)** | 업로드된 증거·분석 결과·플랜·체크리스트·서류·기한을 묶는 최상위 단위. 이 서비스의 모든 상태는 사건에 매달립니다 | `Case` |
| **증거 (Evidence)** | 사건에 첨부된 녹음·이미지·텍스트. 다중 파일이 하나의 사건이 됩니다 | `Evidence` |
| **슬롯 (Slot)** | 플랜 생성에 필요한 정보 조각(송금 여부·수단·기관·금액·시각 등). T0/T1/T2로 티어링 → [02](../backend/08-14-slot-tiering.md) | `Slot` |
| **경유 서비스 (Channel)** | 돈이 지나간 금융 서비스 유형(은행·간편송금·가상자산 등 8종). **절차 분기의 핵심 축** → [03](../backend/08-14-channel-matrix.md) | `Channel` |
| **플랜 (Plan)** | 사건 상황에 맞춰 생성된 단계별 대응 절차. KB 근거 인용을 동반합니다 | `Plan` |
| **부산물 (Artifact)** | 절차를 실제로 수행하면 남는 것(사건접수번호·접수 문자·접수증). 완료 판정의 근거 → [05](../backend/08-14-completion-hook.md) | `Artifact` |
| **토큰 (PII Token)** | 개인정보를 치환한 표식. `[계좌-1]`, `[이름-1]` 형식 → [04](08-14-pii-boundary.md) | `PiiToken` |
| **매뉴얼 KB** | 경유 서비스별 절차 지식베이스. 출처·시행일 메타를 갖는 버전드 데이터 → [07](../backend/08-14-kb-operations.md) | `ManualKB` |

## 전제 (기획서 §0)

- **입력 가정** — 피해자 또는 돕는 가족이 녹음(m4a/mp3), 스크린샷(문자·카톡·이체내역), 텍스트 붙여넣기 중 **하나 이상**을 제공할 수 있다.
- **당사자 본인 녹음은 합법** (통신비밀보호법상 당사자 녹음).
- **데스크톱 웹 우선** — 파일 다중 업로드·서류 작성·기한 관리라는 사무 작업형 UX가 중심이고, 가족이 함께 대응하는 경우가 많으며, 심사 데모 환경(노트북·빔프로젝터)에 맞습니다. 모바일 반응형은 P1.
- **사용자는 패닉 상태**라고 가정합니다. 정보를 못 주는 것이 정상입니다.

## 파이프라인 (기획서 §1)

```
업로드 → 텍스트화 → PII 스크러버 → LLM 분석 → 매뉴얼 분기 → 실행 보드
CLIENT   SERVER     SERVER(격리경계)  LLM API    LLM + KB      CLIENT
```

각 단계가 UI에서 **보이는 것**이 설계 의도입니다(전사가 흐르고, PII가 토큰으로 바뀌고, 경유 서비스 감지가 배지로 뜸).

## 기술 스택 (기획서 §9)

| 영역 | 선택 |
| --- | --- |
| 프론트 | Next.js (App Router, 3-패널 SPA) |
| LLM | Claude API — 분석·플랜 생성·챗, tool use |
| STT | Whisper급 + 브라우저 Web Speech 폴백 |
| OCR | Vision 입력 |
| KB | 구조화 JSON + RAG |
| PII | 클라이언트 정규식 + 서버 NER |
| 문서 | docx 생성 |
| 배포 | Vercel (배포 URL 요건) |
| 백신 모드 음성 | TTS + WebRTC 웹 통화 (**전화망 미사용**) |
