## 계산의 전제

| 항목 | 규칙 |
| --- | --- |
| 타임존 | **`Asia/Seoul` 고정.** 서버·클라이언트 어디서 계산해도 같은 날짜가 나와야 합니다 |
| 단위 | **날짜 단위**로 셉니다. 시각으로 세지 않습니다 (법정 기한이 날짜 기준). KB 의 `deadline.kind` 는 셋 — `business_days` · `calendar_days` · `months`(역법, 아래 「개월」) |
| 기준 시계 | **서버 시계.** 클라이언트 시계를 신뢰하지 않습니다 — 사용자 기기의 날짜가 틀리면 기한을 놓칩니다 |
| 계산 주체 | **코드.** LLM 응답에서 날짜를 파싱해 쓰지 않습니다 |

## 기산점은 부산물입니다

기한은 "사용자가 했다고 말한 시점"이 아니라 **절차가 실제로 남긴 부산물의 시점**부터 셉니다.
이래야 [완수 검증](../backend/08-14-completion-hook.md)과 기한 추적이 같은 사실 위에 섭니다.

> 2026-09-04 개정. 아래 표가 「지급정지 완료」를 3영업일의 기산 이벤트로 적고 있었는데
> **시행령 제3조 ②는 「피해구제를 신청한 날부터」입니다** → [data-model §8.0](../backend/08-16-data-model.md) ·
> [research/05 §10](../../docs/research/05-미확인-목록.md) 「함께 바로잡은 것」. 공고 2개월의 기산일도 「접수」가 아니라
> **통지문에 적힌 공고일**입니다 → [ADR-054](../../decisions/054-notice-anchor.md). 표를 코드가 실제로 쓰는 슬롯으로 다시 적었습니다.

## 영업일

**영업일 = 금융회사가 영업하는 날.** 기한을 내는 곳이 금융회사이므로 **은행 기준**입니다.

```
영업일에서 빼는 날 = 주말 + 공휴일 + 근로자의 날(5/1)
```

### 공휴일의 정본 — 한국천문연구원 특일 정보 API

```
공공데이터포털 15012690 · 파라미터 solYear · solMonth
```

**임시공휴일이 반영됩니다.** 그래서 **하드코딩한 공휴일 배열을 코드에 굽지 마세요** —
매년 바뀌고 임시공휴일은 갑자기 생깁니다.

> 2026-09-04 현황. **규칙은 그대로인데 구현은 아직 표입니다** — `src/lib/holidays-table.ts`(관공서 공휴일 2024~2035 ·

> (`config-report.ts` 「공휴일 · 임시공휴일」)이 드러냅니다. 범위 밖 연도는 「아니다」가 아니라 **던집니다.**
> ⬜ API 어댑터는 구현 전(인증키·캐싱 미정) — 붙으면 표는 예비로 내려갑니다. 그 전까지 임시공휴일이 지정되면
> 표를 손으로 갱신해야 하고, 안 하면 영업일을 하나 더 세어 기한이 하루 앞당겨집니다.

### 초일은 세지 않습니다 — 민법 제157조

> 기간을 일, 주, 월 또는 연으로 정한 때에는 **기간의 초일은 산입하지 아니한다.**

**통신사기피해환급법에 다른 규정이 없으면 이 원칙이 적용됩니다.**
민법 제161조(말일이 토요일·공휴일이면 익일 만료)는 **「영업일」로 정한 기간에는 겹치지 않습니다** —
영업일은 애초에 공휴일을 세지 않기 때문입니다.

> ⬜ TODO(근거 필요): **특별법에 별도 기간 규정이 있는지.** 조문 전문을 대조하기 전까지 **추론**입니다.
> 하루 차이가 곧 효력 상실이므로, **D-day를 단정적으로 표시하기 전에 이것부터 확인하세요.**

### 개월은 역법으로 셉니다 — 민법 제160조

> 2026-08-26 추가 (#33 · [ADR-054](../../decisions/054-notice-anchor.md)). 채권소멸공고와 통장묶기 이의제기 창이 「개월」로
> 정해져 있어 `months` 단위가 생겼습니다. 2026-09-04 기준 이 단위를 쓰는 KB 항목은 둘 — 위 기산 표.

**일수로 바꾸지 않습니다.** 초일을 세지 않고(제157조), 최후의 월에서 기산일에 해당한 날의 **전일**에 만료하며(제160조 ②),
해당일이 없으면 **그 달 말일**입니다(제160조 ③). 구현과 예시는 `src/modules/date-checker/compute.ts` 의 `addMonths` 주석.

**말일 이월(제161조)은 달력일·개월 기간에만 겁니다.** 영업일 기간에는 걸지 않습니다 — 위에서 말한 대로 영업일은 말일이
휴일일 수 없고, 또 밀면 하루가 늘어납니다. 이월에서 보는 「공휴일」은 관공서 공휴일이라 **근로자의 날은 빼지 않습니다**
(영업일 계산과 기준이 다릅니다) → `src/modules/date-checker/README.md` 「판단이 필요했던 자리」.

## 기한의 주인이 종류를 정합니다

KB 의 `deadline.owner` 가 `deadline.kind` 를 정합니다 — `user` 면 사용자가 지켜야 하는 `primary`(+`grace`),
`bank`·`agency` 면 안내용 `info` 입니다. 정본은 [data-model §11.4.2](../backend/08-16-data-model.md#1142-기한의-주인을-명시합니다) ·
[§8.3](../backend/08-16-data-model.md#83-info-종류); 적재기가 셋 밖이면 거부하고(`kb-load.ts`), `compute-deadlines.ts` 의 `KIND_OF_OWNER` 가 옮깁니다.
**`info` 에만 `rule_snapshot.starts_at`(그날 시작)을 붙입니다** — 공고 대기 카드가 「시작 · 지금 · 만료」 달력 앵커를 그리는 왼쪽 끝이고
([ADR-048](../../decisions/048-horizon-carries-meaning.md) · [API §3.7](08-14-api.md) `starts_at`·`elapsed` 2026-08-23 확정), 사용자 기한은 D-day 로 충분해 안 답니다.
