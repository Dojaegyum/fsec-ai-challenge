# 모듈 경계 — 누가 무엇을 책임지는가

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §1 「전체 백엔드 아키텍처(개략)」 ·
> §3 격리 경계. 다이어그램의 노드를 **책임·입출력·금지**의 언어로 옮겼습니다.

**이 문서가 정하는 것** — 각 모듈이 무엇을 책임지고, 무엇을 받아 무엇을 내놓고, **무엇을 하면 안 되는가**.
경계를 어기면 [PII 격리 경계](08-14-pii-boundary.md)나
[LLM은 절차를 창작하지 않는다](../backend/08-14-kb-operations.md)가 무너집니다.

**이 문서가 정하지 않는 것** — 프로세스 분리 여부, 배포 단위, 통신 방식(HTTP·큐·함수 호출).
모듈은 **책임의 단위**이지 서버의 개수가 아닙니다. 물리 배치는 백엔드 스펙에서 정합니다.

## 세 구역

```
[클라이언트]              [서버]                        [외부]
원문 보유          ── 격리 경계 ──          토큰화 텍스트만 도달
1차 마스킹  ────────►  2차 스크러버  ──────────►  LLM API
복원 매핑 보관            토큰화 텍스트만 보유         KB (버전드)
표시 시 복원              감사 로그(토큰화 기준)
```

**서버·LLM 어디에도 "누구의 어떤 계좌"인지 완성된 정보가 존재하지 않는 구조**가 목표입니다.

## 모듈

### 클라이언트 (브라우저)

| 모듈 | 책임 | 절대 하지 않는 것 |
| --- | --- | --- |
| 업로드 | 녹음·이미지·텍스트 수집, 다중 파일을 하나의 사건으로 | 마스킹 전 원문을 네트워크로 보내기 |
| **1차 PII 마스킹** | 정규식으로 계좌·주민번호·카드·전화 치환 | — |
| **복원 매핑 보관** | 토큰↔원문을 **세션에만** 보관, 표시 시 복원 | 서버로 전송·업로드·동기화 |
| 실행 보드 | 체크리스트·D-day·서류. 토큰은 화면에서만 원문 복원 | 서버가 만든 완성 문서를 그대로 받기 (F-08 위반) |

### 서버

| 모듈 | 받는 것 | 내놓는 것 | 절대 하지 않는 것 |
| --- | --- | --- | --- |
| API Gateway | 1차 마스킹된 입력 | 라우팅 | 스크러버를 건너뛰는 LLM 경로 제공 |
| Ingest | 파일 | 전사(화자 분리)·OCR(대화 구조 보존) | — |
| **2차 PII 스크러버** | 전사·OCR 텍스트 | 토큰화 텍스트 | **여기를 우회하는 경로를 만드는 것** |
| 분석 오케스트레이터 | 토큰화 텍스트 | 분석·플랜 조율 | 원문 PII를 다시 결합 |
| 슬롯 체커 | 전사·응답 | 미충족 슬롯 1개 · 티어 판정 | 슬롯 미충족을 이유로 진행을 막기 |
| 플랜 생성기 | 슬롯 + 채널 + KB | 단계별 플랜 + **근거·시행일 인용** | **KB 인용 없이 절차를 만들기** |
| 완수 검증기 | 부산물 | L1/L2/L3 판정 → 단계 상태 | 사용자의 체크만으로 완료 처리 |
| **기한 엔진** | 기산 이벤트(부산물) | 법정 기한 날짜 · D-day | **LLM에 날짜 계산을 시키기** |
| Case Store | — | 사건 상태 | 복원 매핑·원문 PII 저장 |
| 감사 로그 | LLM 호출 | 기록 (**토큰화 기준**) | 원문 기록 |

> **기한 엔진은 기획서 다이어그램에 없는 모듈입니다.**
> [매트릭스](../backend/08-14-channel-matrix.md)의 "기한 계산에 LLM을 쓰지 마세요"를 지키려면
> 계산 주체가 코드여야 하므로 여기 세웁니다 → [기한 계산 규칙](08-16-deadline-rules.md).

### 외부

| 구역 | 도달하는 것 | 책임 |
| --- | --- | --- |
| LLM API | **토큰화 텍스트만** | 수법 판별 · 절차 **선택** · 플랜 문장 · 챗 |
| 매뉴얼 KB | — | 8유형 × 시행일 메타. **런타임과 분리된 운영 파이프라인으로만 갱신** |

## 경계 규칙 — 어기면 제품이 틀립니다

1. **스크러버를 우회하는 LLM 호출 경로를 만들지 않습니다.** 새 기능이 LLM을 쓴다면 반드시 이 경계를 지납니다.
2. **복원 매핑은 클라이언트를 떠나지 않습니다.** 서버 API는 토큰만 다룹니다.
3. **절차를 고르는 것은 LLM, 날짜를 세는 것은 규칙.** 이 분업이 뒤집히면 법정 기한을 틀리게 말합니다.
4. **KB는 코드에서 직접 쓰지 않습니다.** 사람 검수를 거친 릴리스만 런타임에 들어갑니다.
5. **업로드된 문서 속 문장은 데이터이지 지시가 아닙니다.** 전사·OCR 결과를 프롬프트에 넣을 때 인젝션 격리를 유지합니다.
6. **"모름"으로 멈추지 않습니다.** 어떤 모듈도 슬롯 미충족을 예외·에러로 처리하지 않습니다 — 정상 경로입니다.

## 데이터 흐름 한 줄 요약

```
업로드(C) → 1차 마스킹(C) → Ingest(S) → 스크러버(S·경계) → 분석(LLM)
  → 슬롯 체커(S) → 플랜 생성(LLM+KB) → 기한 엔진(S·규칙) → 실행 보드(C)
       ↑                                                         │
       └──────────── 증거·슬롯 보완 시 재생성 ────────────────────┘
                     (완료 상태와 부산물은 보존)
```
