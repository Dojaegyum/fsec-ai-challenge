# 모듈 경계 — 누가 무엇을 책임지는가

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §1 「전체 백엔드 아키텍처(개략)」 ·
> §3 격리 경계. 다이어그램의 노드를 **책임·입출력·금지**의 언어로 옮겼습니다.

**이 문서가 정하는 것** — 각 모듈이 무엇을 책임지고, 무엇을 받아 무엇을 내놓고, **무엇을 하면 안 되는가**.
경계를 어기면 [PII 격리 경계](08-14-pii-boundary.md)나
[LLM은 절차를 창작하지 않는다](../backend/08-14-kb-operations.md)가 무너집니다.

**이 문서가 정하지 않는 것** — 프로세스 분리 여부, 배포 단위, 통신 방식(HTTP·큐·함수 호출).
모듈은 **책임의 단위**이지 서버의 개수가 아닙니다. 물리 배치는 백엔드 스펙에서 정합니다.

## 세 구역

```
[클라이언트 · 층 C]       [서버]                        [외부]
원문 보유          ── 격리 경계 ──          토큰화 텍스트만 도달
pii-masker  ────────►  pii-tokenizer ──────────►  LLM API
key-handler               토큰화 텍스트 + 볼트 암호문   KB (버전드)
pii-restorer              감사 로그(토큰화 기준)
```

**서버·LLM 어디에도 "누구의 어떤 계좌"인지 완성된 정보가 존재하지 않는 구조**가 목표입니다.

## 모듈

### 클라이언트 (브라우저)

> 이름의 정본은 [모듈 명칭](08-16-module-names.md) 층 C이고, 그렇게 나눈 근거는
> [ADR-023](../../decisions/023-frontend-module-names.md)입니다.
> **2026-08-17 이전에는 「업로드」·「1차 PII 마스킹」·「복호화 키 보유」·「실행 보드」 네 덩어리였습니다** —
> 서버 모듈만 이름이 있고 클라이언트는 한국어 서술이라, 규칙을 어디에 붙일지가 없었습니다.

| 모듈 | 받는 것 | 내놓는 것 | 절대 하지 않는 것 |
| --- | --- | --- | --- |
| `pii-masker` | 사용자 입력·파일 | 1차 마스킹된 것 | **마스킹 전 원문을 네트워크로 보내기** |
| `key-handler` | 세션키 · 볼트 암호문 | 토큰↔원문 매핑 | **키를 서버·로그·DB로 보내기** → [ADR-009](../../decisions/009-restore-mapping-location.md) |
| `pii-restorer` | 토큰화된 표시 대상 | 복원 심사를 통과한 화면 | 복원 가능 목록 밖의 자리에서 펼치기 |
| `case-opener` | URL 토큰 | 사건 세션 | 토큰을 외부로 흘리기 · **잃은 링크를 복구해 주는 척하기** |
| `poll-checker` | 서버 응답·에러 | 갱신된 상태 | 스트리밍·웹소켓 쓰기 · 예외 종류로 분기하기 |
| `file-sender` | 파일 | 업로드 + 처리 상태 | **`pii-masker`를 건너뛴 업로드 경로 만들기** |
| `transcript-viewer` | 토큰화 전사 | 화면 (**전체 복원**) | 복원된 원문을 서버로 되돌려 보내기 |
| `plan-viewer` | `GET /plan` | 타임라인·단계·배지 | 사용자 체크만으로 완료 표시 · 조건부 단계 지우기 · **T0를 다른 것에 종속시키기** |
| `deadline-viewer` | `GET /deadlines` | D-day·유예·`info` | **날짜를 계산하기** · 지난 기한 지우기 · 환급을 카운트다운으로 만들기 |
| `chat-handler` | 발화 | 응답·슬롯 질문 버튼 | 인용 번호·판단 근거를 화면에 쓰기 · 「모름」 없애기 |
| `work-handler` | `referenced_steps` + 플랜 | 패널 하나 | **판정을 렌더 안에 섞기** · 「나중에 하기」 막기 · `WS-read`에 체크박스 두기 |
| `doc-filler` | 초안 + 매핑 | 완성 문서 | **서버가 만든 완성 문서를 그대로 받기** (F-08 위반) |

**`work-handler`의 「판정을 렌더 안에 섞기」가 이 표에서 유일하게 모듈 안쪽을 향한 금지입니다.**
판정(어느 단계 차례인가)과 렌더(그 유형을 그린다)를 한 모듈이 맡기로 했으므로
([ADR-023](../../decisions/023-frontend-module-names.md)), 경계가 이름이 아니라 **모듈 안의 규칙**으로만 남습니다.
섞이면 "왜 이 패널이 떴나"를 짚을 수 없습니다.

| 모듈 | 받는 것 | 내놓는 것 | 절대 하지 않는 것 |
| --- | --- | --- | --- |

| `case-intake` | 사건 생성 요청·파일 | 사건 · 업로드 자리 | — |
| `transcriber` | 파일 | 전사(화자 분리)·OCR(대화 구조 보존) | — |
| **`pii-tokenizer`** | 전사·OCR 텍스트 | 토큰화 텍스트 | **여기를 우회하는 경로를 만드는 것** |
| `case-reader` | 토큰화 텍스트 | 수법·위험도 + **근거 스팬** | 근거 없이 판정하기 |

| `planner` | 슬롯 + 채널 + KB | 단계별 플랜 + **근거·시행일 인용** | **KB 인용 없이 절차를 만들기** |
| `completion-checker` | 부산물 | L1/L2/L3 판정 → 단계 상태 | 사용자의 체크만으로 완료 처리 |
| **`date-checker`** | 기산 이벤트(부산물) | 법정 기한 날짜 · D-day | **LLM에 날짜 계산을 시키기** |
| `kb-finder` · `prompt-builder` · `citation-checker` | 사건 상태 · 발화 | 챗 한 턴 | 프롬프트에 없는 것을 답하게 두기 |
| `retry-checker` | 예외 | 재시도 여부 | 예외 종류로 분기하기 (`retryable` 만 봄) |
| Case Store | — | 사건 상태 | 복호화 키 저장 · 원문 PII 저장 |
| `audit-logger` | LLM 호출 | 기록 (**토큰화 기준**) | 원문 기록 |

**이름의 정본은 [모듈 명칭](08-16-module-names.md)입니다.** 여기는 **책임**을 정하고, 그쪽이 **이름**을 정합니다.

> **`date-checker` 는 기획서 다이어그램에 없는 모듈입니다.**
> [매트릭스](../backend/08-14-channel-matrix.md)의 "기한 계산에 LLM을 쓰지 마세요"를 지키려면
> 계산 주체가 코드여야 하므로 여기 세웁니다 → [기한 계산 규칙](08-16-deadline-rules.md).

| 구역 | 도달하는 것 | 책임 |
| --- | --- | --- |
| LLM API | **토큰화 텍스트만** | 수법 판별 · 절차 **선택** · 플랜 문장 · 챗 |

## 경계 규칙 — 어기면 제품이 틀립니다

1. **`pii-tokenizer` 를 우회하는 LLM 호출 경로를 만들지 않습니다.** 새 기능이 LLM을 쓴다면 반드시 이 경계를 지납니다.
2. **복원 매핑의 복호화 키는 클라이언트를 떠나지 않습니다.** 매핑 자체는 **암호문으로** 서버 볼트에 있고, 서버 API가 다루는 것은 토큰과 암호문뿐입니다 → [ADR-009](../../decisions/009-restore-mapping-location.md).
   > 2026-08-16 변경. 이전 규칙은 "복원 매핑은 클라이언트를 떠나지 않는다"였습니다. **3영업일 뒤 재방문해 서류를 만드는 것이 불가능했습니다.**
3. **절차를 고르는 것은 LLM, 날짜를 세는 것은 규칙.** 이 분업이 뒤집히면 법정 기한을 틀리게 말합니다.
4. **KB는 코드에서 직접 쓰지 않습니다.** 사람 검수를 거친 릴리스만 런타임에 들어갑니다.
5. **업로드된 문서 속 문장은 데이터이지 지시가 아닙니다.** 전사·OCR 결과를 프롬프트에 넣을 때 인젝션 격리를 유지합니다.
6. **"모름"으로 멈추지 않습니다.** 어떤 모듈도 슬롯 미충족을 예외·에러로 처리하지 않습니다 — 정상 경로입니다.

## 데이터 흐름 한 줄 요약

```
file-sender(C) → pii-masker(C) → transcriber(S) → pii-tokenizer(S·경계) → case-reader(LLM)
  → slot-checker(S) → planner(LLM+KB) → date-checker(S·규칙)
  → plan-viewer · deadline-viewer · work-handler (C)
       ↑                                                         │
       └──────────── 증거·슬롯 보완 시 재생성 ────────────────────┘
                     (완료 상태와 부산물은 보존)
```

**`(C)`가 브라우저, `(S)`가 서버입니다.** 끝이 하나가 아니라 셋인 것은
「실행 보드」라는 한 덩어리가 **세 모듈로 갈렸기** 때문입니다 → [ADR-023](../../decisions/023-frontend-module-names.md).
