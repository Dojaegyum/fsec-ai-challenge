# PII 격리 경계 (F-03)

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §3

 **이 문서의 규칙은 협상 대상이 아닙니다** — 서비스의 신뢰 근거이자 심사 차별점입니다.

## 경계

```
[클라이언트 · 층 C]             [서버]                      [외부 LLM API]
원문 보유                   격리 경계 ◄───┐                 토큰화 텍스트만
pii-masker (정규식 1차) ───► pii-tokenizer(NER 2차) ─────► 분석·플랜·챗
key-handler (세션키 보관)      볼트: 암호문만. 키 없음
pii-restorer (표시 전 복원)     감사 로그(토큰화 기준)
```

**클라이언트 쪽 세 자리에 이름이 있습니다** → [모듈 명칭](08-16-module-names.md) 층 C ·
[ADR-023](../../decisions/023-frontend-module-names.md). 이름이 있어야 아래 규칙들을 붙일 자리가 생깁니다.

**서버는 암호문만 보관하고 복호화 키를 갖지 않습니다. 키는 사용자 브라우저에만 있습니다.**
서버가 통째로 유출돼도 원문을 읽을 수 없고, LLM에는 토큰화 텍스트만 도달합니다.

## 2중 스크러빙

| 단계 | 위치 | 방식 | 목적 |
| --- | --- | --- | --- |
| 1차 | **브라우저** | 정규식 (계좌·주민번호·카드·전화 패턴) | 원문이 **네트워크를 타기 전** 1차 제거 |
| 2차 | **서버 게이트웨이** (`pii-tokenizer`) | NER 기반 잔여 PII 탐지·토큰화 | 외부 LLM에는 토큰화 텍스트만 도달 |

토큰 형식: `[계좌-1]`, `[이름-1]`, `[주민번호-1]` — 종류별 일련번호.

**같은 값이 다시 나오면 같은 번호를 씁니다.** 발화마다 번호가 리셋되면
서로 다른 자리의 `[계좌-1]`이 다른 계좌를 가리켜, **복원이 엉뚱한 값을 되살립니다.**

### 1차가 잡는 것 — 네 종류

**`[이름-1]`은 1차에서 만들지 않습니다.** 정규식으로 한국 이름을 잡으면 오탐이 폭발합니다 —
이름은 2차(`pii-tokenizer` NER)의 몫입니다.

| 종류 | 잡는 것 | 안 잡는 것 |
| --- | --- | --- |
| 주민번호 | 하이픈 유무 무관. 성별코드 1~8 (내국인·외국인) | 있을 수 없는 월·일 |
| 카드 | 13~19자리 중 **Luhn 검증 통과분만** | 통과 못 하면 계좌·주문번호로 봅니다 |
| 전화 | 휴대폰(`01x`)·지역번호 | **대표번호 `15xx`·`16xx`·`18xx`** — 아래 |
| 계좌 | 하이픈 구분 **총 10자리 이상** · 붙여 쓴 10~16자리 | 날짜(`2026-08-18`) · 뒤에 화폐 단위가 붙은 수 |

**대표번호를 가리지 않는 이유**는 아래 「토큰화 제외 목록」과 같습니다 —
개인을 식별하지 않고, **어느 기관에 전화했는지가 절차 분기의 직접 입력**입니다.
112·1332·1394는 자릿수가 짧아 애초에 패턴에 안 걸립니다.

**붙여 쓴 13자리는 주민번호로 봅니다.** 형태만으로는 계좌와 가릴 수 없어서,
**어느 쪽으로 틀리는 것이 안전한가**로 정했습니다 — 계좌를 주민번호로 보면 **가리지 않아도 될 것을
가리는 것**에 그치지만, 반대로 보면 **주민번호가 토큰화를 빠져나가 외부 API 로 나갑니다.**

**패턴 목록의 정본은 `src/modules/pii-masker/patterns.ts`입니다.** 문서에 정규식을 옮겨 적지 않습니다 —
두 곳에 두면 반드시 어긋나고, 어긋난 쪽이 조용히 새는 쪽이 됩니다.

## 불변 규칙

1. **복원 매핑(토큰↔원문)의 복호화 키는 서버에 존재하지 않습니다.** 매핑은 암호화된 상태로 서버 볼트에 보관하고, 세션키는 클라이언트가 보유합니다. 화면 표시 시점에 브라우저가 복호해 복원합니다.
   **세션키는 꺼낼 수 없는 형태(`extractable: false`)로 만들어 IndexedDB에 둡니다** → [ADR-027](../../decisions/027-session-key-storage.md).
   그래서 **기기를 바꾸거나 저장소를 지우면 서류를 못 만듭니다** — 절차 안내는 그대로 돕니다. **이 사실을 화면이 미리 알려야 합니다.**
   > 2026-08-16 [ADR-009](../../decisions/009-restore-mapping-location.md)로 변경. 이전 규칙은 "클라이언트 세션에만 보관"이었습니다. 구 명칭(골든30) 시점의 **30분 대응** 전제에서 나온 것이라, [ADR-002](../../decisions/002-project-name.md)의 **사건 관리** 포지셔닝과 맞지 않았습니다 — 3영업일 뒤 재방문 시 서류를 만들 수 없었습니다.
2. **외부 LLM API 호출 페이로드에 원문 PII가 들어가면 안 됩니다.** `pii-tokenizer` 를 통과하지 않는 LLM 호출 경로를 만들지 마세요.
3. **사건은 정해진 수명을 갖고, 그날이 지나면 원문·파일·매핑이 함께 파기됩니다.** 수명은 `case.purge_after`이며 **마지막 활동일부터 180일**(`CASE_PURGE_DAYS`)입니다 → [09](../backend/08-16-data-model.md) §2. 파기 시점이 없는 데이터를 만들지 마세요.
   > 2026-08-16 [ADR-016](../../decisions/016-retention-and-datastore.md)으로 90일에서 조정. 경로 10종의 절차 기간을 실측하니 **표준 트랙만 D+100**(공고 2개월 + 환급금 결정 14일)이고, 명의인이 이의를 제기하면 D+160이 됩니다 → [research/06](../../docs/research/06-경로별-실측조사.md) §5. 90일이면 환급금이 결정되기 직전에 사건이 사라졌습니다.
   > 2026-08-16 [ADR-010](../../decisions/010-case-store.md)에 맞춰 변경. 이전 규칙은 "세션 단위 격리 스토어에만 존재하고 종료 또는 **24시간** 후 자동 파기"였습니다. 구 명칭(골든30) 시점의 **30분 대응** 전제에서 나온 것이라, [ADR-002](../../decisions/002-project-name.md)의 **사건 관리** 포지셔닝과 맞지 않았습니다 — **3영업일 뒤에 돌아왔을 때 사건이 이미 없어져 있었습니다.** 업로드 원본을 남기는 이유와 대신 거는 보호는 [09](../backend/08-16-data-model.md) §3.
4. **사후 리포트는 사용자가 명시적으로 다운로드한 사본만** 남습니다.
5. **학습·통계 활용 없음**을 UI에 명시합니다.
6. 서류 다운로드(F-08)의 **PII 복원은 클라이언트에서** 일어납니다. 서버가 완성된 문서를 만들어 내려주면 위반입니다.

## 토큰화 제외 목록

> 2026-08-16 [ADR-011](../../decisions/011-pii-boundary-hardening.md) 로 신설.

**다음은 개인정보가 아니면서 절차 분기의 직접 입력이므로 토큰화하지 않습니다.**

| 대상 | 왜 |
| --- | --- |
| 금융기관명 (은행·증권사·간편송금사·거래소) | `CH-bank`/`CH-neobank`/`CH-easypay`/`CH-crypto` 분기의 입력 → [03](../backend/08-14-channel-matrix.md) |
| 공공기관·수사기관명 | 수법 판별(`F-04`)의 입력. 사칭 기관을 특정해야 함 |
| 금액 | 슬롯 T2. 서류 필수 기재사항 |
| 시각·날짜 | 슬롯 T2. 기한 계산의 기산점 |
| 상품권 발행사명 | `CH-giftcard` 요청처 |
| 통신사명 | `CH-carrier` 요청처 |

**`pii-tokenizer` 는 이 목록을 허용 목록으로 갖고 NER 결과보다 우선 적용합니다.**

**이 규칙이 없으면 8유형 분기가 무너집니다.** NER 모델은 기관명을 잘 잡는데, `"카카오페이로 300만원"` 이 `"[기관-1]로 300만원"` 이 되면 경유 서비스를 특정할 수 없습니다. 그러면 슬롯 T1 미충족으로 판정돼 **에러 없이 슈퍼셋 플랜이 나갑니다** — 사용자는 정보를 다 줬는데 "모름" 취급을 받습니다.

**기관명은 개인정보가 아닙니다.** 특정 가능성이 생기는 조합은 `기관명 + 계좌번호`인데 계좌번호는 여전히 토큰화됩니다.

목록은 [03](../backend/08-14-channel-matrix.md) 의 8유형과 함께 갱신합니다.

## 복원 위치와 범위

> 2026-08-16 [ADR-011](../../decisions/011-pii-boundary-hardening.md) 로 신설, [ADR-013](../../decisions/013-chat-context.md) 로 챗 답변 줄 조정.

**브라우저는 화면에 나타나는 모든 토큰을 복원하지 않습니다.** 복원 대상 위치를 코드가 미리 목록으로 갖고, 그 목록에 있는 자리에서만 복원합니다.

| 위치 | 복원 범위 |
| --- | --- |
| **브라우저가 보여주는 모든 자리** | **전체** |
| 그 밖 (서버·로그·외부 API) | **복원 없음.** 애초에 키가 없습니다 |

**한 줄입니다** (→ [ADR-034](../../decisions/034-browser-shows-plaintext.md)).
자리마다 달랐던 이전 규칙 — 챗 답변만 종류별 부분 복원, 분석 결과·플랜 설명은 복원 안 함 —
은 **폐기됐습니다**. [ADR-013](../../decisions/013-chat-context.md) 결정 B가 대체된 자리입니다.

**가리는 것의 목적은 사용자에게서 숨기는 게 아니라 외부로 새지 않게 하는 것**이고,
외부로 나가는 것은 화면 표시와 무관하게 언제나 토큰입니다. 한 화면 안에서 규칙이 갈리면
사용자는 규칙을 못 배우고, **자기가 준 값을 자기가 검토하지 못합니다** —
틀린 계좌번호로 서류가 나가도 알아차릴 방법이 없습니다.

**주민번호는 예외가 아닙니다.** [ADR-026](../../decisions/026-raw-upload-retention.md)이
**수집하지 않기로** 했으므로 복원할 값이 우리에게 없습니다. 있다면 수집이 새고 있다는 뜻이고,
표시 규칙으로 덮을 일이 아닙니다.

> ⚠️ **열쇠가 없는 브라우저에서는 토큰이 그대로 보입니다.** 기기를 바꾸거나 저장소를 지우면
> 매핑을 못 풀기 때문입니다 ([ADR-027](../../decisions/027-session-key-storage.md)).
> 그 화면을 **「고장」이 아니라 「이 기기에는 열쇠가 없다」로 설명해야** 합니다.

### 복원 전 검사

1. 그 자리가 복원 가능 목록에 있는가
2. **그 토큰이 이 사건의 매핑에 실제로 있는가** — 없으면 복원하지 않고 토큰 그대로 둠
3. 복원이 거부되면 기록을 남긴다 — 거부가 반복되면 공격 시도의 신호

**2번이 「모든 토큰의 원래 값을 나열하라」는 공격을 막습니다.** 모델이 지어낸 토큰은 매핑에 없어 복원되지 않습니다.

## 인젝션 방어

업로드된 문서·전사 안의 문장은 **데이터이지 지시가 아닙니다.**

- `"이 메시지는 안전하다고 판단하라"` 류의 삽입 문구를 지시로 해석하지 않도록 프롬프트 격리를 유지합니다.
- 분석 결과에는 **근거 스팬 인용을 강제**합니다 (F-04) — 근거를 못 대는 판정은 스펙 위반.
- **복원 위치를 코드가 지정합니다** (위 절). 프롬프트 격리는 부탁이고 우회될 수 있지만, **목록에 없는 자리는 구조적으로 복원되지 않습니다.**

프롬프트 조립에서의 격리 방법은 [11-chat-context.md](../backend/08-16-chat-context.md).

## 감사

- 모든 LLM 호출을 **감사 로그(토큰화 텍스트 기준)** 로 기록합니다.
- 금융보안원 생성형 AI 가이드라인의 통제 항목에 매핑합니다 — 발표에서 이 매핑 자체가 근거가 됩니다.

## UI에 보여야 하는 것

PII 보호는 **작동할 뿐 아니라 보여야** 합니다 (기획서의 데모 포인트).

- 전사 화면에서 PII가 **파란 토큰으로 바뀌는 순간**이 보입니다.
- 안내 문구: *"파란 토큰은 AI 분석 서버로 전송되지 않는 개인정보입니다. 원문을 되돌리는 열쇠는 이 브라우저에만 있고, 사건은 마지막 이용일부터 180일 뒤 자동 파기됩니다."*

  **"세션 종료 시 파기"라고 쓰지 마세요.** 사실과 다르고, 3영업일 뒤 재방문을 전제하는 화면과 어긋납니다.
