# 사용자 여정 — 경우별

> **출처가 다릅니다.** 다른 `spec/` 문서는 기획서 HTML 에서 추출했지만, 이 문서는
> **구현본 `src/` 를 읽어서** 세웠습니다 (기준 `feat/pii-pending-and-copy` · 2026-08-21).
> 그래서 이 짝에서는 **이 문서가 정본이고** [읽기용 아티팩트](../../assets/artifacts/plans/08-21-user-journeys.html)가
> 사본입니다 — 평소와 방향이 반대이니 헷갈리지 마세요
> (평소 규칙은 [CLAUDE.md](../../CLAUDE.md) 「spec과 아티팩트의 관계」).

## 이 문서가 하는 일

[서비스 골자](08-17-service-concept.md) 「여정 — 여섯 국면」이 **세로축(시간)** 을 그립니다.
이 문서는 **가로축(경우)** 입니다 — 같은 국면 2에 있어도 대면편취인 사람과 은행 계좌이체인
사람은 다른 화면을 봅니다.

**여정은 화면 목록이 아닙니다.** 화면이 무엇처럼 생겼는지는
[화면 설계](../frontend/08-14-screens.md)에 있습니다. 여기 있는 것은
**어떤 사람이 어디로 흘러가고, 어디서 갈라지고, 어디서 끝나는가**입니다.

**「구현」 칸은 계약이 아니라 사실입니다.** 계약과 어긋난 자리를 숨기지 않으려고
같은 표에 두었습니다 — 다르면 아래 「어긋난 자리」에 이유가 있습니다.

## 여정을 가르는 것 — 갈림길 여덟

| # | 갈림길 | 값 | 무엇이 갈리나 | 정한 곳 |
| --- | --- | --- | --- | --- |
| **①** | **이메일을 줬나** | 있음 / 없음 | **180일 관리 ↔ 일회성 조회.** 가장 큰 갈림길입니다 | [ADR-021](../../decisions/021-reentry-and-identity.md) |
| ② | 트랙 | `victim` / `frozen_account` | 절차가 통째로 다릅니다 | [data-model](../backend/08-16-data-model.md) §2 |
| ③ | 경유 서비스 | `CH-*` 여덟 | 요청처·기한·환급 가능 여부 | [channel-matrix](../backend/08-14-channel-matrix.md) |
| ④ | 슬롯 티어 | T0 / T1 / T2 | 플랜의 정밀도. **막지는 않습니다** | [slot-tiering](../backend/08-14-slot-tiering.md) |
| ⑤ | 자료 처리 결과 | `done`·`processing`·`failed`·`pending` | 증거함 본문 | [screens S-08](../frontend/08-14-screens.md) |
| ⑥ | **PII 를 풀 수 있나** | 같은 기기 / 다른 기기 | 값이 보이나, 복사가 되나 | [pii-boundary](08-14-pii-boundary.md) · [ADR-034](../../decisions/034-browser-shows-plaintext.md) |
| ⑦ | 재진입 시점 | 첫 방문 / 며칠 뒤 / 두 달 뒤 | **첫 화면이 챗이냐 플랜이냐** | [screens](../frontend/08-14-screens.md) 「무엇으로 고르나」 |
| ⑧ | 누가 보나 | 본인 / 가족 | **아무것도 안 갈립니다** — 권한 구분이 없습니다 | [ADR-021](../../decisions/021-reentry-and-identity.md) |

**①과 ⑦이 곱해집니다.** 이메일을 안 준 사람은 리마인더가 없으므로 ⑦의 「며칠 뒤」가
**스스로 기억해서 올 때만** 일어납니다. 우리가 만들 수 있는 여정이 아닙니다.

**⑧이 갈리지 않는 것은 결정이지 누락이 아닙니다.** 링크를 아는 사람이 곧 주인이고,
가족용 축소 화면을 따로 두지 않습니다.

## 여정 A — 표준 (`victim` · `CH-bank` · 이메일 있음)

**나머지 여정은 전부 이 줄기에서 갈라집니다.** 기준선으로 삼으세요.

| 국면 | 어디 | 사용자가 하는 것 | 시스템이 하는 것 | 구현 |
| --- | --- | --- | --- | --- |
| 0 발견 | 검색 결과 | 검색해서 들어옴 | — | — |
| 1 | **`/` (S-04)** | 「지금 시작하기」 **하나** | 112 우선 안내 · 환급 미보장 고지 | **섬** |
| 1 | **`/start` (S-05) 1/2** | 동의 전문 → 조항 다섯 확인 → Q1 하나 → (선택) 자료 올리기 | 동의만 관문. 자료·문진은 건너뛸 수 있음 | **UI만** |
| 1 | **`/start` 2/2** | 주소 복사 · 이메일 입력 | 링크 발급 | **UI만** |
| 1 | **`/c/{token}` · 본문 챗** | 진술을 적음 | T0 레일 즉시 노출 · 슬롯 추출 · 한 번에 한 문항 | **UI만** |
| 2 | 본문 챗 + **오른쪽 워크스페이스** | 대본 읽고 전화 · 접수번호 받아적기 | `WS-call` · 부산물로 완료 판정 | **UI만** |
| 3 | **본문 플랜 (S-07)** | 「지금 하실 일은 하나」 | 기한 계산 · D-day | **UI만** |
| 3 | **본문 기재 안내 (S-10)** | 칸마다 값 복사 → 은행에 제출 | 서식 칸과 값을 짝지음. **서류를 만들지 않음** | **UI만** |
| 3 | 본문 증거함 (S-08) | 접수증 올리기 | 전사·마스킹 · 부산물 판정 | **UI만** |
| 4 | 본문 플랜 | **할 일이 없음** | 「공고 2개월」 카드 · 통지 해독 · 명의도용 점검 | **UI만** |
| 5 | 본문 플랜 | 결과 확인 | 결정 → 환급 또는 장기화 | **없음** |
| — | — | 닫거나, 그냥 안 옴 | 마지막 활동일 **+180일** 파기 | **`case-purger` 있음** |

**국면 1의 성공은 우리 화면에 머무는 것이 아니라 112·1332 로 나가는 것입니다.**
T0 레일이 본문 밖 왼쪽에 고정된 이유가 이것입니다 — 국면이 바뀌어도 안 사라집니다
([ADR-036](../../decisions/036-t0-rail.md)).

## 여정 B — 이메일 없이 (`①` = 없음)

**A 와 화면이 같습니다. 다른 것은 「다시 온다」가 없다는 것 하나입니다.**

| | A | B |
| --- | --- | --- |
| 기한 알림 | 이메일 | **없음** |
| 링크를 잃으면 | 메일 본문의 링크로 복구 ([ADR-039](../../decisions/039-link-token.md) ③) | **사건을 통째로 잃습니다** |
| 실질 | 180일 관리 | **일회성 조회** |

- **막지 않습니다.** 거절 버튼 이름이 「이메일 없이 시작하기」이고, 무엇을 포기하는지가
  버튼 이름에 있습니다. 경고는 입력칸 **옆에 같은 크기**로 둡니다.
- **검증하지 않습니다.** 오타는 알림이 안 갈 뿐이고 여기서 사용자를 막지 않습니다.
- ⬜ **오타로 못 받은 사람과 안 준 사람이 화면에서 구별되지 않습니다.** 둘 다 아무 일도
  안 일어나는데, 전자는 자기가 알림을 받는 줄 압니다.

## 여정 C — 건너뛰고 바로 시작 (`④` = T0)

**`/start` 에서 「건너뛰고 바로 시작」은 주 버튼과 같은 크기로 나란히 있습니다.**
동의만 하고 Q1·자료를 전부 지나칩니다.

| | |
| --- | --- |
| 무엇이 남나 | **T0 넷** — 112 · 1332 · 추가 송금 금지 · 비행기모드 |
| 플랜 | **슈퍼셋** — 유형을 모르면 넓게 잡습니다 |
| 어떻게 좁아지나 | 챗에서 진술이 쌓이는 만큼. **한 번에 한 문항** |

**정보를 안 줬다고 화면이 멈추지 않습니다** ([CLAUDE.md](../../CLAUDE.md) 불변 규칙 5).

## 여정 D — 며칠 뒤 재진입 (`⑦`)

**빈 챗창이 뜨면 관리 서비스가 아닙니다.** 그래서 도착지가 다릅니다.

```
plan.steps 가 비어 있지 않으면 → 본문 플랜      그 밖 → 본문 챗
지금 할 단계가 있으면          → 오른쪽 워크스페이스   그 밖 → 사건 파일
```

- **서버가 「이 화면을 열어라」라고 지목하지 않습니다.** 응답의 사실로 `case-opener` 가
  고릅니다 ([API 계약](08-14-api.md) §3.10).
- **`focus: "evidence"` 로는 열지 않습니다.** 증거함은 눌러서 가는 곳이지 도착지가 아닙니다.
- 첫 로드는 **`GET /api/cases/{case_token}` 하나**입니다. 셋을 따로 부르면 첫 화면까지
  왕복이 넷이고 그동안 빈 화면입니다.

## 여정 E — 대면편취 (`③` = `CH-facetoface`)

**안내 순서가 역전됩니다.**

| | 표준 (A) | 대면편취 |
| --- | --- | --- |
| 첫 단계 | 송금은행에 지급정지 | **112 신고** |
| 왜 | 계좌를 아니까 | **피해자가 직접 지급정지를 못 합니다** — 계좌를 수사기관이 특정합니다 |

**T0 의 「112」가 이 트랙에서는 T0 가 아니라 절차의 1번입니다.** 같은 항목이 유형에 따라
안내인지 단계인지가 달라집니다.

## 여정 F — 사각지대 (`③` = `CH-giftcard` · `CH-carrier`)

**환급 절차가 없습니다.** 통신사기피해환급법의 대상이 아닙니다.

| | |
| --- | --- |
| 할 수 있는 것 | 발행사 핀 사용정지 시도 · 통신사 결제 차단 · 분쟁조정(소비자원) · 형사 절차 |
| 하면 안 되는 것 | **「신청하면 돌려받습니다」로 읽히게 쓰는 것** |
| 재발 방지 | 소액결제 차단 설정 안내 |

**이 트랙에서 D-day 를 띄우지 마세요.** 셀 법정 기한이 없습니다.

## 여정 G — 가상자산 (`③` = `CH-crypto`) · 시행일이 여정을 가릅니다

| 피해 시점 | 여정 |
| --- | --- |
| **2026.10 이후** | 환급 대상. 코인 단위 반환 또는 전담기관 매도 후 금전 지급 (평가는 **지급정지 시점** 기준) |
| 그 전 | **형사 절차 중심** — 환급 트랙이 아닙니다 |

**같은 사용자, 같은 화면인데 날짜 하나로 여정이 갈립니다.** 그래서 절차를 코드에
박지 않고 KB 의 `effective_from` 으로 가릅니다 ([CLAUDE.md](../../CLAUDE.md) 불변 규칙 1).

## 여정 H — 통장묶기 (`②` = `frozen_account`)

**피해자가 아니라 억울하게 묶인 사람입니다.** 사기범이 남의 계좌에 소액을 넣어
그 계좌를 묶는 수법이라, 우리가 아는 절차가 통째로 안 맞습니다.

| | |
| --- | --- |
| 무엇을 하나 | 소명자료 제출 → **5영업일 안에 결과 통보** (2026.5~ 표준화) |
| 어디서 갈리나 | **Q1 「내 계좌가 갑자기 묶였어요」** |
| 화면 | 같은 셸을 씁니다. 플랜의 내용만 다릅니다 |

⬜ **MVP 포함 여부가 미정입니다** ([channel-matrix](../backend/08-14-channel-matrix.md)).
**그런데 Q1 선택지에는 이미 있습니다** — 고르면 갈 곳이 없습니다. 아래 「어긋난 자리」.

## 여정 I — 가족이 링크로 들어옴 (`⑧`)

**본인과 완전히 같은 화면입니다.** 계정·권한·열람 범위 구분이 없습니다.

| | |
| --- | --- |
| 어떻게 오나 | 헤더의 **「가족에게 링크 보내기」** 로 주소를 받아서 |
| 무엇이 다른가 | **아무것도.** 이것이 결정입니다 |
| 왜 | 공유가 전제인 서비스에서 무효화·권한 분리는 반대 방향입니다 ([ADR-039](../../decisions/039-link-token.md) ⑥) |

**단 ⑥(PII 복원)에 걸립니다** — 아래 여정 K 와 같은 상태가 됩니다.

## 여정 J — 자료가 처리되지 않을 때 (`⑤`)

| 상태 | 무엇이 보이나 | 사용자가 할 수 있는 것 |
| --- | --- | --- |
| `pending` | 「아직 차례를 기다리는 중입니다」 | 기다리기 |
| `processing` | 「가리는 중 74%」 + **원본은 아직 이 브라우저 안에** | 기다리기 |
| **`failed`** | 「주민번호를 못 가려 제외됨」 | **「다른 파일 올리기」 또는 「없이 진행」** |
| `done` | 전사 본문 | 읽기 |

**`failed` 는 막는 자리가 아니라 갈림길입니다.** 그 파일 하나만 빠지고 사건은 갑니다.
**빨강이 아니라 앰버**입니다 ([ADR-026](../../decisions/026-raw-upload-retention.md)).

**애초에 안 받는 것이 낫습니다** — 업로드 자리에 「신분증·주민등록증은 올리지 마세요」를 씁니다.

## 여정 K — 다른 기기에서 열기 (`⑥`)

**복호화 키는 그 브라우저에만 있습니다.** 링크를 다른 기기에서 열면 값이 안 풀립니다.

| | 같은 기기 | 다른 기기 |
| --- | --- | --- |
| 서류 기재 안내 | 값이 보이고 복사됨 | **가려진 칩** (`계좌·2`) · 복사 불가 |
| 무엇이라고 말하나 | — | **「고장이 아닙니다」** |

**이것을 에러로 그리지 마세요.** 설계대로 동작한 것이고, 사용자에게는 「원래 그렇다」로
읽혀야 합니다.

## 여정 L — 끝

| | |
| --- | --- |
| 언제 끝나나 | **사용자가 닫을 때.** 닫기 전까지는 열려 있습니다 |
| 수명 | **마지막 활동일 + 180일** — 닫혔든 열려 있든 같습니다 |
| 무엇이 지워지나 | 볼트 → 객체 저장소 → DB 순. **`audit_log` 는 남습니다** |

**순서가 계약입니다.** DB 행이 「무엇을 지워야 하는가」의 유일한 단서라 마지막입니다 —
먼저 지우고 뒤에서 실패하면 어디에 뭐가 남았는지 알 방법이 없습니다.

⬜ **`localStorage` 는 이 셋 밖입니다.** S-10 의 「어디까지 옮겼는지」가 기기에 남고,
파기 대상에 안 들어 있습니다 → [ADR-016](../../decisions/016-retention-and-datastore.md).

## 지금 구현본에서 여정이 끊기는 자리

**아래는 계약 위반이 아니라 「아직 안 이은 것」입니다.** 화면은 전부 목 데이터로 돕니다.

| 어디 | 무엇이 끊겨 있나 |
| --- | --- |
| **`/start` → `/c/{token}`** | **버튼 셋(`저장하고 시작하기`·`이메일 없이 시작하기`·`건너뛰고 바로 시작`)이 아무 데도 안 갑니다.** 라우팅도 `useRouter` 도 없습니다 |
| 사건 주소 | `CASE_URL` 이 상수입니다 (`finally.kr/c/7fK2p-Qx9mR4`). **`fin-ally` 가 아니라 `finally` 로 적혀 있습니다** |
| 축을 고르는 것 | 서버 시그널 대신 **개발용 스위치**(`?view=` · 우하단 dev 버튼)가 대신하고 있습니다 |
| 전 화면 | `GET /api/cases/{case_token}` 미연결 — 슬롯·플랜·기한·전사가 전부 파일 안 상수 |
| `action: "confirm"` | **패널이 없어 `panelFor` 가 `null` 을 돌려줍니다.** KB 에 그 단계를 넣는 순간 **화면에서 조용히 사라집니다** |
| S-11 | 핸드오프만 받아 뒀고 화면이 없습니다 — 「이 답변에 무엇이 나갔나」가 여정에 없습니다 |
| S-03 피싱 백신 | 없습니다 (부가 기능) |
| 국면 5 | 결정·환급 화면이 없습니다 |

**임의로 맞추지 않았습니다** ([CLAUDE.md](../../CLAUDE.md) 「spec과 아티팩트의 관계」).

### ✅ 「앱에서 신청」 대 「영업점 서면」 — **해소됐습니다** (2026-08-21)

`plan.tsx` 는 「국민은행 **앱에서** 제출하세요」, `doc.tsx` 는 「**영업점에 서면** 제출」이라
서로 다른 곳을 가리키고 있었습니다. **기한이 3영업일 안쪽이라 헛걸음이 그대로 손해입니다.**

**둘 중 하나를 고르지 않았습니다** → [ADR-042](../../decisions/042-submit-paths.md).

| | |
| --- | --- |
| 무엇이 바뀌었나 | `org.contact.submit_place`(문자열) → **`submit`(배열)**. 앱과 영업점을 **함께** 담습니다 |
| 순서 | **배열 순서가 곧 권장 순서.** 화면이 정렬하지 않습니다 — 「앱이 먼저」를 코드에 박으면 KB·NH 사용자가 앱을 뒤지다 3영업일을 씁니다 |
| 지금 데이터 | KB·NH 는 `branch` 하나. **나머지 다섯은 빈 배열** — 그러면 카드를 아예 그리지 않습니다 |
| 지도 | **임베드하지 않습니다.** 「가까운」을 우리가 정하려면 **사용자 위치**가 필요하고, 얻는 것은 은행 공식 지점찾기보다 못합니다. `submit[].url` 로 내보냅니다 (⬜ [U-31](../../docs/research/05-미확인-목록.md)) |

**두 화면이 이제 같은 값을 봅니다.** `plan.tsx` 히어로는 제출처를 말하지 않고
「무엇을 적는지 보기」로 넘기고, `doc.tsx` 의 첫 카드가 `submit` 을 순서 그대로 그립니다.

> **`spec/` 세 곳이 틀렸던 것도 함께 고쳤습니다.** 「서면 신청은 낡은 표현」이라고
> 적혀 있었는데 **1차 출처는 반대**였습니다 — 「낡은 표현」이 아니라 **「기관마다 다른 것」**입니다.

### ✅ 랜딩의 폐기된 약속 셋 — **고쳤습니다** (2026-08-21)

랜딩은 2026-08-19 에 마감됐고 아래 결정들은 **그다음 날** 나왔습니다.

| 이전 | 지금 | 왜 |
| --- | --- | --- |
| 카드 3 「서류를 **만들어** 드립니다」 | 「서류는 **칸마다 짚어** 드립니다」 | [ADR-037](../../decisions/037-doc-guidance-not-generation.md) — 만들지 않습니다 |
| 「서류 **초안까지 만듭니다**」 | 「서류는 칸마다 짚어 드립니다」 | 같음 |
| 「**파란 토큰 = 서버로 안 갔다는 뜻**」 | 「가려진 값은 **이 기기에서만 풀립니다**」 | [ADR-034](../../decisions/034-browser-shows-plaintext.md) 이후 앞 문장은 **사실이 아닙니다** |

**셋 다 「덜 해주는 쪽」으로 옮겼습니다.** 랜딩은 기대치를 관리하는 자리인데
반대로 부풀리고 있었습니다.

### ⬜ Q1 에 갈 곳 없는 선택지가 있습니다

「내 계좌가 갑자기 묶였어요」를 고르면 `frozen_account` 트랙인데,
**그 트랙은 MVP 포함 여부가 미정**입니다. 고르게 해놓고 안 받으면 안 됩니다 —
**넣거나, 선택지에서 빼거나** 둘 중 하나입니다.

### ⬜ 「3영업일」이 확정이 아닙니다

랜딩이 「3영업일·2개월 같은 법정 기한」이라 쓰고 있는데,
[U-30](../../docs/research/05-미확인-목록.md) 이 **「3일」과 「3영업일」이 출처마다 다르다**고
남겨 뒀습니다. `src/kb/common.json` 의 `deadline` 이 전부 `null` 인 것도 같은 이유입니다.
