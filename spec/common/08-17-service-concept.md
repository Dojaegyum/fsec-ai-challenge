# 서비스 골자 — 무엇을 약속하고 무엇을 약속하지 않는가

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §0을
> 그 뒤에 확정된 결정들과 대조해 **다시 세운 것**입니다. 차이는 아래 「§0에서 바뀐 것」이 전부입니다.

**이 문서가 정하는 것** — 이 서비스가 무엇이고, 무엇이 아니고, 누가 어디서 들어와 어떻게 돌아오는가.
화면·기능·데이터 판단이 갈릴 때 **거슬러 올라와 대조하는 자리**입니다.

**이 문서가 정하지 않는 것** — 화면 구성([화면 설계](../frontend/08-14-screens.md)) ·
기능 목록([기능명세](08-14-features.md)) · 엔티티와 상태([도메인 모델](08-16-domain-model.md)).

## 무엇인가

> 보이스피싱 피해자가 **진술만 하면**, 자기 사건에 맞는 절차를 찾아주고
> **기한과 서류를 몇 달에 걸쳐 대신 관리**하는 웹서비스.

이름의 근거는 [ADR-002](../../decisions/002-project-name.md)입니다 — Fin(금융) + Ally(동행자), 그리고 *Finally*.

## 무엇이 아닌가

**이 셋은 기능 범위가 아니라 정체성입니다.** 어기면 다른 서비스가 됩니다.

| | 왜 |
| --- | --- |
| **112를 대체하지 않는다** | 신고 **이후**의 며칠~몇 달을 맡습니다. 긴급 신고를 우리 화면 안에서 처리하려 들면, 가장 급한 순간에 사용자를 붙잡아 두는 셈이 됩니다 |
| **"알려주는 서비스"가 아니다** | 3영업일을 설명하는 글은 이미 넘칩니다. **사건을 대신 관리**하는 것이어야 합니다 — 알림 하나가 전부면 은행 앱이 흡수합니다 |
| **받을 수 있다고 말하지 않는다** | 자율배상은 1년 4개월간 41건 · 피해액의 0.1% · 평균 116일이었습니다. **"대상인지 진단해주는 것"**까지가 우리 몫입니다 |

## 누가 쓰는가

| | 누구 | 무엇을 전제하나 |
| --- | --- | --- |
| **주 사용자** | 방금 당한 본인 | **패닉 상태이고 고령 비중이 높습니다.** 한 화면에서 요구하는 판단을 최소화하고, 접근성을 기능으로 취급합니다 → [접근성 기준](../frontend/design-system/08-16-accessibility.md) |
| **함께 보는 사람** | 가족 | **링크를 공유해 같은 화면을 봅니다.** 별도 계정·권한·열람 범위 구분이 없습니다 → [ADR-021](../../decisions/021-reentry-and-identity.md) |

## 어디서 들어와 어떻게 돌아오는가

| | 정한 것 | 근거 |
| --- | --- | --- |
| **진입** | **검색·직접 접속.** 상담 종료 후 링크 유입은 기대하지 않습니다 | 우리가 제어할 수 없는 경로에 진입을 걸 수 없습니다 |
| **진입 플로우** | **랜딩 → 개인정보 사용동의 + 기본 데이터 선택 제공 → 챗 인터페이스** | [진입 플로우 초안](../../assets/artifacts/plans/08-16-entry-flow-mockup.html) |
| **재진입** | **익명 링크 토큰 — URL이 곧 열쇠.** 계정·로그인이 없습니다 | [ADR-021](../../decisions/021-reentry-and-identity.md) |
| **알림** | **이메일만 선택 입력.** 안 주면 알림이 없고 **일회성 조회로 끝납니다 — 이 차이를 UI에 적습니다** | [ADR-021](../../decisions/021-reentry-and-identity.md) |
| **종결** | **사용자가 닫을 때.** 닫기 전까지는 열려 있습니다 | ↓ 「언제 끝나는가」 |
| **수명** | **마지막 활동일 + 180일**. 닫혔든 열려 있든 같습니다 | [ADR-016](../../decisions/016-retention-and-datastore.md) |

**진입 경로를 검색으로 잡은 것이 랜딩의 역할을 정합니다.** 상담원이 건넨 링크로 들어오는 사람은
이미 한 번 걸러진 사람이지만, 검색으로 오는 사람은 **여기가 뭐 하는 곳인지 모르는 상태**입니다.
랜딩은 그 사람을 3초 안에 납득시켜야 합니다.

## 증거는 관문이 아니다

녹음·스크린샷·이체내역이 **있으면 받습니다.** 있으면 슬롯이 자동 추출돼 플랜이 정밀해집니다
→ [슬롯 티어링](../backend/08-14-slot-tiering.md) T2.

**없어도 진술만으로 시작합니다.** T0는 진입 자체로 충분하고, 공통 안전 절차가 즉시 나갑니다.

> ⚠️ **제공을 요구해 사용자를 막는 흐름을 만들지 마세요.**
> 두 번째 화면의 데이터 제공은 **선택**이고, 「건너뛰고 바로 시작」이 같은 화면에 함께 보입니다.
> 관문이 될 수 있는 것은 **동의(법적 필수)뿐**입니다.

## 기기 — 하나의 반응형 웹서비스입니다

**「모바일 앱」도 「데스크톱 전용」도 아닙니다. 웹서비스 하나이고, 화면 폭에 맞춰 배치가 달라집니다.**

**심사위원이 배포된 주소를 받아 자기 기기에서 엽니다.** 제출물이 라이브 데모가 아니라
**웹서비스 주소**이기 때문입니다 → [AGENDA 제출물](../../docs/context/AGENDA.md).
어느 폭에서 열려도 깨지지 않는 것이 취향이 아니라 **제출 요건에 가깝습니다.**

> ⚠️ **화면마다 「폰용」·「데스크톱용」을 정하지 마세요.** 그렇게 나누는 순간 한쪽이 이류가 되고,
> 실제로는 **같은 사용자가 같은 사건을 두 폭에서 오갑니다** — 통화는 폰으로, 서류는 큰 화면으로.
> 계정이 없어 URL로 이어지므로, **폭이 바뀌어도 같은 주소가 같은 사건을 엽니다.**

**모든 화면은 두 폭을 다 지원합니다.** 다만 국면마다 주로 쓰일 폭이 달라, 어느 쪽을 먼저 맞춰야
하는지는 다릅니다 — 이건 **설계 우선순위지 지원 범위가 아닙니다.**

| 국면 | 자주 열리는 폭 | 왜 |
| --- | --- | --- |
| 최초 진입 · 리마인더 확인 · 기다리는 구간 | 좁은 폭 | 방금 당한 사람이 손에 든 것으로 검색해 들어옵니다 |
| 증거 업로드 · 서류 작성 · 사건 보드 | 넓은 폭 | 파일을 다루고 여러 정보를 나란히 봅니다 |

기획서 §0이 데스크톱을 고른 근거 셋 중 ①(사무 작업형 UX)·②(가족이 함께)는 그대로 유효하고,
**③(빔프로젝터·노트북 심사 환경)은 이 대회의 심사 방식이 아니므로 폐기합니다.**

## 핵심 구조 — 사건 파일(Case)

증거·분석·플랜·체크리스트·서류·기한이 **하나의 사건 폴더로 묶입니다.**
[도메인 모델](08-16-domain-model.md)의 관계 트리가 `Case`에서 시작하는 것이 이 사상의 표현입니다.

180일 관리로 옮겨오면서 오히려 더 맞아졌습니다 — 몇 달에 걸친 상태가 매달릴 곳이 필요합니다.

**"3-패널 상황실"은 여기서 뺍니다.** 그건 사상이 아니라 레이아웃 선택이고,
[진입 플로우 초안](../../assets/artifacts/plans/08-16-entry-flow-mockup.html)은 이미 3-패널이 아닙니다.
레이아웃은 [화면 설계](../frontend/08-14-screens.md)에서 정합니다.

## §0에서 바뀐 것

| §0이 말한 것 | 지금 | 왜 |
| --- | --- | --- |
| 증거를 "제공할 수 있다"가 **입력 가정** | 증거는 **선택**, 진술이 시작점 | 전제 자체는 유지되지만, 거기서 나온 **첫 화면이 업로드 화면**이었던 것이 틀렸습니다 |
| 데스크톱 전용 · 모바일 P1 | **반응형** | 심사가 라이브 데모가 아니라 배포 주소 제출 |
| 데스크톱 근거 ③ = 심사 데모 환경 | **폐기** | 이 대회의 심사 방식이 아님 |
| 핵심 설계 사상 = Case 중심 **+ 3-패널** | Case 중심**만** | 레이아웃은 사상이 아님 |
| (없음) | **무엇이 아닌가** 3항 | 골자의 절반이 빠져 있었습니다 |
| (없음) | **재진입·수명** | 30분 서비스에는 필요 없던 칸 |

## 언제 끝나는가

**사건은 사용자가 닫을 때 끝납니다.** 시스템이 판단해 닫지 않습니다.

| | |
| --- | --- |
| **종결 주체** | 사용자. 환급 결정이 났든, 사각지대라 받을 것이 없든, **닫는 것은 사람이 합니다** |
| **닫기 전까지** | 열려 있습니다. 절차가 끝난 것처럼 보여도 이의제기로 두 달이 더 붙을 수 있습니다 |
| **수명** | **닫아도 `case.purge_after`는 그대로 180일입니다.** 닫자마자 지우지 않습니다 |

**닫아도 바로 지우지 않는 이유**는 잘못 닫는 것이 되돌릴 수 없기 때문입니다.
닫은 뒤에 통지가 오거나 이의제기가 붙는 경우가 있고([경로별 실측조사](../../docs/research/06-경로별-실측조사.md) §2),
그때 다시 열 수 있어야 합니다. 파기는 [ADR-016](../../decisions/016-retention-and-datastore.md)의 규칙 하나로만 일어납니다.

> **"끝났습니다"를 시스템이 먼저 선언하지 마세요.** 환급 결정이 나도 명의인 이의제기로 2개월이 얹힐 수 있고,
> 카드·명의도용은 3년 창이 따로 남습니다. 우리가 아는 것은 "지금까지 할 일이 없다"까지입니다.
