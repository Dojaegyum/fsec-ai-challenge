# 도메인 모델 — 무엇이 사건에 매달리는가

> **출처** — [서비스 기획서 v1.2](../../assets/artifacts/plans/08-13-service-plan.html) §0 · §1 · §2 · §4 · §5 를
> 기존 spec([용어](08-14-glossary.md) · [슬롯 티어링](../backend/08-14-slot-tiering.md) ·
> [완수 검증](../backend/08-14-completion-hook.md) · [경유 서비스 매트릭스](../backend/08-14-channel-matrix.md))과
> 대조해 **엔티티 단위로 다시 정리**한 것입니다. 새 사실을 추가하지 않았습니다.

**이 문서가 정하는 것** — 어떤 것이 존재하고, 무엇에 매달리고, 어떤 상태를 가지며,
**어느 쪽에 저장되면 안 되는가**. 백엔드·프론트가 같은 이름으로 같은 것을 가리키기 위한 계약입니다.

**이 문서가 정하지 않는 것** — 테이블·컬럼·타입·인덱스·정규화 수준. 물리 스키마는 백엔드 스펙에서 정합니다.
여기는 그 **입력**입니다.

## 관계

```
Case (사건)  ── 이 서비스의 모든 상태가 매달리는 최상위 단위
 ├─ Evidence*      업로드된 증거 (녹음·이미지·텍스트)
 │   └─ Transcript   전사·OCR 결과 (F-02)
 ├─ Analysis       수법 분류·위험도·근거 스팬 (F-04)
 ├─ Slot*          플랜 생성에 필요한 정보 조각 (T0/T1/T2)
 ├─ Plan           생성된 대응 절차 — 재생성되면 새 버전
 │   ├─ PlanStep*    번호 매겨진 실행 단계
 │   │   ├─ Artifact*   부산물 (접수번호·접수 문자·접수증)
 │   │   └─ Deadline?   법정 기한 (규칙으로 계산 · 별도 문서)
 │   └─ (인용) KbEntry  단계의 근거 — KB 항목 참조
 ├─ ChatMessage*   대응 비서 챗 이력 (F-07)
 └─ Document*      서류 초안 (F-08 · P1)

Channel (경유 서비스)   참조 데이터 — 사건이 가리키는 코드표, 8유형
KbEntry / KbRelease     버전드 절차 지식 — 사건에 매달리지 않음
AuditLog                모든 LLM 호출 기록 (토큰화 텍스트 기준)
```

`*` 여럿 · `?` 있을 수도 없을 수도.

## 엔티티

| 엔티티 | 무엇 | 근거 |
| --- | --- | --- |
| `Case` | 증거·분석·플랜·체크리스트·서류·기한을 묶는 최상위 단위 | §0 핵심 설계 사상 |
| `Evidence` | 사건에 첨부된 녹음·이미지·텍스트. **다중 파일이 하나의 사건** | F-01 |
| `Transcript` | STT(화자 분리)·OCR(대화 구조 보존) 결과. 증거에 종속 | F-02 |
| `Analysis` | 수법 분류·위험도·**근거 스팬**. 근거 없는 판정은 스펙 위반 | F-04 |
| `Slot` | 송금 여부·수단·기관·금액·시각 등. 티어(T0/T1/T2)와 확정 여부를 가짐 | [슬롯 티어링](../backend/08-14-slot-tiering.md) |
| `Channel` | 돈이 지나간 금융 서비스 유형. **절차 분기의 축** | [매트릭스](../backend/08-14-channel-matrix.md) |
| `Plan` | 사건 상황에 맞춰 생성된 단계별 절차. KB 근거 인용 동반 | F-05 |
| `PlanStep` | 플랜의 실행 단계. 완료 판정의 단위 | §5 |
| `Artifact` | 절차 수행이 남기는 부산물. **완료 판정의 근거이자 다음 단계의 입력** | [완수 검증](../backend/08-14-completion-hook.md) |
| `Deadline` | 단계에 붙는 법정 기한. **규칙으로 계산** → [기한 계산 규칙](08-16-deadline-rules.md) | [매트릭스](../backend/08-14-channel-matrix.md) |
| `ChatMessage` | 사건 컨텍스트를 유지하는 Q&A 이력 | F-07 |
| `Document` | 피해구제신청서·자율배상 신청 초안 (P1) | F-08 |
| `KbEntry` · `KbRelease` | 절차 지식 항목과 그 버전. **출처 링크·시행일 메타 필수** | [KB 운영](../backend/08-14-kb-operations.md) |
| `AuditLog` | LLM 호출 기록 — 토큰화 텍스트 기준 | §1 · §3 |

### 사건에 매달리지 않는 것

- **`Channel`** 은 사건마다 만드는 것이 아니라 **8개짜리 코드표**입니다. 사건은 그중 하나(또는 미확정)를 가리킵니다.
- **`KbEntry`·`KbRelease`** 는 사건과 무관하게 **운영 파이프라인으로만** 갱신됩니다. 사건은 인용할 뿐입니다.
- **피싱 백신(F-09 · P1)** 은 사건이 아니라 가족 단위 훈련 데이터라 이 트리 밖입니다.
  훈련 데이터는 가족 계정에만 보관합니다 → [화면 설계 S-03](../frontend/08-14-screens.md).

## 상태 — 값의 집합은 계약입니다

**상태 집합 자체는 확정**입니다(spec 근거 있음). 괄호 안 코드 식별자는 **제안**이고, 백엔드 스펙에서 확정합니다.

### PlanStep — 완료 판정의 핵심

```
미시작 → 진행중 → 완료(증빙됨)
   │        └→ 미확인            (L3 자기신고)
   └→ 건너뜀                     (플랜 재생성 시 해당 없어짐)
```

| 상태 | 뜻 | 식별자(제안) |
| --- | --- | --- |
| 미시작 | 아직 손대지 않음 | `not_started` |
| 진행중 | 착수했으나 부산물 없음 | `in_progress` |
| 완료(증빙됨) | 부산물이 L1 또는 L2를 통과 | `done_verified` |
| 미확인 | 사용자가 했다고만 말함 (L3) | `unconfirmed` |
| 건너뜀 | 이 사건에 해당 없음 | `skipped` |

**식별자는 [데이터 모델](../backend/08-16-data-model.md) §6 에서 확정됐습니다.** 위 표의 값이 정본입니다.

- **`미확인`은 종결 상태가 아닙니다.** 리마인더 추적 대상으로 남습니다.
- **사용자의 체크만으로 `완료(증빙됨)`가 되는 경로를 만들지 마세요.** 이 기능의 존재 이유가 사라집니다.

### 검증 레벨 — Artifact에 붙습니다

| 레벨 | 방식 | 결과 |
| --- | --- | --- |
| `L1` | 접수번호 포맷 체크 · 접수증 OCR 대조 | 완료(증빙됨) |
| `L2` | 캡처·서류 업로드 (**PII 스크러버 통과 필수**) | 완료(증빙됨) |
| `L3` | 자기 신고 | 미확인 |

### Slot — 티어와 확정 여부

| 티어 | 슬롯 | 없을 때 |
| --- | --- | --- |
| `T0` | (없음) | 공통 안전 절차 즉시 제공 |
| `T1` | 송금 여부 · 송금 수단 | 버튼 1문항 → **"모름" 상시 제공** → 보수적 슈퍼셋 플랜 |
| `T2` | 기관명 · 금액 · 시각 · 경과시간 · 상대 연락수단 | 증거 자동 추출 우선, 실패 시 질문, 미확정은 **'미확인' 배지** |

슬롯은 **값과 함께 출처**를 가집니다 — 자동 추출인지, 사용자 응답인지, "모름"인지가 구분돼야
플랜 재생성 시 무엇을 다시 물을지 판단할 수 있습니다.

### Channel — 8유형 + 미확정

`CH-bank` · `CH-neobank` · `CH-securities` · `CH-easypay` · `CH-crypto` · `CH-facetoface` ·
`CH-giftcard` · `CH-carrier` → 정의는 [매트릭스](../backend/08-14-channel-matrix.md).

**미확정("모름")은 오류가 아니라 정상 값**입니다. 채널 없이도 플랜이 생성됩니다.

## 저장 경계 — DDL에 존재하면 안 되는 것

[PII 격리 경계](08-14-pii-boundary.md)의 불변 규칙을 **데이터 모델의 언어로** 옮긴 것입니다.
**이 표를 어기는 컬럼이 하나라도 생기면 서비스의 신뢰 근거가 무너집니다.**

| 데이터 | 클라이언트 | 서버 | 외부 LLM |
| --- | --- | --- | --- |
| 업로드 원본 파일 | 보유 | 객체 저장소 · `case.purge_after` 에 파기 | ✗ |
| 원문 PII (계좌·주민번호·전화·이름) | 보유 | ✗ (`pii-tokenizer` 통과 후 토큰만) | ✗ |
| **복원 매핑의 복호화 키** | **여기에만** | **✗ 절대** | ✗ |
| 복원 매핑 (암호문) | — | 볼트에 보관 · 키 없음 | ✗ |
| 토큰화된 전사·분석 텍스트 | 표시용 복원 | 보유 | 보유 |
| 부산물(접수번호 등) | 보유 | TODO — 아래 미결 ① 참조 | ✗ |
| 감사 로그 | — | 보유 (**토큰화 기준**) | — |

- **복호화 키를 담는 테이블·컬럼·로그·캐시를 만들지 마세요.** 클라이언트에만 존재합니다.
  매핑 자체는 암호문으로 볼트에 있고, **서버는 그것을 풀 수 없습니다** → [ADR-009](../../decisions/009-restore-mapping-location.md).
- **`pii-tokenizer` 를 우회하는 저장 경로를 만들지 마세요** — 업로드된 접수증도 통과합니다.
- 학습·통계 활용 없음을 UI에 명시하므로, **분석용 사본 테이블도 만들지 않습니다.**

| --- | --- |
| 토큰화된 사건 상태 | `case.purge_after` |

**원본을 남기는 대신** 객체 저장소를 저장 시 암호화하고 사건별 키를 씁니다. 즉시 파기하면 **전사·판독 오류를 되돌릴 수 없고**, 충격 상태의 사용자에게 재업로드를 요구하게 됩니다.

**진입 플로우의 동의 문구("24시간 후 자동 파기")를 같이 고쳐야 합니다** → [진입 플로우 초안](../../assets/artifacts/plans/08-16-entry-flow-mockup.html). **아직 안 고쳤습니다.**

### ③ KB의 저장 위치 — **해소됨**

> 2026-08-16 [ADR-012](../../decisions/012-kb-collection.md) 으로 **관계형 DB** 결정.

**조회 조건이 세 개 축(기관·유형·시행일)의 조합**이라 파일에서는 매번 전부 읽어 걸러야 합니다. 시행일 분기(`effective_from`/`effective_until`)를 조건으로 거는 것도 DB 쪽이 자연스럽습니다.
